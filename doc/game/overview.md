# ゲーム概要

[企画索引](README.md) / [探索と進行](../features/stage-progression.md) / [戦闘システム](../features/combat.md)

「てくてくダンジョン」は、現実の歩数が運動量「ACT」として異世界側の力になる健康×ハクスラRPGである。
[初期企画](brief.md)と2026-09-15のユーザー提示仕様を基に、2026-09-27の[企画見直し](redesign-2026-09-27.md)で戦闘・運動連動・ダンジョン・課金を大きく変更した。
個々のルールと数値は[節の区分](../rules/documentation-policy.md#mdの形式と状態)を区別して読む。

## 確定している方針

| 項目 | 方針 |
|---|---|
| 正式ゲーム名・アプリ表示名 | てくてくダンジョン |
| 内部コードネーム・リポジトリ名 | `baryonyx` |
| 対象 | Android先行のスマートフォンRPG |
| 基本体験 | 現実で歩く → ルーンを得る → RPGで戦う・育てる → さらに歩く |
| 運動の位置づけ | 運動しないと遊べないゲームにはせず、歩くほど成長しやすく、冒険を有利にする。対象は当面、歩数だけとする |
| 課金の位置づけ | 課金しないと進めない設計にはしない。ルーンは販売しない |

4人パーティで、Slay the Spireのような分岐ルートを選びながらダンジョンを進み、深奥のボスを目指す。
戦闘はターン制のカードバトルとし、4人の固有スキル・スキル・アイテムを合わせたデッキと、毎ターン決まった量のエネルギーで戦う（[エネルギーとコスト](../features/combat/rules.md#エネルギーとコスト)）。
負けると冒険は終わって次は1階からになるが、獲得した装備・スキルなどは残る。
詳細は[戦闘](../features/combat.md)と[探索と進行](../features/stage-progression.md)を正本とする。

## 設計方針

### 優先するプレイヤー体験

「短時間でも進展がある」「自分の一手が効く」「育成で以前より楽になる」「負けても獲得した装備・スキルを失わない」を優先する。
装備と育成で強くなり、以前勝てなかった敵の撃破や、より深い階への到達につながる体験を目指す。
放置を主目的にせず、プレイヤーの判断が戦況を変えるゲームにする。

待ち時間、損失への不安、過剰な操作を減らす。
負けると1階からやり直すため、序盤の階が作業にならない工夫を検討する（工夫は[未決](../features/stage-progression/status.md#未決事項)）。
戦闘での判断や攻略の歯ごたえは残す。

### コアループ

```text
歩いてルーンを得る
    ↓
ルーンでレベルアップする／装備・スキル・編成を見直す
    ↓
冒険に出て、分岐ルートから行き先を選ぶ
    ↓
カードバトル・スキルと装備とアイテムの獲得
    ↓
深奥のボスを目指して先へ進む／マスの区切りで中断する
    ↓
負けたら冒険終了（獲得物は残る）、またはルーンで復活して続ける
```

ルーンの受け取りや強化を毎戦必須の操作にはしない。
運動していない日も遊べる。
歩かない日のペナルティは設けず、歩いて得たルーンが育成と冒険を後押しする。
ルーンの用途と経済数値は[ルーン経済](../features/economy.md)、冒険の進め方は[探索と進行](../features/stage-progression.md)で管理する。

### 短いプレイの積み重ね

従来の「1セッション15分」は想定例であり、15分の連続プレイを要求しない。
冒険はマスの区切りで中断し、次回は続きから再開できる。
1回の冒険の長さの目安とマスの数は、[冒険の道とマスの数](../features/stage-progression/run.md#冒険の道とマスの数)を正本とする。

## 今回採用しない方針

街発展・街づくりは、いったん入れない。
依頼、スタミナ・挑戦回数制限など、機能ごとの対象外は[各機能仕様](../features/README.md)に記す。

## 実装との対応

歩数の同期とルーンの獲得（[起動時の連携と歩数の同期](../features/startup-sync.md)）、編成・商会・神殿・ライブラリ、冒険の世界地図と探索・戦闘の1周（[画面一覧](../features/screens.md)）を試作として実装した。
機能ごとの実装の状況は、[機能索引](../features/README.md)から各文書の「実装との対応」を見る。
深度に応じた敵などは未実装であり、コアループ全体が実装済みであることは意味しない。
アプリ表示名は[Player Settingsの `productName`](../../client/ProjectSettings/ProjectSettings.asset)で管理する。
AndroidのApplication IDとAPKファイル名は[既存のビルド設定](../rules/client-android-testing.md)を維持する。
