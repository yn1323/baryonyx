# MVPと企画の判断基準

[企画索引](README.md) / [戦闘システム](../features/combat.md) / [探索と進行](../features/stage-progression.md)

## 確定している方針

2026-09-15のユーザー提示仕様に基づき、最初の戦闘試作とプレイヤー目線の評価基準を定める。
ゲーム全体のMVPと初回リリース範囲は引き続き未決である。
企画全体の機能一覧を、そのまま最初のリリース範囲と扱わない。

### 最初に作る戦闘試作

ボスの大技予告、ダウン、スロー、キャストタイム、個別クールダウンを中心に検証する。
以下は試作の範囲であり、完成版のキャラ数やスキル数、最終的なバランス値ではない。

| 対象 | 最初の範囲 |
|---|---|
| パーティ | 4人 |
| アクティブスキル | 各キャラ2つ |
| 固有パッシブ | 少数。各キャラ1つ程度を仮設定とする |
| 通常敵 | 数種類 |
| ボス | 1体 |
| 装備効果 | 少数 |
| 追撃 | 詳細を決めてから最小の例を加える。現在は詳細の議論を保留 |

戦闘の判断と手応えを先に確かめるため、複数エリア・大量のキャラ・起爆・連携予約などは先に作らない。
具体的なキャラ・スキル・パッシブ・敵行動・装備効果は未確定とする。
[戦闘時間](../features/combat.md#戦闘時間の仮目標)と[スキル性能のサンプル](../features/combat.md#スキル性能の数値サンプル)は比較・試作用の仮設定であり、個別性能としての採用は未確定とする。

### 検証する3場面

| 場面 | 確認すること |
|---|---|
| 通常戦 | 少ない介入でも、技を使った手応えがあるか |
| 初回ボス | 同じ手順の反復でなく、温存・ダウン・防護を判断する場面があるか |
| 強化後の再挑戦 | 以前より早く楽に倒せ、成長を実感できるか |

### 合意した品質基準

1. クールダウン完了のたびに全スキルを押す作業にしない。
2. ダウンは有利だが必須ではなく、敵を常時拘束するだけの戦闘にしない。
3. キャストタイムを内部に持たせても、入力への反応と、ダウン後に落ち着いて攻める余裕を確保する。
4. 標的・リング・大技予告・ダウン表示を、派手な演出で隠さない。
5. 無料での再挑戦を普通に選べるようにし、ルーン復活への圧力を作らない。

「残していた技で大技を止めた」「ダウン中に大きく削れた」「装備を替えたら狙った流れが成立した」が、実際に気持ちよく感じられるかを最重視する。

## 判断を記録する形式

範囲を決めたら、対象・対象外・理由・受入条件・対応する仕様へのリンクを記す。
計測を採用する場合は、収集項目・目的・保存期間・利用者への説明も決める。
このページへの項目追加だけでは、計測や機能の採用を決定しない。
