# MVPと企画の判断基準

[企画索引](README.md) / [戦闘システム](../features/combat.md) / [探索と進行](../features/stage-progression.md)

## 確定している方針

ゲーム全体のMVPと初回リリース範囲は未決である。
企画全体の機能一覧を、そのまま最初のリリース範囲と扱わない。

2026-09-15に決めた最初の戦闘試作と品質基準は、リアルタイムのセミオート戦闘を検証するためのものだった。
2026-09-27の[企画見直し](redesign-2026-09-27.md)で戦闘をターン制のカードバトルへ変更したため、これらを[変更と判断の記録](#変更と判断の記録)へ移した。
カードバトルの試作範囲と評価基準は未決である。

## ワイヤー後の体験評価

2026-09-19の[ユーザー評価](../features/game-wireframe.md#2026-09-19のユーザー評価と残った課題)では、ワクワク感と楽しさの中心をまだ判断できていない。
探索の改善要求は[ダンジョン内の見た目による行き先選択](../features/stage-progression.md#ダンジョン内の見た目による行き先選択)に反映する。
グラフィックの追加によって面白さも解決すると確定せず、次の観点で体験を評価する。

| 評価すること | 確かめる内容 |
|---|---|
| 現在地と行き先の分かりやすさ | 自分たちがどこにいて、どの入口へ進めるかを画面から読み取れるか |
| 進路を選ぶ理由 | 見た目と短いヒントから先を想像し、行きたい入口を選べるか |
| 進んだ実感 | 選んだ入口への移動と次の部屋の表示で、場所が変わったことが分かるか |
| 冒険を続ける動機 | 先が気になる、獲得物を使いたい、強くなって再挑戦したいと感じられるか |

仮の絵と簡単な演出で短い一連の体験を作る案は、会話で挙がった検証方法の候補とする。
最初に試す場面、必要な戦闘・報酬の実装範囲、合格とする評価方法は未決である。

## 判断を記録する形式

範囲を決めたら、対象・対象外・理由・受入条件・対応する仕様へのリンクを記す。
計測を採用する場合は、収集項目・目的・保存期間・利用者への説明も決める。
このページへの項目追加だけでは、計測や機能の採用を決定しない。

## 実装との対応

2026-09-19に、旧仕様の試作として4人・各2スキル・通常敵・1体のボス・少数のパッシブと装備効果を実装した。
画面は2026-09-24に削除し、戦闘計算だけがコードに残っている（[戦闘の実装との対応](../features/combat.md#実装との対応)）。
この計算は現行のカードバトルと一致せず、扱いは開発者と相談して決める。
現在の実装は[機能索引](../features/README.md#現在の実装)を参照する。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| 最初の戦闘試作では、ボスの大技予告、ダウン、スロー、キャストタイム、個別クールダウンを中心に検証する。4人、各キャラのアクティブスキル2つ、固有パッシブ1つ程度、数種類の通常敵、ボス1体、少数の装備効果 | 旧戦闘の試作範囲として使わない。カードバトルの試作範囲は未決 |
| 検証する3場面（通常戦で少ない介入でも手応えがあるか、初回ボスで温存・ダウン・防護を判断できるか、強化後の再挑戦で成長を実感できるか） | 旧戦闘の評価場面として使わない |

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様を根拠に、最初の戦闘試作、3つの検証場面、5つの品質基準を反映した。キャスト・ダウン・温存の手応えを検証するための範囲であり、ゲーム全体のMVPや完成版の数値は確定しない。戦闘とパーティの仕様からこの試作範囲を参照する。
