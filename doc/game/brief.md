# 初期企画の記録

[企画索引](README.md)

2026-09-13にユーザーが提示した企画を、確度を保って整理した記録である。
同日の追加指示により、この企画で述べた内容以外は未決として扱う。
後続の仕様決定は各仕様に理由と日付を記録し、この初期入力を書き換えて過去の合意を作らない。

## ゲームの核

- 現実の運動が異世界側の力になる、健康×ハクスラRPG。
- Android先行のスマートフォンRPG。歩行・ランニング・自転車などを進行に利用する。
- 運動しないと遊べないゲームにはしない。運動と目標達成で成長しやすくする。
- 現代×王道ファンタジー。現実の活動が異世界の主人公たちへ力として送られる。
- 運動 → ルーン獲得 → ステージ選択 → 2〜4分戦闘 → 装備・素材獲得 → キャラ・装備強化 → より高難度へ。
- 1セッションは15分程度を想定する。

## 健康と目標

- Androidの取得元はHealth Connectへ一本化する。
- 歩数、ウォーキング、ランニング、サイクリング、運動時間、距離、運動セッションなどを利用する方針。
- Strava・Fitbit・Samsung HealthなどからHealth Connectを経由する構造を基本とし、ゲームから各サービスへ直接接続しない。各サービスの対応状況をこの入力で確認したものではない。
- 現実活動から得る主軸資源を「ルーン」とする。キャラクター育成、装備・素材、ガチャなどに使える汎用資源とする方向。
- 厳密な消費カロリー計算はせず、METの思想を取り入れた簡略な運動価値を使う方向。活動強度を補正する。「歩行 < 速歩 < ランニング」は例であり、係数は未決。
- 年齢・性別・体格まで使った厳密な補正は現状行わない方向。
- 単純な運動量よりも、自分で目標を立てて達成することを重視する。
- 目標の例は1日8,000歩、週20kmの歩行、30分ランニング、19〜21時の運動、週3回の運動。初期値・必須目標として決定したものではない。
- 未達成ペナルティは設けない。達成時のルーン倍率上昇・ボーナス報酬を想定する。
- 簡単すぎる目標の係数を下げるなど、難易度との連動は検討中。
- 基本運動報酬より、目標を立てて達成した報酬が大きくなるバランスを狙う。

## パーティと戦闘

- 4人パーティ固定。キャラは固定職業、固有スキル、固有パッシブ、装備可能な武器・防具を持つ。転職は今のところ入れない。
- リアルタイム＋セミオート。通常攻撃は自動、スキルはプレイヤー操作。
- 各キャラのアクティブスキルは2〜3個。パーティ共通スキルゲージと個別クールダウンを使う。
- 別の必殺技ゲージは設けない。スキル選択中は時間が強くスローになる。
- 敵の次の行動を予告する。防御・回復・妨害で対応し、攻撃チャンスにバフを重ねる判断を楽しさにする。
- 雑魚複数戦と単体ボス戦を用意する。基本のクリア条件は敵全滅。
- 敗北時のルーン減少、装備ロスト、挑戦回数減少は設けない。

## ハクスラと収益化

- 同じ装備でもレア度・付与効果・数値幅をランダムにする。
- 装備×パッシブ×スキル×パーティ構成でシナジーを作る。倍率が積み重なり、数字が伸びる気持ちよさを狙う。
- ステージの危険度を選択でき、危険度が高いほど敵強化・報酬量上昇・高レア装備率上昇につながる。
- スタミナ・挑戦回数制限は設けない。
- 全ユーザー共通のデイリー変異は検討中。敵攻撃力上昇・特定属性強化・回復量低下は条件の例。
- キャラガチャ、武器ガチャ、ルーン購入、目標達成などの報酬倍率上昇、追加キャラなどは収益化の候補。
- 運動や課金をプレイ・進行の必須条件にはしない。

## ビジュアルと技術

- 2D / HD-2D寄り。キャラはSNES後期程度の小型ドット絵、オクトパストラベラー方向の王道ファンタジー。
- 戦闘時はドット絵、ステータス・ガチャなどでは高品質イラストを使う方向。
- 街発展・街づくりはいったん入れない。
- Unity、Android、Health Connect、GitHub、GitHub Actions、CSharpier、Microsoft.Unity.Analyzers、.editorconfigを基本構成とする。
- iOSを出す場合はHealthKitを別途実装する。
