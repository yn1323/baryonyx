# 保存先の決め方の変更と判断の記録

[保存先の決め方](data-storage.md)

- 2026-11-02：スキルとdocの整理で、今のコードに合わせて、獲得したスキルとアイテムの保存を「実装済み」にし、PlayerPrefsに表示設定を書くデバッグルームの一覧に4つを足した（根拠：server/migrations/0013_drops.sql の `skill_cards`・`item_holdings`、InventoryLab.cs・BattleMomentLab.cs・ExplorationMomentLab.cs・TempleSummonLab.cs のキー）。
- 2026-10-29：ユーザーの依頼で、入れ子の地図のマスを開くルーンの支払いを楽観的更新にした（[マスを開くルーン](../features/world-atlas/maps.md#マスを開くルーン)）。手元の配置の値段で払えるかを決めてすぐ跳び、サーバーの答えた残高を確かめた残高にする。受けなかった支払いは、あとから払ったマスとまとめて取り消し、駒を開けているマスへ戻す。
- 2026-10-29：入れ子の地図でルーンを払って開けたマスをサーバーに、開発用の消費のオンオフを端末に置いた（[マスを開くルーン](../features/world-atlas/maps.md#マスを開くルーン)）。払ったマスはルーンの増減を伴い、消えると払い直しになるため、[判断の基準](data-storage.md#判断の基準)からサーバーにした。複数マスを進むときの確認を省く選択は、ユーザーの指示「clientだけで保持する情報」によりメモリーにだけ持ち、起動し直すと戻る。
- 2026-10-25：画面を開いたときの待ち時間を減らすため、前に読んだ内容を先に出す画面を、ライブラリ・旅の案内所のお宝・商会の「買う」へ広げ、互いに依存しない読み込みを同時に行うようにした（[サーバーに置くときの作り方](data-storage.md#サーバーに置くときの作り方)）。ライブラリの記録は、見つけた物と日々の歩数を別々に読んでいたものを同時に読む。商会の「売る」「合成」「品質強化」は、選んだ物をサーバーへ送る画面で、前に読んだ内容に売った物や前の倍率が残りうるため、先に出さずに同時に読むだけにした。読み直せなかったときに出している内容を残す扱いは、パネルの共通部品（`GuidePanel`）にまとめた。
- 2026-10-22：ユーザーの「キャラのスキル表示に1秒ちょっとかかる」を受け、開き直した画面で前に読んだ編成と装備をすぐ出し、裏で読み直すようにした（[サーバーに置くときの作り方](data-storage.md#サーバーに置くときの作り方)）。あわせて、育成・装備の画面は編成と装備を同時に読み、同時に届いた要求のログインを1回にまとめた。Devで測ると、育成の画面の約1.1秒は、DBとの往復と端末からサーバーまでの経路にかかり、画面を描く時間は数msだった（[処理時間の計測](backend-design.md#処理時間の計測server-timing)）。対象は編成の一覧・育成・スキル・育成の人選び・装備の付け替えで、ボーナスとライブラリは今までどおり読むまで「読み込み中…」を出す。参考：[stale-while-revalidate](https://developer.dynatrace.com/develop/guides/code-optimization/stale-while-revalidate/)。
- 2026-10-18：ユーザーの依頼で、戦闘で開示した敵の弱点をサーバーに保存するようにし、[置き場所の一覧](data-storage.md#置き場所の一覧)の行を「実装済み」にした。3つの問いではどちらにも決め手が弱い（消えても遊べ、書き換えても弱点が見えるだけ）が、仕様が開示を「プレイヤーの記録」としていること、機種変更やデータの削除のあとも残ることから、サーバーを提案し、ユーザーが選んだ。
- 2026-10-18：ユーザーの依頼で、装備・仲間などの変更を楽観的更新にした（[サーバーに置くときの作り方](data-storage.md#サーバーに置くときの作り方)）。ユーザーは「基本的に、待たないと次が何もできない箇所以外は楽観的更新に」とし、ルーンを使うレベルアップも含めた。編成の枠・スキル・装備・ACTボーナスの付け替えとレベルアップをすぐ表示し、冒険の開始・報酬・復活・終了・マスの移動は保存を待つまま残した。サーバーのAPIは変えていない。
- 2026-10-18：ライブラリで新しく載った項目を「もう見た」記録は、消えても印がもう一度付くだけで困らないため、ユーザーの判断で端末に置くことにし、[端末に置くもの](data-storage.md#端末に置くもの)に加えた。
- 2026-10-18：[ライブラリ](../features/library.md)の設計で、一度でも手に入れた物と遭遇した敵の記録をサーバーに置く方針をユーザーが了承したため、[置き場所の一覧](data-storage.md#置き場所の一覧)に加えた。所持の記録は売却や合成で消えるため、別の記録として持つ。
- 2026-10-06：持ち物にアクセサリー・アイテム（道具・素材）・合成の記録が加わり、スキルを1枚ずつ持つことになったため、「獲得したスキル・素材」の行を分け、どれも「案」として[置き場所の一覧](data-storage.md#置き場所の一覧)に加えた（[持ち物の分類](../features/inventory.md)）。保存先は作るときにユーザーに確かめる。
- 2026-10-05：ユーザーの指示で、編成で付け替える装備を最初からサーバーに保存することにし、持っている装備とキャラごとの武器・防具を「実装済み」にした。付け替えは装備やルーンを増減させないため、要求IDは付けていない。獲得したスキルと、商会で売り買いする素材は「案」のまま残した。
- 2026-10-04：探索の分岐ルートを冒険ごとに作る形にし、サーバーには道を作る乱数の種と、今いるマスの階と種類を保存することにした。ユーザーは「途中の進捗はUnity内に保存する形でOK」としたが、進み具合は再開や別の端末で失わないよう、これまでどおりサーバーに置き、道そのものは種から端末が作る形にした。マスの種類を端末から受け取ることは、未決事項に加えた。
- 2026-10-04：ユーザーの依頼で、保存先を決める基準と、今の置き場所の一覧を定めた。消えたら困るもの・書き換えられたら困るものをサーバーへ、端末ごとに違ってよいもの・消えても作り直せるものを端末へ置く。保存先が未決の項目は「案」として載せ、仕様の決定は変えていない。この基準で作業を進める [data-storage](../../.agents/skills/data-storage/SKILL.md) スキルを作った。
