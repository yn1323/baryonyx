# 効果音とBGM

[設計・開発ルールの索引](README.md) / [外部素材のクレジット](credits.md)

ゲームの音（効果音とBGM）の素材の入手先、加工、置き場所、Unityへの取り込みの決まりを定める。
作業の進め方は [sound-authoring](../../.agents/skills/sound-authoring/SKILL.md) にある。
ゲームに入れた音は、[押したときの音](#押したときの音)の2つである（2026-10-26）。

## 確定している方針

- 音は、[効果音ラボ](https://soundeffect-lab.info/)と[魔王魂](https://maou.audio/)の素材から探して使う。AIで音を作ることは、今は行わない。
- 使う音は、必ずユーザーが聞いてから決める。候補選び、加工、差し替えのどれも、AIが聞かずに決めない。
- 音を見せるときは、その音を鳴らす場面の動画と一緒に出し、「この動画の〇秒の動作で、この音を使いたい」または「この動作の候補として、これらの音を挙げる」の形で示す。動画には、候補の音をその動作の時刻に重ねる。
- スキルの演出の長さに合わせるなど、素材を伸ばす・切る・重ねる加工をしてよい。どちらの配布元も規約で改変を認めている。加工した音も、元の配布元をクレジットに載せる。
- 新しい配布元の素材を使うときは、[外部素材のクレジット](credits.md)の決まりに従って配布元を記録する。
- 音を入れたら、[クライアントアセット展示室](../features/showcase.md)で再生できることを確かめる。展示室は `AudioClip` を自動で一覧に載せ、再生ボタンを付ける。

## 押したときの音

どの画面でも、ボタンを押したときに次の音を鳴らす（2026-10-26、ユーザーが候補を聞いて決めた）。
音のファイルと配布元は [UIの音](../../client/Assets/Baryonyx/Shared/Audio/UI/README.md) にある。

| 押した物 | 音 | 音量 |
|---|---|---|
| 押せるボタン（決定・戻る・選ぶ） | `UiPress`（効果音ラボ「カーソル移動1」） | 0.5 |
| 押せないボタン（選ぶ前の決定ボタン、ルーンが足りないときなど） | `UiDenied`（効果音ラボ「ビープ音2」） | 0.3 |

決定・戻る・選ぶは、ユーザーが同じ音を選んだため分けていない。
音量は、ユーザーの「少し小さめ」で下げた値である。
押せない音は、同じ音量では押せる音より大きく聞こえるため、さらに下げている。

鳴らすのは、指を離して押したと決まったとき（uGUIのクリック）だけである。
一覧のスクロール、ドラッグ、すりガラスのカードの長押しのあと、何もない所のタップでは鳴らさない。
押せないかどうかは、ボタンが押せるか（親の `CanvasGroup` を含む）と、すりガラスのカードの `Interactable` で決める。

| 仕組み | 内容 |
|---|---|
| [UiSounds](../../client/Assets/Baryonyx/Shared/Audio/UI/UiSounds.cs) | ゲームの開始時に1つ置き、シーンをまたいで残す。画面に現れた `Button` と `Toggle` に `UiClickSound` を付けるため、画面ごとの変更は要らない |
| [GlassCard](../../client/Assets/Baryonyx/Shared/UI/GlassCard/GlassCard.cs) | 長押しのあとを押したことにしないため、自分で鳴らす |
| [UiSoundBank](../../client/Assets/Baryonyx/Shared/Audio/UI/UiSoundBank.cs) | 音と音量を持つ。ビルドの間だけ Preloaded Assets に入れ（`UiSoundBuildStep`）、ゲームの開始時に読み込まれるようにする。Editorでは置き場所から読む |

`Button` でもすりガラスのカードでもない押す処理（戦闘の手札、戦闘の画面のタップ）は、今は鳴らない。
画面ごとの音とご褒美の音は、まだ決めていない。

## 仮設定

最初の音を入れるときに試し、合わなければ直す。

### 置き場所と名前

| もの | 置き場所 |
|---|---|
| 採用前の候補と、加工の試し | リポジトリのルートの `output/sound/<用途>/`（Git対象外） |
| 1つの機能だけで使う音 | その機能の `Audio/`（例：`Features/Combat/Audio/`）。[コードとアセットの配置](frontend-design.md#コードとアセットの配置)に従う |
| 2つ以上の機能で使う音（UIの基本の音など） | `Shared/Audio/<分類>/`（例：`Shared/Audio/UI/`） |

ファイル名は、既存のアセットと同じく英語のパスカルケースで、用途が分かる名前にする（例：`UiConfirm.wav`、`SlashHeavy.wav`）。
音を置いたフォルダーには `README.md` を置き、[フォントの記録](../../client/Assets/Baryonyx/Shared/UI/Fonts/README.md)と同じ形で、ファイルごとの配布元・元の名前・加工の内容・取り込み日を表にする。
加工の内容は、同じ音を作り直せるように、使ったコマンドの引数まで書く。

### ファイルの形式と音量

- Unityへは16bitのWAVで入れる。Unityが取り込み時に配布向けの形式へ圧縮し直すため、元は劣化のない形式にしておく。
- 魔王魂はWAVで取得する。効果音ラボはmp3しかないため、加工の前にWAVへ直す。mp3は頭と終わりに無音が入る（エンコーダーが足す余白）ため、そのまま入れると押してから鳴るまでが遅れる。
- 加工の最後に、頭の無音を切り、ピークを−1dBFSにそろえる。音ごとの聞こえ方の差は、ファイルではなく再生する側の音量で合わせる。

### Unityの取り込み設定

| 音 | Load Type | Compression Format（Android） | そのほか |
|---|---|---|---|
| 1秒前後までの効果音（UI、攻撃、被弾） | Decompress On Load | ADPCM | Force To Monoを付ける。Preload Audio Dataを付ける |
| 長い効果音（数秒の演出） | Compressed In Memory | Vorbis | 左右の広がりが要るときだけステレオにする |
| BGM | Streaming | Vorbis | ループさせる曲は、つなぎ目で途切れないことを確かめる |

設定の意味は [Unityの AudioClip の取り込み設定](https://docs.unity3d.com/6000.3/Documentation/Manual/class-AudioClip.html)（2026-10-26確認）による。

## 未決事項

| 項目 | 決めること |
|---|---|
| 鳴らす仕組み | 押したときの音のほかの音（技・ご褒美・BGM）を持つ場所、`AudioMixer` のグループ（BGM・効果音・UIなど） |
| 音量の設定 | [プレイヤーの設定](../features/player-settings.md)の「音量、音楽・効果音・音声の分離」と一緒に決める |
| 押してから鳴るまでの遅れ | `ProjectSettings/AudioManager.asset` の `m_DSPBufferSize` は1024になっている。Unityの設定画面のどの選択肢（Best Latencyなど）に当たるかは未確認。ボタンの音を入れたら、Androidエミュレーターで遅れが気になるかを確かめ、必要なら変える |
| 同じ音の連続 | 攻撃などで同じ音が続くときに、Unityの `Audio Random Container` で数種類から選んで鳴らすか |

## 変更と判断の記録

- 2026-10-26：ユーザーの依頼で、音は必ずユーザーが聞いてから決め、見せるときは鳴らす場面の動画と一緒に、どの動作でどの音を使うかを示すことにした。
- 2026-10-26：ユーザーが、効果音とBGMは効果音ラボと魔王魂から探して使い、AIで音を作らないと決めた。スキルの長さに合わせて音を伸ばすなどの加工をすることもあるため、加工してよいことと、加工の記録の仕方を定めた。置き場所・形式・取り込み設定は、まだ音を入れていないため仮設定とした。
- 2026-10-26：ユーザーの依頼で、ボタンを押したときの音を入れた。候補は、ユーザーの「音のファイルも貼ってほしい」で、動画に重ねずに音のファイルで送り、ユーザーが聞いて決めた。決定・戻る・選ぶを同じ音にし、押せない音を分け、どちらも少し小さくした。スクロールでは鳴らさない。最初の音を入れたことで、置き場所（`Shared/Audio/UI/`）・WAVの形式・取り込み設定を試した。
