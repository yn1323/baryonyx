# ホーム画面「野営地」の見た目モック

計画の状態：完了（Unity Editorで実装・検証済み。Androidエミュレーターでの確認は未実施）

TOPから遷移するホーム画面を、ダンジョンの広間で焚き火を囲む「野営地」の構成へ作り替える。
今回は見た目と操作の手触りを確かめるモックとし、健康データ・ルーン残高・サーバーなどの実データには接続しない。

## 背景と今回の範囲

現在は遊べる試作の段階で、ホームの具体的な構成は[画面一覧](../features/screens.md#未決事項)で未決である。
既存の[Homeシーン](../../client/Assets/Baryonyx/App/Scenes/Home.unity)は単色の空画面で、[Top](../../client/Assets/Baryonyx/App/Scenes/Top.unity)の遷移先はワイヤー画面の`Main`になっている。

2026-09-24、ユーザーはデザインモック（[ホーム画面 改修案](https://claude.ai/artifact/37YmCN3jjXE5j3Cwhx9Vp9)の「A2 採用案」）の構成を採用した。
同時に、キャラクター名を表示しないこと、左下の「持ち物」を「装備」に変えることを指示した。

横長の画面では、空いた横幅をキャラクターの立ち絵ではなく、背景の世界とパーティ全員で埋める。
TOPの広間と同じ背景を使い、シャッターが開くと同じ場所でパーティが待っている流れにする。

今回の範囲は次のとおりとする。

- Homeシーンへ野営地の画面を作り、TOPの遷移先をHomeへ変える。
- 表示する値はモック用の固定値とし、Health・ExerciseRewards・Wireframeの状態へ依存しない。
- ボタンは押下の反応と遷移先の仮表示までとし、各画面の新規実装は含めない。
- 展示室への登録、テスト、画面サイズ別の撮影を同じ変更で行う。

## 画面構成

設計座標は1920×1080とし、[UI設計ルール](../rules/ui-design.md)の中央16:9 Core AreaとSafe Areaに従う。
背景と世界の要素は画面中央を基準にし、操作UIはSafe Areaの四隅へアンカーで固定する。
横長の端末では背景だけが左右に広がり、ボタンは画面端、パーティは中央に残る。

| 領域 | 要素 | 役割と操作 |
|---|---|---|
| 全面 | TOPの広間の背景、暗幕、上下の濃淡 | `ResponsiveBackground`で比率を保って画面全体を覆う |
| 中央（世界） | 奥の門の光と「つづき 森の遺跡 B3F」 | 門を押すと「冒険へ」と同じ操作 |
| 中央（世界） | 焚き火、火の粉、揺らぐ光 | 演出のみ |
| 中央（世界） | パーティ4人（名前は表示しない） | 4人の範囲を押すと「パーティ」と同じ操作 |
| 左上 | 今日の歩み（歩数、今日の目標、20区切りのゲージ、残り歩数、今週の目標） | 枠全体が1つのボタン。押すと「ルーンを取得」のモック結果を表示する |
| 右上 | 所持ルーン、設定 | ルーンは表示のみ。設定はボタン |
| 左下 | パーティ、装備（新着数のバッジ）、目標 | 各136×136の管理画面ボタン |
| 右下 | 行き先を選ぶ、冒険へ（再開先を併記） | 主操作。冒険へは460×156 |

タップ領域は[Androidの目安](https://support.google.com/accessibility/android/answer/7101858?hl=ja)の48dpを基準にする。
高さ1080の設計座標は、縦411dpの端末で1dpが約2.6px、縦360dpの端末で約3pxに当たるため、主要ボタンは約130px以上を確保する。
見た目が小さい設定ボタン（88px）と行き先ボタン（高さ88px）は、透明な当たり判定を広げて約130pxにする。

歩数の枠は「途中」「達成」「未連携」の3状態を持つ。
「未連携」では歩数とゲージを隠し、「歩数がまだ届いていません」と連携の案内を出す。
装備のバッジは新着数が0なら隠す。

## モックの値と操作

表示値はHome専用のモックデータアセットに置き、Inspectorで切り替えて見た目を確認できるようにする。
値はすべて仮であり、経済やバランスの確定値として扱わない。

| 項目 | 初期値 |
|---|---|
| 歩数の状態 | 途中 |
| 今日の歩数・目標 | 3,820歩・5,000歩（達成時は6,240歩） |
| 今週の目標 | 2 / 3回（達成時は3 / 3回） |
| 所持ルーン | 12,480 |
| 新しい装備 | 3件 |
| 再開先 | 森の遺跡 B3F |

実データの接続先は既存の仕様に合わせる。
歩数は1歩1ルーンで換算し、起動時の自動取得と画面上の「ルーンを取得」の両方に対応する（[運動報酬](../features/exercise-rewards.md#歩数のルーン変換)）。
今回のモックでは、歩数の枠を押すと「ルーンを取得（モック）」の短い通知を表示するだけにする。

ボタンの押下は、画面ごとに1つのイベントとしてPresenterへ渡す。
今回は共通の通知で「〇〇（準備中）」を表示し、二重押下を防ぐ。
画面遷移の実装は、遷移先の画面を作る段階で差し替える。

## 配置と責務

ホームは独立した機能として`Features/Home/`に置く。
依存方向はApp → Home → Sharedとし、HomeはHealth・ExerciseRewards・Wireframeを参照しない。

| 予定の配置 | 責務 |
|---|---|
| `Features/Home/Runtime/HomeMockData.cs` | モックの値を持つScriptableObject |
| `Features/Home/Runtime/HomeViewState.cs` | 表示用の文字列・ゲージの区切り数・バッジの表示可否を計算する通常のC#クラス |
| `Features/Home/Runtime/HomeView.cs` | Prefab内の参照を持ち、状態を描画し、ボタン入力をイベントとして出す |
| `Features/Home/Runtime/HomePresenter.cs` | 入力を受けて通知を出し、二重押下を防ぐ |
| `Features/Home/UI/HomeScreen.prefab` | 画面のuGUI階層 |
| `Features/Home/UI/Art/` | 焚き火のドット絵、門の光などHome専用の画像 |
| `Features/Home/Data/HomeMockData.asset` | モックの値 |
| `Features/Home/Editor/HomeScreenAssets.cs` | Prefabと専用画像・枠の生成。メニューは`Baryonyx/Home/Create Screen Assets` |
| `Features/Home/Tests/EditMode/`・`PlayMode/` | 表示状態の計算とPrefabの入力の検査 |
| `App/Runtime/HomeBootstrap.cs` | Homeシーンでモックデータ・View・Presenterを組み立てる |
| `App/Editor/TopHomeSceneSetup.cs` | Homeシーンの配置、TOPの遷移先、Homeの開く演出を更新する |

パーティの画像は、ワイヤー画面で使っていた `Adventurers.png` を使う。
HomeとWireframeの両方で使う素材になるため、Unityの移動機能でGUIDを保ったまま[Shared/Art/Characters/](../../client/Assets/Baryonyx/Shared/Art/Characters/Adventurers.png)へ移し、参照している文書のパスも更新する。
背景は既存の[TopDungeonBackground.png](../../client/Assets/Baryonyx/App/Art/Top/TopDungeonBackground.png)を参照する。

演出は既存のHD-2D部品を使う。
`Hd2dFlickerLight`で焚き火の橙の光と門の青緑の光、`Hd2dEmberEmitter`で焚き火の火の粉を出す。
位置は背景画像上の正規化座標で指定し、画面比率が変わっても背景に重なるようにする。
焚き火の本体は11×14ドットの静止画を新しく作り、揺れは光と火の粉で表す。

パネルの枠は、ワイヤーと同じ方法でUnityから生成する9-sliceの角欠け枠にする。
文字はすべてDotGothic16を使う。

## 進める順序

1. **素材の準備**：キャラクター画像を共有の配置へ移し、焚き火の画像と枠を生成する。ワイヤー画面の表示が変わらないことを確認する。
2. **表示状態とView**：モックデータ、表示状態の計算、View、PresenterをHomeに作る。表示状態の計算からEditModeテストを書く。
3. **Prefabの生成**：生成スクリプトで上記の階層を作る。世界の要素は中央基準、操作UIはSafe Area配下の四隅に置く。
4. **シーンと遷移**：HomeシーンにPrefab、演出、`SceneTransition`（開く演出はTopと同じ上下Shutter）を置き、TOPの遷移先をHomeへ変える。
5. **展示室**：Homeシーン、HomeのPrefab、焚き火の画像、移動したキャラクター画像を登録し、一覧とプレビューで確認する。
6. **検証と文書**：テスト、画面サイズ別の撮影を行い、仕様と索引を更新する。

TOPの遷移先を変えると、ワイヤー画面（`Main`）へ実機で入る経路がなくなる。
経路を残すかは下の「決める事項」で扱う。

## 検証と完了条件

- EditMode：3状態ごとの表示文字列とゲージの区切り数、バッジの表示条件、主要ボタンの当たり判定が約130px以上であること。
- PlayMode：TOPの全面押下でHomeが上下Shutterで開くこと。各ボタンの押下で通知が出て、連打しても1回だけ処理されること。Homeの起動で健康データの取得処理が作られないこと。
- 既存の[TopHomeSceneTests](../../client/Assets/Baryonyx/App/Tests/PlayMode/TopHomeSceneTests.cs)は遷移先をHomeとして更新する。
- Gameビュー：1920×1080、2340×1080、2400×1080、4:3、非対称Safe Areaで撮影し、背景の歪み、操作UIのSafe Area外へのはみ出し、文字の欠け、パーティと下のボタンの重なりを確認する。
- 展示室：追加・変更したアセットが一覧に出て、プレビューで変更後の内容を確認できること。
- C#はCSharpierで整形し、再コンパイルでエラーがないこと。

完了時は、[操作ワイヤー](../features/game-wireframe.md)のTOPの遷移先、[クライアントの構成](../rules/frontend-design.md)の配置図、[clientのAGENTS.md](../../client/AGENTS.md)の起動シーンの説明、[画面一覧](../features/screens.md)のホームの記録を更新する。
Androidエミュレーターでのタップ位置とシステムバーの確認は、ユーザーに起動を依頼して行う。

## 決定した事項

2026-09-24、ユーザーは計画の推奨どおりに進めることを指示した。

| 項目 | 決定 |
|---|---|
| 「冒険へ」の押下 | 既存のワイヤー画面（`Main`）へShutter演出で遷移する。門を押しても同じ |

## 検証結果

- EditMode：156件中155件成功。ホームの表示状態・ゲージ・バッジ・世界の縮小率・冒険開始の重複防止を含む。失敗した1件はHD-2Dのポストプロセス設定値の検査（`Hd2dLightingVfxTests`）で、今回変更していない設定が対象である。
- PlayMode：33件すべて成功。TOPからHomeへの遷移、仮データの表示、健康データ処理を作らないこと、タップ領域、通知、冒険ボタンの連打で`Main`を1回だけ読み込むことを含む。
- Gameビュー：1920×1080、2400×1080（20:9）、1440×1080（4:3）で撮影し、背景の比率、松明の光の位置、Safe Area内のボタン、4:3でパーティと下のボタンが重ならないことを確認した。撮影画像は `client/Assets/DevCaptures/Home/` に保存する（Git対象外）。
- 展示室：Homeシーン、HomeScreen Prefab、焚き火・アイコン・枠の画像、仮データ、移動したキャラクター画像が一覧に入り、Prefabのプレビューで仮データを含む画面を確認した。
- C#はCSharpierの検査に合格し、再コンパイルでエラーはない。

2340×1080と非対称Safe Area、Androidエミュレーターでのタップ位置・システムバーは未確認である。

## 再生成の手順

1. 画面の見た目を変えるときは `Baryonyx/Home/Create Screen Assets` でPrefabと画像を作り直す。
2. シーン構成を作り直すときは、Home.unityを閉じてから `Baryonyx/App/Create Home Scene` を実行する。
3. TOP・Home・Mainのシャッター演出と遷移先は `Baryonyx/App/Create Scene Transition Assets` で揃える。

## 実装後の見た目の見直し

2026-09-24、実装後にユーザーが枠と右下のボタンを見直した。
変更内容は[画面一覧](../features/screens.md#ホーム画面の見た目モック)に記す。

- 四角い白い枠をやめ、縁をぼかした暗い下地・端へ暗くなる下地・丸い影で文字を読ませる。
- パーティ・装備・目標は台のないアイコンのボタンにし、アイコンを3色のドット絵で描き直した。
- 右下は行き先カードとワールドマップにした。カードの背景に使う `Forest.png` は、キャラクター画像と同じく `Shared/Art/Dungeons/` へ移した。
- 文字の影はTextMeshProのアンダーレイを使う共通マテリアル（`HomeTextShadow.mat`）で付ける。
- uGUIはリニア色空間で合成するため、Webのモックと同じ不透明度では暗い下地が弱く見える。下地の不透明度はモックより高くしている。

検証：EditModeは156件中155件成功（失敗は前回と同じHD-2Dの設定値の検査）、PlayModeは33件すべて成功した。1920×1080、2400×1080、1440×1080で撮影し、表示を確認した。
4:3ではカードの左端がパーティの右端と近く、次の調整候補とする。
