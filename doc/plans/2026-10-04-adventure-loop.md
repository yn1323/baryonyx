# 冒険の1周（出発・探索・戦闘・報酬・復活・結果・中断と再開）

計画の状態：完了（実装と自動テスト、Unity EditorでローカルのサーバーにつないだPlayでの1周の確認は完了。Androidエミュレーターでの確認と、戦闘に実際の編成とカードを反映することは未実施。[検証結果](#検証結果)・[残っている作業](#残っている作業)）

[計画索引](README.md) / [画面一覧と操作](../features/screens.md#冒険の画面) / [探索とダンジョンの進行](../features/stage-progression.md) / [戦闘システム](../features/combat.md)

## 目的

Homeから冒険に出て、部屋を選んで進み、戦闘と宝箱で報酬を得て、最奥のボスを倒すか負けるかやめるかしてHomeへ戻る1周を、すべての画面を通して遊べるようにする。
途中でアプリを閉じても、最後に選んだ部屋から再開できるようにする。

## 現状と今取り組む理由

拠点の画面（Top・Home・酒場の編成と育成とカードスキルとボーナス）は、サーバーへの保存まで実データでつながっていた。
一方、冒険の側は、旅の案内所の「出発」が準備中の通知を出すだけで、探索の画面と冒険の結果はなく、戦闘はどちらかが全滅すると次のターンに復活して終わらないモックだった。
コアループのうち「冒険に出て、戦って、持ち帰る」部分に画面がなく、拠点の決まり（冒険中はボーナスを付け替えられない、など）も試せなかった。

ユーザーは、画面とその遷移の検討（2026-10-04）を受けて次を決め、まず全シーンを作って1周できるようにすることを求めた。

| 決めた事項 | ユーザーの回答 |
|---|---|
| 分岐ルートのマップと部屋の探索画面の関係 | 部屋の画面だけで進み、ルート全体は冒険のメニューの地図で見る |
| 戦闘中にアプリが終わったときの扱い | 直前の分岐で部屋を選んだ状態から再開する。選んだ時点の保存先は検討を任された（[方針](#方針)の2） |
| 自分から冒険をやめられるか | やめられる。戦闘の途中でも中断してよい |
| 冒険していないときのHome右下 | 旅の案内所を開くカードにする。左下の旅の案内所のボタンは、再開のカードに近い形に変える |
| 足りない素材 | Codex CLIで作る |

## 参照した一般的な手順

次は一般的な手順であり、このプロジェクトへの当てはめは[方針](#方針)に書く。

- Androidは、裏に回ったアプリのプロセスを、終了の通知（`onDestroy`）なしに止めることがある。続きが要る状態は、区切りごとに消えない保存先へ書く（[Activity state changes](https://developer.android.com/guide/components/activities/state-changes)・[Save UI states](https://developer.android.com/topic/libraries/architecture/saving-states)）。
- 通貨の消費のように不正の影響が大きい処理は、サーバーで検証して確定させる（[Unity Cloud Code：Server authority](https://docs.unity.com/en-us/cloud-code/server-authority)）。
- Unityは複数のシーンを重ねて読み込める（[Set up multiple scenes](https://docs.unity3d.com/6000.2/Documentation/Manual/setupmultiplescenes.html)）。

## 方針

このプロジェクトの状況から判断した方針である。

1. **冒険の状態はサーバーに置く**：今いる部屋・通った部屋・部屋の出来事を終えたか・復活の回数・手に入れた報酬を、ユーザーごとにサーバーのDBへ保存する（`server/src/features/adventure/`）。シーンはその状態を読んで表示するだけにし、シーン同士で状態を手渡ししない。酒場の編成やACTボーナスと同じ形である。
2. **部屋を選んだ時点で保存する**：ユーザーの回答の「選択したあと保存が必要か」には、必要と判断した。保存先は端末ではなくサーバーにした。復活でルーンを使い、報酬で持ち物を増やすため、どちらもサーバーで確定させる必要があり、冒険の状態だけを端末に置くと両者が食い違うためである。戦闘中にアプリが終わると、その部屋の戦闘を始めからやり直す。
3. **戦闘は今の戦闘画面に「勝敗で終わるモード」を足して使う**：戦闘画面のモック（`BattleInspectView`）に、部屋の敵の組み合わせを決める入口、どちらかが全滅したら戦闘を終えて知らせる処理、ルーンでの復活（味方は全快、敵の減ったHPはそのまま）を加えた。既定では今までどおり終わらないため、モックと敵・スキルのデバッグルームの動きは変わらない。
4. **探索は戦闘と同じ3Dの舞台に立てる**：探索の画面は、行き先の戦闘の背景（森の遺跡は朝霧の森）に、戦闘で味方が立つ位置へ4人を、敵が立つ位置へ遺跡の門を立てる。[アセットを増やしすぎない構成](../features/stage-progression.md#アセットを増やしすぎない構成)の「エリア共通の背景に扉などの差分を組み合わせる」に合わせた。
5. **シーンは場所ごと、結果や確認は重ねる画面にする**：探索（`Exploration`）と戦闘（`Battle`）をシーンにし、出発前の確認・冒険のメニュー・ルートの地図・報酬・復活・冒険の結果は、共通の確認ダイアログ（`GameDialog`）とルートの画面を重ねて出す。戦闘はシーンを切り替えて開く（重ねて読み込まない）。探索と戦闘のどちらにも3Dの舞台・カメラ・ポストプロセスがあり、重ねると二重になるためである。
6. **冒険中はACTボーナスの枠を付け替えられない**：[枠の付け替え](../features/step-bonus.md#枠の付け替え)の決まりを、サーバーが拒否し、酒場のボーナス設定が理由を知らせる形で実装した。

## 作ったもの

### サーバー

| API | 内容 |
|---|---|
| `GET /v1/adventure` | 進行中の冒険（行き先の部屋の構成と、この冒険で手に入れた物を含む）、行き先ごとの記録、所持ルーン |
| `POST /v1/adventure` | 行き先の入口から冒険を始める。進行中の冒険があれば409 |
| `POST /v1/adventure/move` | 今いる部屋の入口から次の部屋へ進む。出来事を終えていない・つながっていない部屋は409 |
| `POST /v1/adventure/clear` | 今いる部屋の出来事（戦闘の勝利・宝箱）を終え、ACTボーナスを1つ手に入れる。最奥のボスなら冒険を終えて結果を返す |
| `POST /v1/adventure/revive` | 負けた戦闘からルーンで復活する。費用はサーバーが計算し、要求IDで再送を見分ける |
| `POST /v1/adventure/end` | 負けて帰還する（`defeat`）か、自分からやめる（`retreat`）。結果を返す |

テーブルは、冒険（`adventure_runs`。進行中は1人に1つ）、部屋ごとの報酬（`adventure_rewards`）、復活の記録（`adventure_revives`）、行き先ごとの記録（`adventure_records`）の4つである（[0005_adventure.sql](../../server/migrations/0005_adventure.sql)）。
報酬・部屋の終了・持ち物の更新・記録の更新は1回の `batch()` で行い、復活は残高と復活の回数を条件にしたレベルアップと同じ形で、ルーンの減算までを1回の `batch()` で行う。

冒険先は森の遺跡だけで、部屋は4階の6部屋の仮の構成である（入口 → 魔物の気配／宝箱 → 魔物の気配／強い魔物の気配 → 最奥の間）。
報酬のランクの重み、復活の費用（1回目100ルーン、以後100ずつ上がる）も仮の値である。

### クライアント

| 画面 | 内容 |
|---|---|
| Home | 左下を酒場・装備・神殿の3つにした。右下のカードは、冒険の途中なら行き先の絵と「森の遺跡 B2F 再開」、そうでなければ世界地図の絵と「冒険に出る 旅の案内所 出発」 |
| 旅の案内所 | 地図の森の遺跡で「出発」を押すと、最深到達と冒険中の決まりを書いた確認を出し、「出発する」で冒険を始めて探索へ移る |
| 探索（`Exploration.unity`） | 朝霧の森の舞台に4人と、次の部屋への遺跡の門（最大2つ）を立てる。門の足元の札に部屋の種類のアイコンと手掛かり。門を押すと4人が歩いて、シャッターで次の部屋へ。宝箱の部屋は宝箱を押して報酬。戦闘の部屋は少し見せてから戦闘へ。左上のメニューで、ルートの地図・中断してホームへ・冒険をやめる |
| 戦闘（`Battle.unity`） | 部屋の敵の組み合わせで戦い、勝てば報酬を見せて次の部屋へ、ボスなら冒険の結果を見せてHomeへ。全滅すると、ルーンでの復活と帰還を同じ形で並べる。右上のメニューで、中断してホームへ・冒険をやめる |
| 酒場のボーナス | 冒険の途中は付け替えを受け付けず、「冒険の途中は、ボーナスを付け替えられません」と知らせる |

端末の戻るキーは、ルートの地図・ダイアログを開いていればそれを閉じ、探索と戦闘ではメニューを開く。
サーバーの接続先がないとき（展示室のプレビューなど）は、同じ決まりをアプリの中だけで持つ冒険（`AdventureLocalSource`）を使う。

## 検証結果

- サーバー：冒険APIのテスト13件（認証・入力・冒険がないとき・部屋の保存と進む条件・報酬が1回だけ入ること・ランクの比較・復活の費用と再送と残高不足・負けたときの記録・自分からやめる・ボスで終わる・冒険中のボーナスの拒否・ユーザーの分離）と、ACTボーナスAPIのテストが成功した。ローカルのD1にマイグレーションを適用し、`GET`・`POST /v1/adventure` の応答を確かめた。
- クライアント：EditModeテスト372件が成功した（冒険の状態の読み取り、部屋の表示、アプリ内の冒険の決まり、結果の文、旅の案内所の出発、ボーナスの拒否を含む）。PlayModeテストは全95件が成功した（冒険の1周を通す9件を含む）。
- Unity Editor：ローカルのサーバーにつないだPlayで、Home → 旅の案内所 → 出発 → 宝箱の部屋 → 戦闘の部屋 → 勝利 → 最奥の間 → 全滅 → ルーンで復活 → 勝利 → 踏破 → Home を通し、続けて戦闘の途中で中断 → Home（再開のカード）→ 酒場のボーナスが付け替えられないこと → 再開して戦闘が始めからになること → 冒険をやめる、までを確かめた。勝敗はEditorから敵や味方のHPを0にして起こした。撮影した画面は `client/Assets/DevCaptures/Adventure/`（Git対象外）にある。
- 展示室：扉・宝箱・部屋の種類のアイコン・探索画面・冒険のメニュー・探索シーンが一覧に載り、扉と探索画面をプレビューで表示できることを確かめた。
- 撮影で見つけて直した点：確認の文が窓の幅で折り返していた（窓を1360に広げた）、門の上の札が遠近で門から離れて見えた（札を門の足元に移した）、戦闘の「メニュー」が左上の行動順と重なっていた（右上に移した）。

## 残っている作業

- 戦闘の味方は戦闘画面のモックの4人と16枚のままで、酒場の編成・Lv・カードスキルを反映していない。モックのカードはEditorで組み立てているため、実行中に編成から作る仕組みが要る。冒険のメニューから編成・装備を変える入口も、これとあわせて作る。
- 敵は戦闘画面のモックの3体から部屋ごとに選んでいるだけで、強い魔物の気配は同じ2体のHPを1.6倍にしただけである。
- 戦闘中の中断で戦闘を始めからやり直せるため、負けそうなときに中断すれば、実質的に戦闘をやり直せる（[無料再戦の廃止](../features/combat.md#確認待ち)との関係）。
- Androidエミュレーターでの確認（戻るキー、アプリを閉じてからの再開）は未実施である。
- 冒険中の報酬は、まだACTボーナスだけである（装備・カードスキルの入手は未実装）。
