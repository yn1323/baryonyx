# Homeの昼の森と、HD-2Dのレンズ・色調・カメラ

[計画の索引](README.md) / 仕様の正本：[3Dの舞台](../art/hd2d-stage.md) / 前の計画：[Top・Home・戦闘画面の3Dの舞台](2026-10-02-hd2d-3d-stage.md)

状態：完了（Editorでの実装と検証。Android端末での確認は未実施）

## 依頼

2026-10-02、[3Dの舞台への移行](2026-10-02-hd2d-3d-stage.md)に続いて、ユーザーから次の依頼を受けた。

- Homeが、Play Modeでないとき2Dのままである。停止中もHD-2Dに見えるようにする。
- Bloom・カメラ・ライティングが足りない。Homeなどを昼の森の中に変え、もっとHD-2Dらしくする。
- 既存のHD-2Dのスキルにとらわれず、オクトパストラベラーやHD-2Dの作り方をWebで調べ、ライティング・カメラワーク・ポストプロセスを実装する。
- 取り入れた手法をスキルに記録する。

## 調べたことと取り入れた手法

開発者の発言と再現例から、次の手法を取り入れた。
資料の一覧と要点は、スキルの[調査資料](../../.agents/skills/hd2d-lighting-vfx/references/research-sources.md#hd-2dのライティングカメラポストプロセス2回目)に記す。

| 資料で述べられていること | 取り入れた形 |
|---|---|
| 被写界深度で奥行きを出す。ティルトシフトでジオラマのように見せる | 舞台のレンズ（`Hd2dStageFocus`）。キャラの奥行きにピントを合わせ、手前と奥の舞台をぼかす |
| ライティングでウソをつかないと、キャラと背景のマッチングが破綻する | キャラの板は光を受けつつ底上げし、太陽の木漏れ日（ライトクッキー）は受けない。影を寒色、光を暖色に寄せる色調 |
| 入力待ちではカメラをゆらゆら揺らし、山場では固定してメリハリを付ける | 入力待ちのゆっくりした揺れと、画面を開いたときのすべり込み。戦闘は従来どおりUIの動きに合わせる |
| 環境光で影を真っ黒にしない。動的なライトでドット絵を照らす | 空・木々・地面の3色の環境光。太陽を主光源にしてキャラの影を落とす |
| 再現例では、被写界深度・Bloom・周辺減光・色調補正・光の筋・漂う粒子を組み合わせる | 舞台ごとのProfile（`<舞台>Look`）、光の筋のシェーダー、漂う塵 |

## 開発段階と判断

モックの段階で、画面の操作とテストはUIのまま動いている。
前の計画の構成（UIの位置からキャラを3Dに立たせる）を変えず、見た目の層だけを足した。

| 決めたこと | 理由 |
|---|---|
| 被写界深度は自作し、半透明の列の前に不透明の舞台だけをぼかす | URPの被写界深度は最後にかかり、深度を書かないキャラの板・HPバー・演出を、奥の地面と同じだけぼかす |
| ぼかしは半分の解像度で、各点が自分のぼけの半径まで広がる方式にする | 1回目の試作では、手前のぼけた木の縁が、くっきりした地面の前で階段状に切れた。半分の解像度にしてスマートフォンでの負荷も抑えた |
| 停止中はキャラの板を保存しない物として作り、2Dのときだけの部品は描画だけを止める | シーンやPrefabに3D用の状態を保存しない。無効にするとシーンが変更扱いになる |
| 部品の登録を `Awake` から `OnEnable` へ移した | このプロジェクトはEnter Play Mode Optionsでシーンの再読み込みを省いており、停止中に一度起きた部品はPlay Modeで `Awake` が呼ばれない。1回目はPlay Modeで2Dの背景が消えなかった |
| 太陽の影はハードにする | Editor（PC用設定）のソフトシャドウは薄く、キャラの影が見えなかった。スマートフォン用の設定はソフトシャドウを使わないため、見た目を合わせた |
| 戦闘画面は夜のままにする | 加算の光の演出が暗い背景で映える。昼にするかは未決とした |
| Top・Homeを共通の `Hd2dPostProcess` から舞台ごとのProfileへ移す | 舞台ごとにピントの距離と色が違う。共通Profileは2Dの背景向けの値に戻した |

## 実施した内容

1. 3Dの舞台のカメラ・キャラの板・2Dのときだけの部品を停止中も動かし、HomeとBattleInspectのGameビューにキャラが3Dで立つようにした。
2. Codex CLIでHomeの昼の森のテクスチャ8枚（草地・空き地・遠景・大木・茂み・枝葉・丸太・テント）を生成し、32色の `.aseprite` にした。依頼文は [prompts.json](../../client/ArtSource/Stages/prompts.json) に記録した。
3. 昼の森の舞台（`ForestGladeStage`）を組み、Homeを広間から移した。太陽、木漏れ日のライトクッキー、光の筋、漂う塵、3色の環境光、霧を加えた。
4. 舞台のレンズ（`Hd2dStageFocus` とRenderer Feature）を作り、3つの舞台のProfile（`DungeonHallLook`・`ForestGladeLook`・`ForestRuinsLook`）にBloom・色調・周辺減光と合わせて設定した。
5. 舞台のカメラに、画面を開いたときのすべり込みを加え、HomeとTopに設定した。Homeには入力待ちの揺れも加えた。
6. 展示室に新しい舞台・テクスチャ・Profile・シェーダーが並び、舞台がプレビューされることを確かめた。
7. スキル（[hd2d-lighting-vfx](../../.agents/skills/hd2d-lighting-vfx/SKILL.md)）に、調べた手法と手順・つまずいた点を記録した。

## 完了条件と結果

| 完了条件 | 結果 |
|---|---|
| 停止中のHomeがHD-2Dで見える | Editorで確認済み。EditModeテストで、停止中にキャラが3Dに立ち、保存される状態が変わらないことを検査する |
| Homeが昼の森で、HD-2Dらしい光・カメラ・ポストプロセスを持つ | Editorの停止中とPlay Modeで確認済み |
| キャラ・HPバー・演出がぼけない | EditModeテストで、レンズの設定とキャラの板の描く順番を検査する。Play Modeの戦闘画面で確認済み |
| EditModeとPlayModeのテスト | EditMode 262件、PlayMode 66件がすべて成功 |

## 未確認の事項

- Android端末（エミュレーター含む）での表示と負荷は確認していない。舞台のレンズ、Bloom、影、光の筋の負荷を端末で確かめる必要がある。
- Homeの構図は、Play Modeで16:9・20:9・4:3を確かめた。19.5:9とSafe Areaのある画面は確かめていない。
