# Top・Home・戦闘画面の3Dの舞台（HD-2D）

[計画の索引](README.md) / 仕様の正本：[3Dの舞台](../art/hd2d-stage.md)

状態：完了（Editorでの実装と検証。Android端末での確認は未実施）

## 依頼

2026-10-02、ユーザーから次の依頼を受けた。

- 2Dの画面を、3Dの技法でドット絵を立たせ、影を落とすHD-2Dの技法に変える。
- まずTop・Home・BattleInspectを、地面と背景の3Dにする。テクスチャはCodex CLIで生成する。
- キャラも3D空間に立たせ、カメラから見て薄っぺらく見えないようにする。
- カメラとライティングは、オクトパストラベラーの記事などを参考にする。
- HUD、枠、カード、カードの挿絵、HP、敵の弱点は、今までどおり2Dで手前に表示する。
- 取り入れた技法はスキルに記録しながら進める。
- マップ移動はしないため、凝ったマテリアルは要らない。

## 開発段階と判断

モックの段階で、戦闘のロジックや画面の操作はUIで組み上がっている。
そこで、画面の操作・当たり判定・テストはUIのまま残し、キャラの絵だけをUIの位置から3Dに立たせる形にした。
UIの位置と大きさを写す板にしたため、既存の画面ロジックとPlayModeテストを書き換えずに済んだ。

| 決めたこと | 理由 |
|---|---|
| キャラはカメラの面と平行な板にする | 真横から見られず、ドット絵が薄く見えない。UIの見た目の位置・大きさと一致する |
| 影は光へ向けた垂直の影の板で落とす | 見える板は後ろへ傾くため、その影は光の向きでつぶれる |
| マテリアルはURPの `Simple Lit` | 移動しない舞台で、光と影を受ければ足りる |
| 被写界深度は使わず、疑似ティルトシフトを続ける | 舞台のUI（HPバー・カーソル）は深度を書かず、背景の距離でぼけてしまう |
| 主光源は左上の横から当てる | 奥からだと影がHPバーの下に、正面からだとキャラ自身の板に隠れた |

参照した資料は、スキルの[調査資料](../../.agents/skills/hd2d-lighting-vfx/references/research-sources.md#hd-2dの3dステージ)に記す。

## 実施した内容

1. Codex CLIでテクスチャ10枚（広間の床・壁・門・旗・松明、森の石舞台・草地・遠景・崩れた柱・古木）を生成し、格子を作り直して32色の `.aseprite` にした。
2. キャラの板、接地影、炎、光の粒のシェーダーと、3Dの舞台のカメラ・キャラの板・2Dのときだけの部品・光の揺らぎのランタイム部品を作った。
3. 舞台の部品と2つの舞台（`DungeonHallStage`・`ForestRuinsStage`）をコードで組み立てた。
4. Top・Home・BattleInspectのシーンに舞台を置き、HomeとBattleInspectの画面のPrefabにキャラの板と2Dのときだけの部品を付けた。
5. 戦闘のカメラの円運動と揺れを3Dのカメラの動きにも置き換え、手前と奥に視差を付けた。
6. モバイル用のURP設定で追加ライトの影を有効にし、主光源の影の距離を40mにした。共通のポストプロセスのBloomのしきい値を0.9に上げた。
7. 展示室の分類に `Shared/Art/Stages/` を背景・環境として加えた。
8. スキル（[hd2d-lighting-vfx](../../.agents/skills/hd2d-lighting-vfx/SKILL.md)）に、3Dの舞台の手順・技法・つまずいた点、テクスチャを変換するスクリプトを加えた。
