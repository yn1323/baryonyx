# クライアントCIの積み残し

状態：提案（積み残し・未着手）
作成日：2026-09-10
更新日：2026-09-10

VRT、Web E2E、Androidビルド、Androidスモーク／E2Eを、今後追加する検証として管理する。
この文書では対象と着手条件を整理し、CIの実装やサービスの設定は行わない。

既存のEditMode・PlayModeテストとWebビルドは [UnityのテストとWebプレビュー](../rules/client-testing-and-preview.md) を参照する。
Cloudflare PagesのPR Preview公開処理は、後日設定するためコメントアウトしている。
既存CIのGitHub上での初回実行状況は [初期設定の導入計画](2026-09-10-client-tests-web-preview.md) で管理する。

## 未着手の項目

| 項目 | 確認する内容 | 着手条件 |
|---|---|---|
| **VRT（Visual Regression Testing）** | 固定状態のスクリーンショットを基準画像と比較し、意図しない見た目の変化を検出する | 対象画面と、同じ表示状態を再現する方法が決まっている |
| **Web E2E** | PR Preview上で、主要な操作から結果表示までの流れを確認する | Cloudflare PagesのPreviewが利用でき、対象の操作が実装されている |
| **Androidビルド** | Android向けのコンパイルとパッケージ生成、組み込むネイティブ連携のビルドが成立するか確認する | ビルド対象の設定とAndroid用ツール、CIのUnity認証を準備できる |
| **Androidスモーク／E2E** | インストール、起動、権限処理、主要な操作の流れを確認する | Android成果物と実行端末を準備でき、対象機能が実装されている |

各項目の完了条件は、実際の対象で成功し、対象の不具合を検出できることを確認するところまでとする。
テスト未実行、対象0件、すべてSkipは完了扱いにしない。

## VRT

対象画面ごとに、入力データ、乱数、時刻、アニメーションの進行状態を固定する方法を用意する。
撮影時の解像度、描画設定、実行環境をそろえ、読み込み完了を確認してから撮影する。
Unity上で撮影するか、Web版をブラウザで撮影するかは、対象画面を決める際に選ぶ。

- [ ] 比較する画面と状態を列挙する。
- [ ] 毎回同じ状態へ遷移できるテスト用データと操作を用意する。
- [ ] 基準画像の保存先、比較の許容差、変動部分の除外範囲を決める。
- [ ] 差分発生時に、基準画像・実際の画像・差分画像をCIの成果物として保存する。
- [ ] 意図した表示変更では、差分をレビューしてから基準画像を更新する手順を設ける。
- [ ] 同一状態の繰り返し撮影が安定し、意図的に加えた表示崩れを検出できることを確認する。

## Web E2E

PR Previewの公開が成功してから、対象PRの成果物に対してテストを実行する。
PreviewのURLと対象コミットを対応づけ、読み込み完了と操作後の状態を確認できる仕組みを用意する。
実行ツールとUnity側のテスト用インターフェースは、主要画面の実装に合わせて選ぶ。

- [ ] Cloudflare Pagesの公開設定を有効にし、PreviewのURLを後続のテストへ渡す。
- [ ] 初回読み込みから開始画面が表示されるまでを確認する。
- [ ] 主要な操作と期待する結果を、機能仕様からテストシナリオにする。
- [ ] テスト用データと保存状態を毎回初期化し、実行間の影響を防ぐ。
- [ ] 失敗時のスクリーンショットとブラウザログを保存する。
- [ ] 読み込み失敗や操作後の状態不一致が、CIの失敗として報告されることを確認する。

現在のローカルブラウザでのSampleScene表示確認は、PR Preview上の自動E2Eとは別の検証として扱う。

## Androidビルド

Androidを対象にしたビルド処理とCI jobを追加する。
ビルドの成功と、端末上でのネイティブ機能の動作は、それぞれの結果として記録する。

- [ ] Unity版に対応するAndroid Build Support、SDK、NDK、JDKをそろえる。
- [ ] アプリ識別子、対応OS、CPU構成、スクリプティングバックエンド、成果物形式を決める。
- [ ] スモークテストへ渡す成果物の署名方法と、必要な設定値の管理方法を決める。
- [ ] Android用のビルド入口とCI jobを追加し、他のビルド対象とキャッシュを分ける。
- [ ] 使用するネイティブプラグインを含めたビルドとパッケージ生成を確認する。
- [ ] ビルド失敗をCIへ伝え、ログと成功時の成果物を保存する。

ネイティブプラグイン導入前は、Android向けの基本ビルドを確認した段階として記録する。
プラグイン導入後に、その依存関係を含めて再検証する。

## Androidスモーク／E2E

最初にインストールと起動を確認するスモークテストを用意し、機能の実装に合わせて権限処理と主要操作を追加する。
自動実行する端末環境と、実機で確認する項目を決め、実行結果に端末・OS・対象コミットを残す。

- [ ] Androidビルドの成果物を端末へインストールし、起動と開始画面の表示を確認する。
- [ ] 権限の許可・拒否と、設定画面から権限を変更した後の動作を確認する。
- [ ] アプリの再起動やバックグラウンドからの復帰後に、期待する状態へ戻ることを確認する。
- [ ] 主要な操作をE2Eのシナリオにし、保存状態を初期化して実行する。
- [ ] 失敗時の端末ログと画面を保存し、クラッシュやタイムアウトをCIの失敗にする。

### 実機での歩数取得

歩数取得は、実機で確認する独立した項目として残す。
取得方式と仕様を確定した後に、対応する端末を用意して次を確認する。
モックやエミュレーターでの成功だけでは、この項目を完了扱いにしない。

- [ ] 権限を許可した状態で実際に歩き、取得値と画面への反映を確認する。
- [ ] 権限拒否・取消しや、取得機能を利用できない端末での案内を確認する。
- [ ] 再起動、バックグラウンドからの復帰、日付変更時の集計を、決めた仕様と照合する。
- [ ] 端末、OS、取得方式、操作手順、期待値、実測結果を記録する。

## 着手順序と更新方法

Androidビルドは、画面の完成を待たずに着手できる。
Androidスモークはその成果物を使い、権限処理と歩数取得の検証は対応機能の実装後に追加する。
Web E2EはPreview公開後、VRTは表示状態を固定できる画面ができた段階で着手する。

着手した項目には実施日と状態を追記し、完了時は検証結果と残る制約を記録する。
確定した実行手順は `doc/rules/` の関連文書へ反映し、この計画からリンクする。
