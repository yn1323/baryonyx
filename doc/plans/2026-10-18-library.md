# ライブラリの実装計画

状態：進行中（2026-10-19にサーバーの記録とAPI、クライアントの画面を実装し、サーバーのテスト、EditModeの全件、関係するPlayModeのクラス、ローカルのサーバーにつないだEditorで確かめた。Androidの実機・エミュレーターでの確認は未実施）

入手した物・遭遇した敵・日々の歩数を見返す[ライブラリ](../features/library.md)を作る。
動作と方針の正本は[ライブラリの仕様](../features/library.md)であり、この計画は作る順序・置き場所・完了条件と、並行する作業との分担を記す。

## 依頼と決定した事項

2026-10-18、ユーザーは「入手した様々な情報を確認できる」ライブラリのシーンを依頼し、DBでの管理が要るだろうと添えた。
対象には、キャラクター（固有スキル）・武器・防具・アクセサリー・スキル・アイテム・敵（弱点）と、続けて日々の歩数を挙げた。

設計方針の提案に対し、ユーザーは次を決めた。

| 項目 | 決定 |
|---|---|
| 定義と記録の分け方 | 定義はDBに入れず各機能の正本から読み、見つけた記録だけをサーバーのDBに置く（提案を了承） |
| 載せる基準 | 今持っている物ではなく、一度でも手に入れた物（提案を了承） |
| まだ見つけていない項目 | 枠と番号だけを見せ、名前を伏せる。絵は「？」ではなく影にする |
| 敵 | 遭遇した時点で載せ、倒した数も数える |
| 入口 | ホームにボタンを足す |
| 固有スキルの進化後の段階 | 進化させるまで伏せる |

続けて未決事項を相談し、ユーザーは次を決めた。

| 項目 | 決定 |
|---|---|
| 番号 | 分類ごとに定義の並び順で振る。未リリースの間はずれてよい |
| 伏せた項目の名前 | 名前の欄ごと消す |
| 倒した数 | 体数で数える。全滅で終わった戦闘で倒した分も数える |
| 日々の歩数 | 日ごとの歩数とACTを並べる。端末を複数使った日は、いちばん多い端末の値 |
| 案内人 | 新しく司書を作る。絵ができるまでは仮の絵 |
| 武器・防具の絵 | 当面は種類のアイコンを使う |
| スキル | 1枚ずつ持つ仕組みができるまで、編成で付けたことがあるカードを載せる |
| 倍率と☆の個体差 | 今は出さない |
| 新しく載った印 | 付ける。見た記録は端末に置く |

## 方針

ゲームの図鑑は、ゲームに用意した物の定義と、プレイヤーが見つけた記録を重ねて見せる画面である。
このプロジェクトでは、定義はすでにクライアントの静的テーブルとScriptableObjectにあり（キャラ9人、カード約50枚、武器8種、防具6種、敵3体）、足りないのは見つけた記録である。
そのため、新しく作るものは、見つけた記録の保存と、定義と記録を重ねる画面の2つになる。

参照した資料：

- 見つけた物と見つけていない物をタブで分ける例：[Flight Rising](https://www1.flightrising.com/forums/ann/2763435)
- 見つけていない項目を代わりの表示で出すか隠すかを選べる図鑑の部品：[Ren'Py Encyclopaedia](https://renpy-encyclopaedia.readthedocs.io/)
- 中小規模のゲームでは、読み取りだけの定義をScriptableObjectや静的テーブルで持つのが普通であること：[What MasterMemory Solves](https://dev.to/gamedevtoollab/what-mastermemory-solves-and-what-it-doesnt-a-practical-guide-to-static-game-data-in-unity-dn1)

## 並行する作業との分担

開示した敵の弱点の保存は、別のチャットの作業（敵の弱点記憶機能）が担当する。
2026-10-18に、その作業と次のように取り決めた。

| 対象 | 担当 | ライブラリ側の扱い |
|---|---|---|
| 敵の定義（ID・名前・弱点） | 弱点の作業。クライアントは [CombatEnemies](../../client/Assets/Baryonyx/Features/Combat/Runtime/CombatEnemies.cs)、サーバーは [combat/catalog.ts](../../server/src/features/combat/catalog.ts) の `ENEMY_IDS` | 参照するだけで編集しない。敵IDは `moss-slime`・`moss-wolf`・`forest-guardian` の形 |
| 開示した弱点の保存 | 弱点の作業。`combat_revealed_weaknesses`、`GET`・`POST /v1/combat/weaknesses`、クライアントの `RevealedWeaknessSession` | 読むだけで書き込まない |
| 戦闘と冒険をつなぐ処理（`BattleAdventureFlow.cs`） | 弱点の作業が先に数行を足す | 遭遇と撃破を送る変更は、弱点の作業の変更が入ってから行い、触る前に知らせる |
| マイグレーションの番号 | 弱点の作業が `0010` を使う | ライブラリは、作る時点で空いている次の番号を使う |

固有スキルの進化の保存は、[固有スキルの進化](../features/skill-evolution.md#進化の保存)の仕様で決まっているが未実装である。
ライブラリの作業では作らず、保存ができるまでは、アプリを動かしている間の進み具合を読む。

## 作るもの

ここに書くファイル名・テーブル名・APIのパスは、作るときの配置案であり、まだ存在しない。

### サーバー

`server/src/features/library/` を新しく作る。

| 部品 | 内容 |
|---|---|
| テーブル `library_discoveries` | user_id・分類（`character`・`weapon`・`armor`・`accessory`・`skill`・`item`・`enemy`）・entry_id・初めて見つけた日時・倒した数（敵だけが使う）。主キーは user_id・分類・entry_id |
| 記録を書く関数 | キャラ・装備を付与する処理（初めに配る分を含む）と、カスタムスキルの枠にカードを付ける処理（`PUT /v1/party/characters/:id/cards/:slot`、初めに付いているカードを含む）から呼び、同じ `db.batch()` で書く。同じ物をまた手に入れたときは、初めて見つけた日時を変えない |
| `GET /v1/library` | ログイン中の利用者の、見つけた記録をすべて返す。定義は返さない |
| `GET /v1/library/steps` | `exercise_reward_days` から日ごとの歩数を返す。同じ日に端末が複数あるときは、いちばん多い値を返す（[日々の歩数](../features/library.md#日々の歩数)） |
| 開発用データ（seed） | 見つけた記録を足す（[開発用データ（seed）](../rules/backend-design.md#開発用データseed)） |

敵の遭遇と撃破は、`POST /v1/adventure/clear` と、全滅で冒険を終える `POST /v1/adventure/end` の入力に、遭遇した敵のIDと、種類ごとの倒した体数を足して受け取る。
サーバーは敵IDを `ENEMY_IDS` で確かめる。
これは冒険の機能の入力を変えるため、[探索とダンジョンの進行](../features/stage-progression.md)の仕様にも記す。

未リリースのため、今あるキャラ・装備の所持から見つけた記録を作り直す処理は作らない。
DBを作り直して、初めに配る分から記録させる。

### クライアント

`client/Assets/Baryonyx/Features/Library/` を新しく作り、シーン `Library` を足す。

| 部品 | 内容 |
|---|---|
| 記録の読み込み | 見つけた記録と日々の歩数を読む窓口。サーバー版と、接続先がないとき（展示室など）の仮データ版を作る（[サーバーに置くときの作り方](../rules/data-storage.md#サーバーに置くときの作り方)） |
| 分類ごとの変換 | 各機能の正本の定義を、一覧の項目（ID・番号・名前・☆・絵・説明）に変える。定義は写さない |
| 画面 | 案内人の画面の部品（`GuideMenuDefinition` と分類ごとのパネル）で、メニュー・タイル一覧・個別の画面を作る。まだ見つけていない項目は、絵を影にして名前の欄を消す。案内人は司書の絵ができるまで仮の絵を使う |
| 見た記録 | 新しく載った印を消すための「もう見た」記録を、`PlayerPrefs` に利用者ごとのキー（案：`Library.Seen.<ユーザーID>`）で置く（[端末に置くときの作り方](../rules/data-storage.md#端末に置くときの作り方)） |
| シーンと入口 | シーンを生成するEditorのメニューに `Library` を足し、ホームにボタンを足す |
| 展示室 | シーンと画面のPrefabを[展示室](../features/showcase.md)に載せ、仮データでプレビューできるようにする |

## 進める順序

1. **案内人**：司書の人物と背景を決め、絵を作る。画面は仮の絵で先に作れるため、2以降と並行してよい。
2. **サーバーの記録**：テーブル・記録を書く関数・`GET /v1/library`・seed とテストを作る。キャラと装備の付与から記録させる。
3. **日々の歩数**：`GET /v1/library/steps` とテストを作る。
4. **クライアントの画面**：シーン・メニュー・タイル一覧・個別の画面を、キャラ（固有スキル）・武器・防具・スキル・敵（弱点）・日々の歩数について作る。アクセサリーとアイテムは定義がないため、メニューには出して「準備中」と知らせる。ホームの入口と展示室も整える。
5. **敵の遭遇と撃破**：弱点の作業の変更が入ったあとに、冒険の部屋を終えた知らせと冒険の終了へ敵を載せ、記録させる。
6. **仕様の反映**：[ライブラリの仕様](../features/library.md)の「実装との対応」、[画面一覧と操作](../features/screens.md)、[保存先の決め方の置き場所の一覧](../rules/data-storage.md#置き場所の一覧)を、作ったものに合わせて直す。

アクセサリー・アイテムの定義、スキルを1枚ずつ持つ仕組み、固有スキルの進化の保存ができたら、それぞれの作業でライブラリの記録と分類を足す。

## 完了条件

- サーバーのテストで、初めて読んだときの値、付与で記録が増えること、同じ物をまた手に入れても初めて見つけた日時が変わらないこと、利用者ごとに分かれること、不正な敵IDを拒むことを確かめている。
- Unityのテストで、分類ごとの変換と、見つけた項目・見つけていない項目の見せ分けを確かめている。
- Editorの接続先をローカルのサーバーにして、キャラや装備を手に入れ、敵と戦うと、ライブラリに載る。Playを止めて開き直しても残っている。
- ホームのボタンからライブラリを開け、展示室で画面をプレビューできる。
- 画面の撮影を見て、まだ見つけていない項目が枠・番号・影だけになり、新しく載った項目に印が付いている。

## 検証の方法

- サーバー：`server/` で `pnpm test`。
- クライアント：ライブラリのEditModeテストと、画面のPlayModeテストのクラスに絞って実行する（[作業中に実行するPlayModeテスト](../rules/client-testing.md#作業中に実行するplaymodeテスト)）。
- つないだ確認：`server/` の `pnpm dev` はユーザーが起動するため、起動を頼む。

## 未確認の事項と危険

- 弱点の作業の変更は、2026-10-18の時点で未コミットである。敵の定義のファイルや、戦闘と冒険をつなぐ処理の形が変わる可能性がある。
- 起動時の同期は直近7日分の歩数だけを送るため、日々の歩数は使い始めた日の7日前より古い日を持たない。

## 実装の記録

2026-10-19、ユーザーの「とりあえず実装してみて」を受けて、上の手順の2〜5を実装した。

- サーバー：`library_discoveries`（[0011_library_discoveries.sql](../../server/migrations/0011_library_discoveries.sql)）、`GET /v1/library`・`GET /v1/library/steps`、編成の初期付与とカードの付け替え・装備の初期付与からの記録、冒険の `clear`・`end` で受け取る遭遇した敵と倒した数、seedの見つけた記録。seedは `src` を読み込めないため、防具のIDだけをseedに写し、[seedのテスト](../../server/tests/integration/seed.test.ts)が装備の定義と照らし合わせる。
- クライアント：`Features/Library/`、`Library.unity`、ホームの「ライブラリ」のボタン、戦闘を終えたときの敵の数え方（[AdventureEnemyTally](../../client/Assets/Baryonyx/Features/Adventure/Runtime/AdventureEnemyTally.cs)）。
- 案内人（手順1）：エルフの司書と大図書館の書庫を Codex CLI で生成し、メニューの6行に白一色のアイコンを付けた（生成指示は [ArtSource](../../client/ArtSource/UI/Library/prompts.json)）。
- 計画からの変更：メニューに8行が収まらなかったため、武器・防具・アクセサリーを「装備」の1行にまとめ、タブで切り替えた。個別の内容は一覧の右に並べた（[画面の作り](../features/library.md#画面の作り)）。

確かめたこと：

- サーバー：`pnpm test` の105件が成功した（ライブラリのAPIの8件とseedの確認を含む）。
- クライアント：EditModeの480件が成功した（ライブラリの記録と印、敵の数え方の7件を含む）。PlayModeは `GuideScenesTests`・`AdventureLoopTests`・`BattleWeaknessRecordTests`・`HomeSceneTests`・`ShowcaseSceneTests` が成功した。
- 撮影：接続先のない仮の記録で、メニュー・キャラクター・装備・敵・日々の歩数のパネルと、ホームのボタンを撮影して確かめた。

ローカルのサーバーにつないだ確認（2026-10-19）：

- ローカルのDBは0011を当てる前の状態だったため、`pnpm db:reset` で作り直した。
- seedの「冒険の途中のプレイヤー」で、ホームの「ライブラリ」から開いた。見つけた記録（キャラ4/9など）、倒した数、seedで開示した苔スライムの雷の弱点、所持ルーンがサーバーの値で出た。
- 探索から戦闘の部屋（`f2-0`）に入り、敵をすべて倒した。サーバーの倒した数が、出た苔スライムと苔むした狼で1ずつ増え（9→10、0→1）、出ていない森の守り手は記録されなかった。
- Playを止めて開き直しても、倒した数と「NEW」の消えた状態が残っていた。
- ホームのACTパネルでEditorの仮の歩数を送ると、日々の歩数に6日分が新しい順に出た（値のない日は出ない）。
- 確認中に、シーンを単体で開いたとき、ライブラリだけが前のPlayの接続先を持ち越す不具合を見つけた。ほかの機能に合わせ、Playを始めるたびに接続先を空に戻すよう直した（[LibrarySession](../../client/Assets/Baryonyx/Features/Library/Runtime/LibrarySession.cs)）。

確かめていないこと：

- 負けて冒険を終えたときに、倒した数が送られること（サーバーのテストでは確かめた）。
- Androidの実機・エミュレーターでの表示。
- 狭い画面（4:3など）での一覧と個別の内容の重なり。
