# 文書の索引生成と検査

[全体索引](../README.md) / [文書管理方針](../rules/documentation-policy.md)

Python 3.10以上の標準ライブラリだけを使う。
以下の例はリポジトリ直下から実行する。
スクリプトの絶対パスを指定すれば、別の作業ディレクトリからも実行できる。

## 個別データを追加・更新したとき

```sh
python -B doc/tools/check_docs.py --write-index
python -B doc/tools/check_docs.py
```

[check_docs.py](check_docs.py)は分類内のREADMEの生成領域と、[外見・性格の比較索引](../art/visual-index.md)の生成領域を更新する。
対象は `doc/catalog/<分類>/<ID>.md` の `definition` と `visual-entity` である。
テンプレートは登録対象に含めない。
画像を持たない定義は分類索引にだけ載り、画像対象は両方へ載る。

生成領域の外にある説明・記入欄は維持する。
元の個別MDと生成された差分を一緒にレビューする。

## 検査すること

- `doc/` 内のMarkdownリンク先の存在と、MD内の見出しへのリンク。
- `doc/README.md`から各MDへリンクをたどって到達できること。
- 新しい企画仕様・個別データの必須メタデータと、文書IDの重複。
- 個別データのIDとファイル名、分類と配置の一致。
- 画像対象の比較用メタデータの存在。
- 個別MDから生成した分類索引・比較索引と、保存された索引の一致。

リンクは通常のMarkdownインライン形式を使う。
コードブロック内の例はリンク検査から除き、外部URLの到達確認は行わない。
未決欄が残っていること自体はエラーにしない。

## 検査処理を変更したとき

```sh
python -B -m unittest discover -s doc/tools -p 'test_check_docs.py'
```

[検査のテスト](test_check_docs.py)は一時ディレクトリで、壊れたリンク・重複ID・未掲載文書・古い生成索引などを確認する。
[Documentation CI](../../.github/workflows/docs-ci.yml)はPRとmain・dev・developへのpushで同じ検査を行う。
コード側のファイル移動も検査するため、変更パスによる絞り込みは設けない。

## 検査できないこと

本文と実装の意味の一致、数値バランス、外部サービスの現状、外見・性格の類似度は自動判定しない。
画像比較索引は類似候補を探す入口であり、重複がないことの保証ではない。
見直す文書の組み合わせは文書管理方針の「変更に合わせた見直し」を使う。
