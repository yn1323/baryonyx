# キャラクターとパーティ編成

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、2026-09-15のユーザー提示仕様、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

- パーティは4人固定とする。編成では4つの枠からキャラを外して空きにもできる（2026-10-04、[編成](screens/adventurers.md#パーティ)）。
- 探索中も仲間を入れ替え、獲得した仲間をすぐに編成できるようにする。
- 前衛・後衛の配置システムは設けない。
- 装備・パッシブスキル・スキル・パーティ構成の組み合わせでシナジーを作る。

### キャラクターの構成

各キャラは次の要素を持つ。

| 要素 | 内容 |
|---|---|
| レベル | ルーンを使ってレベルアップし、ステータスが上がる。パッシブスキルと固有スキルも解放する（[育成](progression.md)） |
| ステータス | キャラ固有の値を持つ。項目は[ステータスの項目](#ステータスの項目)の8つで、敵も同じ項目を持つ |
| パッシブスキル | 2つ。戦闘中に操作なしで働く（[パッシブスキル](passives.md)） |
| 固有スキル | 3つ。Lv1・Lv10・Lv30で1つずつ解放する（2026-10-24、ユーザーの指示。それまではLv5・Lv20・Lv40）。そのキャラ専用のカードで、外せない。戦闘ではデッキのカードになる（[戦闘仕様](combat.md#固有スキル)）。冒険の中で覚醒し、取得した段階のどれを使うかを編成で選ぶ（[固有スキルの覚醒](skill-evolution.md)） |
| 装備 | 武器・防具・アクセサリー。基本的にどのキャラでも装備できる。アクセサリーは最大3つで、初めは0枠からレベルアップで枠が開く（[装備](equipment.md)） |
| カスタムスキル | 3つの枠（2026-10-23）。空けておける。それぞれにスキルかアイテムを1つ入れ、戦闘ではデッキのカードになる。スキルはカード型の技で、キャラごとに装備できる属性が異なる。アイテムは道具や素材である（[アイテム](items.md)） |

1人の6枚（固有スキル3枚と、カスタムスキル3枚）を4人分合わせた最大24枚が、戦闘のデッキになる（2026-10-23）。
枚数はプレイヤーが選ぶものにせず、解放前の固有スキルと空いたカスタムスキルの枠の分だけ少なくなる。
Lvが低いうちはデッキが少ないが、ユーザーはそれでよいとした。
属性の種類とカードの使い方は[戦闘仕様](combat.md#属性と弱点)を正本とする。

### 持っているスキル

スキルは、手に入れるたびに1枚ずつ別に持つ（2026-10-06）。
武器・防具と同じく、同じ種類のスキルを何枚でも持てる。
同じ種類でも1枚ごとに倍率が違い、効果量が違う（[品質](inventory.md#品質)）。
武器・防具と同じく、1枚は1人の1つの枠にだけ付けられる（2026-10-06）。
同じ種類を2枚持っていれば、1人の2つの枠に2枚とも入れられる。

### ステータスの項目

味方のキャラと敵は、同じ8つのステータスを持つ（2026-10-04、ユーザー決定）。
敵ごとの値は[敵の定義](../catalog/enemies/README.md)に書く。

| 項目 | 使い道 | 状態 |
|---|---|---|
| HP | 0になると戦闘不能になる | 確定 |
| 物攻 | 物理（斬・打・貫）の技の威力 | 候補 |
| 物防 | 物理の技で受けるダメージを減らす（[ダメージと防御](combat.md#ダメージと防御)） | 確定 |
| 属攻 | 魔法（炎・氷・雷）の技の威力 | 候補 |
| 属防 | 魔法の技で受けるダメージを減らす（[ダメージと防御](combat.md#ダメージと防御)） | 確定 |
| 速度 | [ターン順](combat.md#ターン順)と連続ターンを決める。これまでの文書の「すばやさ」に当たる | 確定 |
| 会心 | 会心の一撃（ダメージが増える当たり）の出やすさ（[会心の一撃](combat.md#会心の一撃)） | 確定 |
| 幸運 | 状態異常のかかりやすさ、かかりにくさ（[状態異常のかかりやすさ](combat.md#状態異常のかかりやすさ)） | 確定 |

2026-10-04、ユーザーの決定で、物防・属防・会心・幸運の使い道を確定した。
物攻・属攻の使い道は、項目の名前から考えた候補のままである。
属性のない技・回復・ブロックの量にどの項目を使うかは[未決](#未決事項)とする。
会心の一撃の倍率と確率への換算は、2026-10-25に決めた（[会心の一撃](combat.md#会心の一撃)）。
値は、味方も敵もLv100のときの値で定め、各Lvの値は成長率を掛けて出す（[レベルとステータス](progression.md#レベルとステータス)の仮設定）。
防御で受けるダメージと状態異常の付与率は、この成長率に合わせ、同じLv同士ならLvによらず同じ割合になるように計算する（[ダメージと防御](combat.md#ダメージと防御)、[状態異常のかかりやすさ](combat.md#状態異常のかかりやすさ)）。

### キャラと編成の保存

持っているキャラ、各キャラのLvとスキル、パーティの4つの枠は、ユーザーごとにゲームサーバーのDBで管理する（2026-10-04）。
編成の画面のパーティ・スキル・育成は、開くたびにサーバーから読み、変更はすぐ画面に出してから、裏でサーバーに保存する（[楽観的更新](../rules/data-storage.md#サーバーに置くときの作り方)）。保存を待つ間も続けて操作でき、画面を閉じても保存は続く。武器・防具の付け替え（[装備](screens/loadout.md#装備)）も同じで、装備は装備の機能が保存する（[装備の保存](equipment.md#持っている装備と付け替えの保存)）。
保存できなかったときは、出した変更を戻して通知の帯で知らせる。
レベルアップの費用はサーバーで計算し、サーバーのルーンの残高から引く（[育成と強化](progression.md#レベルアップ)）。
画面では、保存を待たずにLvを上げ、同じ決まりで計算した費用を所持ルーンから引いて見せる。

キャラ・Lv・カード・編成は、サーバーの次のAPIとテーブルで、ユーザーごとに保存する（[実装](../../server/src/features/party/routes.ts)）。
どれもログイン中のセッション（ゲストを含む）が必要で、ないときは401を返す。
変更するAPIは、何が変わったか（`change`）と最新の状態を返す。

| API | 内容 |
|---|---|
| `GET /v1/party` | 持っているキャラ（ID・Lv・カスタムスキル3枠の中身。空きはnull。絆の段と絆のしるしの数）、4つの枠のキャラ（空きはnull）、持っているスキル（1枚ずつのID・種類・倍率・品質）とアイテム（種類と数）、所持ルーン、Lvの決まり（上限・1レベルあたりの費用）を返す。枠の中身は、持っているスキルの1枚なら `card:<ID>`、アイテムなら `item:<アイテムのID>` で表す。ログインしたときに、仮の初期データを1回だけ付与する（[equipment/starter.ts](../../server/src/features/equipment/starter.ts) の `grantStarters`）。初めのカードは品質C（×1.00）のスキルとして1枚ずつ持ち物に入れ、その1枚を枠に入れる |
| `PUT /v1/party/slots/{0〜3}` | 本文 `{"characterId": "..."}` で、パーティにいないキャラを枠に入れる。パーティにいるキャラは409（`already_in_party`） |
| `DELETE /v1/party/slots/{0〜3}` | 枠のキャラを外す。最後の1人は409（`keep_one`） |
| `PUT /v1/party/characters/{id}/cards/{0〜2}` | 本文 `{"card": "card:<ID>"}` か `{"card": "item:<アイテムのID>"}` で、持っているスキルの1枚かアイテムを入れる。そのキャラのほかの枠にあれば入れ替える（`swap`）。スキルの1枚をほかのキャラが付けていれば、そのキャラから外して付け替える（`move`、`from` に外したキャラ）。アイテムは持っている数まで別々の枠に入れられ、数だけほかの枠で使っていれば409（`item_in_use`）。持っていない1枚・アイテムは404（`card_not_owned`） |
| `DELETE /v1/party/characters/{id}/cards/{0〜2}` | 枠のスキルかアイテムを外して空きにする（スキルの付け替えの「スキルを外す」、2026-10-24）。空きの枠は変えない（`change` は `none`） |
| `POST /v1/party/characters/{id}/level-up` | 本文 `{"requestId": "...", "fromLevel": 12, "toLevel": 15}` でレベルを上げる。費用はサーバーで計算し、ルーンの減算・Lvの更新・記録を1回の書き込みにまとめる。今のLvが違えば409（`level_changed`）、ルーンが足りなければ409（`insufficient_runes`）で、何も変えない。同じ `requestId` の再送には記録済みの結果を返す |
| `POST /v1/party/characters/{id}/bond` | 本文 `{"bond": 3}`（深めたあとの段）で、絆のしるしを1つ使って絆を1段深める（[キャラが被ったとき](monetization.md#キャラが被ったとき)）。今の段の次でなければ409（`not_next_bond`）、しるしがなければ409（`no_bond_token`）で、何も変えない。すでにその段なら何も変えずに成功を返す（再送） |

知らないIDや範囲外の枠・Lvは400、持っていないキャラは404（`character_not_owned`）を返す。
外す操作を `DELETE` に分けたのは、クライアントが本文を作る `JsonUtility` が `null` の文字列を空文字にして送るためである。

| テーブル | 内容 |
|---|---|
| `party_characters` | ユーザーとキャラごとに1行。Lvと入手・更新日時 |
| `party_slots` | ユーザーと枠ごとに1行（空きは行なし）。同じキャラを2つの枠に入れられない一意制約と、持っているキャラだけを入れられる外部キーを持つ |
| `party_character_cards` | ユーザー・キャラ・カスタムスキルの枠ごとに1行。持っているスキルの1枚（`card_id`）かアイテム（`item_id`）のどちらかを指す。1枚のスキルを2つの枠に入れられない一意制約を持つ |
| `skill_cards` | 持っているスキル1枚ごとに1行。種類と倍率（百分率の整数）。初めのカードと冒険のドロップで増える |
| `item_holdings` | 持っているアイテムの種類ごとに1行。数を持つ |
| `party_level_ups` | レベルアップ1回ごとの記録。要求ID・上げる前と後のLv・使ったルーン・使ったあとの残高。ルーンの消費の記録を兼ねる |
| `party_profiles` | 初期データを付与済みのユーザー。付与した要求を `grant_id` で見分け、同時に届いたログインで初めのカードを二重に入れない |

サーバーはキャラとカスタムスキルのカードのIDだけを持ち、名前・絵・ステータス・固有スキル・パッシブ・カードの属性はクライアントの仮データが持つ。
クライアントの仮データ（[育成](screens/adventurers.md#育成)・[スキル](screens/loadout.md#スキル)・[戦闘画面](screens/battle.md#戦闘画面の見た目モック)のモック）は、[ステータスの項目](#ステータスの項目)の8つをLv100の値で持ち、各キャラのLvでの値を成長率から出す（[自キャラのLv100のステータス](progression.md#自キャラのlv100のステータス)）。
キャラごとに付けられる属性の判定は、決まりが仮のため、クライアントだけで行う（2026-10-04、ユーザー決定）。
初期データ（9人のLv 12〜1、各2枚のカスタムスキル、トーマ・ルカ・アリア・ミナの編成）とLvの決まり（上限Lv 100（2026-10-23に30から改めた）、Lv n から n+1 へ n×100ルーン）は、クライアントの仮データと同じ値をサーバーの[定義](../../server/src/features/party/catalog.ts)にも置いた仮設定である。
サーバーの接続先がないとき（展示室のプレビューなど）だけ、クライアントは仮データを使い、変更はアプリを動かしている間だけ残す。

1人のカードは、2026-10-07から固有スキル2枚とカスタムスキル2枚に分けて実装し、2026-10-23に3枚ずつにした（マイグレーション `0017_three_cards_per_kind`）。
サーバーが保存するのはカスタムスキルの3枠で、固有スキルは育成の仮データ（`TrainingMockData`）が持つ。

2026-10-20に、スキルを1枚ずつ持つ形と倍率、カスタムスキルにアイテムを入れることを実装した（[冒険のドロップ](drops.md)）。
編成のスキルの画面は、サーバーから読んだ持ち物を候補にする。持っているスキルは1枚ずつ別の行にし（品質の高い順）、ほかの人が使っている1枚には「〇〇が使用中」と出して、押すとその人から外して付け替える。アイテムのタブには持っているアイテムを並べ、「所持 3」のように数を出し、数だけ使っていれば押せない。
カスタムスキルに入れたアイテムは、まだ戦闘のデッキに入らない（戦闘での使い方が未実装）。
アクセサリーは持ち物に入るが、付ける枠はまだない（[装備](equipment.md)）。

2026-10-21から、Home・冒険の地図・冒険の戦闘に、今の編成を出す。
どの画面も、編成をサーバーから読んでいなければ先に読み、読めなければ仮データの編成で続ける。

| 画面 | 編成から出すもの |
|---|---|
| Home | 焚き火を囲む4つの立ち位置に、枠の順（奥の左・奥の右・手前の左・手前の右）でその人の戦闘のドット絵を立たせる。右の2人は焚き火を向くよう左右を反転する。空いた枠の位置には誰も立たない |
| 冒険の地図 | 隊列の4つの位置に、枠ごとの人を立たせる。空いた枠の位置は隠す |
| 冒険の戦闘 | 味方の4つの位置に、枠ごとの人の絵・名前・Lv・そのLvのステータスを置き、HPを満タンで始める。デッキは、各人の解放済みの固有スキル（編成でセットした段階）と、カスタムスキルに入れたスキル（1枚ごとの倍率つき）である。各人はLvで解放した[パッシブ](passives.md)を持つ。空いた枠の位置は隠れて、狙えず、復活もしない |

絵のないキャラ（色を掛けた仮の絵）は、Home・地図・戦闘では色だけを使い、左右の反転は使わない。
戦闘で敵の方を向き、Homeで焚き火の方を向くためである。
