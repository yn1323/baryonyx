# キャラクターとパーティ編成

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、2026-09-15のユーザー提示仕様、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

- パーティは4人固定とする。編成では4つの枠からキャラを外して空きにもできる（2026-10-04、[編成](screens.md#編成)）。
- 探索中も仲間を入れ替え、獲得した仲間をすぐに編成できるようにする。
- 前衛・後衛の配置システムは設けない。
- 装備・パッシブスキル・スキル・パーティ構成の組み合わせでシナジーを作る。

### キャラクターの構成

各キャラは次の要素を持つ。

| 要素 | 内容 |
|---|---|
| レベル | ルーンを使ってレベルアップし、ステータスが上がる。パッシブスキルと固有スキルも解放する（[育成](progression.md)） |
| ステータス | キャラ固有の値を持つ。項目は未決 |
| パッシブスキル | 2つ |
| 固有スキル | 2つ。手札とは別に、エネルギーを払っていつでも使える（[戦闘仕様](combat.md#固有スキル)） |
| 装備 | 武器・防具。基本的にどのキャラでも装備できる（[装備](equipment.md)） |
| スキル | 4枚。カード型で、戦闘ではデッキのカードになる。キャラごとに装備できる属性が異なる |

4人のスキルを合わせた4人×4枚＝16枚が、戦闘のデッキになる。
属性の種類とカードの使い方は[戦闘仕様](combat.md#属性と弱点)を正本とする。

### キャラと編成の保存

持っているキャラ、各キャラのLvとスキル、パーティの4つの枠は、ユーザーごとにゲームサーバーのDBで管理する（2026-10-04）。
酒場の編成・スキル・育成は、開くたびにサーバーから読み、変更をサーバーに保存できてから画面に反映する。
保存できなかったときは画面を変えずに知らせる。
レベルアップの費用はサーバーで計算し、サーバーのルーンの残高から引く（[育成と強化](progression.md#レベルアップ)）。

## 設計方針

決まった役割分担を唯一の正解にしない方針は[装備更新と戦い方](equipment.md#戦い方を変える装備更新)で管理する。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| ステータスの項目 | 未決。すばやさ（[ターン順](combat.md#ターン順)）を持つことだけが決まっている |
| レベルの上限、必要ルーン、パッシブ・固有スキルを解放するレベル | 未決 |
| キャラごとに装備できるカードの属性の組み合わせ | 未決。酒場の[スキル](screens.md#スキル)のモックでは、仮データで最初に付けているカードの属性を仮に使う |
| 装備を「基本的に」どのキャラでも付けられるとした例外の有無 | 未決 |
| スキルの入手方法 | 冒険でスキルを獲得できる（[探索と進行](stage-progression.md#分岐ルートを選んで進む冒険)）。ほかの入手方法、持っている枚数の数え方、同じカードを複数のキャラが付けられるかは未決。酒場の[スキル](screens.md#スキル)のモックでは、50枚すべてを持ち、同じカードを複数のキャラが付けられるものとして仮に扱う |
| キャラの具体的な構成と加入方法 | 未決。召喚からキャラが出る可能性がある（[召喚](monetization.md)） |
| 初期メンバー、未所持枠の扱い | 未決。サーバーは仮に、初めて読むユーザーへ仮データの9人（Lv・カード・4人の編成を含む）を付与する（[実装との対応](#実装との対応)） |
| 同じキャラを複数編成できるか | 未決 |
| 入れ替え・装備変更が可能なタイミング | 探索中に変更できる。戦闘中の変更と、復活画面から変更できるかは未決 |
| 控えメンバーの有無 | 未決 |
| 4人に満たないパーティで冒険に出られるか、最低の人数 | 未決。[編成](screens.md#編成)では仮に1人以上を残し、最後の1人は外せない |

回答を得るまで、ほかの仕様や実装へ波及させない。

| 項目 | 既存・旧仕様 | 今回の内容 | 影響する範囲 |
|---|---|---|---|
| 職業の扱い | 各キャラが固定職業を持ち、転職は設けない。職業ごとの役割・得意不得意を定義する | キャラの構成に職業がない。装備は基本的にどのキャラでも付けられ、キャラごとの違いは装備できるカードの属性で表す | 職業を残すか廃止するか。残す場合の役割（カードの属性の組み合わせを職業で決めるかなど）。[職業定義](../catalog/classes/README.md)、[キャラ定義](../catalog/characters/README.md) |

## 実装との対応

本ページは企画上の要求・未決事項を記す。
現在の実装範囲は[機能索引の実装欄](README.md#現在の実装)で確認する。

キャラ・Lv・カード・編成は、サーバーの次のAPIとテーブルで、ユーザーごとに保存する（[実装](../../server/src/features/party/routes.ts)）。
どれもログイン中のセッション（ゲストを含む）が必要で、ないときは401を返す。
変更するAPIは、何が変わったか（`change`）と最新の状態を返す。

| API | 内容 |
|---|---|
| `GET /v1/party` | 持っているキャラ（ID・Lv・4枠のカード）、4つの枠のキャラ（空きはnull）、所持ルーン、Lvの決まり（上限・1レベルあたりの費用）を返す。初めて読むユーザーには、仮の初期データを1回だけ付与する |
| `PUT /v1/party/slots/{0〜3}` | 本文 `{"characterId": "..."}` で、パーティにいないキャラを枠に入れる。パーティにいるキャラは409（`already_in_party`） |
| `DELETE /v1/party/slots/{0〜3}` | 枠のキャラを外す。最後の1人は409（`keep_one`） |
| `PUT /v1/party/characters/{id}/cards/{0〜3}` | 本文 `{"skillId": "..."}` でカードを入れ、そのキャラのほかの枠にあれば入れ替える |
| `POST /v1/party/characters/{id}/level-up` | 本文 `{"requestId": "...", "fromLevel": 12, "toLevel": 15}` でレベルを上げる。費用はサーバーで計算し、ルーンの減算・Lvの更新・記録を1回の書き込みにまとめる。今のLvが違えば409（`level_changed`）、ルーンが足りなければ409（`insufficient_runes`）で、何も変えない。同じ `requestId` の再送には記録済みの結果を返す |

知らないIDや範囲外の枠・Lvは400、持っていないキャラは404（`character_not_owned`）を返す。
外す操作を `DELETE` に分けたのは、クライアントが本文を作る `JsonUtility` が `null` の文字列を空文字にして送るためである。

| テーブル | 内容 |
|---|---|
| `party_characters` | ユーザーとキャラごとに1行。Lvと入手・更新日時 |
| `party_slots` | ユーザーと枠ごとに1行（空きは行なし）。同じキャラを2つの枠に入れられない一意制約と、持っているキャラだけを入れられる外部キーを持つ |
| `party_character_cards` | ユーザー・キャラ・枠ごとに1行。1人のキャラの4枠で同じカードを持てない一意制約を持つ |
| `party_level_ups` | レベルアップ1回ごとの記録。要求ID・上げる前と後のLv・使ったルーン・使ったあとの残高。ルーンの消費の記録を兼ねる |
| `party_profiles` | 初期データを付与済みのユーザー |

サーバーはキャラとカードのIDだけを持ち、名前・絵・ステータス・スキル・カードの属性はクライアントの仮データが持つ。
キャラごとに付けられる属性の判定は、決まりが仮のため、クライアントだけで行う（2026-10-04、ユーザー決定）。
初期データ（9人のLv 12〜1、各4枚のカード、トーマ・ルカ・アリア・ミナの編成）とLvの決まり（上限Lv 30、Lv n から n+1 へ n×100ルーン）は、クライアントの仮データと同じ値をサーバーの[定義](../../server/src/features/party/catalog.ts)にも置いた仮設定である。
サーバーの接続先がないとき（展示室のプレビューなど）だけ、クライアントは仮データを使い、変更はアプリを動かしている間だけ残す。

## 変更と判断の記録

- 2026-10-04：ユーザーの指示により、「カードスキル」の呼び名を「スキル」に改めた（[用語集](../game/glossary.md)）。酒場・育成の画面では、付け替える対象を「カード」ではなく「スキル」と書く。戦闘の手札・山札は「カード」のままとする。
- 2026-10-04：ユーザーの依頼で、持っているキャラ・Lv・カードスキル・編成をユーザーごとにサーバーのDBへ保存するようにした（[計画](../plans/2026-10-04-tavern-party-save.md)）。レベルアップに使うルーンもサーバーの残高から引く。初期データには仮データの9人を付与し、カードの属性の判定はサーバーでは行わないことをユーザーが決めた。

- 2026-10-04：ユーザーの依頼で、酒場に[カードスキル](screens.md#スキル)の画面を作った。パーティにいない仲間も含め、キャラごとの4枚を付け替えられる。付け替えたカードは編成・レベルと同じく、アプリを動かしている間だけ残す。
- 2026-10-04：ユーザーの依頼で、酒場に[編成](screens.md#編成)の画面を作った。左の4つの枠と右の仲間で入れ替え、ユーザーの指示で仲間の最後に置いた「外す」で枠を空けられる。空きを許すと4人に満たないパーティができるため、冒険に出られる最低の人数を未決事項に加えた。画面では仮に1人以上を残す。編成はアプリを動かしている間だけ残り、保存はしない。
- 2026-09-30：ユーザーと相談し、デッキを12枚から16枚に増やし、カードスキルをキャラごとに4枚にした。毎ターン3枚を引く決まり（[手札](combat.md#手札)）と合わせて、5ターン前後で山札が一巡する枚数にした。
- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、キャラの構成（レベル、ステータス、パッシブスキル×2、固有スキル×2、武器・防具、カードスキル×3）と、12枚のデッキ、ルーンによるレベルアップを反映した。装備は基本的にどのキャラでも付けられるとし、職業による装備適性の制限を置き換えた。新しい構成に職業がないため、職業そのものの扱いは確認待ちとした。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| 職業に応じて武器・防具の装備適性を制限する | 装備は基本的にどのキャラでも付けられる。キャラごとの違いは、装備できるカードの属性で表す |
| 各キャラが固定職業・固有スキル・固有パッシブを持ち、転職は設けない | 固有スキル2つとパッシブスキル2つをレベルで解放する。職業の扱いは確認待ち |
| 最初から自由にスキルを付け替える構成は前提にしない | キャラごとに3枚のスキルを、装備できる属性の範囲で付け替える |
| 試作では各キャラのアクティブスキルを2つとする | スキル3枚と固有スキル2つの構成へ変更 |

- 2026-09-19：参照会話と実装指示により、探索中の仲間変更と獲得直後の編成導線を追加した。ワイヤーのサンプルと本番の加入・編成ルールを区別する。

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様を根拠に、前衛・後衛なし、固定職業による装備適性、固有スキルを中心とする編成を明記した。完成版のスキル構成を試作の数と区別し、MVP・装備・戦闘から参照する。
