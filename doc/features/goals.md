# 運動目標と達成報酬

[機能索引](README.md) / [ルーン経済](economy.md) / [運動データ](exercise-rewards.md) / [セーブ](accounts-save.md)

2026-09-15にユーザーが提示した「てくてくダンジョン：運動目標設定の仕様まとめ」を管理する。
任意の日次・週次目標に運動実績を自動集計し、目標条件の難易度と直近の達成実績からルーン倍率を決める。
ルール・設計方針・仮設定・未確定は[仕様の確度](README.md#仕様の確度)を区別し、具体的な報酬量や未採用の倍率を確定値として扱わない。
[初期企画](../game/brief.md)や以前の案から変更した点は、末尾の変更記録へ分ける。

## 確定している方針

### 目標枠と任意設定

| 項目 | 仕様 |
|---|---|
| 目標枠 | 「1日の目標」1枠と「1週間の目標」1枠 |
| 設定 | 両方任意。一方だけでも、両方未設定でもよい |
| 未設定の場合 | ゲームを遊べる。目標とは別に[歩数によるログインボーナス](economy.md#目標報酬と歩数ログインボーナス)がある |
| 頻度 | 枠によって決まる。日次・週次を自由に組み合わせて2つ作る方式にはしない |
| 曜日・日数指定 | 「週○日」「曜日指定」は設けない |
| 設定の継続 | 同じ設定で次の日・週も継続し、毎回設定し直す必要はない |
| 同じ運動の反映 | 両方の条件を満たす運動は、日次・週次それぞれの進捗に反映する |
| 重複制限 | 時間帯や運動方法の重複を制限せず、日次1枠・週次1枠という構成で整理する |

例えば「1日5,000歩」と「週合計25,000歩」を設定して今日5,000歩いた場合、日次は達成し、週次は5,000歩進む。
実際に歩いた量は5,000歩であり、活動履歴で両方の進捗を合算して「10,000歩歩いた」と表示しない。
同じ運動を両方の目標へ反映できることと、両目標の倍率を掛け合わせることは別であり、報酬計算は未確定とする。

### 設定の流れと判定基準

```text
目標枠を選ぶ → 運動方法 → 判定基準・目標量 → 任意で時間帯
```

日次・週次は枠で決まるため、設定画面で改めて頻度を選ばせない。

| 運動方法 | 選べる判定基準 | 最初に表示する基準 |
|---|---|---|
| ウォーキング | 歩数・距離・運動時間 | 歩数 |
| ランニング | 距離・運動時間 | 距離 |
| サイクリング | 距離・運動時間 | 距離 |

1つの目標では判定基準を1つ選ぶ。
「5,000歩かつ30分」のように複数基準を同時指定する方式は、現行仕様に含めない。
目標量は基本的に選択式とし、候補に合わない場合は「細かく設定」から調整できるようにする。
選択肢と調整幅は[仮設定](#目標量の選択肢と調整幅)で管理する。

### 時間帯の指定

| 項目 | 仕様 |
|---|---|
| 初期状態 | 指定なし |
| 指定方法 | 開始・終了時刻を選択 |
| 選択単位 | 1時間刻み |
| 指定範囲 | 同じ日の中だけ。23時〜翌1時など、日付をまたぐ指定は設けない |
| 指定なし | その日全体を集計対象にする |
| 指定あり | 指定時間帯に行った分だけを集計する |

週目標に時間帯を指定した場合は、各日の指定時間帯に行った分を1週間で合計する。
例えば「週合計25,000歩・19〜20時」なら、その週の各日19〜20時の歩数を合計する。

### 集計期間

| 目標 | 集計期間 |
|---|---|
| 1日の目標 | 0時〜24時 |
| 1週間の目標 | 月曜0時〜翌月曜0時 |

時間帯を指定しても、日次・週次の集計期間そのものは変えない。
基準タイムゾーンの扱いは実装前に決める。
目標以外の日付ルールとの関係は[日付の仕様](daily-rules.md)を参照する。

### 運動実績の集計

1回の運動で達成する必要はなく、対象期間・時間帯の中で行った運動を合算する。

歩数目標は、通勤・買い物などの日常の移動も含める。
明示的なウォーキングの運動記録に限定せず、取得した歩数を対象にし、ランニング中の歩数も含める。

距離・運動時間の目標は、選択した運動方法に対応する記録を使う。
必要な距離データを確認できない場合は状況を説明し、時間目標への切り替えを案内する。
記録がまだないだけで利用不可と決めつけない。

時間帯指定は、運動を開始した時刻だけでは判定しない。
指定時間帯に該当する実績だけを集計し、時間帯をまたぐ記録の具体的な分割・集計方法は実装前に定義する。

### 未起動中の運動と遅れて届く記録

ゲームの起動や報酬の受け取り操作ではなく、実際の運動記録で達成を判定する。
後から取得できた記録も、実際に運動した日・週へ反映する。
日付や週が変わってから達成を確認した場合は、達成履歴と継続倍率を訂正する。

記録を確認できていない状態と、実績がゼロの状態は区別する。
再取得・再同期で、同じ記録や達成実績を二重加算しない。
同期遅延の猶予・訂正範囲・ルーンの差額処理は未確定とする。

### 倍率の構成

目標の倍率は、次の2つを分けて設計する。

```text
目標条件の難易度による倍率 × 継続倍率
```

**難易度による倍率**は目標条件から決める。
**継続倍率**は、直近の一定期間に達成した日数・週数から決める。
生涯累計や連続達成日数では計算しない。
日次・週次の報酬の組み合わせや、倍率を掛けるルーンの範囲は[報酬設計](economy.md#目標報酬と歩数ログインボーナス)で別途決める。

### 継続倍率に使う実績

| 項目 | 1日の目標 | 1週間の目標 |
|---|---|---|
| 集計対象 | 当日を含む直近90日 | 今週を含む直近12週 |
| 評価する実績 | 達成した日数 | 達成した週数 |
| 達成実績の加算上限 | 1日1回 | 1週1回 |
| 達成の反映タイミング | その日の達成直後 | 週末を待たず、達成直後 |
| 最大になる条件 | 90日すべて達成 | 12週すべて達成 |
| 継続倍率の上限の大小関係 | 週次より高くする | 日次より低くする |

上限までの目安は約3か月だが、管理単位は90日／12週とする。
以前の13週案は使わない。
日次・週次の継続実績は独立して管理する。
具体的な最大倍率と増え方は仮設定・未確定事項として分ける。

### 未達や休息による継続倍率の変化

未達成のペナルティは設けない。
1日・1週未達でも全リセットしない。
古い達成実績が90日／12週の対象期間から外れ、新しい達成で補えなければ、倍率が徐々に下がる。
未達そのものに別の減点を加える方式ではない。

達成しても、同時に古い達成が対象外になれば、倍率が上がらず維持になることがある。
「達成するたびに必ず倍率アップ」とは説明しない。
達成実績がなくなった場合は継続倍率×1.0、すなわち継続ボーナスなしとする。
ルーン獲得量がゼロになる意味ではない。

### 倍率の反映タイミング

達成による上昇は即時、未達に伴う低下は締め切り後に反映する。
新しい日・週が始まった直後に、まだ挑戦中なのに倍率が下がる表示は避ける。
直近期間の入れ替えと、締め切りまでの猶予を組み合わせる厳密な計算手順は、実装時に定義する。

達成によって上がった継続倍率は、今回獲得するルーンから適用し、次回まで待たせない。
何のルーンに倍率を掛けるか、すでに受け取った分へ遡及適用するか、遅延反映時の差額をどう処理するかは報酬設計で決める。

### 初回設定

当日／今週の取得できた記録のうち、設定した条件に合う分を最初から進捗に含める。
例えば、今日すでに3,000歩いてから「1日5,000歩」を設定した場合は、3,000／5,000歩から始める。
時間帯を指定した場合は、その時間帯に該当する分だけを含める。

初回にデータがなければ、固定ルーンを配布する。
配布量・回数・「データがない」の判定条件は未確定である。
初回の締め切りも明示し、日曜夜などの途中参加で、説明なく通常の1週間分を要求する見せ方は避ける。
初回の端数期間の評価や、固定ルーンを達成実績に含めるかは未確定とする。

### 編集・削除・再設定

| 操作 | 継続実績・適用の扱い |
|---|---|
| 目標量の変更 | 継続実績を引き継ぐ |
| 時間帯の変更 | 継続実績を引き継ぐ |
| 運動方法の変更 | 継続実績を引き継ぐ |
| 歩数・距離・時間の基準の変更 | 継続実績を引き継ぐ |
| 日次目標の設定変更 | 原則、翌日から反映 |
| 週次目標の設定変更 | 原則、翌週から反映 |
| 反映前の変更予約 | いつから変わるかを表示し、取り消せるようにする |
| 目標を外し、後で再設定 | その目標枠の継続履歴を保持する |

継続実績は、特定の運動方法や条件ではなく、「1日の目標枠」「1週間の目標枠」に残す。
運動方法を変えても継続側の積み上げは残り、新しい条件に応じて難易度側の倍率を計算する。
日次・週次の履歴を移し替えたり、合算したりはしない。

目標を外している間も、90日／12週の対象期間は通常どおり進む。
履歴を残すことと、倍率を永久に固定することは別である。
過去の達成は当時の条件で保持し、現在の目標設定を使って過去を書き換えない。

### 設定画面

初回から両方の目標設定を求めず、両方スキップして始められるようにする。
片方が空いていても、未完了や警告として扱わない。
時間帯は「指定なし」を初期状態とし、指定したい人だけ開く。

保存前には条件を一文にまとめる。

> 1日の目標：19〜20時の間に5,000歩

> 1週間の目標：時間帯指定なしでサイクリング30km

条件を変えるたびに倍率表示も更新し、調整結果が分かるようにする。
目標期間と時間帯から達成できない組み合わせは、理由を表示して選択を防ぐ。
例えば日次目標で「19〜20時の1時間内に90分運動する」は選べない。

### 進捗と履歴の表示

| 状態・情報 | 表示方針 |
|---|---|
| 両方未設定 | 今日の歩数・ログインボーナスを中心に表示。目標設定への導線は置くが警告しない |
| 進行中 | 運動方法、基準、目標量、期間、時間帯、対象実績、残りの量を表示 |
| 歩数目標 | 日常の移動も含むことを明示 |
| 達成後 | 「達成済み」を残し、目標を超えた実績も増やし続ける |
| 継続倍率 | 倍率と、直近90日の達成日数／12週の達成週数を確認できる |
| 次回達成の効果 | 実際の計算に応じて「倍率アップ」「今の倍率を維持」を表示 |
| 未設定期間・開始前 | 未達と同じ扱いにせず、「—」などで区別 |
| データ未確認 | 実績ゼロ・未達と区別して表示 |
| 変更予約中 | 変更後の条件と適用開始日を表示 |

例えば5,000歩を達成後に6,500歩まで進んだ場合、達成済みのまま6,500歩と表示する。
達成した瞬間にゼロへ戻し、再び未達になったようには見せない。

現在の進捗だけでなく、過去に何の運動をどれだけ行ったかも確認できるようにする。
過去の目標履歴では、当時の目標条件・対象となった運動量・達成状況・適用倍率を確認できるようにする。

### サーバーに保存する実績と履歴

実績系のデータはサーバーに保存する方針とする。
表示と継続計算に必要な情報は次のとおりであり、具体的なDBスキーマや保存粒度を確定する一覧ではない。

| 情報 | 用途 |
|---|---|
| 運動方法・運動量・対象日時 | 現在と過去の活動実績を表示する |
| 当時の目標条件 | 過去の目標を当時の条件のまま表示・判定する |
| 日次・週次の達成状況 | 達成履歴の表示と継続倍率の計算 |
| 目標枠ごとの継続履歴 | 編集・削除・再設定後も履歴を引き継ぐ |
| 適用倍率 | 過去にどの倍率を適用したかを確認する |

現在の設定で過去を書き換えない一方、遅れて届いた記録によって過去の実績・達成状況を正しく訂正する。
外部から取得した元データをどこまで保存するか、保存期間、端末とサーバーの処理分担は未確定である。
ゲーム全体の保存方針との関係は[アカウントとセーブ](accounts-save.md)で管理する。

### 歩数以外の目標設定時のワーニング

歩数以外の指標（距離・運動時間）を条件に含む目標を設定するときは、設定の確定前にワーニングを表示する。
目標に必要なデータを対応する運動アプリや機器で記録し、そのアプリでHealth Connectへの書き込みを許可する必要があることを案内する。

- Health Connectの設定を開く導線を設ける。
- 運動アプリごとの書き込み設定方法を説明する公式ヘルプのWebページへのリンクを設ける。
- 設定後にデータを再取得して確認できるようにする。

記録がないことだけを理由に、運動アプリが未接続であると断定しない。
baryonyx自身の読み取り権限が不足している場合は、その許可を別途案内する。
対象アプリとリンク先は実装時に公式情報を確認して決める。
この案内は必要な記録元・権限を説明するものであり、目標の未設定枠に対する警告とは区別する。

## 設計方針

### 毎日の目安と継続の評価

「1日の目標」は、その日の目安として見せる。
毎日必ず達成する義務や、連続達成を途切れさせてはいけない課題として扱わない。
単純な運動量より、ユーザーが目標を立てて達成することを重視する。
基本運動報酬より、目標設定・達成を伴う報酬が大きくなるバランスを狙う。
継続による上乗せを重視し、厳しい条件を選ぶこと以上に、続けることが報われる設計にする。

### 目標条件の難易度

条件が厳しいほど倍率を高くする。
目標条件から「難易度」のような指標を計算する仕組みを設け、具体的な評価式は今後設計する。

| 評価する要素 | 方針 |
|---|---|
| 目標量 | 必要な歩数・距離・運動時間が多いほど、難易度に反映する |
| 日次・週次の違い | 週内でまとめて達成できる目標より、毎日取り組む目標の制約を評価する |
| 時間帯の指定 | 指定なしより指定あり、広い時間帯より狭い時間帯を高く評価する |
| 条件の組み合わせ | 時間帯の狭さだけでなく、その中で必要な運動量と合わせて評価する |
| 運動方法 | 種目そのものによる倍率差は設けない |

例えば「19〜20時に5,000歩」は高難易度として扱うが、「19〜20時に10歩」を時間帯の狭さだけで高倍率にはしない。
同じ運動時間・期間・時間帯などの条件なら、ウォーキング・ランニング・サイクリングという種目名だけでは倍率を変えない。
歩数・距離・時間という異なる基準の比較方法は未確定とする。
この難易度倍率は、[運動自体のルーン換算](exercise-rewards.md)とは区別して設計する。

## 仮設定と候補

### 目標量の選択肢と調整幅

以下は設定画面の選択肢の初期案であり、健康上の推奨量として提示するものではない。
週合計向けの候補値は別途調整する。

| 運動方法・基準 | 数値候補 |
|---|---|
| ウォーキング・歩数 | 1,000／3,000／5,000／8,000／10,000歩 |
| ウォーキング・距離 | 1／2／3／5／10km |
| ランニング・距離 | 1／3／5／8／10km |
| サイクリング・距離 | 5／10／20／30／50km |
| 全種目・運動時間 | 10／20／30／45／60／90分 |

「細かく設定」の調整幅は、500歩・0.5km・5分刻みを候補とする。
これらの値と、最小値・最大値などの入力範囲は未確定である。

### 継続倍率の仮の上限

| 目標 | 最大倍率のたたき台 |
|---|---:|
| 1日の目標 | ×3.0 |
| 1週間の目標 | ×2.0 |

確定しているのは、日次の上限を週次より高くすることと、90日／12週の実績で評価することまでである。
上限値と達成数に対する増え方は未確定とする。

### 初回サポートと週内の追加挑戦

初回の固定ルーンを「達成実績に含めない初回サポート」とする案は、提案段階であり確定していない。
週内の追加挑戦の採用は保留し、追加報酬などの意味があるかを報酬設計と合わせて考える。
採用する場合も、継続実績への加算は1週1回までとする。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 難易度の計算 | 歩数・距離・時間の比較方法、目標量・日次／週次・時間帯の評価式、倍率の上限 |
| 継続倍率の具体値 | 日次・週次の最大倍率と達成数に対する増え方。×3.0／×2.0は仮 |
| 倍率を掛ける対象 | 運動から得るルーンか達成報酬かなど。歩数ログインボーナスとの関係も含めて設計 |
| 日次・週次の報酬の関係 | 同じ運動を両方へ反映した場合の計算。両目標の倍率を掛け合わせる仕様は未決 |
| 達成前後のルーン計算 | 今回のルーンへの適用は確定。達成前の受け取り分への遡及適用、遅延反映時の差額処理は未決 |
| 週内の追加挑戦 | 採用は保留。採用時も継続実績は週1回まで |
| 初回の固定ルーン | 配布量、対象条件、配布回数の単位、重複配布防止、達成実績に含めるか |
| 数値候補と入力範囲 | 週合計向けの歩数・距離・時間のプリセット、細かい設定の刻み・最小値・最大値 |
| 初回の端数期間 | 当日／今週から始める際のお試し扱いや未達の評価など |
| 集計の境界・訂正処理 | 基準タイムゾーン、時間帯をまたぐ記録の扱い、同期遅延の猶予・訂正範囲、締め切りまで倍率低下を猶予する計算手順 |
| 保存設計 | 実績の保存粒度、元データの保存範囲・期間、端末・サーバーの責務分担 |

## 実装との対応

本ページは企画上の要求・設計方針・仮設定・未確定事項を記す。
2026-09-15時点で、目標設定・達成判定・継続倍率・履歴保存・歩数ログインボーナス・初回固定ルーンは未実装である。
歩数以外の目標設定時のワーニングと設定への導線も未実装である。

現在の起動経路（Top・Home）は健康データを読み取らず、サーバー同期も呼ばない。
既存の[サーバー保存定義](../../server/src/features/health/db-schema.ts)は日別歩数などを扱い、目標枠・当時の条件・達成履歴・適用倍率を保存する定義はない。
[健康データの現行仕様](health-data.md#保存と再送)にある7日分の再取得や、元レコードを分割しない表示仕様を、そのまま本ページの期間集計・遅延訂正の実装と見なさない。
90日／12週の履歴と時間帯集計を満たす保存・取得・訂正方式は別途設計する。
現在の実装範囲は[機能索引の実装欄](README.md#現在の実装)を参照する。

## 変更と判断の記録

- 2026-09-14：ユーザー指定により、歩数以外の目標設定時にワーニングを表示する方針を確定した。必要な記録元と書き込み設定を案内するため、目標設定画面にHealth Connectの設定と運動アプリの公式ヘルプへの導線を設ける。
- 2026-09-15：ユーザー提示の運動目標設定仕様を根拠に、任意の日次・週次各1枠、実績の集計、難易度と継続倍率、変更・履歴・サーバー保存を追加した。確定ルールと数値候補を分け、経済・運動データ・日付・画面・初回体験・保存・用語集・目標定義の入口へ反映した。既存の歩数以外のデータ設定案内は維持し、運動回数の例は現行の判定基準から外した。

| 過去の案 | 現在の扱い |
|---|---|
| 自由に最大2つ設定する | 日次1枠・週次1枠。両方任意 |
| 時間帯や実績の重複を禁止する | 同じ運動を両方へ反映できる。実際の活動量は二重計上しない |
| 累計・連続達成で継続倍率を計算する | 直近の達成日数・週数で評価し、未達でも全リセットしない |
| 週次の評価期間を13週にする | 今週を含む12週 |
| 週3回の運動などを目標の例に含める | 選択基準は歩数・距離・運動時間。「週○日」や曜日指定、運動回数は現行仕様に含めない |
