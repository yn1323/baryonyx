# ルーン経済と資源

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

- 運動量（ACT）から得るゲーム内の主軸資源を「ルーン」とする。
- ルーンは課金で販売しない。
- 運動しないと遊べない、課金しないと進めない設計にはしない。

運動と育成・攻略のつながりは[ゲーム概要](../game/overview.md#コアループ)を参照する。

### ルーンの入手

歩数を1歩＝1ACTで換算し、ACTを1ACT＝1ルーンで変換する。
1日の上限は設けず、1万ACTを超えても得られる。
ゲーム起動時の自動処理と画面上の明示操作で未変換分を受け取り、初回はサーバーに保存された過去7日分を対象にする。
ゲーム起動後のリアルタイム監視や定期ポーリングは行わない。
歩数が後から減っても、付与済みのルーンは取り消さない。
変換の詳細は[運動データとルーン換算](exercise-rewards.md#actのルーン変換)を正本とする。

[ACTボーナス](step-bonus.md)と、販売予定の[チケット](monetization.md#5000act分運動したことにするチケット)はルーンを増やさない。
商会で装備・スキル・素材を売ると、ルーンを得る（2026-10-05、ユーザー決定。値段と実装は未決）。

### ルーンの用途

| 用途 | 状態 |
|---|---|
| キャラのレベルアップ | 確定（[育成](progression.md)）。サーバーで費用を計算し、サーバーの残高から引く（実装済み） |
| 敗北時の復活 | 確定。[消費の選択と再開](combat.md#敗北とルーン復活)は戦闘仕様を正本とする。サーバーで費用を計算し、残高から引く（2026-10-04に仮の費用で実装） |
| 召喚 | 見直しの資料の法務メモは、召喚をルーンで引く無償通貨のみのガチャとして整理している（[課金](monetization.md)）。召喚の方式は未決 |
| 商会での購入 | 確定（2026-10-05、ユーザー決定）。[商会](screens.md#商会)で装備・スキル・素材をルーンで買う。値段と実装は未決で、商会の画面は仮の一覧である |

育成費用、復活費用、上限などの経済数値は本ページで別途設計する。

## 候補と例

合成など、その他の成長要素への利用を想定する。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 用途ごとの必要量 | レベルアップ・復活・召喚の費用は未決 |
| 運動しない日の入手・成長経路と開始時の資源 | 未決 |
| 1日・1セッションの想定収支と育成速度 | 未決 |
| 上限・所持桁数・端数・失効の有無 | ACT変換の日次上限は設けない。所持上限、失効、消費時の扱いは未決 |
| 他の通貨・素材との変換・売却 | 装備・スキル・素材の売買はルーンで行う（2026-10-05）。値段、売って得るルーンの量、ほかの通貨を設けるかは未決 |
| 探索報酬・ACTボーナス・課金効果の適用対象と重複 | 未決。旧危険度選択による倍率は現行仕様の前提にしない |
| 報酬付与・消費の確定、再送・中断時の整合 | ACT変換は日別チェックポイントとルーン台帳で再送時の二重付与を防ぐ。消費はレベルアップと冒険の復活を実装し、どちらも要求IDで再送時の二重消費を防ぐ。消費はレベルアップの記録（`party_level_ups`）と復活の記録（`adventure_revives`）に残し、増える分の台帳とは分けている。召喚の消費は未実装 |

## 確認待ち

既存の仕様と今回の内容のどちらを採るか、開発者の判断が必要な事項である。
回答を得るまで、ほかの仕様や実装へ波及させない。

| 項目 | 既存・旧仕様 | 今回の内容 | 影響する範囲 |
|---|---|---|---|
| ACTログインボーナス | 運動目標とは別に、運動量によるログインボーナスを用意する。目標を設定しない場合も利用できる。条件と量は未決だった | 運動目標を廃止し、[日次のACTボーナス](step-bonus.md)が目標の役割を担う。ログインボーナスへの言及はない | ACTボーナスへ統合するか、別に残すか |
| 初回の固定ルーン | 運動目標の初回設定で、当日・今週のデータがない場合に固定ルーンを配布する（配布量・回数は未決） | 運動目標を廃止。初回の配布への言及はない | 運動データがない人への初回の資源、[初回体験](onboarding.md) |

## 実装との対応

本ページは企画上の要求・未決事項を記す。
ルーンの付与は[運動報酬](exercise-rewards.md#実装との対応)、レベルアップでの消費は[キャラと編成の保存](party.md#キャラと編成の保存)、ルーン復活での消費は[探索と進行](stage-progression.md#実装との対応)で実装した。
ルーンの残高と増減の記録はサーバーに置く（[置き場所の一覧](../rules/data-storage.md#置き場所の一覧)）。

## 変更と判断の記録

- 2026-10-05：ユーザーの指示により、[商会](screens.md#商会)での装備・スキル・素材の売買にルーンを使うことにした。新しい通貨（世界観の設定にある銅貨・銀貨・金貨）を設ける案は採らなかった。売却でルーンが増えるため、歩数以外のルーンの入手経路になる。値段は未決で、売買はまだ実装していない。

- 2026-10-04：ユーザーの指示により、運動量の単位の名前を「UPT」から「ACT」（読みはアクト、画面の表記はACT）へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。換算は1歩＝1ACT、1ACT＝1ルーンで変えない。

- 2026-10-04：[冒険の1周](../plans/2026-10-04-adventure-loop.md)で、敗北時の復活のルーンの消費を実装した。費用は仮に1回目100ルーン、以後100ずつ上げる。

- 2026-10-04：ユーザーの依頼で、レベルアップに使うルーンをサーバーの残高から引くようにした（[キャラと編成の保存](party.md#キャラと編成の保存)）。費用はサーバーで計算する。消費の記録は、歩数から得た分の台帳（`rune_ledger`）を作り直さず、レベルアップの記録に残した。台帳は歩数の日と請求に結び付き、増える量だけを記録する作りのためである。

- 2026-09-28：ユーザーの指示により、運動量の単位の名前を「ワット」から「UPT」へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。ルーンの名前と変換量（1UPT＝1ルーン）は変えない。ワットログインボーナスはUPTログインボーナスへ改名した。

- 2026-09-27：ユーザーの指示により、ゲーム内の運動量の単位を「歩」から「ワット」（1歩＝1ワット）へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。ルーンは1ワット1ルーンとし、変換量は変えない。歩数ログインボーナスはワットログインボーナスへ改名した。

- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、ルーンを販売しないこと、レベルアップにルーンを使うことを確定した。運動目標の廃止に伴い、目標報酬の倍率を外し、歩数ログインボーナスと初回の固定ルーンの扱いを確認待ちとした。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| ルーン購入を収益化の候補とする | ルーンは販売しない |
| 目標報酬に難易度倍率と継続倍率を掛ける | 運動目標とともに廃止 |
| 無料再戦とルーン復活を選べる | 復活だけにルーンを使う。無料再戦の廃止は[開発者の最終確認待ち](combat.md#確認待ち) |

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様を根拠に、任意のルーン復活への利用を明記した。消費の操作と再開状態は戦闘仕様へ集約し、費用・収支は未確定のまま残す。旧危険度選択の倍率を経済計算の前提から外した。

- 2026-09-15：ユーザー提示の運動目標設定仕様に基づき、歩数ログインボーナス、初回固定ルーン、難易度と継続倍率を報酬設計へ接続した。日次・週次の進捗への重複反映と報酬の重複計算を区別し、具体値と遡及・差額処理を未決として残す。

- 2026-09-20：ユーザー確認により、歩数変換を1歩1ルーン、日次上限なし、端末タイムゾーン単位、過去7日分の初回請求、起動時と明示操作の両対応として確定した。目標報酬の倍率やルーン消費の費用とは分けて扱う。
