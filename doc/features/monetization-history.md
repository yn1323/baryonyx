# ガチャと課金の検討項目の変更と判断の記録

[ガチャと課金の検討項目](monetization.md)

- 2026-11-02：スキルとdocの整理で、今のコードに合わせて、神殿の召喚がサーバーで引くこと、限界突破の呼び名（突破のしるし）、限界突破の効果を仮の値で入れたことを直した（根拠：server/src/features/summon/、client/Assets/Baryonyx/Features/Temple/Runtime/TempleSummon.cs、client/Assets/Baryonyx/Features/Training/Editor/TrainingAssets.Bond.cs）。
- 2026-10-25：ユーザーの「月パスと、あとは、まあ、広告見るとドロップが増えるとか、あとは広告見ると1日1回10連無料とか、広告見ると全滅した時に復活できるみたいな感じの仕組みを入れておきたい」「まだ実装はせず、ドキュメントに残して」を受け、[月パスと報酬つきの広告](monetization.md#月パスと報酬つきの広告)を加えた。中身・値段・回数は未決事項に置いた。AdMobの報酬つきの広告のポリシーを確かめて記した。影響先として、[戦闘の復活](combat/rules.md#敗北とルーン復活)・[ドロップの未決事項](drops.md#未決事項)・[ルーンの用途](economy.md#ルーンの用途)・[保存先の一覧](../rules/data-storage.md#サーバーに置くもの)にリンクを足した。
- 2026-10-24：ユーザーの指示で[ACTボーナス](../archive/step-bonus.md)を廃止した。続けてユーザーの指示「（チケットは）やめて削除して」により、効果がACTボーナスだけだった「5,000ACT分運動したことにする」チケットの販売予定を取りやめ、節と未決事項を削除した。召喚から除く物の記述と、週次ボーナスへの言及を外した。
- 2026-10-24：ユーザーの依頼「獲得したアイテムキャラをServer側で保存できるようにもして」を受け、[召喚の保存](monetization.md#召喚の保存)を実装した。絆とかけらの置き場所、かけらの量（上限を超えた1人につき1つ）、絆とかけらを読むAPI、サーバーの接続先がないときに仮に引くことは、こちらで決めた（ユーザーには未確認）。
- 2026-10-24：ユーザーの相談「何凸までできるのがいいですか？それとどこから凸しましょう？」に、3段（2体目から1段ずつ、効果は全ステータスの％）を提案した。ユーザーは「やっぱり5凸までにしましょう」「今は全ステータス＋でいいですが、ほんちゃんでは、じっくり考えたい」とし、絆の上限を5段にした。効果はキャラごとに決めるものとし、仮データの9人の定義を作って仮の値（1段ごとに全ステータス+2%）を書いた。続けてユーザーの「いや、やっぱり6凸にしよう！」で、上限を6段に改めた。まだ実装していない。

- 2026-10-24：ユーザーの相談「召喚は1つでいいかも。アイテム、装備、キャラ闇鍋方式で！」「割合ってどうしましょう？」から、割合と値段を決めた（[召喚](monetization.md#召喚)）。キャラは「2%で（10連で20%って感じで）」、☆は「もうちょい渋くてもいい」を受けて☆5 0.5%・☆4 3.5%に、品質は案のS 2%にした。ユーザーは「ガチャはおまけで、本編をやったほうがお得な感じの設計にしたい」「でも、ガチャって脳汁だしたい」とし、平均では冒険より得をせず、当たりの瞬間を演出で盛り上げる方向にした。値段は提案した1回300・10回3,000（☆3以上1つ確定）をユーザーがOKとした。出る物の範囲と主の物の扱いは決めていない。同じ日に、神殿の画面を召喚1つの画面に作り替えた。

- 2026-10-23：ユーザーの相談「ガチャでもキャラがでるのですが、被った場合どうしようか考え中」に、限界突破の素材・別の育成要素・かけらと交換所の3つの一般的なやり方を挙げ、2段構えの案を出した。ユーザーの「これでいいと思う」で[キャラが被ったとき](monetization.md#キャラが被ったとき)を加え、ダンジョンの報酬のキャラも同じ決まりで扱うとした。法務メモに交換所の確認を足した。まだ実装していない。

- 2026-10-04：ユーザーの指示により、運動量の単位の名前を「UPT」から「ACT」（読みはアクト、画面の表記はACT）へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。換算は1歩＝1ACT、1ACT＝1ルーンで変えない。チケットの仮称を「5,000ACT分運動したことにする」チケットへ改めた。

- 2026-09-28：ユーザーの指示により、運動量の単位の名前を「ワット」から「UPT」へ改め、チケットの仮称を「5,000UPT分運動したことにする」チケットへ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。正式な名称は引き続き未決とする。

- 2026-09-27：ユーザーの指示により、ゲーム内の運動量の単位を「歩」から「ワット」（1歩＝1ワット）へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。チケットの仮称を「5,000歩歩いたことにする」から「5,000ワット分運動したことにする」へ改め、正式な名称は引き続き未決とした。

- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、ルーンを販売しないことと、「5,000歩歩いたことにする」チケットの販売予定を反映した。チケットの型・名称・使用条件と召喚の方式は未決とし、法務メモは要専門家確認として記録した。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| ルーン購入を収益化の候補とする。ルーンを購入できて有償の抽選になる場合は、購入の前に確率を表示する | ルーンは販売しない |
| 目標達成などの報酬倍率上昇を収益化の候補とする | 運動目標の廃止に伴い、候補から外す |
