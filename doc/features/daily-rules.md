# 日付の区切りとデイリー変異

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

機能ごとの1日の区切りは次のとおりである。

| 対象 | 1日の区切り | 正本 |
|---|---|---|
| ACTボーナスの段階判定と有効期間 | 朝4時。「朝4時から今までのACT」で判定し、段階に届いて有効になったボーナスは翌日の朝4時まで有効 | [ACTボーナス](step-bonus.md#1日の区切りと有効期間) |
| ACTのルーン変換とホームの「今日のACT」 | 朝4時。端末のタイムゾーンで朝4時から翌朝4時までを1日とし、Health Connectの歩数をこの区切りで日ごとに集計する | [運動データとルーン換算](exercise-rewards.md#actのルーン変換) |

デイリー変異の採用は引き続き未決とする。

## 候補と例

全ユーザー共通で、その日の特殊条件を変える仕組みを検討する。
敵攻撃力上昇、特定属性強化、回復量低下は候補の例である。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 朝4時の基準となるタイムゾーン | 未決 |
| 端末時計・旅行・タイムゾーン変更への対応 | 未決 |
| 朝4時をまたいだ同期 | 4時より前に歩いた分を、4時を過ぎてから同期した場合の扱い |
| 変異の採否、条件数、選出方法、配信元 | 未決 |
| 条件の数値、組み合わせ、報酬補正 | 未決 |
| 更新時に戦闘中・オフラインだった場合 | 未決 |
| 告知方法、予定の公開、変更履歴 | 未決 |

## 実装との対応

本ページは企画上の要求・未決事項を記す。
端末（`HealthDays.kt`）が朝4時区切りで日ごとの歩数を集計し、サーバーは朝4時ちょうどに始まる日の記録だけを受け付ける。ホームの「今日」も同じ区切りで決める（`HealthDays.cs`）。
ACTボーナスは未実装である。
現在の実装範囲は[機能索引の実装欄](README.md#現在の実装)で確認する。

## 変更と判断の記録

- 2026-10-04：ユーザーの指示により、運動量の単位の名前を「UPT」から「ACT」（読みはアクト、画面の表記はACT）へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。換算は1歩＝1ACT、1ACT＝1ルーンで変えない。

- 2026-09-28：ユーザーの指示により、運動量の単位の名前を「ワット」から「UPT」へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。1日の区切りは変えない。

- 2026-09-27：ユーザーの指示により、ホームの「今日のワット」を朝4時区切りにし、同じ日ごとの記録を使うルーン変換の区切りも朝4時にそろえた（未決だった区切りのそろえ方を解消）。

- 2026-09-27：ユーザーの指示により、ゲーム内の運動量の単位を「歩」から「ワット」（1歩＝1ワット）へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。

- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、運動目標の集計期間を廃止し、歩数ボーナスの1日を朝4時で区切ることを確定した。ルーン変換の区切り（0時）とそろえるかは未決とした。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| 運動目標の集計期間（日次は0時〜24時、週次は月曜0時〜翌月曜0時）と、継続倍率の期間入れ替え | 運動目標とともに廃止 |

- 2026-09-15：ユーザー提示の運動目標設定仕様を根拠に、目標の日次・週次の区切りを確定事項として参照した。タイムゾーン、遅延訂正、倍率低下の猶予を実装前の未決事項へ残し、デイリー変異や他機能の区切りへは自動適用しない。
