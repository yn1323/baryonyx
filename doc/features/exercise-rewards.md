# 運動データとルーン換算

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

- Androidの運動データ取得元をHealth Connectへ一本化する。
- 外部の記録サービス → Health Connect → ゲームの構造を基本にし、ゲームから各サービスへ直接接続しない。
- 対象は歩数だけとする。ランニング・サイクリングの距離・運動時間は当面扱わない。
- Health Connectに求める権限も、歩数の読み取りだけとする。
- iOSを提供する場合は、HealthKit対応を別途行う。

### ゲーム共通の単位「ACT」

ゲーム内で運動量を表す単位の正式な名称を「ACT」（読みはアクト）とし、画面では「ACT」と書く。ゲームの数値・表示に「歩」を単位として使わない。
歩数は1歩＝1ACTで換算する。
ルーンとACTで威力が変わるカードは、どちらもACTを基準にする。
Health Connectから受け取る歩数は計測値であり、取得・権限・保存では「歩数」のまま扱う。
歩数以外の指標（自転車の距離など）を扱うときも、ACTへ換算して同じ仕組みに載せる。換算率は、その指標を扱うときに決める。

### ACTのルーン変換

ACTは1ACTにつき1ルーンへ変換する。歩数からは1歩＝1ACT＝1ルーンとなる。
1日の獲得上限は設けず、1万ACTを超えてもルーンを得られる。
ルーンは課金で販売しない（[ルーン経済](economy.md)）。
日付はHealth Connectから受け取った端末のタイムゾーンごとに扱う。
未変換分は、HomeのACTパネルを押す明示の操作で受け取る（[HomeのACTパネル](startup-sync.md#homeのactパネル)）。起動時の同期では受け取らない。
ゲーム起動後のリアルタイム監視や定期ポーリングは行わない。
初回の請求では、サーバーに保存された過去7日分を対象にする。

サーバーは日ごとにルーンへ変換済みの累計歩数を保存し、最新の歩数との差分をACTへ換算して付与する。
Health Connectの値が後から減っても、付与済みのルーンは取り消さない。
同じ歩数の再取得と通信の再送では、ルーンを二重に付与しない。

画面を開いたまま歩数が増えても、リアルタイム監視や定期ポーリングは行わず、次回の起動または取得操作後に表示を更新する。

### 1日の区切り

ルーン変換は朝4時で1日を区切る（[日付の区切り](daily-rules.md)）。

## 候補と例

Strava・Fitbit・Samsung Healthは連携経路の例であり、サービスごとの書き込み項目・地域・端末・契約条件は未確認である。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 複数アプリ・端末が記録した歩数の重複処理 | 現行の実装はHealth Connectの日別集計を使う（[健康データ](health-data.md)）。仕様としての扱いは未決 |
| 元データの訂正・削除・手入力・異常値・再取得への対応 | 歩数の減少時に付与済みのルーンを取り消さないことは確定。ほかは未決 |
| 権限拒否・欠測・通信失敗時のゲーム進行 | 未連携でも開始できる（[起動時の同期](startup-sync.md#top画面の流れ)）。その後の扱いは未決 |
| 歩数以外の指標を再び扱うか | 当面は扱わない。再開する時期と条件、ACTへの換算率は未決 |
| 運動量を報酬に変える処理の保存先・検証主体 | ACTのルーン変換は、サーバーで計算して日別の変換チェックポイントとルーン台帳へ保存する（実装済み） |

## 実装との対応

本ページは企画上の要求・未決事項を記す。
1歩＝1ACT＝1ルーンのため、サーバーはACTを保存せず、歩数の差分をそのままルーンの付与量にしている。換算率を1以外にする場合や、歩数以外の指標を加える場合は、付与済みACTの保存を追加する。
サーバーのD1保存、報酬API、冪等請求、歩数減少時の保全を実装した（[API](../../server/src/features/exercise-rewards/routes.ts)・クライアントの要求（保存と請求は[HealthApiClient](../../client/Assets/Baryonyx/Features/Health/Runtime/Sync/HealthApiClient.cs)、残高は[ExerciseRewardsApiClient](../../client/Assets/Baryonyx/Features/ExerciseRewards/Runtime/ExerciseRewardsApiClient.cs)））。
2026-09-24に削除した歩数画面は、起動時の請求と明示の請求、直近7日の履歴表示も行っていた（[削除した歩数画面の記録](../archive/health-data-local-screen.md)）。
Homeでは、ACTパネルを押す操作を明示請求とし、獲得量を演出で表示する（[HomeのACTパネル](startup-sync.md#homeのactパネル)）。日ごとの歩数とACTは、ライブラリの[日々の歩数](library.md#日々の歩数)で見る。
選んだ環境のURLが空のときは、歩数を端末のメモリだけに保持する（[実行環境と接続先](startup-sync.md#実行環境と接続先)）。
Unity実機でのGoogle認証、Health Connect権限、サーバー公開環境への接続は別途確認する。

起動時の同期は歩数の権限だけを要求して読むが、Androidライブラリのマニフェストは歩数を含む16種類の読み取り権限を宣言しており、歩数だけとする企画と一致しない（[健康データの実装状況](health-data.md#現在の実装状況)）。
