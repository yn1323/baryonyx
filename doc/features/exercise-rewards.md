# 運動データとルーン換算

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

- Androidの運動データ取得元をHealth Connectへ一本化する。
- 外部の記録サービス → Health Connect → ゲームの構造を基本にし、ゲームから各サービスへ直接接続しない。
- 対象は歩数だけとする。ランニング・サイクリングの距離・運動時間は当面扱わない。
- Health Connectに求める権限も、歩数の読み取りだけとする。
- iOSを提供する場合は、HealthKit対応を別途行う。

### ゲーム共通の単位「ACT」

ゲーム内で運動量を表す単位の正式な名称を「ACT」（読みはアクト）とし、画面では「ACT」と書く。ゲームの数値・表示に「歩」を単位として使わない。
歩数は1歩＝1ACTで換算する。
ルーン、[ACTボーナス](step-bonus.md)、ACTで威力が変わるカードは、いずれもACTを基準にする。
Health Connectから受け取る歩数は計測値であり、取得・権限・保存では「歩数」のまま扱う。
歩数以外の指標（自転車の距離など）を扱うときも、ACTへ換算して同じ仕組みに載せる。換算率は、その指標を扱うときに決める。

### ACTのルーン変換

ACTは1ACTにつき1ルーンへ変換する。歩数からは1歩＝1ACT＝1ルーンとなる。
1日の獲得上限は設けず、1万ACTを超えてもルーンを得られる。
ルーンは課金で販売しない（[ルーン経済](economy.md)）。
日付はHealth Connectから受け取った端末のタイムゾーンごとに扱う。
ゲーム起動時の自動処理と、画面上の明示操作の両方で未変換分を受け取れる。
ゲーム起動後のリアルタイム監視や定期ポーリングは行わない。
初回の請求では、サーバーに保存された過去7日分を対象にする。

サーバーは日ごとにルーンへ変換済みの累計歩数を保存し、最新の歩数との差分をACTへ換算して付与する。
Health Connectの値が後から減っても、付与済みのルーンは取り消さない。
同じ歩数の再取得と通信の再送では、ルーンを二重に付与しない。

起動時に前回からの差分がある場合は、今回の獲得量と日付ごとの差分をポップアップで表示する。
画面上の「ルーンを取得」操作では、差分が0の場合も処理結果をポップアップで表示する。
直近7日分の歩数、変換済み歩数、日ごとの付与ルーン、現在残高を画面から確認できる（健康データの確認画面）。
画面を開いたまま歩数が増えても、リアルタイム監視や定期ポーリングは行わず、次回の起動または取得操作後に表示を更新する。

### ACTボーナスとの関係

歩数から換算した同じACTを、ルーン変換と[ACTボーナス](step-bonus.md)の段階判定に使う。
ルーン変換も[ACTボーナス](step-bonus.md)と同じく朝4時で1日を区切る（[日付の区切り](daily-rules.md)）。
販売予定の[チケット](monetization.md#5000act分運動したことにするチケット)ではルーンは増えず、Health Connectにも書き込まない。

## 候補と例

Strava・Fitbit・Samsung Healthは連携経路の例であり、サービスごとの書き込み項目・地域・端末・契約条件は未確認である。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 複数アプリ・端末が記録した歩数の重複処理 | 現行の実装はHealth Connectの日別集計を使う（[健康データ](health-data.md)）。仕様としての扱いは未決 |
| 元データの訂正・削除・手入力・異常値・再取得への対応 | 歩数の減少時に付与済みのルーンを取り消さないことは確定。ほかは未決 |
| 権限拒否・欠測・通信失敗時のゲーム進行 | 未連携でも開始できる（[起動時の同期](startup-sync.md#top画面の流れ)）。その後の扱いは未決 |
| 歩数以外の指標を再び扱うか | 当面は扱わない。再開する時期と条件、ACTへの換算率は未決 |
| 運動量を報酬に変える処理の保存先・検証主体 | ACTのルーン変換は、サーバーで計算して日別の変換チェックポイントとルーン台帳へ保存する（実装済み）。ACTボーナスの判定主体は未決 |

## 実装との対応

本ページは企画上の要求・未決事項を記す。
1歩＝1ACT＝1ルーンのため、サーバーはACTを保存せず、歩数の差分をそのままルーンの付与量にしている。換算率を1以外にする場合や、歩数以外の指標を加える場合は、付与済みACTの保存を追加する。
サーバーのD1保存、報酬API、冪等請求、歩数減少時の保全、既存Health画面からの起動時請求と明示請求、直近7日履歴表示まで実装した。
Homeでは、ACTパネルを押す操作を明示請求とし、獲得量を演出で表示する（[HomeのACTパネル](startup-sync.md#homeのactパネル)）。起動時の自動請求と、日ごとの差分のポップアップ表示は未実装である。
サーバーURLを設定アセットへ登録していない環境では、既存のローカルHealth Connect表示だけを使う。
Unity実機でのGoogle認証、Health Connect権限、サーバー公開環境への接続は別途確認する。

起動時の同期は歩数の権限だけを要求して読むが、Androidライブラリのマニフェストは歩数を含む16種類の読み取り権限を宣言しており、歩数だけとする企画と一致しない（[健康データの実装状況](health-data.md#現在の実装状況)）。
現在の実装範囲は[機能索引の実装欄](README.md#現在の実装)で確認する。

## 変更と判断の記録

- 2026-10-04：ユーザーの指示により、運動量の単位の名前を「UPT」から「ACT」（読みはアクト、画面の表記はACT）へ改めた（[ゲーム共通の単位](#ゲーム共通の単位act)）。換算は1歩＝1ACT、1ACT＝1ルーンで変えない。UPTは「うんどーポイント」の略として付けた名前で、響きを見直した。

- 2026-09-29：UPTの略さない形を確認したところ、ユーザーの指示により「UPT」そのものを正式な名称とした（[用語集](../game/glossary.md)）。

- 2026-09-28：ユーザーの指示により、運動量の単位の名前を「ワット」から「UPT」へ改めた（[用語集](../game/glossary.md)）。換算は1歩＝1UPT、1UPT＝1ルーンのままとし、自転車・ランニングの距離などもUPTへ換算する方針は変えない。ワットボーナスはUPTボーナス、チケットは「5,000UPT分運動したことにする」チケット（仮称）へ改名した。電力の単位と区別するための注記は削除した。

- 2026-09-27：ユーザーの指示により、ホームの「今日のワット」とルーン変換の1日の区切りを0時から朝4時に改めた。端末が朝4時区切りで日ごとの歩数を集計し、サーバーは朝4時ちょうどに始まる日の記録だけを受け付ける。0時区切りで保存済みの開発用データは、DBをリセットして作り直す。

- 2026-09-27：ユーザーの指示により、ゲーム内の運動量の単位を「歩」から「ワット」へ改めた。今後、自転車の距離なども同じ単位で扱うためである。換算は1歩＝1ワット、ルーンは1ワット1ルーンとし、変換量は変えない。Health Connectの計測値は歩数のまま扱う。歩数ボーナスはワットボーナス、チケットは「5,000ワット分運動したことにする」チケット（仮称）へ改名した。

- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、対象を歩数だけに絞り、Health Connectの権限も歩数だけとした。1歩1ルーンの変換は継続し、1万歩を超えても得られること、ルーンを販売しないことを明記した。運動目標の廃止に伴い、目標の集計・倍率への参照を歩数ボーナスとの関係に置き換えた。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| 歩数、ウォーキング、ランニング、サイクリング、運動時間、距離、運動セッションなどを利用する | 当面は歩数だけ |
| METの思想による簡略な運動価値と活動強度の補正（「歩行 < 速歩 < ランニング」は例）。年齢・性別・体格による補正は行わない | 歩数だけを1歩1ルーンで変換するため、当面は扱わない |
| 運動目標の集計（日常の歩数、種目別の距離・時間、時間帯）、目標の難易度倍率・継続倍率との関係 | 運動目標を廃止。[歩数ボーナス](step-bonus.md)と同じ歩数を使う |

- 2026-09-20：ユーザー確認により、歩数の基本変換を1歩1ルーン、上限なし、端末タイムゾーン単位、過去7日分の初回請求、起動時と明示操作の両対応として確定した。歩数減少時は付与済みルーンを取り消さず、目標報酬や追加指標の換算は未決のまま分けて管理する。

- 2026-09-15：ユーザー提示の運動目標設定仕様に合わせ、日常歩数・種目別記録・時間帯・遅延訂正の正本へ接続した。活動強度による運動自体の換算と、種目名では差を付けない目標難易度倍率を区別し、未確定の換算式は維持する。
