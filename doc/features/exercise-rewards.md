# 運動データとルーン換算

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)

## 確定している方針

- Androidの運動データ取得元をHealth Connectへ一本化する。
- 歩数、ウォーキング、ランニング、サイクリング、運動時間、距離、運動セッションなどを利用する方針とする。
- 外部の記録サービス → Health Connect → ゲームの構造を基本にし、ゲームから各サービスへ直接接続しない。
- 厳密な消費カロリー計算は行わず、METの思想を取り入れた簡略な運動価値と活動強度の補正を使う方向とする。
- 年齢・性別・体格まで使った厳密な補正は現状行わない方向とする。
- iOSを提供する場合は、HealthKit対応を別途行う。

### 運動目標の集計と倍率との関係

日常の移動・ランニングを含む歩数、種目別の距離・運動時間、時間帯内の実績の扱いは[目標の集計仕様](goals.md#運動実績の集計)に従う。
同じ運動を日次・週次の両方の進捗へ反映できるが、活動履歴上の運動量は二重に数えない。
遅れて届く記録の達成履歴・継続倍率への反映は[遅延記録の扱い](goals.md#未起動中の運動と遅れて届く記録)を参照する。

運動自体のルーン換算に使う活動強度の補正と、[目標条件の難易度倍率](goals.md#目標条件の難易度)は適用範囲を分ける。
目標側では同じ運動時間・期間・時間帯などの条件なら、種目名だけで倍率を変えない。
今回の目標仕様は、運動自体の換算係数を確定・廃止するものではない。

## 候補と例

「歩行 < 速歩 < ランニング」は補正の例であり、採用する分類と係数は未決である。
Strava・Fitbit・Samsung Healthは連携経路の例であり、サービスごとの書き込み項目・地域・端末・契約条件は未確認である。

|---|---|
| 対象種別とHealth Connectのレコード・項目の対応 | 未決 |
| 種別ごとの換算式・係数・単位・端数処理 | 未決 |
| 歩数・距離・セッションが重なる場合の二重計上防止 | 具体的な処理は未決。目標進捗への反映と活動履歴上の運動量を区別する |

| 獲得上限・最低量・過去分の対象期間 | 未決 |
| 権限拒否・欠測・通信失敗時のゲーム進行 | 未決 |
| 運動量を報酬に変える処理の保存先・検証主体 | 未決 |
