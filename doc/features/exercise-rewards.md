# 運動データとルーン換算

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)

## 確定している方針

- Androidの運動データ取得元をHealth Connectへ一本化する。
- 歩数、ウォーキング、ランニング、サイクリング、運動時間、距離、運動セッションなどを利用する方針とする。
- 外部の記録サービス → Health Connect → ゲームの構造を基本にし、ゲームから各サービスへ直接接続しない。
- 厳密な消費カロリー計算は行わず、METの思想を取り入れた簡略な運動価値と活動強度の補正を使う方向とする。
- 年齢・性別・体格まで使った厳密な補正は現状行わない方向とする。
- iOSを提供する場合は、HealthKit対応を別途行う。

### 歩数のルーン変換

歩数は1歩につき1ルーンへ変換する。
1日の獲得上限は設けない。
日付はHealth Connectから受け取った端末のタイムゾーンごとに扱う。
ゲーム起動時の自動処理と、画面上の明示操作の両方で未変換分を受け取れる。
ゲーム起動後のリアルタイム監視や定期ポーリングは行わない。
初回の請求では、サーバーに保存された過去7日分を対象にする。

サーバーは日ごとにルーンへ変換済みの累計歩数を保存し、最新の歩数との差分だけを付与する。
Health Connectの値が後から減っても、付与済みのルーンは取り消さない。
同じ歩数の再取得と通信の再送では、ルーンを二重に付与しない。

起動時に前回からの差分がある場合は、今回の獲得量と日付ごとの差分をポップアップで表示する。
画面上の「ルーンを取得」操作では、差分が0の場合も処理結果をポップアップで表示する。
直近7日分の歩数、変換済み歩数、日ごとの付与ルーン、現在残高を画面から確認できる。
画面を開いたまま歩数が増えても、リアルタイム監視や定期ポーリングは行わず、次回の起動または取得操作後に表示を更新する。

歩数の変換は、日次の目標報酬や週次の目標報酬とは別の処理として管理する。
目標の難易度倍率、継続倍率、目標報酬への適用は未決のままとする。

### 運動目標の集計と倍率との関係

日常の移動・ランニングを含む歩数、種目別の距離・運動時間、時間帯内の実績の扱いは[目標の集計仕様](goals.md#運動実績の集計)に従う。
同じ運動を日次・週次の両方の進捗へ反映できるが、活動履歴上の運動量は二重に数えない。
遅れて届く記録の達成履歴・継続倍率への反映は[遅延記録の扱い](goals.md#未起動中の運動と遅れて届く記録)を参照する。

運動自体のルーン換算に使う活動強度の補正と、[目標条件の難易度倍率](goals.md#目標条件の難易度)は適用範囲を分ける。
目標側では同じ運動時間・期間・時間帯などの条件なら、種目名だけで倍率を変えない。
今回の目標仕様は、運動自体の換算係数を確定・廃止するものではない。

## 候補と例

「歩行 < 速歩 < ランニング」は補正の例であり、採用する分類と係数は未決である。
Strava・Fitbit・Samsung Healthは連携経路の例であり、サービスごとの書き込み項目・地域・端末・契約条件は未確認である。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 対象種別とHealth Connectのレコード・項目の対応 | 未決 |
| 種別ごとの換算式・係数・単位・端数処理 | 未決 |
| 歩数・距離・セッションが重なる場合の二重計上防止 | 具体的な処理は未決。目標進捗への反映と活動履歴上の運動量を区別する |
| 複数アプリ・端末が記録した運動の重複処理 | 未決 |
| 報酬の確定・受け取り時点、遅れて届くデータ | 歩数の基本変換と受け取り操作は確定。目標の達成履歴・継続倍率への反映は別途決める |
| 元データの訂正・削除・手入力・異常値・再取得への対応 | 未決 |
| 獲得上限・最低量・過去分の対象期間 | 歩数は上限なし、過去7日分を初回請求の対象とする。距離・時間など追加指標は未決 |
| 権限拒否・欠測・通信失敗時のゲーム進行 | 未決 |
| 運動量を報酬に変える処理の保存先・検証主体 | サーバーで計算し、日別の変換チェックポイントとルーン台帳へ保存する計画 |

## 実装との対応

本ページは企画上の要求・未決事項を記す。
サーバーのD1保存、報酬API、冪等請求、歩数減少時の保全、既存Health画面からの起動時請求と明示請求、直近7日履歴表示まで実装した。
サーバーURLを設定アセットへ登録していない環境では、既存のローカルHealth Connect表示だけを使う。
Unity実機でのGoogle認証、Health Connect権限、サーバー公開環境への接続は別途確認する。
現在の実装範囲は[機能索引の実装欄](README.md#現在の実装)で確認する。

## 変更と判断の記録

- 2026-09-15：ユーザー提示の運動目標設定仕様に合わせ、日常歩数・種目別記録・時間帯・遅延訂正の正本へ接続した。活動強度による運動自体の換算と、種目名では差を付けない目標難易度倍率を区別し、未確定の換算式は維持する。

- 2026-09-20：ユーザー確認により、歩数の基本変換を1歩1ルーン、上限なし、端末タイムゾーン単位、過去7日分の初回請求、起動時と明示操作の両対応として確定した。歩数減少時は付与済みルーンを取り消さず、目標報酬や追加指標の換算は未決のまま分けて管理する。
