# ライブラリの変更と判断の記録

[ライブラリ](library.md)

- 2026-11-04：ユーザーの指示（キャラクターの右の分かりにくい固有スキルの表示を消し、固有スキルを独立したカードで、パッシブを専用の欄で出す。パッシブはステータスの情報から取る）で、[キャラクターの固有スキルとパッシブ](library.md#キャラクターの固有スキルとパッシブ)を作った。カードは今セットしている段階にし（初めは帯の下までの小さい形にしたが、ユーザーの「スクロールになってもいいので、今使われているカードをちゃんと表示して」で、効果の文まで出す大きさにして欄をスクロールにした）、下に覚醒した数を添えること、パッシブの解放するLvを書くことは、こちらで決めた。あわせて、ユーザーの指示「防具とアクセサリーのロックを解除」で、錠前の付いていたアクセサリーの分類を開けた（防具は前から開いていた）。
- 2026-11-04：合成の材料の札からライブラリのページを開くことになり、まだ見つけていない項目にも入手先だけは出すことにした（こちらで決めた。どこで集めるかを見せるため）。入手先の解放の判定を、今の世界地図で町のマスを開けた場合も含む DungeonUnlocks にそろえた。
- 2026-11-04：ユーザーの「ライブラリーの装備とかアイテム欄にもし今のダンジョンで出るところあれば情報も書いておいてほしい。ダンジョンはもし解放してないところであれば書かなくて大丈夫」を受け、武器・防具・アクセサリー・スキル・アイテムの個別の画面に[入手先](library.md#入手先)を1行で出すことにした。置く場所（レシピの下か説明の下）、主の物を「〇〇の最奥」と書くこと、解放の判定を街道でクリアした街で行うことは、こちらで決めた。
- 2026-11-04：続けてユーザーの「ミストラ遺跡とか押したら、そこにダンジョンに入れるようにしてください。ポップアップでこのダンジョンに入ります。行きますか。イエスノーみたいな感じ」を受け、入手先のダンジョン名を押せる札にし、確かめる窓から冒険を始めるようにした。文言はユーザーから任され、ボタンを「やめる」「行く」にした。押せる範囲を確保するため、1行の文字から札に替えた。
- 2026-11-02：ユーザーの判断で、未決だった「ホームのボタンの図案と置く位置」を、今の作り（左下に並ぶボタンの4つ目、白一色の開いた本）で[確定](library.md#入口)にした（根拠：client/Assets/Baryonyx/Features/Home/Editor/HomeScreenAssets.cs の `BuildNavigation`・HomeScreenArt.cs の `OpenBook`、[ホーム画面](screens/top-home.md#ホーム画面の見た目モック)）。
- 2026-11-02：ユーザーの判断で合成のレシピの正本をコードにしたため、レシピを読む先を、レシピの一覧の文書から WorkshopRecipes に直した（[ライブラリの合成のレシピ](library.md#合成のレシピ)・[合成のレシピ](synthesis.md#レシピ)）。
- 2026-11-02：スキルとdocの整理で、今のコードに合わせて、スキルの載る条件（手に入れた時点）、武器・防具の絵、記録の状態（すべて実装済み）、見つけた記録を書く処理、固有スキルの進み具合の読み方を直した（根拠：server/src/features/inventory/grants.ts の `inventoryGrants`、server/src/features/party/starter.ts、client/Assets/Baryonyx/Features/Party/Runtime/PartyUniqueSkills.cs、client/Assets/Baryonyx/Features/Library/Runtime/LibrarySeen.cs）。
- 2026-10-31：ユーザーの「ライブラリーにもこのレシピを見れるようにしておいて」を受け、武器・防具・アクセサリー・スキルの個別の画面に[合成のレシピ](library.md#合成のレシピ)を出すことにした。見つけた項目だけに出すこと、まだ見つけていない材料を商会の合成と同じく影と「？？？」にすること、持っている数は出さないこと、レシピのない物は欄を出さないことは、こちらで決めた。材料の並べ方は、行・札・帯の3案を今の画面に重ねて比べ、ユーザーが札を横に並べる形を選んだ。
- 2026-10-18：ユーザーの依頼「入手した様々な情報を確認できるライブラリシーンを作りたい。たぶんDB管理がいると思う」を受け、この文書を作った。分類は、ユーザーが挙げたキャラクター（固有スキル）・武器・防具・アクセサリー・スキル・アイテム・敵（弱点）に、続けて挙げた日々の歩数を加えた。定義はDBに入れずに各機能の正本から読み、見つけた記録だけをサーバーに置く方針と、「一度でも手に入れた物」を載せる基準を提案し、ユーザーが了承した。まだ見つけていない項目は、候補（「？」の枠で数を見せる・見つけた物だけ出す・すべて見せる）に対して、ユーザーが「枠と番号だけ表示。名前も伏せる、ただ、？ではなく、影みたいな感じにしたい」とした。敵は遭遇で載せて撃破数を数える案、入口はホームのボタン、固有スキルの進化後は進化させるまで伏せる案を、ユーザーが選んだ。開示した弱点の保存は並行する作業の担当とし、ライブラリは読むだけにすることを、その作業と取り決めた。
- 2026-10-18：続けて未決事項をユーザーと相談し、次を決めた。番号は定義の並び順、伏せた項目は名前の欄ごと消す、倒した数は体数で数え全滅した戦闘で倒した分も数える、端末を複数使った日はいちばん多い端末の値、案内人は新しい司書、武器・防具の絵は当面は種類のアイコン、1つずつ違う倍率と☆は今は出さない、新しく載った項目に印を付け見た記録は端末に置く。いずれも提案した案をユーザーが選んだ。日々の歩数は、ACTとその日に得たルーンを並べる案に対し、ユーザーは歩数とACTの両方を選んだ。スキルは、1枚ずつ持つ仕組みができるまで全部見つけた扱いにする案に対し、ユーザーは編成で付けたことがあるカードだけを載せる形を選んだ。
- 2026-10-19：ユーザーの「とりあえず実装してみて」を受けて実装した。8つの分類をメニューに1行ずつ並べると画面の高さに収まらなかったため、武器・防具・アクセサリーを「装備」の1行にまとめ、見出しのタブで切り替える形にした（ユーザーには未確認）。個別の内容は別の画面に移さず、一覧の右に並べた。
- 2026-10-19：ユーザーの「ライブラリの背景、フクロウ以外の人に切り替えて」「リストにも各々アイコンが欲しい」を受け、仮に使っていた旅の案内所のフクロウと背景を、新しい司書と大図書館の書庫に替え、メニューの6行にアイコンを付けた。司書は、三つ編みの若い女性の司書（A案）とエルフの青年の司書（B案）を生成し、ユーザーがB案を選んだ。アイコンの図案はこちらで決め、撮影した画面を見たユーザーが「このままでよい」とした。
- 2026-10-19：ユーザーの「キャラクターのカードをもう少し下に下げてほしい。×、ルーンと近すぎる」を受け、6行以上ある案内人の画面のメニュー（今はライブラリだけ）の行の間隔を20pxから12pxに詰め、メニュー全体を28px下げた。1行目のカードの上端は、×とルーンの帯の下から約40px離れる。5行以下のメニューは変えていない。
- 2026-10-25：画面を開いたときの待ち時間を減らすため、見つけた記録と日々の歩数を同時に読み、開き直したときは前に読んだ記録をすぐ出して裏で読み直すようにした（[開き直したときの表示](../rules/data-storage.md#サーバーに置くときの作り方)）。読み直せなかったときは、出している記録を残して通知の帯で知らせる。
- 2026-10-26：テストプレイで「開いたときに右の詳細の欄が空」と報告し、ユーザーの「これはおかしいです。デフォルトで最初のものを選択状態にしておいてほしいです」を受け、分類を開いたときに最初の見つけた項目を選んでおくようにした（[画面の作り](library.md#画面の作り)）。影の項目しかない分類は空のままにすること、自動で選んだ項目の新しく載った印を押すまで残すことは、こちらで決めた。
- 2026-11-01：画面の共通化（[計画](../plans/2026-11-01-ui-design-system.md)）で、各分類の一覧を商会の買う・売ると同じ格子と詳細のテンプレートから作り、一覧と詳細の分け目を1180から1160にそろえた。札の部品の型を `ItemTile` にし、「NEW」を右上へ移した。日々の歩数の行を全幅にした。
