# 探索とダンジョンの進行

[機能索引](README.md) / [ゲーム概要](../game/overview.md) / [戦闘システム](combat.md) / 根拠：[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

2026-09-15にユーザーが提示した「てくてくダンジョン｜探索・進行・戦闘仕様」の探索と進行を基に、2026-09-27の企画見直しでSlay the Spireのような分岐ルートの冒険へ変更した。
負けたら1階からやり直す構成になり、進捗を持ち越す旧方針は[変更と判断の記録](#変更と判断の記録)へ移した。
[節の区分](../rules/documentation-policy.md#mdの形式と状態)を区別し、[初期企画](../game/brief.md)にあった危険度選択中心の進行は現行ルールへ混ぜない。

## 確定している方針

### 分岐ルートを選んで進む冒険

1階から深奥のボスを目指す1回の挑戦を**冒険**と呼ぶ。
冒険では、Slay the Spireのような分岐ルートを選んで進む。
リスクを取って強敵などに挑み、スキル・装備を獲得する。
キャラのステータス〇％アップなどを重ね、深奥のボスを倒す。
ダンジョンには深奥のボスという終点があり、完全な無限ダンジョンにはしない。

### 冒険の終了と獲得物の保持

負けたら冒険は終了し、次の冒険は1階からやり直す。
負けても、それまでに獲得した装備・スキルなどは保持する。
失うのは、その先のボスの報酬などを得る機会であり、これを負けるリスクとする。
ルーンを使えば復活して、続きから再開できる（[ルーン復活](combat.md#敗北とルーン復活)）。

### 冒険の中断と再開

2026-10-04、ユーザーは次を決めた。

- 冒険は、探索でも戦闘の途中でも中断してホームへ戻れ、ホームの行き先カードから再開できる。
- 戦闘中にアプリが終わった場合や戦闘の途中で中断した場合は、直前の分岐で部屋を選んだ状態から再開する。その部屋の戦闘は始めからやり直す。
- 自分から冒険をやめられる（戦闘の途中でも）。負けたときと同じく冒険は終わり、手に入れた物は残る。

部屋を選んだ時点で、その選択をサーバーに保存する（[画面と遷移](screens.md#冒険の画面)）。
戦闘を始めからやり直せることと、[無料再戦の廃止](combat.md#確認待ち)との関係は、[確認待ち](#確認待ち)に記録する。

### 依頼を前提にしない探索

依頼システムは入れず、受注・報告・再受注を冒険の前提にしない。
「欲しい装備がある」「今なら強敵に勝てそう」「まだ見ていない奥へ進みたい」を行き先を選ぶ理由にする。
特定のボスで行き詰まっても、別の場所で育成・装備集めができる自由を残す。
冒険のスタミナ・挑戦回数制限は設けない。

### 行き先を選ぶ情報

「1-1」「1-2」などのステージ番号を前面に出さず、場所の名前と情報から行き先を選ぶ。
番号を隠すだけでなく、選択に目的を持たせる。

| 見せる情報 | 選ぶ理由 |
|---|---|
| 敵の傾向・弱点 | 今の編成で挑むか判断する |
| 狙える装備・報酬の種類 | 必要な装備を探す |
| 未探索・さらに深く進む方向 | 探索を進める |
| 発見済みの強敵 | 以前の相手に再挑戦する |

具体的なドロップ品や未踏の先のすべてを確定表示するわけではない。
敵の弱点は、戦闘で[開示した](combat.md#弱点の開示)ものだけを見せる。
それ以外の情報の開示範囲は未決とする。
[ACTボーナス](step-bonus.md)で、宝箱の中身、次の部屋の敵、敵が激化するターンなどをより詳しく見せる案と、霧の向こうまで見える距離を延ばす案が候補にある。

### ダンジョン内の見た目による行き先選択

ダンジョンに入った後の探索画面では、今いる場所と次に進める行き先を見て分かるようにする。
これはダンジョン内の操作であり、出発前に森・坑道などの冒険先を選ぶ画面とは分ける。

2026-10-04、ユーザーは、探索画面を森を斜め上から見下ろす地図にし、分岐ルートを俯瞰しながら進むと決めた（[計画](../plans/2026-10-04-exploration-route-map.md)）。
同日の先の決定（分岐ルートのマップを独立させず部屋の画面だけで進み、ルート全体は冒険のメニューの地図で見る）は改めた。
地図では、部屋と部屋を森の中の道で結び、パーティが今いる部屋と、次に進める部屋を描く。

| 表示するもの | 伝えること |
|---|---|
| 地図の上の今いる部屋と、そこに立つパーティ | 自分たちが今どこにいるか |
| 今いる部屋から次の部屋へ続く道 | どこを選べば、どちらへ進むか |
| 部屋の種類のアイコンと短い手掛かり | 敵・お宝・出来事など、行き先を選ぶ手掛かり |
| 遠くの部屋の印と、霧の向こうの最奥 | この先に何が待っていそうか |
| 選んだ道を歩く移動と、着いた部屋 | 選択した場所へ進んだこと |

行き先の説明文だけを並べた二択を、探索画面の完成形にはしない。
短いテキストは見た目を補う情報として、行き先の部屋の近くに置く。
次に進める部屋の数を、常に2つに固定する仕様ではない。

近い部屋ほど詳しく見せ、遠くの部屋は霧で隠す。
霧の向こうまで見える距離は、ACTボーナスで延ばせるようにする方向とする（[ACTボーナスの候補](step-bonus.md#候補)）。
見える距離の基本値、遠くの強い魔物と最奥を見せるか、地図のカメラと描き方は[未決](#未決事項)とする。

### 部屋単位の探索と操作

行きたい部屋をタップすると、4人パーティが自動でその部屋まで道を歩き、部屋の出来事（戦闘・宝箱など）が始まる。
自由移動、移動スティック、長い移動待ちは入れない。
移動は短い雰囲気づくりの演出とする。

毎回ヒントを聞きに行く操作は前提にしない。

参考イメージは、当初はユーザーが挙げた『ポケットモンスター エメラルド』のバトルチューブ風の分岐・部屋単位探索で、2026-10-04からは、あみだくじのように分岐する道を森の地図で俯瞰する形（[計画](../plans/2026-10-04-exploration-route-map.md#比べた案)の案B）である。
原作の運要素・連戦ルールを丸ごと採用する意味ではない。

### 冒険の道と部屋の数

2026-10-04、ユーザーは次を決めた。

- 冒険の道は、冒険を始めるたびにランダムに作る。
- 入口から最奥の間までに通る部屋の数は、ダンジョンごとのサーバーの設定値にし、あとから変えられるようにする。
- 最初のダンジョンは、道中の部屋を8つ通った先に最奥の間を置く。深いダンジョンは、道中の部屋を10〜12に延ばす。

1階ごとに1部屋を通る。
最初のダンジョンでは、入口（B1F）の次のB2FからB9Fまでが道中の部屋で、最奥の間はB10Fになる。

1回の冒険の長さは15〜20分を目安とし、最初のダンジョンで約15分、道中12部屋の深いダンジョンで約20分と見積もった。
見積もりは[戦闘の長さ](combat.md#戦闘の長さ)の目安を前提とし、前提と計算は[計画の方針](../plans/2026-10-04-exploration-route-map.md#方針)に置いた。
戦闘と移動の時間はまだ実測していない。

## 設計方針

### 冒険の道の作り方

2026-10-04に、次の形で実装した（[計画](../plans/2026-10-04-exploration-route-map.md#実装したこと)）。
階ごとの決まりと見える距離は、遊んで確かめるための仮の値である。

- 冒険を始めると、サーバーが道を作る乱数の種を決め、冒険と一緒に保存する。端末は、種と部屋の数から毎回同じ道を作り、道そのものはどこにも保存しない。中断して再開しても、別の端末でも、同じ道になる。
- 道の進み具合（今いる部屋・通った部屋・出来事を終えたか）は、これまでどおりサーバーに保存する。部屋を選ぶと、端末はその部屋の階と種類をサーバーへ送り、サーバーは1階ずつ進むことと、最奥の階にだけボスがいることを確かめる。
- 道はあみだくじの形にする。平行な3〜4本の道が蛇行しながら奥へ進み、隣の道の次の階へ移る横道でつながる。横道は交差させず、部屋の札が重ならないよう道同士の間隔に下限を設ける。
- 階ごとの決まり（仮）：最初の階（B2F）は魔物、強い魔物はB4F以降で最奥の直前（B9F）には置かない、道中の中ほどの階（B6F）はどの道も宝箱、同じ道で強い魔物や宝箱を続けない、強い魔物を道全体で2つ以上置く。
- 部屋の種類は、魔物・強い魔物・宝箱・最奥の間の4つである。「なにか起きそう」（出来事）と「ひと休みできそう」（休憩）は、中身が決まっていないため入れていない。

道の部屋の種類は端末が作るため、端末を書き換えれば、選ぶ部屋の種類（報酬のランクの重み）を変えられてしまう。
ユーザーが「途中の進捗はUnity内に保存する形でOK」としたため、サーバーで道を作り直して確かめる処理は入れていない（[確認待ち](#確認待ち)）。

### 段階的な解放

「冒険団の成長によって行き先が段階的に増える」方向は支持済みである。
ランク・最深到達がそれぞれ何を解放するかは未決とする。
ダンジョンの規模と長期目標の置き方は、旧方針との関係を[確認待ち](#確認待ち)に記録する。

### 成長の記録

最深到達の更新、前回遊んだ時点からの進展、以前勝てなかった敵の撃破を見せる。
必要に応じて、前回記録と自己ベストを区別する。
他者との競争より、「前回より深く進めた」「以前の相手が楽になった」を中心にする。
深度・階層の表記方法と、比較記録の具体的な単位は未決とする。

### アセットを増やしすぎない構成

エリア共通の分岐背景・戦闘背景に、扉・階段・宝箱などの差分を組み合わせる方向とする。
大きな自由移動マップを前提にしない。

同じ素材でも、敵の編成、報酬、選ぶ理由に違いを作る。
深い地域で背景を変えるなど、新しい場所へ到達した節目を演出する。
必要アセット数や地域数は未決である。

## 未決事項

| 領域 | 決める項目 |
|---|---|
| マップ | 道の本数・横道の数・階ごとの決まり、部屋の種類（「なにか起きそう」の出来事と「ひと休みできそう」の休憩を加えるか）。探索画面を地図にすること、道を冒険ごとに作ること、部屋の数は2026-10-04に決定 |
| 冒険の長さ | 戦闘と移動の時間を実測したうえでの部屋の数の調整。目安の15〜20分と、最初のダンジョンの道中8部屋は2026-10-04に決定 |
| 序盤 | 序盤の階が作業にならない工夫（候補：序盤の敵を早く終わらせる、倍速） |
| 冒険中の強化 | 冒険中に得たステータス〇％アップが、その冒険限定か永続か |
| ダンジョン構造 | ダンジョン数、最終深度、区間の分け方、敵編成とボス出現 |
| 解放 | ランクと最深到達の関係、各解放条件 |
| 情報 | 地図や場所選択での開示範囲、ACTボーナスで増やす情報と見える距離を延ばす効果の形、深度・階層の表記、成長を比較する記録単位 |
| 探索画面 | 地図のカメラの角度と動き、2Dの絵で描くか3Dの舞台で描くか、霧で見える距離の基本値（候補：2部屋先まで詳しく、4部屋先まで小さい印）、遠くの強い魔物と最奥を見せるか、宝箱・出来事を地図の上で開くか、部屋のタップ範囲 |

| 報酬 | 抽選・確定・受け取りタイミングと、冒険終了・中断時の未確定報酬の扱い |
| 個別コンテンツ | 通常敵・ボスの行動、狙える装備、地域数と必要アセット数 |

## 確認待ち

既存の仕様と今回の内容のどちらを採るか、開発者の判断が必要な事項である。
回答を得るまで、ほかの仕様や実装へ波及させない。

| 項目 | 既存・旧仕様 | 今回の内容 | 影響する範囲 |
|---|---|---|---|
| 中断による戦闘のやり直し | 戦闘単位の無料再戦は廃止する（[戦闘の確認待ち](combat.md#確認待ち)） | 戦闘の途中で中断すると、再開したときにその戦闘を始めからやり直す（2026-10-04） | 負けそうなときに中断すれば、実質的に戦闘をやり直せる。中断を戦闘の途中で認めるか、戦闘の状態を保存して途中から再開するか |
| ダンジョンの規模と長期目標 | 巨大なダンジョンの進捗を持ち越し、短い冒険を積み重ねる。果てしなく遠く感じる規模を目指し、近い目標は次の区間への進行、長期の目標は踏破とする | 1回の冒険で深奥のボスを目指し、負けたら1階から。冒険の長さは15〜20分が目安（2026-10-04） | 長期目標（深奥のボスの撃破か、複数のダンジョンの解放か）、[ホーム](screens.md#ホーム画面の見た目モック)のワールドマップと行き先カード |
| 部屋の種類を端末から受け取ること | 書き換えられたら困るデータはサーバーに置く（[保存先の決め方](../rules/data-storage.md#判断の基準)） | 道は端末が種から作り、部屋の階と種類を端末からサーバーへ送る。ユーザーは「途中の進捗はUnity内に保存する形でOK」とした（2026-10-04） | 端末を書き換えると、宝箱や強い魔物の部屋を選び続けて報酬を増やせる。サーバーにも同じ道を作る処理を置いて確かめるか、リリース前に決める |
| 再出発と周回の候補 | 帰還後は解放済みの野営地・中継地点から出発する案、同じ敵・場所をリザルトから直接再挑戦する案 | 冒険が終わると1階からやり直す | 両案を廃止するか、別の形で残すか |

## 変更と判断の記録

2026-10-04：探索の地図と、冒険ごとに作る道を実装した。ユーザーの「途中の進捗はUnity内に保存する形でOK」を受け、道はサーバーに保存せず、サーバーが決めた種から端末が作る形にした。進み具合は、再開や別の端末で失わないよう、これまでどおりサーバーに保存した。部屋の種類を端末から受け取ることを[確認待ち](#確認待ち)に加えた。
