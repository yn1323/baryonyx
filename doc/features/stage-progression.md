# 探索とダンジョンの進行

[機能索引](README.md) / [ゲーム概要](../game/overview.md) / [戦闘システム](combat.md) / 根拠：[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

2026-09-15にユーザーが提示した「てくてくダンジョン｜探索・進行・戦闘仕様」の探索と進行を基に、2026-09-27の企画見直しでSlay the Spireのような分岐ルートの冒険へ変更した。
負けたら1階からやり直す構成になり、進捗を持ち越す旧方針は[変更と判断の記録](#変更と判断の記録)へ移した。
[仕様の確度](README.md#仕様の確度)を区別し、[初期企画](../game/brief.md)にあった危険度選択中心の進行は現行ルールへ混ぜない。

## 確定している方針

### 分岐ルートを選んで進む冒険

1階から深奥のボスを目指す1回の挑戦を**冒険**と呼ぶ。
冒険では、Slay the Spireのような分岐ルートを選んで進む。
リスクを取って強敵などに挑み、スキル・装備を獲得する。
キャラのステータス〇％アップなどを重ね、深奥のボスを倒す。
ダンジョンには深奥のボスという終点があり、完全な無限ダンジョンにはしない。

### 冒険の終了と獲得物の保持

負けたら冒険は終了し、次の冒険は1階からやり直す。
負けても、それまでに獲得した装備・スキルなどは保持する。
失うのは、その先のボスの報酬などを得る機会であり、これを負けるリスクとする。
ルーンを使えば復活して、続きから再開できる（[ルーン復活](combat.md#敗北とルーン復活)）。

部屋の区切りで中断すると進捗を保存し、次回は続きから再開する。
戦闘中にアプリを閉じた場合の保存・再開方法は、この中断とは分けて未決とする。

### 依頼を前提にしない探索

依頼システムは入れず、受注・報告・再受注を冒険の前提にしない。
「欲しい装備がある」「今なら強敵に勝てそう」「まだ見ていない奥へ進みたい」を行き先を選ぶ理由にする。
特定のボスで行き詰まっても、別の場所で育成・装備集めができる自由を残す。
冒険のスタミナ・挑戦回数制限は設けない。

### 行き先を選ぶ情報

「1-1」「1-2」などのステージ番号を前面に出さず、場所の名前と情報から行き先を選ぶ。
番号を隠すだけでなく、選択に目的を持たせる。

| 見せる情報 | 選ぶ理由 |
|---|---|
| 敵の傾向・弱点 | 今の編成で挑むか判断する |
| 狙える装備・報酬の種類 | 必要な装備を探す |
| 未探索・さらに深く進む方向 | 探索を進める |
| 発見済みの強敵 | 以前の相手に再挑戦する |

具体的なドロップ品や未踏の先のすべてを確定表示するわけではない。
情報の開示範囲は未決とする。
[ワットボーナス](step-bonus.md)で、宝箱の中身、次の部屋の敵、敵が激化するターンなどをより詳しく見せる案が候補にある。

### ダンジョン内の見た目による行き先選択

ダンジョンに入った後の探索画面では、部屋・通路とパーティを描き、今いる場所と次に進める入口を見て分かるようにする。
プレイヤーは、画面内に見えている扉や通路などの入口をタップして行き先を選ぶ。
これはダンジョン内の操作であり、出発前に森・坑道などの冒険先を選ぶ画面とは分ける。
分岐ルートのマップと、この部屋単位の探索画面との関係は未決である。

| 表示するもの | 伝えること |
|---|---|
| 現在の部屋・通路と、その中にいるパーティ | 自分たちが今どこにいるか |
| 次の部屋につながる扉・通路などの入口 | どこを選べば、どちらへ進むか |
| 入口やその先の見た目と短いヒント | 敵・お宝・先の様子など、行き先を選ぶ手掛かり |
| 選んだ入口への移動と次の部屋の表示 | 選択した場所へ進んだこと |

行き先の説明文だけを並べた二択を、探索画面の完成形にはしない。
短いテキストは見た目を補う情報として入口の近くに置く。
分岐が2本の場合も、部屋の中の異なる入口として選べるようにする。
入口の数を常に2つに固定する仕様ではない。

「部屋の奥に扉があり、右側には暗い通路がある」は会話で挙がった表示例であり、全室共通の配置や確定した部屋データではない。
視点・カメラ・一画面に見せる範囲は未決とする。

### 部屋単位の探索と操作

行きたい入口をタップすると、4人パーティが自動でその入口へ歩き、次の部屋へ進む。
自由移動、移動スティック、長い移動待ちは入れない。
移動は短い雰囲気づくりの演出とする。

毎回ヒントを聞きに行く操作は前提にしない。

参考イメージは、ユーザーが挙げた『ポケットモンスター エメラルド』のバトルチューブ風の分岐・部屋単位探索である。
原作の運要素・連戦ルールを丸ごと採用する意味ではない。

## 設計方針

### 段階的な解放

「冒険団の成長によって行き先が段階的に増える」方向は支持済みである。
ランク・最深到達がそれぞれ何を解放するかは未決とする。
ダンジョンの規模と長期目標の置き方は、旧方針との関係を[確認待ち](#確認待ち)に記録する。

### 成長の記録

最深到達の更新、前回遊んだ時点からの進展、以前勝てなかった敵の撃破を見せる。
必要に応じて、前回記録と自己ベストを区別する。
他者との競争より、「前回より深く進めた」「以前の相手が楽になった」を中心にする。
深度・階層の表記方法と、比較記録の具体的な単位は未決とする。

### アセットを増やしすぎない構成

エリア共通の分岐背景・戦闘背景に、扉・階段・宝箱などの差分を組み合わせる方向とする。
大きな自由移動マップを前提にしない。

同じ素材でも、敵の編成、報酬、選ぶ理由に違いを作る。
深い地域で背景を変えるなど、新しい場所へ到達した節目を演出する。
必要アセット数や地域数は未決である。

## 未決事項

| 領域 | 決める項目 |
|---|---|
| マップ | マップの規模・ノードの種類、部屋単位の探索画面との関係 |
| 冒険の長さ | 1回の冒険の長さの目安（候補：15〜20分で深奥のボスまで） |
| 序盤 | 序盤の階が作業にならない工夫（候補：序盤の敵を早く終わらせる、倍速） |
| 冒険中の強化 | 冒険中に得たステータス〇％アップが、その冒険限定か永続か |
| ダンジョン構造 | ダンジョン数、最終深度、区間の分け方、敵編成とボス出現 |
| 解放 | ランクと最深到達の関係、各解放条件 |
| 情報 | 入口や場所選択での開示範囲、ワットボーナスで増やす情報、深度・階層の表記、成長を比較する記録単位 |
| 探索画面 | 視点・カメラ・一画面に見せる部屋や通路の範囲、入口の見せ方とタップ範囲。ミニマップ・通過経路の表示・未探索部分を段階的に見せる演出の採否 |
| 中断 | 戦闘中の保存・再開 |
| 報酬 | 抽選・確定・受け取りタイミングと、冒険終了・中断時の未確定報酬の扱い |
| 個別コンテンツ | 通常敵・ボスの行動、狙える装備、地域数と必要アセット数 |

## 確認待ち

既存の仕様と今回の内容のどちらを採るか、開発者の判断が必要な事項である。
回答を得るまで、ほかの仕様や実装へ波及させない。

| 項目 | 既存・旧仕様 | 今回の内容 | 影響する範囲 |
|---|---|---|---|
| ダンジョンの規模と長期目標 | 巨大なダンジョンの進捗を持ち越し、短い冒険を積み重ねる。果てしなく遠く感じる規模を目指し、近い目標は次の区間への進行、長期の目標は踏破とする | 1回の冒険で深奥のボスを目指し、負けたら1階から。冒険の長さは候補15〜20分 | 長期目標（深奥のボスの撃破か、複数のダンジョンの解放か）、[ホーム](screens.md#ホーム画面の見た目モック)のワールドマップと行き先カード |
| 再出発と周回の候補 | 帰還後は解放済みの野営地・中継地点から出発する案、同じ敵・場所をリザルトから直接再挑戦する案 | 冒険が終わると1階からやり直す | 両案を廃止するか、別の形で残すか |

## 実装との対応

本ページは企画上の要求・設計方針・未決事項を記す。
分岐ルートの冒険、部屋単位の探索画面、冒険の保存は未実装である。
2026-09-19時点の[操作ワイヤー](game-wireframe.md)は文字のボタンで戦闘・獲得へ進む試作で、2026-09-24に削除した。

2026-09-15：ユーザー提示の探索・進行・戦闘仕様を根拠に、情報を見て進路を選び、短い冒険の進捗を持ち越す進行へ更新した。
ゲーム概要、用語集、MVP、画面、保存要件、データ定義の記入欄へ反映した。

| 過去の案 | 現在の扱い |
|---|---|
| 危険度を数段階から選ぶことが進行の中心 | 探索先の情報を見て選び、奥へ進む構造へ変更。旧案の敵・報酬・高レア率の倍率を現行仕様の前提にしない |
| 毎回1階から出発し、超早送りで限界まで潜る | 2026-09-15に、進捗を持ち越して短い冒険を積み重ねる形へ変更。超早送りを必須前提にしない |
| 依頼を受注・報告して進む | 依頼システムを入れない |
| 巨大なダンジョンの進捗を持ち越し、毎回1階から潜り直す形は採用しない（2026-09-15） | 2026-09-27に、負けたら冒険終了して1階からやり直す形へ変更。獲得した装備・スキルなどは保持する |
| 敗北後は無料再戦・編成変更・別の行き先・帰還を選ぶ | ルーン復活か帰還を選ぶ。無料再戦の廃止は[開発者の最終確認待ち](combat.md#確認待ち) |
