# 画面一覧と操作

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)

## 確定している方針

画面は横持ちとし、1920×1080の設計座標で作る（[UI設計ルール](../rules/ui-design.md#画面方向と拡縮)）。
2026-09-18の参照会話で採用した、探索中の仲間・装備変更、左右の戦場、上部の敵予告、下部のHP・スキルの配置は、[操作試作の記録](../archive/game-wireframe.md)に残す。
このうち戦闘画面の配置は、2026-09-27に廃止したリアルタイム戦闘のワイヤーで採用したものである。
カードバトルの画面構成（手札、エネルギー、敵の弱点と行動の予告）は未決とする。

冒険の探索は、森を見下ろす地図で分岐ルートと部屋の印を見せ、行ける部屋の札を押して進む（[冒険の画面](#冒険の画面)）。
出発前の行き先選び（旅の案内所）と、入った後の探索の操作を区別する。
探索・戦闘・ACTボーナスの具体的な表示要件と未確定事項は、下表の正本に従う。

| 対象 | 操作・表示の正本 |
|---|---|
| ダンジョン内の現在地・入口・見た目による選択 | [ダンジョン内の見た目による行き先選択](stage-progression.md#ダンジョン内の見た目による行き先選択) |
| 探索の入口・移動・短いヒント | [部屋単位の探索と操作](stage-progression.md#部屋単位の探索と操作) |

| 標的・敵HP・弱点・行動の予告の優先順位 | [戦闘中の情報](combat.md#戦闘中の情報の優先順位) |
| カードの威力の書き方（ステータスの割合） | [カードの数値の見せ方](combat.md#カードの数値の見せ方) |

### 持ち物のカード風の見た目

武器・防具・アクセサリー・ACTボーナス・アイテムも、今後はスキルのようなカード風の見た目にしていく（2026-10-06、ユーザーの意向）。
具体的な形（挿絵・枠・[レア度](inventory.md#レア度)の星・[品質](inventory.md#品質)の文字の置き方）と、どの画面から変えるかは未決である。

## 停止中の表示の切り替え

押すと同じシーンの中で表示が切り替わる画面は、停止中のUnity Editorでも、Inspectorの「停止中の表示の切り替え」のボタンで各表示を確かめられる（規則と作り方は[停止中の表示の切り替え](../rules/ui-design.md#停止中の表示の切り替え)）。
中身は生成時に作り込んだ仮データと、見本の値（冒険は [`AdventureDialogSamples`](../../client/Assets/Baryonyx/Features/Adventure/Runtime/AdventureDialogSamples.cs)）で、ダイアログはPlay中と同じ組み立て（[`AdventureDialogs`](../../client/Assets/Baryonyx/Features/Adventure/Runtime/AdventureDialogs.cs)）で出す。
「元の表示」で戻り、シーンやPrefabの保存とPlay Modeの前にも自動で戻る。

| シーン | 選ぶオブジェクト（部品） | 切り替えられる表示 |
|---|---|---|
| `Top` | `TopScreen`（`TopSceneController`） | 案内の読み込み中・TAP TO START・通信の失敗・歩数の読み取りの失敗・案内なし（連携待ち） |
| `Top` | `HealthLinkModal`（`HealthLinkModalView`） | 連携の許可・設定を開く・入手が必要・更新が必要・確認中（押せない）。Play中はモーダルの間は案内を隠すため、`TopScreen` の「案内なし」と合わせて見る |
| `Home` | `HomeScreen`（`HomeView`） | 歩数の連携なし・同期中・歩数の取得前・ボーナスをすべて獲得・冒険の途中・獲得ルーンなし・通知 |
| `Pub`・`Shop`・`Temple` | `PubScreen` など（`GuideMenuView`） | メニューの各項目。パネルの中の表示は「項目 › 表示」で並ぶ。編成では、冒険者・装備（人選び）・ボーナス・育成・スキル・装備の付け替えの「読み込み中」「取得できない」、ボーナスのタブ（すべて・探索・ドロップ・戦闘）、育成の「レベルアップ」、装備の付け替えの「防具」「アクセサリー」のタブ（仮データの先頭の人と仮の装備で、Play中と同じ切り替えを通す） |
| `Exploration` | `ExplorationScreen`（`ExplorationView`） | 冒険のメニュー・やめる確認・宝箱・結果（踏破・帰還）・取得できない |
| `Battle` | `AdventureOverlay`（`AdventureOverlay`） | 勝利・勝利（最奥）・全滅（復活できる・ルーン不足）・メニュー・やめる確認・結果（冒険の終わり）・保存できない |
| `BattleLab`・`Battle` | `BattleInspectScreen`（`BattleInspectView`） | ターンの帯（味方・連続・敵）・技名の帯・エネルギー不足・カードを選んだ（タップ）・カードを敵へ向けた（スワイプ）・キーワードの説明札。帯は開ききって止まった1コマ。カードは初めの手札のうち、初めのエネルギーで出せる敵1体向けのものを持ち上げ、使い手の1歩・金の輪・名前、ねらえる敵のカーソルを出す。スワイプでは照準の点を最初の敵まで引く（ねらった敵を白く光らせる表示は出さない）。キーワードの説明札では、初めの手札のうち説明文にキーワードがあるカードを持ち上げ、右に説明札を出す |
| `CardSkillLab` | `CardSkillLabScreen`（`CardSkillLab`） | 一覧を閉じた・一覧を開いた（Play中と同じくスキルを使い手の列に並べ、1番目を選んだ印を付ける）。保存したシーンは一覧が開いて中身が空のため、「元の表示」はその状態になる |
| `QualityLab` | `QualityLabScreen`（`QualityLab`） | スキル（品質S）・武器（品質A）・ACTボーナス（品質C）。それぞれの1つ目を、その品質の中ほどの倍率で出す。左の一覧の行はPlayの開始時に作るため、出さない |
| 各画面 | 通知の帯（`NoticeBand`） | 短い文・長い文の、消えずに止まった帯 |

旅の案内所（`TravelOffice`）は行き先の一覧だけで、切り替える表示がない。
編成のパネルの「取得できない」は、パネルの中の文字だけを出す。Play中に合わせて出る通知の帯は、`NoticeBand` で見る。

## 3Dの舞台（HD-2D）

Top・Home・戦闘画面（BattleLab・Battle）は、3Dの地面と背景にドット絵のキャラを立たせ、3Dの光と影で見せる構成である。
冒険の探索（Exploration）は3Dの舞台を使わない。
Topは星空の夜の山の門、ホームは昼の森の野営地、戦闘画面のモックは夕暮れの高原の環状列石に立つ。3つの画面で時間帯と色を分け、空と遠景は描いた絵を光を当てずに見せる。
キャラの位置・大きさ・動き、タップの判定、HUD・手札・HPバー・弱点などの表示と操作は変えず、UIが決めた位置の地面に3Dの板として立たせる。
キャラは主光源（ホームは太陽）の影を地面に落とし、足元に接地影が付く。
キャラの奥行きにピントを合わせ、手前と奥の舞台をぼかす。キャラ・HPバー・演出はぼかさない。
入力を待つ間はカメラがゆっくり揺れ、TopとHomeは開いたときにカメラがすべり込む。
カメラ・光・ポストプロセス・テクスチャ・描く順番は[3Dの舞台](../art/hd2d-stage.md)を正本とする。
3Dのキャラと影は、停止中のシーンでもPlay Mode中でも表示する。停止中も舞台の粒子が動き、Sceneタブはシーンを開くと舞台のカメラから見る設定になる（手前のUIはGameタブで見る）。展示室で画面のPrefabを単体で見るときは従来の2Dの背景のまま表示する。

## Top

起動シーンのTopは、[3Dの舞台](#3dの舞台hd-2d)の星空の夜の山の門の手前に、題名と開始の案内を出す。

- 画面を覆った状態からFade演出（0.75秒）で開き、開き終わるまではタップを受け付けない。開き終わってから開始の案内を表示し、全面押下の受付を始める。
- 起動時のスプラッシュ画面や開く演出の途中で押した操作は、Homeへの遷移に使わない。
- 開始の案内は、起動処理が終わるまで「LOADING...」、終わると「TAP TO START」になる。起動処理、連携モーダル、失敗時の再試行は[起動時の連携と歩数の同期](startup-sync.md#top画面の流れ)を正本とする。
- 全面を押すと、上下から閉じるShutter演出（閉じる・開くとも0.75秒）でHomeへ移る。シーン間の移動でこの長い演出を使うのは、TopからHomeへの移動だけとする。
- 題名と開始の案内は、Safe Areaに追従する `TopSafeArea` の中のアンカーで置く。

### 画面遷移の演出

画面遷移の演出は [SceneTransitionController](../../client/Assets/Baryonyx/Shared/UI/SceneTransition/SceneTransitionController.cs) が受け持ち、Fade、Wipe、上下・左右のShutterから選ぶ。
共通のPrefabと、Top・Homeへの配置は `Baryonyx > App > Create Scene Transition Assets` で作り直す。ほかのシーンへの配置は、各シーンを作るメニューが行う。
Inspectorの `Exit` と `Enter` にある `SceneTransitionSettings` で、種類、色、閉じる時間、開く時間、Wipeの向き、Shutterの軸をそれぞれ選べる。
WipeとShutterはドット絵に合わせ、`Stepped Frame Rate`（初期値25）の回数だけ1秒間に位置を更新するコマ送りで動く。値を上げるほど滑らかになり、0で毎フレーム動かす。Fadeは常に滑らかに変化する。
ほかの画面へ移るときは [SceneLoader](../../client/Assets/Baryonyx/Shared/UI/SceneTransition/SceneLoader.cs) が演出で画面を覆ってからシーンを読み込む。
遷移先には `startCovered` と `revealOnStart` を設定し、開く演出を自動で再生させる。
読み込んだ先のシーンは、遷移元が閉じたときと同じ演出で開く。遷移元の `Exit` が閉じ方と開き方を決め、遷移先の `Enter Settings` は起動直後など遷移元がないときにだけ使う。

| 遷移元 | 閉じる・開く演出 |
|---|---|
| Top | 上下のShutter（閉じる・開くとも0.75秒） |
| Top以外（Home、案内人がいる画面、探索、戦闘） | Fade（閉じる・開くとも0.15秒） |

演出は1フレームで最大1/30秒ずつ進める。シーンを読み込んだ直後の重いフレームでも短い演出が一度に終わらず、暗くなってから少しずつ明るくなる。

## ホーム画面の見た目モック

ホーム画面は、デザインモックのA2案（焚き火を囲む「野営地」）を昼の森に置いた構成である。
横長の画面の余白は、キャラクターの立ち絵ではなく背景の世界とパーティ全員で埋める。
Topの全面押下で開く。
計画と判断の経緯は[実装計画](../plans/2026-09-24-home-camp-mock.md)に記す。

| 領域 | 表示と操作 |
|---|---|
| 中央 | 昼の森の野営地（[3Dの舞台](#3dの舞台hd-2d)）、焚き火、パーティ4人（名前なし）。奥にテントと丸太、周りに大木と茂み、上端に枝葉。木々のすき間から光の筋が差し、木漏れ日の斑と漂う塵が見える。4人の影は太陽と反対の右奥へ落ち、焚き火が足元を暖色に照らす。焚き火は、ドット絵の薪から計算で描いた炎が揺らいで立ちのぼり、火の粉が昇る。4人は「パーティ」と同じ操作 |
| 左上 | 今日のACT（歩数を1歩＝1ACTで換算）。数値の右に単位「ACT」、右側に日付（例：9/24（木））を置き、その下にゲージと次のボーナスまでのACT（例：あと 1,180 ACTで次のボーナス獲得）を置く。ボーナスの名前は出さない。ゲージは全員共通で8,000ACT（厚生労働省が成人に勧める1日8,000歩の換算）を最大とし、ユーザーごとの最大値は設けない。ゲージの下には、[ACTボーナス](step-bonus.md)の段階の位置に金の小さな目盛りを置く。区切り線の下の左端に「タップでルーン獲得」を置き、TOPのTAP TO STARTと同じ周期で点滅させる（同期中は「Loading...」で点滅しない）。縁をぼかした暗い下地に置き、下地全体で歩数を同期してルーンを獲得する（[起動時の連携と歩数の同期](startup-sync.md#homeのactパネル)） |
| 右上 | 所持ルーン（サーバーの残高。表示のみ、四方の外側へ向かって薄くなる暗い下地）と設定（丸い影の上に、左下のボタンと同じ描き方の歯車）。設定の下に、[デバッグルームの一覧](#デバッグルームの一覧)を出す丸いボタン（フラスコと星）を置く。ボタンどうしは、広げた押せる範囲が重ならないよう40px空ける |
| 左下 | 編成（アイコンは盾と、その後ろに立てた剣）、商会（天秤）、神殿（円環の中で四方へ光る星。召喚の魔法陣）、[ライブラリ](library.md)（開いた本）。台を置かず、影の上にアイコンと文字を置く。アイコンはドット絵にせず、縁取りのない白一色の形を文字と同じ色で96pxに表示する（[アート方針の例外](../art/direction.md#例外)）。各ボタンは幅128px・高さ168px（設計座標）とし、32pxの間隔を空けて並べる。パーティ4人と焚き火は、ボタンと重ならないよう160px上げて置く |
| 右下 | 行き先カード。冒険の途中は、今いるダンジョンの絵に「ミストラ遺跡 第3層」と「再開」を直接書き、探索を再開する。冒険していないときは、旅の案内所の世界地図の絵に「冒険に出る」「旅の案内所」「出発」を書き、旅の案内所を開く。カードは[すりガラスのカード](#すりガラスのカード)で、金の縁と光（選んだ印）は出さず、絵はカードの角丸で切り抜く |

四角い白い枠は使わず、濃淡の下地で読ませる。
行き先カードはドット絵調にせず、冒険の途中は探索を再開し、冒険していないときは旅の案内所を開く（[冒険の画面](#冒険の画面)）。
旅の案内所はこのカードから開くため、左下には置かない。
検討した案は[デザインモック](https://claude.ai/artifact/37YmCN3jjXE5j3Cwhx9Vp9)の「探索の途中（確定）」に残す。

運動目標は2026-09-27に廃止したため、左上の「今日の目標」と左下の「目標」ボタンは置かない。
残りのACTは、まだ解放していない最初の[ACTボーナス](step-bonus.md)の段階までのACTとする。
段階のACTは未決のため、[ACTボーナスの候補](step-bonus.md#候補)の値を仮に使う。

ACTは「途中」「ボーナスをすべて獲得（8,000ACT以上）」「未連携」の3状態を表示する。
今日のACT（保存した歩数の換算）と所持ルーンはサーバーに保存した値を表示し、それ以外の値は[仮データ](../../client/Assets/Baryonyx/Features/Home/Data/HomeMockData.asset)から表示する。
仮データはInspectorで変えると状態を確認できる。
行き先カードは、開いたときにサーバーから冒険の状態を読み、冒険の途中なら[探索](#冒険の画面)を、そうでなければ[旅の案内所](#編成商会神殿旅の案内所の画面)を開く。読み込む前に押すと「冒険の状態を確かめています」と知らせる。連打しても1回だけ遷移する。
遷移先を設定していない場合（展示室のPrefabのプレビューなど）は、「再開（準備中）」の通知だけを表示する。
左下の編成・商会・神殿は、[案内人がいる画面](#編成商会神殿旅の案内所の画面)を開く。
世界のパーティ4人を押すと、編成の画面を開く。
連打しても1回だけ遷移する。
設定は「設定（準備中）」の通知だけを表示する。
設定の下のボタンは、デバッグルームの一覧を出す。未公開の間に手元で確かめるための入口であり、公開前に外すか開発用のビルドだけに出すかを決める。

#### デバッグルームの一覧

ボタンを押すと、共通のダイアログに、[スキルのデバッグルーム](#スキルのデバッグルーム)・[品質のデバッグルーム](#品質のデバッグルーム)・[戦闘画面のモック](#戦闘の背景を選べる戦闘シーン)・[敵の挙動デバッグルーム](#敵の挙動デバッグルーム)・[戦闘の演出デバッグルーム](#戦闘の演出デバッグルーム)・[探索の演出デバッグルーム](#探索の演出デバッグルーム)と「閉じる」を、この順に1行ずつ並べる（2026-10-21）。
選んだルームは、案内人の画面と同じシャッターの演出で開く。「閉じる」で一覧を閉じると、Homeのまま操作を続けられる。
スキルと品質のデバッグルームは自分の「ホームへ」を持つ。ほかの4つは持たないため、Homeから開いたときだけ、共通の「ホームへ」（`DebugRoomReturn`）を重ねる。置く角はルームごとに、ルームの操作と重ならない所を選ぶ。戦闘画面のモックと戦闘・敵の挙動のデバッグルームは、左上に行動順のアイコンがあるため右上（ルームの名前の下）、探索の演出デバッグルームは、上に場所の名前と操作盤があるため左下に置く。シーンを単体で開いたときや展示室から開いたときは重ねない。
ダイアログの行は、6つのルームと「閉じる」が画面に収まるよう、ほかのダイアログ（5行・高さ112）より低い84にした。
主要な操作のタップ領域は、48dpに相当する約128px（設計座標）以上を確保する。
押している間は、ボタンの明るい部分を少し暗くする（色に約0.72を掛ける）。
行き先カードは行き先の絵を暗くする。
暗い下地に置いたボタン（ACTパネル、設定、デバッグルームの一覧、左下の4つ）は、下地だけでなく上のアイコンと文字も同じ暗さにする。
位置をずらす演出は付けない。
4:3など1920より狭い画面では、中央の世界を縮めて四隅のボタンと重ねない。

### ルーン獲得の演出

ACTパネルを押してルーンを獲得すると、パネルを押した位置からルーンが四方へ一気に広がる（画面の外まで飛んでよい）。押した位置が分からないとき（ボタンを直接呼び出した場合など）は、パネルの「タップでルーン獲得」の文字から広がる。広がる距離も獲得量の桁数に応じて伸ばし、1ルーンで140px、10万ルーン以上で520px（設計座標）を上限にする。
ルーンの数は獲得量の桁数に応じて増やし（1,340で26個、36,896で34個、上限40個）、獲得量より多くはしない。
広がったルーンは間を置かずに（0.08秒）、全部まとめて加速しながら右上の所持ルーンのアイコンへ吸い込まれる。吸い込み始めは0.15秒の幅でばらけ、吸い込まれる時間は平均0.55秒で、ルーンごとに±40%（0.33〜0.77秒）の幅でばらつかせる。
ルーンが1つ着くたびに所持数を付与前の残高から増やし、アイコンを小さく跳ねさせる。
同時に、所持ルーンのアイコンから白から水色へ変わる四芒星と点のキラキラを3粒弾かせ、アイコンに重ねた加算の光を小さく明るくする。最後の1粒では16粒を大きく弾かせ、光を強くしてから広げながら0.5秒で消す。キラキラはルーンと同じ4pxの1ドットで描き（四芒星は5×5ドットの[RuneTwinkle.png](../../client/Assets/Baryonyx/Features/Home/UI/Art/RuneTwinkle.png)）、所持数の文字にかからないよう左寄りへ飛ばす（`Hd2dEmberEmitter` を使う）。
ルーンが弾ける瞬間にも、弾けた位置から同じ色のキラキラを24粒、四方へ散らす。広がるときも吸い込まれるときも、各ルーンは0.07秒ごとに通り道へキラキラを1粒残す。キラキラは飛ぶルーンより手前に描く。
キラキラの後ろには、ぼかした水色の光（モヤ）を漂わせる。弾けた位置には大きなモヤを6つ、通り道にはキラキラ2粒ごとに1つ、着いた位置には1粒ごとに1つ、最後の1粒で4つ出す。モヤは飛ぶルーンより奥に描く。星は強めに瞬かせる。
所持数の文字は吸い込んだ量に比例して大きくし、全部が着いた時点で1.45倍・金色になる。少し止めてから元の大きさと色へ戻す。
所持ルーンのアイコンも文字と同じ倍率で大きくし、その上に1粒ごとの跳ねを重ねる。アイコンは文字の中心から同じ倍率で広げた位置へ寄せ、大きくなった文字と重ならないようにする。吸い込まれるルーン・光・キラキラは、動いたアイコンの位置へ向ける。
所持数の下には「+獲得量」を出し、所持数と一緒に少し大きくし、全部が着いてから消す。
演出は約2秒で終わり（最後の粒が着くまで最長約1.25秒）、早送り・省略の操作は設けない。
獲得量が0のときは、「獲得ルーンはありません」を[共通の通知の帯](../rules/ui-design.md#操作を求めない通知)で約1.4秒表示する。
同期に失敗したときや未連携のときは、演出を出さずに従来のトーストで知らせる。
展示室のPrefabのプレビューでは、ACTパネルを押すたびに見本の獲得（+1,340）と「獲得ルーンはありません」を交互に表示する。

操作は見た目を確かめるための仮の反応である。
カードを押すと、ばねのように弾みながら真っすぐに起き上がり、1.6倍に大きくなって画面の左右中央へ移る。下端は画面の下端から24px上げる。
説明文に[キーワード](combat.md#カードのキーワード)があるカードは、上がっている間、カードの右（右端から16px）に、キーワードごとの説明札を上端をそろえて縦に並べる（Slay the Spireと同じ置き方）。札を合わせた高さがカードより高いときは、札の下端がカードの下端（画面の下端から24px）にそろうまで上へずらし、画面からはみ出さないようにする。札は手前の敵（苔スライム）に重なるが、ユーザーの判断でこの位置にした。札は景色の上に置く[すりガラスのカード](#すりガラスのカード)（濃い紺の板、模様なし）で、幅340pxに、水色のキーワードと、その意味を書く。高さは文の長さに合わせる。同じキーワードは1枚にまとめ、札は4枚までとする。カードを敵へ向けて引っぱっている間（照準の点が出ている間）は、ねらう相手を隠さないよう札を消す。
上がっているカードもタップを受け、もう一度タップすると対象を選ばずに使う（下の「タップする」を参照）。上がっているカードは手札の扇と重なるため、重なった場所のタップも上がっているカードが受ける。
カードの使い方は、引っぱる方法とタップする方法の2つを用意し、どちらでも使える（Slay the Spireのスマホ版と同じ考え方）。
カードが上がっている間は、そのカードで選べるキャラ全員の頭の上に▼のカーソルを出し、1秒ごとに1ドットずつ上下させる。
あわせて、そのカードの使い手が敵の側へ1歩（64px）出て、足元に金の輪（`CasterRing`）を、HPバーの下に名前の札を出す。名前の札は、カードの使い手の行と同じ色の文字を、Topと同じ暗く透ける帯に重ねたものである。ほかの味方は暗くしない（ブロックのように味方全員が対象のカードもあるため）。使い手が自分を対象にできるカード（ヒール）では、輪と▼が両方付く。カードを手札へ戻すと、使い手は元の場所へ戻り、輪と名前の札は消える。
操作を説明する文は出さない。

- **引っぱる**：押したまま上へ100px以上スワイプすると、指の下の対象が白く光る。カードは上がった位置から動かず、カードの中央から指まで点が曲線に並ぶ（Slay the Spireの矢印に当たる）。点は手札より奥に描くため、カードの裏から伸びて見える。点は、指が対象の上にあるときは明るく、ないときは暗い。敵に使うカードは敵、味方1体に使うカード（ヒール）は味方の上で離すと、エネルギーを払ってそのキャラに使う。スワイプが足りないまま離すか、対象のない場所で離すと、カードは手札へ戻る。
- **タップする**：押した場所から24px以内で離すとタップとして扱い、カードを上げたまま対象のタップを待つ。対象のキャラをタップすると、そのキャラに使う。上がっている同じカードをもう一度タップすると、対象を選ばずに使う。敵単体への攻撃とヒールは、選べる相手からランダムに1体を選び、全体が対象のカード（サンダー・ガード）は全員に使う。何もない場所をタップすると、手札へ戻る。別のカードをタップすると、そちらに持ち替える。ターン終了を押したときも手札へ戻る。

対象の判定は、どちらの方法でも、キャラの絵の周りに72pxの余白を足した範囲で行い、余白が重なる場所では絵に近いキャラを選ぶ。
全体が対象のカード（サンダー・ガード）は、押した時点から対象の全員が白く点滅し、カードが上がっている間は点滅を続ける。上へスワイプするか、タップしたあと対象の側のだれかをタップすれば使え、1体を選ばなくてよい。
使ったカードは手札から消え、残りのカードがばねのように動いて中央へ寄り、空きなく扇に並び直す。
敵は赤く光って揺れ、ダメージの数字が浮かび、HPが減る。
弱点の属性なら[属性と弱点](combat.md#属性と弱点)の倍率を掛け、数字を大きく、黄色から橙の色で表示する（「弱点！」の文字は出さない）。
回復した味方には、回復量を緑の小さめの数字で表示する（「+」は付けない）。
弱点は1体に複数持てる。開示済みの弱点は属性のアイコン、未開示の弱点は「？」のアイコンで表し、未開示の弱点を突くとその場で開示する（[弱点の開示](combat.md#弱点の開示)）。
冒険の戦闘では、敵の種類ごとに記録した、前の戦闘までに開示した弱点を最初から見せる（[弱点の開示](combat.md#弱点の開示)）。
単体で開いたモックは記録を使わず、仮の初期値として狼の氷と守り手の炎だけを開示済みにしている。
開示するときは、弱点のアイコンが光る演出（キラーン）を出す。
当たった瞬間から0.1秒かけて「？」が少しふくらみながら白くなり、光が最も強いときに属性のアイコンへ替わる。
同時に、アイコンの右上の角で四方へ光の伸びる星が光り、回りながら小さくなって消える。左下の角でも、遅れて小さな星が光る。
アイコンは白から元の色へ戻りながら弾むように元の大きさへ戻り、その上を右上がりの光の帯がドット単位で左から右へ抜ける。

アイコンの上の光はアイコン自身の形の内側にだけ描き（`Vfx/Shaders/BattleWeaknessGlint.shader`）、星・周りの光・小さな粒はほかの演出と同じく計算で描く。
開示した当たりで敵を倒した場合は、アイコンだけ替わり、星は出さない。
カードを使うと、エネルギーを払ってカードが手札から消えたあと、使い手の味方が敵の側へ1歩（64px）出て、効果が出てから元の場所へ戻る。カードを上げている間に前へ出ていた使い手は、その位置から動きを続け、いったん戻ってから出直すことはしない。

枠は、ユーザーが選んだ属性の色の細い枠（デザイン案D）にした。カード上のコストは、数字までドット絵で描いた案からユーザーが選んだ「菱形の台座」（14×14ドットの金の縁の菱形に、暗い縁取りの4×6ドットの琥珀色の数字）にした。左下のエネルギーの宝石も、同じ金の菱形に琥珀の石をはめた絵にそろえた。菱形の枠（`CardCostFrame`）と数字（`CardCostDigits`、0〜9を横に並べた1枚）は別の絵にし、Unityで数字を枠の中央に重ねる。数字の幅（4ドット＋縁取り）に合わせて枠を偶数の14ドットにしており、中央に置いても半ドットずれない。
2026-09-30、ユーザーの依頼で、コストをカードの左上の角からはみ出す位置から、挿絵の左上の角に重ねる位置へ移した。ドット数はそのままで、1ドット5pxから4pxに下げて一回り小さくした（台座は70pxから56px）。

同日、ユーザーの依頼でカードのデザインを作り直した。
Slay the Spire、Magic: The Gathering、Hearthstone、Marvel SNAPのカードの構成を参考に、試作を7回重ねてユーザーが選んだ（試作とスクリプトは `output/card-redesign/`、Git対象外）。
ドットを細かくして拡大率を下げてよいという判断により、カードを70×98ドットにし、1ドット3pxで表示する（画面上の大きさは210×294pxで、ほぼ変わらない）。
ユーザーの判断で次のようにした。

- 挿絵を大きく見せるフルアートにする。アーチ形の窓は挿絵を作りづらいため使わない。
- 種類（攻撃・回復・防御）、対象（単体・全体）、使い手を必ず見せる。「種類」「使い手」のような見出しと、使い手の顔は出さない。使い手の名前は長くなるため、専用の1行を取る。
- 種類と対象は、札にせず色付きの文字の1行にする。ボタンのように見える板や札は使わない。
- 使い手と名前は挿絵に重ねたうえで、Topと同じ暗く透ける帯を敷いて読みやすくする。帯は、行ごとの文字の長さまでにする。
- 威力の数字は本文と同じ大きさにし、色だけ変える。説明文は威力を含む1文にした（「炎の玉で敵1体を焼き、318ダメージ。」など。仮の文）。
- コストは、数を石の数で表すと多いときに困るため数字で表す。目立ちすぎないよう、11×11ドットの暗い札に琥珀の細い縁と5×7ドットの数字を重ねる。

帯は `BattleInspectCardBand` が描く。Topの帯の画像の中央の列を縦に使い、上下の透け方をそのまま保つ。行ごとに、文字の終わりの6px先から27pxで透明になる。
帯の幅は、カードに文字を入れるときに文字の実際の長さから決める。

同日、ユーザーの依頼で、山札から手札を配る動きを加えた。
山札は16枚で、PlayModeの開始時に切り混ぜる。
2026-10-03から、山札は[スキルの仮設定](combat.md#スキルの仮設定)の50枚のうち、4人に4枚ずつの16枚にした（下の「スキルの山札」）。それまでは6種類のカードを順に繰り返した16枚だった。
`アイスランス` は、エネルギーが足りないカードの見た目を確かめるため、コストを仮に7にしている（エネルギーの最大は開始時5）。
PlayModeでは手札が空の状態で始まり、0.3秒後から0.12秒ごとに1枚ずつ、山札の枠（絵と残りの枚数）の右端から小さく傾いた裏向きのカードが飛び出す。
はじめは山札の絵の中心から出していたが、出たばかりのカードが枚数の数字に重なって読みにくいというユーザーの指摘で、枠の右端に改めた。
カードは0.35秒で手札の位置まで飛び、途中で横幅を縮めて裏から表へ返る。
1枚出るたびに、山札の残りの枚数を1つ減らす。
配り始める前に配り終えたときの並びを決め、1枚目を一番右に置き、以後はその左隣へ順に置く（右詰め）。
着地したカードはその後動かず、飛ぶカードは山札から右へ進むだけで、置き済みのカードの上を横切らない。
エネルギーで払えないカードも、下げた位置へそのまま飛んで着地し、着地したあとに沈まない。暗く透けさせるのは着地してからにする。
はじめは1枚ごとに扇を中央へ寄せ直していたが、先に置いたカードと飛ぶカードが左へ動いて不自然だというユーザーの指摘で、この形にした。
ターン終了で引くカードも同じく左端（山札の側）に入り、手持ちのカードは配り始めに1度だけ右へ寄る。
配っている間は、カードを押せず、ターン終了も押せない。
PlayModeでないときは、最初の6枚が並んだ状態を表示する。開始時のエネルギー（5）で払えないカードは、Play中と同じく暗く透けさせる。
捨てる操作とゴミ箱のボタンは、ユーザーと相談して作らないことにした（[手札](combat.md#手札)）。

2026-10-01、ユーザーの依頼で次の3点を変えた。

同日、2.25倍では大きすぎるというユーザーの指摘で、選んだカードを1.6倍にし、画面の上下左右の中央から、左右中央の下寄せ（下端から24px）に改めた。
このカードに重ならないよう、味方を左へ60px寄せた。
敵は、はじめ右へずらしたが窮屈で、狼の尻尾が守り手の弱点アイコンにかかった。そこでユーザーの提案で、狼（奥）とスライム（手前）を同じ列に上下に並べ、その後ろに守り手を置く配置にした。
引っぱるときの点は、カードの上端からカードの中央へ出どころを移し、手札より奥に描いて、カードの裏から伸びるように見せる。

同日、ユーザーと相談して行動順の見た目と位置を改めた。

### スキルの山札

2026-10-03、ユーザーの依頼で作った[スキルの仮設定](combat.md#スキルの仮設定)の50枚から、4人に4枚ずつの16枚を山札にした。
最初の6枚は、それまでのカード（斬り払い・ファイア・アイスランス・サンダー・ヒール・ガード）で、テストで配る順に並べたときに開始時の手札になる。

| 使い手 | 山札のカード |
|---|---|
| アリア | 斬り払い・ガード・シールドバッシュ・居合一閃 |
| トーマ | ファイア・アイスランス・火の粉・メテオ |
| ルカ | サンダー・急所突き・チェインライトニング・蛇牙の連撃 |
| ミナ | ヒール・リジェネ・ホーリーライト・プロテクト |

居合一閃（コスト5）は、最初のターンのエネルギー（5）で使えるカットインの技として入れた。
メテオ（コスト9）は、エネルギーが足りないカードの見え方を確かめるために入れた。
2026-10-18、ユーザーの依頼で、[キーワード](combat.md#カードのキーワード)の説明札が積み重なる見え方を確かめるため、偵察を外し、キーワードを4つ持つ試作のカード「蛇牙の連撃」を入れた。50枚の外のカードで、挿絵は急所突き、演出は斬り払いのものを使う。
それまでアイスランスのコストを7にしてこの役を持たせていたが、仮設定ではアイスランスを2にしたため、役をメテオへ移した。

カードを使うと、仮設定の効果をモックでも処理する（ダメージ・回復・ブロック・状態・エネルギー・カードを引く・コストを下げる・次のカードを0にする・弱点の開示）。
威力は使い手のステータス（物攻・属攻・物防）の割合で、味方のステータスは各自のLv100の値と仮のLv（トーマ12・ルカ11・アリア10・ミナ10）から出す（[自キャラのLv100のステータス](progression.md#自キャラのlv100のステータス)）。
ACTで威力が変わるカードは、今日のACTの仮の値（`BattleInspectView` の `TodayAct`、6,000）を使う。
ブロックは受けたダメージから先に引き、次の味方ターンの開始時に消える。
HPバーは、キャラと同じ1ドット4pxのドット絵として描く（[BattleHpGauge](../../client/Assets/Baryonyx/Features/Combat/Presentation/BattleHpGauge.cs)）。
角を1ドット欠いた暗い輪郭で囲み、HPの部分は上の1行を明るく、下の1行を暗くした3段の色に、空いた部分は暗くする。下の行には、4分の1ごとに輪郭と同じ色の目盛りを入れる。
大きさは、味方が30×5ドット（緑）、敵が65×6ドット（赤）である。
HPの長さはドット単位で変わり、HPが少しでも残れば1ドットは塗り、満タンのときだけ全部を塗る。
HPが減ると、HPの部分はすぐに縮み、減った分が残像として残る。残像は0.12秒白く光ってから0.35秒とどまり、0.4秒で縮んで消える。縮む動きもドット単位である。
続けて当たったときは、残像が縮みきる前でも、その位置からとどまり直す。ヒットストップで戦闘が止まっている間は、残像も止まる。
残像の色は味方が赤で、敵は赤いバーと見分けるため薄いクリーム色にする。回復ではすぐに伸び、残像は出さない。
ブロックの量は、HPバーの上に左から黄色の細いバー（1ドットの黄色を暗い縁で囲んだもの）を重ねて表す。黄色のバーはHPバーの上へ1ドットはみ出してHPの明るい行を覆い、その下には緑のHPが見えたまま残る。
長さはHPと同じく最大HPを全体とし、最大HPを超える分はバーいっぱいで止める。数値と盾のアイコンは出さない。
ブロックはHPではないため、回復しても黄色のバーは伸びず、減ったHPの分（暗い部分）だけが回復で埋まる。
やけど・毒・リジェネ・爆炎の刻印・雷雲は、敵のターンが終わって味方のターンが始まるときに働く。
状態を付けると、その名前を対象の上に浮かべる。
同じ対象の上に文字がまだ出ているうちに次の文字が出るときは、前の文字の下へ1行ずつずらして並べる（出血・毒・防御ダウンを同時に付けたときなど）。
ダメージ・回復の数字も同じ並びに入れ、ダメージと状態を同時に与えたときは、数字の下に状態の名前を出す（2026-10-20）。
数字は少しだけ、名前は大きく上がるため、止まる位置だけでなく上がる途中でも重ならないよう、後から出す文字を下げる。
仮設定の決まりは [BattleInspectView.Cards](../../client/Assets/Baryonyx/Features/Combat/Presentation/BattleInspectView.Cards.cs) に置く。

打と貫の属性のアイコン（`ElementBlunt`・`ElementPierce`、12×12ドット）と、カードの枠（`CardFrameBlunt`・`CardFramePierce`、70×98ドット）は、2026-10-03にほかの属性と同じスクリプトで描いた（`output/card-skills/new_elements.py`、Git対象外）。打は青銅の地に槌、貫は青緑の地に槍の穂先である。

### カードと手札を見ながら調整する

カードの見た目と手札の並びは、Unity Editor上で見ながら調整できる。
画面の生成（`Baryonyx > App > Create Battle Lab Scene`）は、次の2つが無いときだけ作り、あれば上書きしない。

| 調整したいもの | 開くもの | 内容 |
|---|---|---|
| カード1枚の見た目（挿絵・使い手・名前・種類と対象・説明・コスト・属性のアイコン・帯の位置や大きさ） | `Features/Combat/UI/BattleInspectCard.prefab` | Prefabを開いて子の位置・大きさ・文字の大きさを変える。手札の6枚すべてに反映される |
| 手札の並びと動き（カードの倍率、使えないカードの不透明度、押したときの倍率と画面中央からの上下のずれ、扇の角度・両端の角度の差の上限・半径・沈み方・高さ、配る枚数（開始時・毎ターン）と手札の上限、配る間隔と飛ぶ時間、山札を出るときの大きさと傾き、スワイプ量、タップとみなす動きの幅、当たり判定の余白、行動するキャラが出る距離と時間・効果のあとの待ち・敵の行動の間、ターンの始まりの帯を出しておく時間と現れて消える時間、ばねの強さ） | `Features/Combat/UI/BattleInspectHandSettings.asset` | Inspectorで値を変える。Play中に変えるとその場で反映され、アセットなのでPlayを止めても値が残る |

### スキルの演出と背景

2026-10-01、ユーザーの依頼で、手札のカードを使ったときのスキルの演出（VFX）を加え、背景を差し替えた。
依頼は「ド派手で脳汁が出る」演出で、エフェクトの素材と背景はCodex CLIの画像生成で作った。
同日、ユーザーの判断で、エフェクトは画像をやめて、形をシェーダーで計算して描く作りに改めた（下の変更記録）。
同日、ユーザーの依頼で [vfx-authoring](../../.agents/skills/vfx-authoring/SKILL.md) の手順に沿って演出を作り直した。
最初の版には、周りが照らされない、光がにじまない、描き込んだ1枚の絵を広げて薄めるだけ、すべてがキャラの手前にある、暗い煙が光の手前にある、という「のっぺり」見える原因が重なっていた。
さらに炎は、円形に描かれた炸裂の絵を敵の奥に広げていたため、「敵の奥に丸い模様が見えるのはおかしい、もっとリアルに」とユーザーから指摘を受けた。
そこで丸い炸裂の絵をやめ、写実的な炎・煙・氷の素材を、ちぎれた塊として時間差で重ねる作りに改めた。
演出の時間の組み立ては[VFX Apprenticeの解説](https://www.vfxapprentice.com/blog/the-soul-of-effects-what-is-timing-in-vfx)、ヒットストップは[桜井政博氏のコラムの紹介](https://sourcegaming.info/2015/11/11/thoughts-on-hitstop-sakurais-famitsu-column-vol-490-1/)、閃光の上限は[WCAG 2.3.1](https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold)を参考にした（2026-10-01参照）。

各スキルは、溜め（予備動作）、当たる瞬間（発生）、余韻の3拍で組み立てる。
溜めでは、背景だけを夜の青へ暗くし（キャラは暗くせず、黒にもしない）、使い手の足元に魔法陣を回し、光の粒を使い手へ吸い込ませる。
当たる瞬間には、ヒットストップ（戦闘を一瞬止める）、画面の揺れ、閃光、火花を重ね、効果（ダメージ・回復・ブロック）を出す。
余韻では、炎や氷が細りながら消え、煙や冷気が残って薄れ、背景の明るさが戻る。

2026-10-03、ユーザーの依頼で、[スキルの仮設定](combat.md#スキルの仮設定)の残りの44枚にも、1枚ずつ別の演出を作った。

技の格は、大きさ・長さ・画面効果で分ける。
コスト1の技は短く軽くし、通常の当たりでは画面全体の閃光を出さない。コスト2以上は閃光を出す。
コスト5以上のカード（居合一閃・千刃乱舞・ギガントインパクト・メテオ・ブリザード・絶対零度・シャドウスナイプ・雷雲・雷神の槍・リザレクション）は、使い手が1歩出たあとカットインを約0.66秒出し、溜めで使い手を足元から照らし、当たりで画面をわずかに寄せる。
2026-10-03まではコスト3以上で、サンダーとアイスランス（当時コスト7）がカットインを出していた。大技が増えたため、5以上に引き上げた。
カットインは、画面の中央を少し傾いて横切る暗い帯に、属性の色の流れる線、8倍に拡大した使い手の上半身、スキル名を重ねる。

エフェクトは光源として周りを照らす。
近くのキャラには、絵の上に光の色を加算で重ね、光源の側の角ほど明るくする（`BattleActorLight`）。足元からの光は足元ほど明るくなる。
床には寝かせた光だまりを置き、暗くした背景には光の届く範囲だけ柔らかな光を戻す。炎の光は揺らぐ。
弱点を突いた当たりととどめの当たりは、ヒットストップ・揺れ・炸裂を大きくする。
当たった敵は一瞬白く光ってから赤くなり、後ろへはじかれて揺れる。揺れはヒットストップの間も続ける（止まっている間も当たったキャラを揺らす、格闘ゲームの工夫）。
倒した敵は、止まる・崩れる・余韻の3拍で消える。
まず戦闘を止め、敵を白く光らせたまま0.1秒震わせる。
次の0.55秒で、敵は元の色に戻りながら、当たった側と上からドットごとにまだらに削れて消え、削れの先頭のドットは白く光る（`BattleDefeat.shader`）。
削れたドットは、そのドットの色をした四角い光の粒（形の `Mote`）になり、回らずに上と当たった向きへ舞って薄れる。足元では土ぼこりが床を這い、近くのキャラと背景を照らす。
崩れ始めに画面を当たった向きへ揺らし、戦闘を0.25秒だけ0.5倍の速さにする。雑魚の撃破では画面全体の閃光を出さない。
ボス（`BattleInspectEnemy` の `Boss`。モックでは森の守り手）は、白く光る間を0.42秒に延ばして画面全体を2回光らせ、強く震わせ、1.1秒かけて多くの粒に崩し、画面をわずかに寄せる。
2026-10-04までは、絵を6×6の四角いかけらに割り、回しながら飛び散らせていた。かけらの四角い縁と、回したドット絵の格子の崩れが雑に見えたため作り直した（その前は0.5秒で薄く消えていた）。
敵の攻撃が味方に当たったときは、赤い爪痕・小さな光・火花と、短いヒットストップ・揺れを出す。プレイヤーの技より控えめにし、画面全体の閃光は出さない。
ダメージと回復の数字は、1.8倍の大きさで飛び出してから元の大きさへ縮み、1.3秒（それまでは0.9秒）で消える。
当たる瞬間に集中線（漫画の効果線）を出す案と、空中に光の輪を広げる案も試したが、前者はユーザーの判断で、後者は写実に合わないため外した。輪は剣・雷・回復・防御でだけ、床に寝かせて使う。炎・氷・撃破の衝撃は、輪ではなく床を這う土ぼこりや冷気で見せる。

画面全体の閃光は、前の閃光から0.34秒以上あけ、1秒に3回を超えないようにする。間隔が短いときは弱い光にとどめる。
閃光の濃さは最大30%（加算）とし、大きな当たりでも画面を白く飛ばさない。サンダーは最初の落雷だけで閃光を出す。
揺れはドットの格子に合わせて4px単位で動かす。
`ScreenCanvas` の `BattleSkillVfx` のInspectorで、画面の揺れ（`ShakeStrength`）と閃光（`FlashStrength`）を弱め、ヒットストップ・撃破のスロー・画面の寄せ（`UseHitStop`）を止められる。カットインを出すコスト（`CutInCost`）も同じ場所で変える。
演出ごとの秒数・大きさ・色は [BattleSkillVfx](../../client/Assets/Baryonyx/Features/Combat/Presentation/BattleSkillVfx.cs) のコードに持つ。最初の6枚の後に作った44枚と、後から働く状態の演出は [BattleSkillVfx.Cards](../../client/Assets/Baryonyx/Features/Combat/Presentation/BattleSkillVfx.Cards.cs) に置く。

戦闘画面は、光のにじみ（Bloom）を通すために2つのCanvasに分けた。
背景・床の霧・キャラ・エフェクトは `StageCanvas`（Screen Space - Camera）に置き、シーンのカメラのポストプロセスを通す。
行動順・手札などの操作UI、画面全体の閃光、カットイン、数字は `ScreenCanvas`（Screen Space - Overlay）に置き、にじませない。
プレハブはシーンのカメラを参照できないため、`BattleStageCamera` が開始時にシーンのカメラを `StageCanvas` に設定し、そのカメラのポストプロセスを有効にする。
ポストプロセスは戦闘専用の `Features/Combat/Vfx/BattlePostProcess.asset`（Bloom：Threshold 1、Intensity 1.4、Scatter 0.7。Vignette 0.22）で、Topの共通Profileは使わない。
Bloomの閾値を1にしているため、ドット絵と背景（色はどれも1以下）はにじまず、加算が重なって白を超えた光と、明るさを1.8倍にした芯だけがにじむ。
対象を選ぶ当たり判定とダメージの数字の位置は、`StageCanvas` のカメラを通して画面の座標へ変換する。
描く順番は、背景、背景を暗くする幕、奥の煙、奥の光（魔法陣・光だまり・奥の炎や結晶）、キャラ、手前の煙、手前の光（火球・手前の炎・火花）である。ここまでがBloomを通り、その上に画面全体の閃光、カットイン、操作UI、数字を重ねる。
[3Dの舞台](#3dの舞台hd-2d)では、背景が3Dの石舞台、キャラが3Dの板になる。キャラの奥の層（暗幕・奥の演出）は `StageCanvas` の順番0、キャラは順番10、HPバー・弱点・名前の札を置く `World` は入れ子のCanvasで順番20、手前の演出 `VfxFront` は順番21にして、前後関係を保つ（[描く順番](../art/hd2d-stage.md#描く順番)）。
煙は光る層より奥に描き、明るい中心が灰色に濁らないようにする。

エフェクトの形は、画像を使わずにシェーダーで計算して描く（[エフェクトの描き方](../art/direction.md#エフェクトの描き方)）。
シェーダーは `Features/Combat/Vfx/Shaders/BattleVfxShape.shader` で、形の式は同じ場所の `BattleVfxShapes.cginc` に置く。
形は34種類（`BattleVfxShape`：グロー、輪、光条の星、斬撃の弧、十字の斬撃、火球、氷の槍、稲妻、光の柱、ドーム、魔法陣、流れる火花、丸い火花、きらめき、光の破片、炎の塊、炎の舌、煙、焦げ跡、霜、氷のトゲ、破片、カットインの流れる線、光線、矢、亀裂、竜巻、泡、葉、上向きの矢印、雪の結晶、盾の紋、照準、撃破で舞う四角い粒）で、形ごとのマテリアル `VfxShape〈形の名前〉` を `Features/Combat/Vfx/Materials/` に置く。
煙・焦げ跡・霜・氷のトゲ・破片は通常合成、ほかは加算で描く。
1枚ずつの乱数の種・進み具合・欠けた割合・明るさは、`BattleVfxImage`（RawImageを継承した部品）が頂点の追加のUV（UV1）に書き、シェーダーが読む。このため、エフェクトを描くCanvasの追加のシェーダーチャンネルにTexCoord1を含める。
主な形は一様に薄めず、ノイズに沿って削れる・弧に分かれる・六角形ごとに落ちる・破片に崩れるなど、形ごとに欠けながら消える。
芯は明るさを1.8倍、削れて消える光は1.2倍にして、Bloomでにじませる。
キャラへの照り返しと画面全体の閃光は、キャラの絵の形をした加算の光として `BattleVfx.shader`（マテリアルは `VfxGlow`）で描く。
粒子は `BattleSkillVfx` が `BattleVfxImage` を使い回して動かす（最大360個）。粒ごとに、現れるまでの遅れ、膨らみ方、温度の色、削れ方を変えられる。
ヒットストップは `Time.timeScale` を0にし、実時間で最長0.2秒後に戻す（`BattleSkillVfx` が無効になったときも戻す）。
止めるのはキャラの動きと演出の進行で、炎・火花・光・揺れ・閃光・数字は実時間で動かし続ける。止めた瞬間の画面に、当たりの光が映るようにするためである。

それまでの背景（森に飲み込まれた遺跡の広間）では、苔の緑の敵が同じ色の背景に埋もれていた。
そこでCodex CLIに、キャラが立つ帯（画面の上から約40%〜90%）には障害物や細かい模様を置かず、敵の緑と色相・明るさをずらし、加算の光が映える中〜暗めの明るさにする条件で3案を描かせた（宵の森の石舞台、夕暮れの大樹の広場、地下神殿の大広間）。
3案をPlay中の画面に差し込んで比べ、月明かりの石舞台を採った。青い夜の色で、苔の敵と味方がはっきり浮き、炎・雷・回復の光が最も映えた。
夕暮れの広場は床の石が賑やかで炎がなじみ、地下神殿は柱と石像が味方の後ろで込み合った。
生成画像（1536×1024）の上下を80pxずつ切って16:9にし、`BattleBackground.png` を置き換えた（大きさは前と同じ1536×864）。
3案と依頼文は `output/battle-vfx/bg/`（Git対象外）に置いた。

### カメラの中心のゆっくりした円運動

2026-10-01、ユーザーの依頼で、戦闘中ずっとカメラの中心がゆっくり円を描いて回る動きを加えた。
オクトパストラベラーの戦闘のカメラの動きを、ユーザーの説明に沿って取り入れた（軌道の形・周期・振れ幅を記した一次資料は見つからなかった）。
半径12px（設計座標、3ドット）の円を40秒で1周させる。速さは秒速約1.9pxで、ユーザーが気づかない程度を狙っている。
はじめは半径8pxを24秒で1周させ、画素単位で動かしていた。ユーザーの確認で、もっと滑らかにゆっくり、円は少し大きく、攻撃の演出中も止めずに動かすことになり、今の値と描き方にした。

動かすのは、背景・床の霧・キャラ・エフェクトをまとめた `Stage` だけである。
行動順・手札・エネルギーなどの操作UI、画面全体の閃光、カットイン、ダメージの数字は動かさない。
2026-10-02に背景を[3Dの舞台](#3dの舞台hd-2d)にしてからは、3Dのカメラも `StageDrift`（円運動）と `Stage`（当たりの揺れ）の動きに合わせて動く。
キャラが立つ奥行きでUIと同じ距離だけ動くため、キャラとHPバーは一緒に動き、手前の地面と奥の遠景は視差でずれる。
それまでは背景が1枚の絵だったため、視差は付けず、`Stage` 全体を同じだけ動かしていた。
時間は実時間で進め、スキルの演出中もヒットストップの間も止めない。

動きは画素の端数まで滑らかに進める。
ドット絵は色を補間しない設定（Point）で読み込んでおり、そのまま描くと絵は画素単位で跳んで動く。秒速2px程度では、0.5秒ほど止まっては1画素進む動きになる。
そこで戦場のドット絵（背景、味方と敵、弱点のアイコン、足元の輪、対象のカーソル）は、専用のシェーダー（`UI/Shaders/UiPixelArt.shader`、マテリアルは `UI/StagePixelArt.mat`）で描く。
ドットの内側は最も近いドットの色のままにし、ドットの境目にかかる1画素だけを、境目が画素のどこを通るかに応じて両隣の色で混ぜる。
止まっていればPointと同じくっきりした絵になり、端数の位置ではドットの縁が1画素分だけなじむ。
対象を白く光らせるシェーダー（`UiFlash.shader`）も同じ描き方にし、光っている間も一緒に滑らかに動く。
撃破で崩れる敵の絵（`BattleDefeat.shader`）も同じ標本化で描く。
光を当てる重ね絵（`BattleActorLight`）は、今もPointのまま描く。

`StageCanvas` と `Stage` の間に `StageDrift` を挟み、`BattleStageDrift` がその位置を動かす。
当たりの揺れと寄せは `BattleSkillVfx` が `Stage` を動かすため、2つの動きは足し合わされる。
背景と、背景を暗くする幕は、当たりの揺れのための余白（画面より48px）に加えて、円の半径の上限（16px）だけ広く敷く。操作UIを読みやすくする上下の暗いグラデーションも、同じだけ画面の外へ伸ばす。
`BattleInspectScreen` の `StageDrift` のInspectorで、半径（`Radius`、0〜16、0で止まる）と1周の秒数（`Period`）を変えられる。Play中に変えるとその場で反映される。

画面は[戦闘画面の見た目モック](#戦闘画面の見た目モック)と同じで、背景の3Dの舞台だけを、夕暮れの高原と10種類（草原の街道、朝霧の森、坑道、水晶の洞窟、海辺の岩場、霧の沼地、雪原、火山、夜の墓地、古城の大広間）から選ぶ。

## スキルのデバッグルーム

`CardSkillLab.unity` は、スキルの演出（VFX）だけを確かめるデバッグ用のシーンである。
`BattleLab.unity` では、確かめたいカードが手札に来るまでターンを進め、エネルギーをためてから使う必要があり、演出を作りながら何度も見るには手間が多すぎた。

画面には、戦闘と同じ夕暮れの高原の3Dの舞台に、味方4人と敵3体を戦闘と同じ位置で立たせる。
手札・行動順・エネルギー・HPバー・弱点・ダメージの数字は置かない。
カメラ、ポストプロセス（Bloom・レンズ・色調）、エフェクトの層の順番は戦闘画面と同じにしており、演出は戦闘中と同じ見た目で再生される。
使い手が1歩出る動き、当たった敵が白く光ってはじかれる動き、撃破で崩れて消える動き、カメラの中心のゆっくりした円運動は、戦闘画面の処理（`BattleInspectView`・`BattleStageDrift`）が出すため、このシーンには出ない。

Play Modeにすると、前回選んだスキルを再生する（初回は1枚目の斬り払い）。
選んだスキルと、当たり・ねらう敵・くり返しの設定は、このPCの `PlayerPrefs` に残る。
演出のコードを直してPlayし直すと、同じスキルから確かめられる。

| 操作 | 動作 |
|---|---|
| 上部の表示 | 再生中のスキルの番号・名前と、使い手・コスト・種類・対象の範囲 |
| スキル一覧 | 全スキルを、戦闘と同じカード（挿絵・説明文・[キラキラ](../art/direction.md#カードのキラキラ)）で並べて開く。「カードスキル」（1〜50番、1行に8枚）と「[固有スキル](skill-evolution.md)」（51〜106番、1行に7枚で、1行が1本の進化ツリー）の2つのタブに分け、上下のスワイプでスクロールする。開くと再生中のスキルのタブとカードの位置に合わせ、そのカードの後ろに金の光を出す。押したスキルをすぐ再生し、一覧を閉じる。開いているあいだは上部の表示と下の操作の列を隠す |
| 前へ・次へ | 一覧の番号の順で、前後のスキルを再生する |
| もう一度 | 今のスキルを最初から再生する |
| 当たり | 通常・弱点・とどめを順に切り替えて再生し直す。弱点ととどめでは、ヒットストップ・揺れ・炸裂が大きくなる |
| ねらう敵 | 敵1体に使うカードの対象を、苔スライム・苔むした狼・森の守り手の順に切り替えて再生し直す |
| くり返し | 入にすると、再生が終わった0.9秒後に同じスキルを再生し続ける。切にすると1回で止まる |

どの操作でも、再生中のスキルを途中で打ち切り、次のスキルを最初から再生する。
打ち切るときは、残っている形・粒子・光、背景の暗さ、閃光、カットイン、画面の揺れと寄せ、ヒットストップで止めた時間を元に戻す（`BattleSkillVfx.Clear`）。
味方1人に使うカードは使い手の次の味方に、全体に使うカードは全員に当たる。
やけど・毒・出血・リジェネ・爆炎の刻印・雷雲のように後から働く状態は、カードの演出に続けて、働くときの演出も再生する。
使い手と対象の決め方と再生の順序は、展示室の自動再生（`BattleSkillVfxPreview`）と同じ処理を使う。

一覧のカードはPlayの開始時にスキルの定義（`CardSkills` と固有スキルの進化ツリー）から作るため、カードを足してもシーンを作り直さずに一覧へ出る。ただし挿絵はPlay中に読み込めないため、生成のときに焼き込む。新しい挿絵を足したら `Baryonyx > Combat > Create Card Skill Lab Assets` で作り直す。
停止中のシーンでは一覧の中身が空のため、並びは `CardSkillLabScreen` のInspectorの「一覧を開いた（カードスキル）」「一覧を開いた（固有スキル）」で確かめる（[停止中の表示の切り替え](#停止中の表示の切り替え)）。
下の操作ボタンと一覧を閉じるボタンは、指で押せる高さ（設計上128）にした。
ボタンは景色の上に置く濃い板の[すりガラスのカード](#すりガラスのカード)にした。
一覧のカードは戦闘の手札のカードを0.8倍にしたもので、手札のドラッグの操作は外しており、カードの上でスワイプしても一覧がスクロールする。

シーンは `Baryonyx > App > Create Card Skill Lab Scene` で作り直す。
画面のPrefabは `Features/Combat/UI/CardSkillLabScreen.prefab` である。
[ホーム](#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](showcase.md)のシーン一覧から開く。
ホームから開くときは、案内人の画面と同じシャッターの演出で切り替わる。
左上の「ホームへ」を押すと、再生中のスキルを止めてホームへ戻る。連打しても1回だけ遷移する。
「ホームへ」は一覧の見出しと重なるため一覧を開いているあいだは隠し、戻り先を設定していないとき（展示室のPrefabのプレビュー）も出さない。

## 敵の挙動デバッグルーム

`EnemyLab.unity` は、敵の挙動だけを確かめるデバッグ用のシーンである。
`BattleLab.unity` で敵を動かすには、ターン終了を押して行動順で敵の番が来るのを待つ必要がある。
凍結や出血が付いた敵の行動、撃破の動きを見るには、そのカードが手札に来るまでターンを進める手間もかかる。

画面は[戦闘画面の見た目モック](#戦闘画面の見た目モック)と同じPrefab・3Dの舞台・カメラ・ポストプロセスを使い、手札・エネルギー・山札・ターン終了だけを隠す。
行動順、HPバー、弱点のアイコン、スキル名とターンの帯、ダメージの数字は戦闘と同じく出る。
敵の動きは、戦闘画面のモックの処理（`BattleInspectView`）をそのまま呼び出して再生する。
そのため、モックの敵の行動や被弾の処理を直すと、このシーンにも同じ変更が出る。
[スキルのデバッグルーム](#スキルのデバッグルーム)は演出だけを再生し、当たった敵の反応を出さない。このシーンは、敵の側の動きと反応を確かめるためのものである。

画面の下に2段の操作盤を置き、上の段で敵を、下の段で行動を選ぶ。
選んだ敵の頭の上には、カードで対象を選ぶときと同じ▼のカーソルを出す。
行動のボタンを押すと、選んだ敵がすぐにその行動をする。
操作盤の板とボタンも[すりガラスのカード](#すりガラスのカード)にし、最後に押した行動を金の縁と光で示す。

| 操作 | 動作 |
|---|---|
| 敵の表示 | 選んでいる敵の名前、攻撃の名前と威力、HP（現在/最大）、付いている状態 |
| 前の敵・次の敵 | 選ぶ敵を、画面の左から苔スライム・苔むした狼・森の守り手の順に切り替える |
| くり返し | 入にすると、最後に押した行動を、終わるたびに0.8秒おいて再生し続ける。毎回「元に戻す」と同じ状態に戻してから再生するため、どの回も同じ状態から始まる |
| 元に戻す | 敵と味方を開始時のHPに戻し、状態とブロックを消し、弱点の開示を開始時に戻す（狼の氷と守り手の炎だけが開示済み） |
| 攻撃 | 敵のターンと同じ攻撃。1歩前に出てスキル名を出し、立っている味方1人をランダムに選んで攻撃し、戻る |
| 被弾 | 最大HPの10%のダメージを受ける。白く光り、赤くなって揺れ、数字が浮かび、HPバーが減る |
| 弱点に被弾 | 同じダメージを、まだ開示していない弱点（なければ1つ目の弱点）の属性で受ける。ダメージは弱点の倍率を掛けた値で、弱点の数字で表示する。未開示の弱点は光って開示する |
| 撃破 | 残りのHPと同じダメージを受けて崩れて消え、行動順から消える。守り手はボスとして長く重く崩れる |
| 凍結中に攻撃 | 凍結を付けてから攻撃させる。「凍結で動けない」と出て行動せず、凍結が消える |
| 麻痺中に攻撃 | 麻痺を付けてから攻撃させる。威力が25%下がる。麻痺は、元に戻すか、敵のターンを重ねて持続ターンが尽きるまで残る |
| 出血中に攻撃 | 出血を付けてから攻撃させる。行動のあとに出血のダメージを受ける |
| 反射に攻撃 | 立っている味方全員に反射を付けてから攻撃させる。攻撃は敵自身へはね返る。使われなかった反射は、攻撃のあとに外す |
| 敵のターン | 戦闘と同じ敵のターン。「敵のターン」の帯を出し、行動順で次の味方のターンまでの敵が順に行動してから、次の味方のターンを始める |

付ける状態の持続ターンと威力は、その状態を付けるスキルの定義（`CardSkills`）から取る。
このシーンではカードの使い手が決まらないため、威力の元になるステータスが最も高い味方が付けたものとする（出血はアリアの物攻から決まる）。
倒れた敵を選んで行動させると、その敵のHPを戻してから行動させる。味方が全員倒れているときも、味方を戻してから行動させる。
行動中は操作盤のボタンを押せない。くり返しの間だけは行動のボタンを押せ、次の回から再生する行動が切り替わる。

選んだ敵・行動・くり返しの設定は、このPCの `PlayerPrefs` に残る。
敵の処理を直してPlayし直すと、同じ敵と行動から確かめられる。くり返しを入にしたまま終えると、次のPlayの開始時から再生を始める。
操作盤のボタンは、指で押せる高さ（設計上128）にした。

今の敵の行動は、戦闘画面のモックの仮の動き（敵ごとに単体攻撃が1種類）だけである。
敵の行動と予告、激化の内容は[未決](combat.md#未決事項)であり、敵の行動を作ったときは、このシーンの行動の種類も合わせて増やす。

シーンは `Baryonyx > App > Create Enemy Lab Scene` で作り直す。
操作盤のPrefabは `Features/Combat/UI/EnemyLabPanel.prefab` で、戦闘画面のPrefab `BattleInspectScreen` はモックと共用する。
[ホーム](#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](showcase.md)のシーン一覧から開く。

| 魔物が現れた | 敵が自分の場所の右奥から暗い影のまま1体ずつ歩み出て、光の中に入るにつれて色が戻り、着地で土煙と床の輪を出す。そろったら赤い帯で「魔物が現れた！」、続けて「味方のターン　ターン1」を出す |
| 強敵が現れた | ほかの敵がそろったあと、景色を暗くしてからボス（森の守り手）が遅く重く歩み出る。着地で土煙を多く上げ、床に赤い光を広げ、画面を揺らす。帯は「強敵が現れた！」 |
| 味方のターン・連続ターン | 戦闘と同じターンの帯（「味方のターン　ターン1」「連続！ もう一度 味方のターン」） |
| 敵のターン | 戦闘と同じ敵のターン。帯を出し、行動順で次の味方のターンまでの敵が順に行動する |
| エネルギー不足 | スキル名の帯に、戦闘と同じ赤で「エネルギー不足」を出す |
| 勝利 | 立っている敵が0.18秒ずつずれて崩れて消え、少し間をおいて金の帯で「勝利！」を出す。味方は足元に金の光だまりを置いて照らされ、2回跳ねて喜び、間から光の粒が立ちのぼる |
| ドロップ | 最後に倒した敵から光の玉が飛び出して手前の床へ落ち、2回弾む。床から少し浮いて力をためてから弾け、手に入れた物の札を出す（下記）。敵が立っていれば、先に消してから落とす |
| 勝利→ドロップ | 勝利のあとにドロップを続けて再生する。戦闘の終わりの流れを通して見るためのもの |
| 全滅 | 立っている味方が0.16秒ずつずれて被弾して倒れ、景色が暗くなって灰色の帯で「全滅してしまった…」を出す |
| ルーン復活 | 倒れた味方の足元から淡い青の光の柱が立ち、灰色から元の色に戻ってHPが満ちる（回復の数字を出す）。青の帯で「復活！」、続けて「味方のターン」を出す。味方が立っていれば、先に倒れた状態にしてから再生する |
| ドロップ：S | 次のドロップの品質を、C・B・A・S・なし（何も見つからなかった）の順に切り替える |
| くり返し | 入にすると、選んだ演出を、終わるたびに1秒おいて再生し続ける |
| 元に戻す | 敵と味方を開始時のHPと場所に戻し、帯と暗さとエフェクトを消す |
| 探索の演出へ | [探索の演出デバッグルーム](#探索の演出デバッグルーム)のシーンへ移る |

ドロップの光は、品質が高いほど大きく長くする。
光の玉と柱は品質の色（[品質](inventory.md#品質)の文字と同じ。Sは金、Aは紫、Bは青、Cは灰）で描く。

| 品質 | 力をためる間 | 弾けたとき |
|---|---|---|
| C | 0.08秒。すぐ弾ける | 白い光と床の輪だけで、柱は立たない |
| B | 0.2秒。光の粒が引き寄せられる | 細い光の柱と光芒 |
| A | 0.45秒。景色が暗くなり、床に魔法陣が開く | 高い柱、2重の床の輪、まわりへの光、画面の小さな揺れ |
| S | 0.75秒。Aより暗くなり、引き寄せる粒も多い | 太く高い柱、多くの光の粒、柔らかな画面の閃光と揺れ |

手に入れた物の札は、画面の上寄りの中央（味方の頭より上）に、弾けるのと同時にばねのように開く。
左にアイコン（品質S・Aは持ち物と同じキラキラを重ねる）、右に種類（今の見本は「ACTボーナス」）、名前、「持ち物に加えました」を書き、右上に品質の文字が大きく落ちてくる。
札は[探索の演出デバッグルーム](#探索の演出デバッグルーム)の宝箱と[冒険の戦闘](#冒険の画面)のドロップと共用する部品（`Shared/UI/Reward/RewardReveal`）である。
札の縁は品質の色にする。
何も見つからなかったときは、光を出さずに札だけを開いて「何も見つからなかった」と書く。
札は次の演出を始めるか、元に戻すまで残る。
ドロップの中身は、ACTボーナスの仮データの先頭6つを順に使う見本で、品質だけを操作盤で選ぶ。

PlayModeにすると、前回選んだ演出を再生する（初回は「魔物が現れた」）。
選んだ演出・ドロップの品質・くり返しの設定は、このPCの `PlayerPrefs`（`Baryonyx.BattleMomentLab.Moment`・`Quality`・`Repeat`）に残る。
演出のコードを直してPlayし直すと、同じ演出から確かめられる。
演出の再生中は操作盤のボタンを押せない。くり返しの間だけは演出のボタンを押せ、次の回から再生する演出が切り替わる。
ドロップとルーン復活は、それぞれの前の状態（敵が消えた状態、味方が倒れた状態）から始める。ほかの演出は、毎回元に戻してから再生する。

出現・勝利・ドロップ・全滅・復活の演出は、[冒険の戦闘](#冒険の画面)でも同じ処理（`BattleInspectView`）で再生する。
冒険の戦闘は、出現（最奥の間では強敵の出現）の演出のあとに手札を配り、勝利の演出、部屋のドロップを1つずつ、全滅の演出のあとにダイアログを出し、ルーンで復活すると復活の演出を再生する。
このシーンで演出を直すと、冒険の戦闘にも同じ変更が出る。

シーンは `Baryonyx > App > Create Battle Moment Lab Scene` で作り直す。
操作盤とドロップの札のPrefabは `Features/Combat/UI/BattleMomentLabPanel.prefab` で、`Baryonyx > Combat > Create Battle Moment Lab Assets` で作り直す。
操作盤のPrefabを作り直したあとは、シーンも作り直す（Prefabの部品のIDが振り直され、シーンに残った古い上書きが札の配置を崩すため）。
[ホーム](#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](showcase.md)のシーン一覧から開く。

## 探索の演出デバッグルーム

`ExplorationMomentLab.unity` は、[探索](#冒険の画面)の節目の演出（魔物の部屋に入ったときの出現、宝箱を開ける、部屋へ進む）を確かめるデバッグ用のシーンである（2026-10-20、ユーザーの依頼「Explorationの各種 魔物が現れた！みたいなやつも入ります」）。
[戦闘の演出デバッグルーム](#戦闘の演出デバッグルーム)と対になり、互いのシーンへ移るボタンを置く。

画面は探索画面のPrefabを、冒険の流れ（`ExplorationBootstrap`）を置かずに使う。
探索画面は見本の道（展示室と同じ種）を入口から描き、冒険の状態もサーバーも読まない。
地図の下側にパーティが立つため、操作盤の2段は画面の上（行き先と階の文字の下）に置く。

| 操作 | 演出 |
|---|---|
| 魔物が現れた | パーティが驚いて小さく跳ね、頭の上に太い「！」がばねのように現れて上下し、地図が少し揺れる。続けて、戦闘のターンの帯と同じ形の赤い帯で「魔物が現れた！」を出し、画面の端から横長の黒い帯が左右交互に閉じる。冒険では、閉じたところで戦闘のシーンへ移る。このシーンでは、閉じたあと帯が開いて地図へ戻る |
| 強い魔物が現れた | 「！」と帯を明るい赤にし、「！」を大きく、地図を強く揺らす。帯は「強い魔物が現れた！」 |
| 最奥の主が現れた | 先に地図を紫がかった暗さにしてから、紫の「！」と帯で「最奥の主が現れた！」を出す。閉じる帯も紫がかった黒にする |
| 宝箱を開ける | パーティのいる部屋の右手前に閉じた宝箱を置き、選んだ品質の中身で開ける（下記） |
| 部屋へ進む | 入口から次の階の最初の部屋へ、パーティが道を歩き、着いてから新しく見えた部屋の印が現れる。探索で部屋を選んだときと同じ動き |
| 宝箱：S | 次の宝箱の品質を、C・B・A・S・なし（何も見つからなかった）の順に切り替える |
| くり返し・元に戻す | 戦闘の演出デバッグルームと同じ。元に戻すと、見本の道の入口に戻り、宝箱と演出の部品を消す |
| 戦闘の演出へ | 戦闘の演出デバッグルームのシーンへ移る |

宝箱は、品質が高いほど長く震えてから開く（C 0.35秒、B 0.5秒、A 0.75秒、S 1.1秒）。
震える間、宝箱の後ろに品質の色の光がふくらみ、Aからは光芒が回り始め、景色が暗くなる（Sのほうが暗い）。
開くと、白い光が弾けてから品質の色の光と光芒（Bから）が広がり、光の粒が飛び上がって落ちる。Sは宝箱から画面いっぱいに光が広がる。
同時に、戦闘のドロップと同じ札で中身を見せる。何も見つからなかったときは、小さな光だけで札に「何も見つからなかった」と書く。
光は、画像を使わずにシェーダー（`Features/Adventure/Vfx/ExplorationLight.shader`。丸い光・光芒・きらめきの3つの形）で計算して描く。
探索画面はポストプロセスを通らない画面（Screen Space - Overlay）のため、Bloomのにじみはなく、光は加算で重ねる。

PlayModeにすると、前回選んだ演出を再生する（初回は「魔物が現れた」）。
選んだ演出・宝箱の品質・くり返しの設定は、このPCの `PlayerPrefs`（`Baryonyx.ExplorationMomentLab.Moment`・`Quality`・`Repeat`）に残る。
どの演出も、毎回見本の道の入口に戻してから再生する。

これらの演出は、まだ冒険の探索に組み込んでいない。
冒険では今も、魔物の部屋に着くと下の案内に「魔物が現れた！」と出して0.9秒後に戦闘へ移り、宝箱は絵が開いて「宝箱を開けた！」のダイアログを出す。
強い魔物と最奥の主の帯の文（「強い魔物が現れた！」「最奥の主が現れた！」）は、このシーンで仮に決めた。

シーンは `Baryonyx > App > Create Exploration Moment Lab Scene` で作り直す。
操作盤と演出の部品のPrefabは `Features/Adventure/UI/ExplorationMomentLabPanel.prefab` で、`Baryonyx > Adventure > Create Exploration Moment Lab Assets` で作り直す。作り直したあとは、シーンも作り直す。
[ホーム](#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](showcase.md)のシーン一覧から開く。

所持ルーンは、Homeや編成の画面がサーバーから読んだ最新の残高を表示し、案内人の画面を開くたびにサーバーから読み直す。
育成でルーンを使うと、その場で数を減らす。

展示室のプレビューで育成の個別の画面を開いたときは、育成の仮データの所持ルーンを出す。

メニューの行・リストの行・決定ボタンは、編成の冒険者の一覧と同じ[すりガラスのカード](#すりガラスのカード)にする。リストの行は文字が左上から始まるため模様を付けない。決定ボタン（「買う」「召喚する」「出発」など）は、模様を付けず、個別の画面の「レベルアップ」と同じ金の縁と光を常に出す。

一覧の内容はすべて仮データであり、キャラ・装備・召喚の方式・地名は確定していない。
召喚の確率は表示しない（[ガチャと課金](monetization.md#法務メモ)）。

### 停止中の確認

項目のパネル（冒険者の一覧・個別の画面・装備やスキルの付け替えなど）は、生成時に仮データでPrefabへ作り込んであるが、どれを出すかはPlay Mode中に案内人の画面が切り替える。
停止中は、`Pub` などのシーンで案内人の画面（`PubScreen` など、`GuideMenuView` を持つオブジェクト）を選び、Inspectorのボタンで各項目を開いた見た目へ切り替える（[停止中の表示の切り替え](#停止中の表示の切り替え)）。
押した項目を開いたときと同じ処理で、パネル・枠・パンくずが切り替わる。

### 枠つきの表示

項目のパネルのうち画面いっぱいを使うもの（[冒険者の一覧](#パーティ)・[冒険者を選ぶ画面](#装備の人選び)・[個別の画面](#育成)・[装備](#装備)と[スキル](#スキル)の付け替え）を開いている間は、案内人の画面を次の形にする（`GuideFramedPanel`）。
商会・神殿のリストと旅の案内所の行き先も、同じ形にする。
これらは案内人を左に残し（ぼかした背景の上に立たせる）、案内人の右（設計座標で横848）に金の2本線を引き、その右に透ける面を置く。
編成・商会・神殿のメニューでは、枠を出さない。
ほかの画面でも同じ見た目にするため、部品は共通にする（[実装との対応](#実装との対応)）。

| 部分 | 表示 |
|---|---|
| 背景 | 背景の絵をぼかした写しを重ねる |
| ヘッダー | 上端から高さ112pxの暗い透ける帯。「もどる」と×のタブ、所持ルーンの下地は消し、「もどる」・パンくず・所持ルーン・×の間に金の細い縦線を引く（端に飾りは付けない） |
| ヘッダーの下 | 左右48pxを空けた金の細い線。両端に小さな金のひし形 |
| 面 | パネルが、左（人やパーティ）と右（一覧や詳細）に酒場が透ける同じ色の面を置き、左右と下は画面の端まで延ばす。ヘッダーの帯は面より濃くする。面の間は金の2本線で区切り、ヘッダーの線と交わる所に大きなひし形を置く。16:9より縦長の画面では面と中身を縮めるが、ヘッダーの線を基準に縮め、線と面の上端の間に背景をのぞかせない |
| 見出し | 金のひし形と明るい金の文字（「パーティ」「一覧」など）。見出しの下に線は引かない |

四隅の飾りは置かない（ユーザーの判断）。

枠つきの表示の上に重ねる画面（[レベルアップ](#育成)と、探索・戦闘の[確認のダイアログ](#冒険の画面)）は、ヘッダーの帯と同じ濃い紺で不透明に塗った窓に、金の細い線の縁と四隅の小さな金のひし形を付け、見出しは面の見出しと同じ金のひし形と明るい金の文字にする（レベルアップには見出しを置かない）。
中のボタン（－・＋・最大・やめる）は模様のないすりガラスのカードにし、決める「レベルアップ」は模様のない金の縁と光のカードにする。
窓を少しでも透かすと、リニア色空間の画面では後ろの文字が読めるほど透けたため、窓は不透明にした。

### すりガラスのカード

押す・長押しするものを並べる共通のカード（`GlassCard`）。

| 部分 | 表示 |
|---|---|
| 地 | うすく透ける角丸（半径22px）の板と、下へずらしたやわらかい影 |
| 縁 | 白い細い縁。左上から光が当たったように、上と左を明るく、下と右を暗くする |
| 模様 | 左上の角から広がり、角から離れるほど消える、ばら窓の4分の1（同心の弧・放射の線・小さな円）を淡い金で描く |
| 選んだとき | 金の縁と外へにじむ金の光、地をうすく金色にする |
| 押したとき | 板が少し沈み、影が縮む。0.5秒押し続けると長押しになり、指を離しても押したことにしない。一覧を動かし始めると取り消す |
| 点線のカード | 空きや「パーティから外す」「外す」のような操作と、アクセサリーの枠は、点線の縁で模様と影を付けない |

模様は、人のカードのように大きなものに付ける。
案内人の画面のメニューの行は、左のアイコンと模様が重なるため、ユーザーの「丸っぽい背景を消して」で付けない。
決定ボタン（リストの「買う」「召喚する」「出発」、レベルアップの画面の「レベルアップ」）には、ユーザーの「Submitボタンにマークは不要」で付けない。
装備の枠・付け替えの一覧の行・固有スキルの行・ボーナスの枠と行のような小さなものは、ユーザーの判断で模様を付けない。
文字が左上から始まる行（商会・神殿のリスト、旅の案内所の行き先）も、文字が読みにくくなるため模様を付けない。
押せない箱（固有スキル・準備中の枠）は、同じ見た目で押せない板にする。

画面の枠とカードは、[枠つきの表示](#枠つきの表示)（重ねる窓を含む）とこのカードの2つだけにする。案内人の画面のほか、ホームの行き先カード、探索の下の案内の帯と右下の凡例、確認のダイアログの選択肢、ボーナス設定の段階とランクの小さな板、デバッグルームのボタンもこのカードにする。透ける面を通さず景色の上に直に置くもの（探索の帯と凡例、デバッグルームのボタン）は、文字が景色に負けないよう、板を面と同じ紺で濃く敷く。段階・ランクのように色で見分ける板は、白い縁をその色にする。2026-10-18に、ドット絵の枠（`GuideFrame`）と角丸の板・輪（`RoundedRect`・`RoundedRing`）を画像とコードごと削除した。新しい枠や板の形は作らず、この2つを使う。


### パーティ

編成のメニューの「冒険者」で、冒険者の一覧を開く。
パーティの入れ替えはこの一覧で行い、1人の装備・スキル・育成は、カードの長押しで開く[個別の画面](#育成)で行う。
開いている間は左の看板娘を隠し、[枠つきの表示](#枠つきの表示)で画面いっぱいに使う。
左右の余白は置かず、左（パーティ）と右（一覧）を金の2本線で区切る。

| 面 | 表示と操作 |
|---|---|
| 左（パーティ） | 透ける面に見出し「パーティ」と、4つの枠のカードを縦に並べる |
| 右（一覧） | 左と同じ透ける面に見出し「一覧」と、パーティにいない持っているキャラのカード（持っている順）を2列で並べ、最後に「パーティから外す」を置く。縦にスクロールする |

カードは[共通のすりガラスのカード](#すりガラスのカード)を使う。
人のカードには、左に立ち姿（周りの余白を切った48×52を4倍）と足元の影、右に名前、その下に「Lv」とLv、付けているスキルの属性のアイコン（12×12を3倍）を出す。
空いたパーティの枠のカードには「空き」とだけ書く。
「パーティから外す」は点線のカードに×と文字で、外せる人を選んでいないときは薄く出す。
「所持 〇人」「控え」の見出し、決定ボタンや変化を説明する文は置かない。

| 操作 | 結果 |
|---|---|
| パーティの枠を押す | その枠を選んで金の縁と光で囲む。空いた枠も選べる。もう一度押すか、別の枠を押すと選び直す |
| 一覧の人を押す | その人を選ぶ。もう一度押すとやめる |
| 枠を選んで一覧の人を押す（逆の順でもよい） | その枠の人と入れ替える。空いた枠なら入れる。入れ替えたあとは何も選んでいない状態に戻る |
| 枠を選んで「パーティから外す」 | 枠を空きにし、外した人は一覧に移る。最後の1人は外せず「パーティには1人以上必要です」と知らせる（1人以上を残す決まりは仮である）。枠を選んでいないか、空いた枠を選んでいるときは「外す人をパーティから選んでください」と知らせる |
| カードを長押し（0.5秒） | その人の個別の画面を開く。押している間はカードが少し沈み、一覧を動かし始めると取り消す |

入れ替え・編成・外したことは、カードを見ればわかるため通知しない。
開いたときは何も選んでいない。

持っているキャラと編成は、開くたびにサーバーから読み、入れ替えはすぐ画面に出してから裏でサーバーに保存する（[キャラと編成の保存](party.md#キャラと編成の保存)）。保存できなかったときは元に戻して通知の帯で知らせる。
付けている武器・防具は、装備の機能から読む（[装備の保存](equipment.md#持っている装備と付け替えの保存)）。
読み込むまでは一覧の面に「読み込み中…」を出し、パーティの枠と一覧を空けて仮データの中身を見せない。
読めなかったときは「編成を取得できませんでした」、保存できなかったときは「編成を保存できませんでした」を通知の帯で知らせ、枠は変えない。
保存を待つ間は、続けて押しても受け付けない。
サーバーの接続先がないとき（展示室のプレビューなど）だけ、仮データの4人（トーマ・ルカ・アリア・ミナ）から始め、変更はアプリを動かしている間だけ残す。
ホームに立つ4人と戦闘画面のモックの4人には、編成をまだ反映しない。
Lvは[育成](#育成)で上げたLvを、属性のアイコンは[スキル](#スキル)で付け替えたスキルを出し、開くたびに読み直す。
キャラと、Lv・スキルの初期値は仮データで、スキルは戦闘画面のモックのものから選んだ。
絵のある4人は戦闘画面のドット絵を使う。
絵のない5人（アンセルム・グレタ・ルッツ・リタ・リツ）は、4人の絵に色を掛けて左右を反転した仮の絵で見分ける。

### 育成

冒険者の一覧でカードを長押しすると、その人の個別の画面を開く。
メニューには出さない項目（`Hidden`）で、ほかの画面からだけ開く。
開いている間は左の看板娘を隠し、[枠つきの表示](#枠つきの表示)で画面いっぱいに使う。
左の面（横640まで）にイラスト、金の2本線の右の透ける面に詳細を置く。
見出し（パッシブ・固有スキル・カスタムスキル・装備）は金のひし形と明るい金の文字にする。

| 区画 | 表示と操作 |
|---|---|
| 左（イラスト） | 縦長の背景付きのイラストを、枠を付けずに左の面いっぱいに敷き（面の大きさに合わせて端を切る）、右端を面の色へなじませる。その右下に戦闘のドット絵（64×64を4倍）を足元の暗いぼかしと影の上に立たせる |
| 右上 | 名前、Lvと使えるスキルの属性のアイコン（12×12を4倍）。右端に「レベルアップ」（模様のない[すりガラスのカード](#すりガラスのカード)に、選んだときと同じ金の縁と光。1レベル上げるのに要るルーンを添える） |
| 右（キャラ自身） | 左にステータス8つ（2列4行。HP・物攻、属攻・速度、会心・物防、属防・幸運）、右に見出し「パッシブ」（板は置かない）。パッシブ2つを1行ずつ、アイコン・名前・効果で出し、未解放のものはアイコンを暗くして錠前を重ね、名前の行の右に「Lv 15で解放」を出す |
| 右（デッキの4枚） | 左に「固有スキル」2枚、縦の線を挟んで右に「カスタムスキル（スキルかアイテム）」2枚。どれも戦闘のカードと同じ組み方（70×98ドットを3倍）で、属性の枠・挿絵・左上のコスト・右上の属性・種類と名前と「攻撃・敵単体」の行・効果を出す。効果の威力はステータスの割合（「属攻の100%」）で書き、その人のステータスは入れない（[カードの数値の見せ方](combat.md#カードの数値の見せ方)）。固有スキルは、[スキルの付け替え](#スキル)でセットしている進化の段階のカードを出す（[固有スキルの進化](skill-evolution.md)）。未解放の固有スキルはカード全体を暗くして、錠前と「Lv 20で解放」を重ねる |
| 右（装備） | 武器・防具・アクセサリー1〜3の5枠を同じ大きさの模様のないすりガラスのカードで並べる（準備中のアクセサリーは点線）。各枠に、アイコン・枠の名前・☆の数と品質の文字、装備の名前と倍率を掛けた効果を出す。品質がS・Aの装備は、アイコンに種類ごとの光り方の[キラキラ](../art/direction.md#カードのキラキラ)を重ねる |

画面の上で指を左へ動かす（フリックする）と次のキャラ、右へ動かすと前のキャラに替わる。
パーティの枠の順、続けて控えを持っている順に1人ずつ替え、端から反対の端へ回る。
横へ120（設計座標）以上動かし、縦の動きより大きいときだけ替える。
イラスト・枠・カードのどこから動かしてもよく、動かし始めるとカードや枠のタップは取り消す。
レベルアップの画面を重ねている間は替えない。
どこを動かせるかを示す手がかりは、ユーザーの判断で置かない。
最後に見ていたキャラは、一覧・付け替えの画面と共有し、アプリを動かしている間は開き直しても残る。

武器・防具の枠を押すと、その人とその枠を選んだ[装備の付け替え](#装備)を開く。
カスタムスキルのカードを押すと、その人とその枠を選んだ[スキルの付け替え](#スキル)を開く。
固有スキルのカードを押すと、その人とその固有スキルを選び、右に[進化ツリー](skill-evolution.md)を出した[スキル](#スキル)の付け替えの画面を開く。未解放の固有スキルも開き、ツリーだけを見られる。
付け替えの画面で「もどる」か端末の戻るキーを押すと、この画面へ同じ人のまま戻る。
アクセサリーの3枠は、Lvで開くまで錠前と解放するLv（「Lv 15で解放」）を出し、開いたら「なし」と出す。[アクセサリー](equipment.md#アクセサリー)の決まりがまだなく、まだ持てないためである。どの枠も押すと、[装備](#装備)の付け替えの画面をアクセサリーのタブで開く。

「レベルアップ」を押すと、詳細の上にレベルアップの画面を重ねて開く。
背面は暗くして押せなくする。
重ねた画面は、[枠つきの表示の上に重ねる窓](#枠つきの表示)にし、画面の中央に1列で並べる。
見出し・キャラの名前・覚えるスキル・次の解放・所持ルーンと残りは出さない（ユーザーの判断）。

| 部分 | 表示と操作 |
|---|---|
| 上 | 今のLvと上げたあとのLv |
| 上げる数 | 「－」「＋」で1ずつ変え、「最大」で所持ルーンで上げられるだけにする。上限のLvは超えない。1つも上げられないときは1のままにして、足りない量を見せる |
| 中 | ステータス8つの、上げる前・上げたあと・増える量（1行の高さ42、窓の幅いっぱい） |
| 下 | 左に使うルーン（右上の所持ルーンと同じ48pxのアイコンと、ステータスの数字と同じ34ptの文字）、右に「やめる」と「レベルアップ」。ルーンが足りないときは使うルーンを赤にし、「レベルアップ」を押せなくする。「やめる」で閉じる |

重ねた画面の「レベルアップ」を押すと、ルーンを使ってレベルを上げ、重ねた画面を閉じる。
上げたことは「トーマが Lv 13 になりました」「トーマが Lv 15 になり、「炎の心得」を覚えました」を[共通の通知の帯](../rules/ui-design.md#操作を求めない通知)で知らせる。
「もどる」と端末の戻るキーは、重ねた画面を開いているあいだはそれだけを閉じ、個別の画面では開いた入口（冒険者の一覧など）へ戻る。
案内人の画面は、戻る操作を、開いている項目のパネルに先に渡す（`IGuideBackHandler`）。

キャラのLv・スキルと所持ルーン、付けている武器・防具は、開くたびにサーバーから読む（[キャラと編成の保存](party.md#キャラと編成の保存)、[装備の保存](equipment.md#持っている装備と付け替えの保存)）。
読み込むまでは名前の位置に「読み込み中…」を出し、ボタンを押せなくして仮データの中身を見せない。
読めなかったときは「キャラを取得できませんでした」を通知の帯で知らせる。
重ねた画面の「レベルアップ」を押すと、保存を待たずに重ねた画面を閉じ、上げたLvと、要るルーンを引いた所持ルーンを出して知らせる。
そのあとで、サーバーが要るルーンを計算し、残高から引いてレベルを上げる。保存を待つ間も、続けてレベルアップできる。
保存を待つ間に右上の所持ルーンを読み直しても、先に引いた分は引いたまま出すので、ホームへ戻っても同じ値を表示する。
保存できなかったときはLvと所持ルーンを戻し、「レベルアップできませんでした」を通知の帯で知らせる。サーバーに断られたとき（別の端末で上げていたなど）は、Lvと所持ルーンを読み直して描き直す。
サーバーの接続先がないとき（展示室のプレビューなど）だけ、仮データのLvと所持ルーン8,450から始め、使ったルーンと上げたLvはアプリを動かしている間だけ残す。

イラストは、Codex CLIで描いた下書き（1024×1536）を `Shared/Art/Characters/Illustrations/<キャラのID>.png` に置き、ぼかして縮める画像として取り込む（Bilinear・ミップマップあり・高品質の圧縮）。
9人ともあり、トーマ・ルカ・アリア・ミナ・リタ・リツの6人は、キャラ設定を作らずに、役割と戦闘のドット絵（4人）から依頼文を作って描いた（依頼文は `output/characters/<キャラID>/illustration-request.md`）。
イラストのないキャラは、枠の中を空けてドット絵だけを出す。
ステータスの伸び、固有スキル・パッシブの名前・効果・解放するLvは仮データである。
要るルーン（Lv n から n+1 へ n×100）と上限（Lv 30）も仮の値で、サーバーの値を使う。
ステータスは、9人それぞれのLv100の値に、Lvに応じた成長率を掛けて出す（[自キャラのLv100のステータス](progression.md#自キャラのlv100のステータス)）。
絵のない5人は、絵を借りたキャラと同じ固有スキル・パッシブにした。
固有スキル・パッシブの絵はまだないため、スキルの挿絵（64×58）の中央24×24ドットを仮のアイコンにしている（戦闘画面のモックの画像を借りている）。
4:3など横幅の狭い画面では、個別の画面とレベルアップの画面を同じ割合で縮める（`WorldLayerFit`）。

画面は `Baryonyx > Tavern > Create Screen Assets` で作り直す。
仮データは `Features/Training/Data/TrainingMockData.asset` で、生成の処理（`TrainingAssets`）が毎回上書きする。

### 装備の人選び

編成のメニューの「装備」（冒険者とボーナスの間）を押すと、冒険者を選ぶ画面を開く。
開いている間は左の看板娘を隠し、冒険者の一覧と同じ枠（ぼかした背景・ヘッダーの帯）の中に、見出し「冒険者を選ぶ」と、持っている全員のカードを3列で並べる。
パンくずは「編成 › 装備」である。

| 場所 | 内容 |
|---|---|
| カード | 冒険者の一覧と同じすりガラスのカード。左に立ち姿（周りの余白を切った48×52を4倍）と足元の影、右に名前、「Lv」とLv、パーティにいる人だけ金の「パーティ」の札、付けている武器・防具の種類のアイコン（24×24を2倍）と名前。付けていない枠は「なし」と書き、アイコンを薄くする |
| 並び | パーティの4枠の順、続けて控えを持っている順。9人は3行で、スクロールせずに収まる |

カードを押すと、その人の[個別の画面](#育成)を開き、そこで武器・防具の枠から[装備](#装備)の付け替えへ進む。
この入口から開いた個別の画面と付け替えの画面は、パンくずを「編成 › 装備 › アリア」「編成 › 装備 › アリア › 装備」とし、個別の画面の「もどる」でこの画面へ戻る。
冒険者の一覧から開いたときは、これまでどおり「冒険者」と出し、一覧へ戻る。

編成と付けている装備は、開くたびにサーバーから読む（[キャラと編成の保存](party.md#キャラと編成の保存)、[装備の保存](equipment.md#持っている装備と付け替えの保存)）。
読み込むまでは「読み込み中…」を出してカードを隠し、読めなかったときは「取得できませんでした」と「編成を取得できませんでした」の通知を出す。
サーバーの接続先がないときは、仮データの編成と、アプリを動かしている間だけの装備（`EquipmentLocalSource`）を使う。

### 装備

[個別の画面](#育成)で武器か防具の枠を押すと、その人とその枠を選んだ装備の付け替えの画面を開く。
メニューには出さない項目（`Hidden`）である。
開いている間は左の看板娘を隠し、[枠つきの表示](#枠つきの表示)で、左の透ける面（横800まで）に人と枠、金の2本線の右の透ける面に持っている装備を置く。
枠と装備の行は模様のない[すりガラスのカード](#すりガラスのカード)で、アクセサリーの枠と「外す」は点線にする。

| 面 | 表示と操作 |
|---|---|
| 左上（人） | 戦闘のドット絵（64×64を2倍）、名前とLvと属性のアイコン。◀▶は置かず、左の面の上で指を左へ動かす（フリックする）と次の人、右へ動かすと前の人に替える。選んでいる枠のまま、パーティの枠の順、続けて控えを持っている順に替え、端から反対の端へ回る。フリックの決まりは[個別の画面](#育成)と同じ |
| 左（人の下） | 選んでいる人のステータス8つ（4列2行）。その下に線を引いて枠と分ける |
| 左（5つの枠） | 「武器」「防具」の枠と、アクセサリーの3枠を、面の下端まで縦に並べる。武器・防具の枠には、種類のアイコン（24×24を3倍）、枠の名前、装備の名前、右端にレア度の★を出す。空いた枠は「なし」と書き、アイコンを薄くする。品質がS・Aの装備は、アイコンに種類ごとの光り方の[キラキラ](../art/direction.md#カードのキラキラ)を重ねる。押した枠を金の枠で囲む。アクセサリーの枠は点線で、開くまで錠前と「Lv 15で解放」、開いたら「なし」を出す。押すとアクセサリーのタブに移る |
| 右（タブと一覧） | 上に、面の幅いっぱいに「武器」「防具」「アクセサリー」のタブ。選んでいるタブは明るい金の文字と金の下線。タブは左の枠と連動し、左で防具の枠を押すと防具のタブ、タブで防具を押すと左の防具の枠を選ぶ。アクセサリーのタブは、選んでいたアクセサリーの枠（なければ1つ目）を選ぶ。アクセサリーはまだ持てないため、一覧は空にして「外す」も出さず、選んだ枠が開いていなければ解放するLv、開いていれば「持っているアクセサリーはありません」とだけ出す。所持数は出さない。持っているその種類の装備を1つ1行で、レア度の高い順（同じなら仮データの順、続けて倍率の高い順、入手の順）に並べる。行には種類のアイコン（品質がS・Aなら[キラキラ](../art/direction.md#カードのキラキラ)を重ねる）、名前、★と[品質](inventory.md#品質)の文字（品質の色）、倍率を掛けた効果を置き、右上に、選んでいる人が付けていれば「装備中」、ほかの人なら「アリアが装備中」と出す。最後に「外す」の行を置き、選んでいる枠が空いている間は暗くして押せなくする |

左で枠を押してから右の装備を押すと、その場でその枠に付ける。
ほかの人が付けている装備を押した場合は、その人から外して付け替え、その人の枠は空きになる。
「外す」を押すと、選んでいる枠の装備を外す。外した装備は持ち物に残る。
決定ボタンは置かない。
付け替え・外したことは、枠と一覧を見ればわかるため通知しない。
「もどる」と端末の戻るキーは、個別の画面へ、付け替えの画面で最後に見ていた人のまま戻る。

持っている装備と付けている装備は、開くたびにサーバーから読み、付け替えはすぐ画面に出してから裏でサーバーに保存する（[装備の保存](equipment.md#持っている装備と付け替えの保存)）。保存できなかったときは元に戻して通知の帯で知らせる。
読み込むまでは右上と名前に「読み込み中…」を出し、枠・装備の行を空けて仮データの中身を見せない。
読めなかったときは「装備を取得できませんでした」、保存できなかったときは「装備を保存できませんでした」を通知の帯で知らせ、装備は変えない。
保存を待つ間は、続けて押しても受け付けない。
サーバーの接続先がないとき（展示室のプレビューなど）は、仮データの装備から始め、サーバーと同じ決まりで付け替え、変更はアプリを動かしている間だけ残す（`EquipmentLocalSource`）。

装備の種類（武器8つ・防具6つ）の名前・レア度・効果は、装備の画面のモックの仮データを引き継いだ。
[アクセサリー](equipment.md#アクセサリー)の決まりは、まだない。装備が1つずつ持つ倍率はサーバーから読み、品質の文字と効果の数字に出す（2026-10-19）。
効果の計算はまだなく、付け替えてもステータスは変わらない。付け替えによる威力の伸びの見せ方（[装備更新と戦い方](equipment.md#戦い方を変える装備更新)）は未決である。
アイコンは装備の画面のモックの付け替え・武器・防具のアイコンを、`Features/Equipment/UI/Art/` へ移して使う。
持っている装備が作り込んだ行（8行）より多いときは、開いたときに行を写して増やす。
画面は `Baryonyx > Tavern > Create Screen Assets` で作り直す。

### スキル

メニューには出さない項目（`Hidden`）である。
左で枠を選んで右を押すと、その場で入れ替わる。
左で固有スキルを押すと、右にその[進化ツリー](skill-evolution.md#進化の段階とツリー)を出し、取得した段階を押すとその場でセットする。

左の並び順と右のタブは、[装備](#装備)の付け替えの画面に合わせる。
固有スキル・カスタムスキルの枠、カードの行、進化ツリーの段階は模様のない[すりガラスのカード](#すりガラスのカード)にし、見出し（固有スキル・カスタムスキル）は金のひし形と明るい金の文字にする。見出しに注記は付けない。

| 枠 | 表示と操作 |
|---|---|
| 左上（人） | [装備](#装備)と同じ。左の面のフリックで、選んでいる枠とタブのまま人を替える |
| 左（人の下） | 選んでいる人のステータス8つ（4列2行）。その下に線を引いて枠と分ける。位置は[装備](#装備)と同じ |
| 左（固有スキル） | 見出し「固有スキル」の下に、選んだ人の固有スキル2つを縦に並べる。行の形はカスタムスキルと同じで、セットしている進化の段階のカードの挿絵（左上にコスト、右上に属性のアイコン）、名前と「攻撃・敵全体」、説明を出す。未解放のものは挿絵を暗くして錠前を重ね、右上に「Lv 20で解放」を出す。押した行は金の枠で囲み、右に進化ツリーを出す |
| 左（カスタムスキル） | 固有スキルの下に、見出し「カスタムスキル」と、選んだ人の2枚を縦に並べる。各行に、スキルの挿絵（64×58ドットを2倍。左上にコスト、右上に属性のアイコン）、名前と「攻撃・敵単体」、説明を出す。説明の数字は、その人の今のLvのステータスから求め、ダメージは黄、回復は緑、ブロックは青にする。種類と数字の色は戦闘のカードと同じである。押した行は金の枠で囲み、右をタブと一覧に戻す |
| 右（タブと一覧） | 上に、面の幅いっぱいに「スキル」「アイテム」のタブ。見た目は[装備](#装備)のタブと同じで、選んでいるタブは明るい金の文字と金の下線。開いたときは「スキル」を選ぶ。タブは左の枠と連動しない（どちらの枠にもスキルとアイテムを入れられるため）。スキルのタブでは、タブの下に「付けられる属性」と、選んだ人が付けられる属性のアイコン、「＋属性なし」を出し、付けられるスキルを1枚1行で、コストの低い順に並べる。枚数は出さない。行は左の2枚と同じ形で、数字も選んだ人のステータスで出す。その人が付けているスキルには、右上に「1枚目」のように何枚目かを出す。アイテムはまだ持てないため、アイテムのタブでは一覧を空にして「持っているアイテムはありません」とだけ出す |
| 右（進化ツリー） | 左で固有スキルを押したとき、タブと一覧の代わりに出す。上に見出し「マナバーストの進化」、その下に7つの段階を1行ずつ縦に並べ、はみ出す分はスクロールする（一覧と同じく上下の縁で薄く消す）。並びは、最初の段階、続けて枝ごとに1段目（1段字下げ）と2段目（2段字下げ）の順である。字下げの手前に縦の線を引き、その段階のカードへ横に線を出す。各段階は左の行と同じ形で、取得した段階は同じ中身を出し、押すとその場でセットする。別の人か別の固有スキルのツリーに替えると、一番上から見せる。セットしている段階は金の枠で囲み、「セット中」を出す。取得していない段階は、名前も効果も出さず、カードの中央に「？」の封印を置いて左右へ鎖を渡した、封じた札にする（押せない）。封印と鎖は背景が透明な生成画像（`StageSeal`・`StageSealChain`、`Features/CardLoadout/UI/Art/`）で、ドット絵ではない。未解放の固有スキルのツリーは見られるが、最初の段階に錠前と「Lv 20で解放」を重ね、どの段階も押せない |

左で枠を押してから右のスキルを押すと、その場でその枠に入れる。
その人のほかの枠にあるスキルを押した場合は、2つの枠の中身を入れ替える。
同じスキルを複数の仲間が付けてもよい（仮）。
決定ボタンや変化を説明する文は置かない。
付け替え・入れ替えたことは、枠を見ればわかるため通知しない。
「もどる」と端末の戻るキーは、個別の画面へ、付け替えの画面で最後に見ていた人のまま戻る。

仲間とスキルは、開くたびにサーバーから読み、付け替えはすぐ画面に出してから裏でサーバーに保存する（[キャラと編成の保存](party.md#キャラと編成の保存)）。保存できなかったときは元に戻して通知の帯で知らせる。
読み込むまでは一覧の面と名前に「読み込み中…」を出し、固有スキル・カスタムスキル・スキルの行と付けられる属性の行を空けて仮データの中身を見せない。
固有スキルの進化の段階は、まだサーバーに保存せず、仮データ（トーマのマナバーストだけ、3つの段階を取得済み）から始めてアプリを動かしている間だけ残す（`UniqueSkillSession`）。
読めなかったときは「スキルを取得できませんでした」、保存できなかったときは「スキルを保存できませんでした」を通知の帯で知らせ、スキルは変えない。
サーバーの接続先がないとき（展示室のプレビューなど）だけ、仮データのスキルから始め、変更はアプリを動かしている間だけ残す（`PartySession`）。
[冒険者の一覧](#パーティ)と[個別の画面](#育成)は、付け替えたスキルを表示する。
スキルの効果の威力は、その人のステータスや今日のACTを入れず、ステータスの割合（「属攻の100%」）で書く（[カードの数値の見せ方](combat.md#カードの数値の見せ方)）。

仲間ごとに付けられる属性は[未決](party.md#未決事項)のため、仮データで最初に付けているスキルの属性を、その仲間が付けられる属性とした。
持っているスキルの仕組みもまだないため、スキル50枚をすべて持っているものとして扱う（仮）。
スキルを1枚ずつ持ち、1枚ごとに倍率を持つ決まりと、カスタムスキルにアイテムを入れる決まり（2026-10-06、[キャラクターの構成](party.md#キャラクターの構成)）は、まだ反映していない。
ステータスとLvは、[育成](#育成)の仮データと上げたレベルを使う。
スキルの挿絵は、戦闘画面のモックの画像（`Features/Combat/UI/Art/`）を借りている。
[ゲーム内の対象の画像](../rules/frontend-design.md#ゲーム内の対象の画像)の決まりでは `Shared/Art/Skills/` へ移すものだが、戦闘と育成の生成処理も同じ場所を読んでいるため、移すのは別の作業とする。
種類の行と説明の数字の色は、戦闘のカードと共有する `Shared/UI/Cards/CardText` で作る。

画面は `Baryonyx > Tavern > Create Screen Assets` で作り直す。
人・4枚・スキルの行は生成時にPrefabへ作り込むので、Prefabを開くと、停止中でも先頭の人のスキルが読める。

### ボーナス設定

編成のメニューの「ボーナス」で、[ACTボーナス](step-bonus.md)の枠にボーナスを入れる。

開いている間は左の看板娘を隠し、編成のほかの画面と同じ[枠つきの表示](#枠つきの表示)で画面いっぱいに使う。
左の透ける面（横800まで）に今日の効果、金の2本線の右の透ける面に持っているボーナスを置く。
枠と行は[すりガラスのカード](#すりガラスのカード)（左上の模様なし）にする。

| 区画 | 表示と操作 |
|---|---|
| 左「今日の効果」 | 見出しの下に、5つの枠のカードを面の下端まで縦に並べる。各カードに、縁を段階の色にした小さなすりガラスの板（中に24×24のアイコンを4倍で、縁と重ならないよう置く）、段階のACTと倍率（例：2,000 ACT ×1.2）、ボーナスの名前、倍率を掛けたあとの効果（例：ドロップ率 +14.4%）を出す。枠の色は段階が上がるほど格を上げる（銅・銅・銀・金・水色）。品質がS・Aのボーナスは、アイコンに種類ごとの光り方の[キラキラ](../art/direction.md#カードのキラキラ)を重ねる。今日のACTが届いていない枠は、アイコン・枠・文字を暗くし、キラキラも同じだけ暗くする。押したカードは金の縁と光になる |
| 右「ボーナス」 | 見出しと同じ高さの右端に「所持 〇 / 〇」、その下に面の幅いっぱいのタブ（すべて・探索・ドロップ・戦闘。選んだタブは金の下線）。持っているボーナスを1種類1行で、[品質](inventory.md#品質)の高い順に並べる。行にはアイコン（品質がS・Aなら[キラキラ](../art/direction.md#カードのキラキラ)を重ねる）、品質（S〜C。縁を品質の色にした小さなすりガラスの板に文字）、名前、倍率を掛けた効果量を置き、どこかの枠に入れているものには右端に印のアイコンを付ける |

左で枠を押してから右のボーナスを押すと、その場でその枠に入れる。
ほかの枠に入っているボーナスを押した場合は、2つの枠の中身を入れ替える。
決定ボタンや変化を説明する文は置かない。
変えると「5,000の枠に「守り」をセットしました」「「幸運」と「宝箱透視」を入れ替えました」を[共通の通知の帯](../rules/ui-design.md#操作を求めない通知)で知らせる。
今日のACTはホームで取得した値を受け取り、単体で開いたときは仮データの3,240ACTを使う。
持っているボーナスと枠の設定は、開くたびにサーバーから読み、付け替えはすぐ画面に出してから裏でサーバーに保存する（[保存](step-bonus.md#持ち物と枠の保存)）。保存できなかったときは元に戻して通知の帯で知らせる。
読み込むまでは右上に「読み込み中…」を出し、仮データの中身は見せない。読めなかったときは「ボーナスを取得できませんでした」、保存できなかったときは「ボーナスを保存できませんでした」を通知の帯で知らせ、枠は変えない。
サーバーの接続先がないとき（展示室のプレビューなど）だけ、仮データの持ち物と枠を使う。
ボーナスの名前・効果量・枠の倍率は仮データである。
品質の文字は、ボーナスの倍率と種類の上限から求める（2026-10-19）。ボーナスのレア度（☆）は未決のため出さない。
アイコン8個は、Codex CLIの画像生成で描き、24×24の格子に合わせて色を拾って清書した（指示文は [client/ArtSource/UI/StepBonus/prompts.json](../../client/ArtSource/UI/StepBonus/prompts.json)）。
セット中の印は、コードで描いた11×11のドット絵である。

### 商会

商会では、装備・スキル・素材の売り買いと合成を扱う。
合成できる物（素材・道具・武器・防具・アクセサリー・スキル）と決まりは[合成](synthesis.md)に従う。
案内人は貴族の少年武具商である。

メニューは「買う」「売る」「合成」の3つで、それぞれ仮の一覧を開く。
一覧の行には、名前、右端に値段（「400 ルーン」）またはレア度、下に種類と効果、または合成に使う素材を書く。
売買にはルーンを使うことを、ユーザーが決めた（[ルーンの用途](economy.md#ルーンの用途)）。
品物・値段・素材・合成の組み合わせはすべて仮データで、決定すると「買う（準備中）」などの通知を出すだけである。
売買と合成の決まりと保存は[未決](equipment.md#未決事項)で、持っている装備は[装備の保存](equipment.md#持っている装備と付け替えの保存)の作りを売買で増減させる前提で作った。

## 冒険の画面

Homeから冒険に出て、部屋を選んで進み、戦闘と宝箱で報酬を得て、最奥のボスを倒すか負けるかやめるかしてHomeへ戻る1周を、次の画面で遊べる。
決めた事項・作り方・検証結果は[実装計画](../plans/2026-10-04-adventure-loop.md)に記す。
冒険の状態（道を作る乱数の種、今いる部屋、通った部屋、部屋の出来事を終えたか、復活の回数、手に入れた報酬）はサーバーに保存し、部屋を選んだ時点で残る（[冒険の保存](stage-progression.md#冒険の中断と再開)）。
探索は森を見下ろす地図で進み、分岐ルートは冒険ごとに作る（[計画](../plans/2026-10-04-exploration-route-map.md)）。

```text
Home ──カード（冒険していない）──▶ 旅の案内所 ──出発──▶ 探索
Home ◀─カード（冒険の途中）──────────────────────────────▶ 探索
探索 ──戦闘の部屋──▶ 戦闘 ──勝利・報酬──▶ 探索（次の部屋を選ぶ）
                      ├─全滅──▶ 復活（ルーン）→ 戦闘を続ける ／ 帰還 → 冒険の結果 → Home
                      └─最奥のボスの撃破──▶ 冒険の結果 → Home
探索・戦闘 ──メニュー──▶ 中断してホームへ（選んだ部屋から再開） ／ 冒険をやめる → 冒険の結果 → Home
```

| 画面 | 作り | 表示と操作 |
|---|---|---|

| 探索（`Exploration`） | シーン | 森を斜め上から見下ろす地図（800×360ドットを3倍。16:9では中央の640ドットが見え、横長の画面ほど左右が広く見える）。見下ろす角度は、画面の中央でおよそ41°、パーティの足元で52°、画面の上端で25°にあたり、地平線は画面より上にある。冒険の種から作った分岐ルートを、森の中を蛇行する土の道で描く。道は、次に選べる道をいちばん太く明るく、その先の行ける道を少し細く暗く、通った道を金色の土で描き、行けなくなった道は細い暗い緑にして森に沈める。行ける道・通った道・開いた空き地・最奥の間のまわりだけ森を元の色で残し、そこから離れた森は暗く灰色に寄せて、道と部屋の札を森から浮かせる。行ける道には木が掛からないよう、道の脇を空ける。光の筋は描かず、下草の岩（明るい灰色が札と紛れる）は地図に立てない。道は縦に長く、画面にはパーティから5階先ほどまでが入り、最奥の間（遺跡の塔）は近づくか先を見ると見える。パーティ4人（戦闘の姿を1ドット1px）が今いる部屋の空き地に立つ。カメラはいつも道の左右の中央に立ち、道の左右の中央を画面の左右の中央に置く。カメラが追うのは道の奥行きだけで、左右に並ぶ部屋へは4人だけが画面の上を左右に動く。通っていない先の部屋は、最奥まで全部の印を種類のアイコン付きで出す。ただし、画面の上端の行き先と階の文字を置く帯に入る部屋は、最奥の間のほかは印を出さず、先を見るか進んで帯の下に来ると出す。霧は遠さを表す見た目で、部屋を隠さず、動かない。札の地の色が部屋の種類を示す（魔物は目立たない青灰色、強い魔物は赤、宝箱は金、最奥の間は紫）。次に選べる部屋と最奥の間は大きい札とアイコン（24×24を3倍）、カメラの立つ階から4階先までのほかの部屋は小さい札とアイコン（2倍）、その先はアイコンを出さずに種類の色の点で出す。小さい札の縁は種類の明るい色にする。行ける道の先の遠くの強い魔物の点には赤い光を添え、最奥の間は紫の光で見せる。行けなくなった部屋の印は灰色にして暗くする。1本指で地図を下へ引くと、パーティの足元の地面が指に付いてくるようにカメラが道の先へ進み、最奥の間の3階手前まで見渡せる。横へ引いても左右には動かない。指を離してもカメラはその位置に留まり、部屋の札を押すと、パーティの所へ戻りながら4人を追う。札の上から引いても札は押されない。左端に、画面に入る階のうちカメラの立つ階から2階先までの階（同じ大きさの文字で、今いる階は金色）、右上に行き先と階（例：ミストラ遺跡 第2層）、下の中央に案内（進む道を選んでください、など）、右下に凡例（種類の色の小さい札とアイコンに「魔物」「強い魔物」「宝箱」「最奥の間」を添えて2列に並べる）、左上に「メニュー」 |
| 部屋の選択と移動 | 探索 | 部屋の出来事（戦闘・宝箱）を終えると、次の階の行ける部屋を大きい札にし、縁を明るい色にする。部屋の種類は札の色とアイコンと右下の凡例で伝え、札の横に文字の手掛かりは出さない。札（押せる範囲は150px四方）を押すと、選んだ道を通った道の色に、ほかの道を行けなくなった道の色に変え、4人が道に沿って1.2秒で歩く。カメラは左右の中央のまま、0.2秒遅れて道の奥へ追い、押してから1.5秒で着いた部屋の階に止まる。地図は消さずに描き続け、木は一度に入れ替わらず、1本ずつ市松模様で現れ・消える。歩く間に動くのは4人とカメラ（と、それに伴う木の入れ替わり）だけで、霧は画面に対して動かない。歩く間に選んだ部屋をサーバーに保存し、両方が済むと着いた部屋を見せる。新しく見えた部屋の印は、手前の階から順に（1階ごとに0.12秒遅れて）0.4秒で薄い所から現れる。道を選んでいる間は何も動かさない。選ばなかった部屋の印はすぐに、選んだ部屋の印は着く少し前に薄れて消える。保存できなければ「冒険を保存できませんでした」と知らせて読み直す |
| 宝箱 | 探索 | 宝箱の部屋では、パーティの右手前に宝箱（32×32を3倍）を置き、押すと開いて報酬を見せる |
| 戦闘の部屋 | 探索 → 戦闘 | 案内に「魔物が現れた！」を0.9秒見せてから、戦闘のシーンを開く |
| 冒険のメニュー | 探索に重ねるダイアログ | 行き先と階、中断しても今いる部屋の続きから再開できること。中断してホームへ・冒険をやめる・閉じる。ルートは地図そのものに出ているため、ルートの画面は置かない |
| 戦闘（`Battle`） | シーン | [戦闘画面のモック](#戦闘画面の見た目モック)を、部屋の敵の組み合わせと行き先の背景で戦う。開くと敵が影から1体ずつ歩み出て、赤い帯で「魔物が現れた！」を出してから、「味方のターン」の帯の下で手札を配る。最奥の間ではボスが最後に景色を暗くして歩み出て、帯は「強敵が現れた！」になる。演出の間は手札がなく、ターンを終えられない。敵をすべて倒すと勝利、味方がすべて倒れると全滅で戦闘を終える。右上に「メニュー」（中断してホームへ・冒険をやめる・つづける）。左上は行動順のため右上に置いた |
| 勝利とドロップ | 戦闘 | 金の帯で「勝利！」を出して味方が跳ねて喜び、そのあいだに勝った部屋を保存する。続けて部屋のドロップを1つずつ、最後に倒した敵から光の玉が落ちて弾け、画面の上寄りに手に入れた物の札（種類と☆、名前、品質、持ち物に加えた・倍率が上がった・手放した）を開く。札を開いてから0.6秒おいて次のドロップへ進み、最後のドロップのあとに札を閉じて「勝利！」のダイアログを出す。何も落ちなければ札に「何も見つからなかった」を出す。光の大きさ・長さと札は[戦闘の演出デバッグルーム](#戦闘の演出デバッグルーム)のとおり。アイコンはACTボーナスだけで、ほかの種類は名前だけを書く。アイテムには品質がないため、品質の文字を出さず、札の縁も品質の色にしない |
| 全滅と復活 | 戦闘 | 景色が暗くなって灰色の帯で「全滅してしまった…」を出し、そのあいだに所持ルーンと復活の費用を読み直してから、復活のダイアログを出す。ルーンで復活すると、倒れた味方の足元から青い光が立って元の色に戻り、HPが満ちて青い帯で「復活！」、続けて「味方のターン」の帯の下で手札を配る |
| 報酬 | 探索・戦闘に重ねるダイアログ | 宝箱は「宝箱を開けた！」、手に入れたACTボーナスのアイコン・名前・[品質](inventory.md#品質)と、持ち物に加えた・倍率が上がった・持っているほうが倍率が高いため手放した、のどれか。戦闘は「勝利！」だけで、手に入れた物はその前の「勝利とドロップ」の札で見せるため本文に書かない。「先へ進む」で探索へ（ボスなら「つぎへ」で冒険の結果へ） |
| 復活 | 戦闘に重ねるダイアログ | 「全滅してしまった…」、手に入れた物は持ち帰れること、復活すると敵の傷はそのままで味方が全快して続けること、所持ルーン（足りなければ不足量）。「ルーンで復活（費用）」と「帰還する」を同じ形で縦に並べ、カウントダウンは付けない（[復活画面](combat.md#復活画面)）。ルーンが足りなければ復活を押せない |
| 冒険の結果 | 探索・戦闘に重ねるダイアログ | 「踏破！」「冒険の終わり」「帰還」、行き先と着いた階、最深記録（更新したら「最深記録を更新！」）、持ち帰ったボーナス（手放したものは除く）。「ホームへ」でHomeへ |

確認・メニュー・報酬・復活・結果は、どれも共通の確認ダイアログ（`GameDialog`）である。
画面全体を暗幕で覆って背面のタップを止め、[枠つきの表示の上に重ねる窓](#枠つきの表示)と同じ窓（不透明な濃い紺に金の細い縁と四隅のひし形）に、明るい金の題名・絵・本文と、最大5つの選択肢を、模様のない[すりガラスのカード](#すりガラスのカード)の同じ形で縦に並べる。
選択肢を押すと、次に表示を変えるまで受け付けない（通信の待ち中に二重に送らない）。
端末の戻るキーは、ダイアログを開いていればそれを閉じ（閉じられない結果・報酬などは何もしない）、探索と戦闘ではメニューを開く。
戦闘の途中で中断すると、再開したときはその部屋の戦闘を始めからやり直す。
探索のシーンは、ホームから開いても単体で開いても、開いたときにサーバーから冒険を読み、冒険の途中なら今いる部屋の地図を出し、冒険がなければホームへ戻る。
開く演出の途中で読み終えたときは、開き終えてからホームや戦闘へ移る。

宝箱・部屋の種類のアイコンは仮の絵で、Codex CLIで描いた（[実装計画の素材](../plans/2026-10-04-adventure-loop.md#素材)）。
地図の木・下草・岩・最奥の遺跡は、PixelLabで作った候補から選び、32色の共通の色にまとめた（[探索の地図の計画](../plans/2026-10-04-exploration-route-map.md#素材)）。下草の絵のうち岩の2枚（4・5フレーム目）は、地図の素材の写しに入れず、地図には立てない。
地図の絵は端末で描くため、`.aseprite` の画素を `Features/Adventure/Data/ExplorationMapArt.asset` に写して使う（`Baryonyx > Adventure > Create Screen Assets` で作り直す）。
展示室で探索画面のPrefabを選ぶと、決まった種の見本の地図を入口から見た形で描く。
停止中も、探索画面のPrefabと `Exploration` シーンは同じ見本の地図・印・パーティ・文字を表示する。生成のときに一度描いて作り込み、地図の絵は `Features/Adventure/UI/Art/ExplorationMapPreview.png` に書き出してEditorOnlyの画像に貼るため、ビルドには入らない。実行中はその絵を隠し、冒険の地図を描く。
戦闘の味方はまだ戦闘画面のモックの4人と16枚で、編成のパーティ・装備・Lv・スキルを反映していない。
冒険のメニューから編成・装備を変える入口も、まだない。
