# ルーン経済と資源の変更と判断の記録

[ルーン経済と資源](economy.md)

- 2026-11-02：ユーザーの判断で、ゲーム起動時の自動処理での未変換分の受け取りを廃止した（コードになく、作らない）。未変換分はHomeのACTパネルを押したときだけ受け取る（[運動データとルーン換算](exercise-rewards.md#actのルーン変換)）。
- 2026-11-02：スキルとdocの整理で、今のコードに合わせて、ルーンの入手にクリア回数の報酬の300ルーンを、用途に商会の合成と行商人の購入を足し、商会の強化と入れ子の地図のマスを開くルーンを実装済みに直し、消費の記録の一覧と実装との対応を足した（根拠：server/src/features/adventure/clear-rewards.ts、server/src/features/workshop/craft.ts、server/src/features/adventure/purchases.ts・merchant.ts、server/src/features/enhancement/records.ts、server/src/features/world-atlas/repository.ts）。
- 2026-10-27：ユーザーとの相談で、ルーンの用途に、街道のマスを開くことを加えた（[探索とダンジョンの進行](stage-progression-world-map.md#街道を開くルーンと日週月の出来事2026-10-27)）。
- 2026-10-26：ユーザーの依頼「ルーンの値段も、リスクがほぼないので上げてほしいです」を受け、1週間の歩数（約4万ルーン）に比べて軽すぎたため、[商会](screens/shop.md#買う)の「買う」の値段と[行商人](stage-progression/rooms.md#マスの中身仮)の値段を5倍にした。商会は☆1の200から1,000ルーン（☆5で16,000）、行商人は☆1の300から1,500ルーンで、どちらも☆ごとに倍にする。商会の売値は据え置き、買う値段の4分の1に倍率を掛けていた式を20分の1に改めて、額を変えなかった。
- 2026-10-24：ユーザーの依頼で、[商会](screens/shop.md#売る)の「売る」を実装し、歩数以外でルーンが増える経路ができた。売値は画面の仮の値（スキル・装備は買う値段の4分の1に倍率を掛ける。アイテムは☆1の10ルーンから☆ごとに倍）のままで、買い戻すと損になる。遊んで確かめて直す。
- 2026-10-24：ユーザーとの相談で、商会の強化に強化素材とルーンの両方を払うことにし、ルーンの用途に加えた（[商会の強化](enhancement.md)）。
- 2026-10-24：ユーザーの依頼で、[商会](screens/shop.md#商会)の「買う」を実装した。これまでに手に入れた（ライブラリに見つけた記録がある）スキル・武器・防具・アクセサリーを、品質の最低（×1.00）で何度でも買える。値段はユーザーから任されたため、☆1の200ルーンから☆ごとに倍にした（☆5で3,200）。品質を選べない代わりに行商人の品質C（☆1で300）より安くし、レベルアップの費用（Lv n→n+1でn×100）と比べて浅い行き先の物は気軽に買える額にした。物の強さは行き先のLvで決まるため、奥の行き先の☆の少ない物は強さの割に安い。遊んで確かめて直す。

- 2026-10-05：ユーザーの指示により、[商会](screens/shop.md#商会)での装備・スキル・素材の売買にルーンを使うことにした。新しい通貨（世界観の設定にある銅貨・銀貨・金貨）を設ける案は採らなかった。売却でルーンが増えるため、歩数以外のルーンの入手経路になる。値段は未決で、売買はまだ実装していない。

- 2026-10-04：ユーザーの指示により、運動量の単位の名前を「UPT」から「ACT」（読みはアクト、画面の表記はACT）へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。換算は1歩＝1ACT、1ACT＝1ルーンで変えない。

- 2026-10-04：[冒険の1周](../plans/2026-10-04-adventure-loop.md)で、敗北時の復活のルーンの消費を実装した。費用は仮に1回目100ルーン、以後100ずつ上げる。

- 2026-10-04：ユーザーの依頼で、レベルアップに使うルーンをサーバーの残高から引くようにした（[キャラと編成の保存](party.md#キャラと編成の保存)）。費用はサーバーで計算する。消費の記録は、歩数から得た分の台帳（`rune_ledger`）を作り直さず、レベルアップの記録に残した。台帳は歩数の日と請求に結び付き、増える量だけを記録する作りのためである。

- 2026-09-28：ユーザーの指示により、運動量の単位の名前を「ワット」から「UPT」へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。ルーンの名前と変換量（1UPT＝1ルーン）は変えない。ワットログインボーナスはUPTログインボーナスへ改名した。

- 2026-09-27：ユーザーの指示により、ゲーム内の運動量の単位を「歩」から「ワット」（1歩＝1ワット）へ改めた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）。ルーンは1ワット1ルーンとし、変換量は変えない。歩数ログインボーナスはワットログインボーナスへ改名した。

- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、ルーンを販売しないこと、レベルアップにルーンを使うことを確定した。運動目標の廃止に伴い、目標報酬の倍率を外し、歩数ログインボーナスと初回の固定ルーンの扱いを確認待ちとした。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| ルーン購入を収益化の候補とする | ルーンは販売しない |
| 目標報酬に難易度倍率と継続倍率を掛ける | 運動目標とともに廃止 |
| 無料再戦とルーン復活を選べる | 復活だけにルーンを使う。無料再戦の廃止は[開発者の最終確認待ち](combat/implementation.md#確認待ち) |

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様を根拠に、任意のルーン復活への利用を明記した。消費の操作と再開状態は戦闘仕様へ集約し、費用・収支は未確定のまま残す。旧危険度選択の倍率を経済計算の前提から外した。

- 2026-09-15：ユーザー提示の運動目標設定仕様に基づき、歩数ログインボーナス、初回固定ルーン、難易度と継続倍率を報酬設計へ接続した。日次・週次の進捗への重複反映と報酬の重複計算を区別し、具体値と遡及・差額処理を未決として残す。

- 2026-09-20：ユーザー確認により、歩数変換を1歩1ルーン、日次上限なし、端末タイムゾーン単位、過去7日分の初回請求、起動時と明示操作の両対応として確定した。目標報酬の倍率やルーン消費の費用とは分けて扱う。
