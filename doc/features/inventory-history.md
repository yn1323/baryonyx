# 持ち物の分類、レア度と品質の変更と判断の記録

[持ち物の分類、レア度と品質](inventory.md)

- 2026-11-02：ユーザーの判断で[持ち物のカード風の見た目](screens/common.md#持ち物のカード風の見た目)を今の作りで確定にしたため、「どの分類もスキルのカードに近づけていく」を、その節に従うという書き方に直した。
- 2026-11-02：スキルとdocの整理で、今のコードに合わせて、アクセサリーの枠の開き方、上限の決め方の表のアクセサリー、実装との対応のスキル（1枚ずつ倍率つきで `skill_cards` に保存）・装備・アイテムの行と持ち物のデバッグルームを直した（根拠：client/Assets/Baryonyx/Features/Equipment/Runtime/AccessorySlots.cs、server/src/features/equipment/catalog.ts、server/src/features/party/db-schema.ts の `skill_cards`）。
- 2026-10-24：ユーザーの指示で[ACTボーナス](../archive/step-bonus.md)を廃止したため、持ち物の分類・レア度・品質の対象から外した。
- 2026-10-24：ユーザーとの相談で、商会で磨き石とルーンを払って倍率を上げる[品質強化](enhancement.md#品質強化)を決め、未決事項の「品質を上げるアイテム」を具体化した。強化素材を持ち物の分類に加えた。
- 2026-10-20：ユーザーの指示により、スキルと装備の上限の仮の×1.5（回数のある種類は×1.3）をやめ、倍率をもっと伸ばしてよいとして、種類ごとの上限を決めた（[上限の決め方](inventory.md#上限の決め方)）。ACTボーナスは今のまま×1.5とした。上限が大きくなると、コストを倍率で割る決まりでは上限×3.0のコスト9が3まで下がり、大技の溜めが消えるため、伸び1.0ごとに1下げる決まりに改めた。
- 2026-10-06：ユーザーの指示により、持ち物の分類にアクセサリーとアイテム（道具・素材）を加え、分類をまたぐ決まりをまとめるためにこの文書を作った。スキルは入手ごとに倍率が違うため、武器・防具と同じく1枚ずつ持つことにした。倍率の決め方として、レア度ごとに固定する案、幅の中でばらつかせる案、両方を組み合わせる案を示したところ、ユーザーは「スキルそのものに倍率を付け、装備も同じ」とした。レア度の呼び方は、SSR・SR・Rの案も挙がったが、ユーザーが「S〜Eよりも☆の方がわかりやすい」として☆1〜☆5にそろえ、ほかの文書も☆にするよう指示した。同日、アイテムは種類ごとに個数で数え、倍率を持たないことをユーザーが選んだ。
- 2026-10-19：ユーザーの指示により、☆（レア度）と、1つずつ違う強さの呼び方を分けた。ユーザーは、レア度を「どのくらいレアなアイテムなのか」とし、☆5でもLv 30程度の弱い物があるとした。1つずつ違う強さは、SSR・SR・Rの案を挙げたうえで、☆と矛盾すると気付き、呼び方を相談した。SSR・SRやRare・Epicは珍しさを表す語で☆と混同するため避け、**品質**（英語はQuality）と呼び、S・A・B・Cで表す案をユーザーが選んだ。幅は下限を基本の効果量（×1.00）、上限を種類ごとの倍率とし、幅の中の位置で品質を分ける区切り（上位10%・30%・60%）はユーザーが決めた。キラキラはレア度ではなく品質に結び付け、Sは出す、Aは少し出す、B・Cは出さない。回数・持続ターン・確率・コストにも倍率を掛けるかを提案したところ、ユーザーは「変えちゃって。なんか面白そう」とした。端数の扱い、コストを割ること、確率を100%で止めること、不利な量を割ること、条件のしきい値を変えないことは、提案した案をユーザーが選んだ。固有スキルはレア度を持たず品質Cで始め、今後のアイテムで強化できるようにしたい、とユーザーが決めた。ACTボーナスも、☆をボーナスそのもののレア度とし、品質を持たせることにした。これにより、未決だった「レア度の付き方」は種類ごとに決まることになった。見出しの「1つずつ持つ倍率」を「品質」に、文書名を「持ち物の分類、レア度と品質」に改めた。
