# 主要画面の操作プレビュー

[機能索引](README.md) / [画面一覧](screens.md) / [実装計画](../plans/2026-09-18-game-wireframe.md)

## 目的と起動

操作ワイヤーの10画面を、背景・キャラ・ピクセル調の枠を使ったUIへ置き換えた。
操作仕様は本書、見た目と今回の検証結果は[ゲームUIと生成素材](../art/game-ui.md)、置き換え前の記録は[ワイヤーの検証記録](../plans/2026-09-18-game-wireframe.md#2026-09-19の実装検証記録)を参照する。

縦持ちの戦闘画面の窮屈さ、探索中の装備・仲間変更、下部UIの情報量を確認する。
専用の[Wireframeシーン](../../client/Assets/Baryonyx/App/Scenes/Wireframe.unity)をUnity Editorで開き、PlayModeに入ると初回案内を表示する。
Unityメニューの `Baryonyx/Wireframe/Open Scene` からも開ける。
既存シーンに未保存の変更があれば先に保存する。

初回案内の「設定せずに始める」からホームへ進める。
右上の「確認」はワイヤー確認用のパネルで、仮の勝敗、表示状態、初期状態へのリセットを選べる。
確認用パネルを閉じた状態で、通常の情報量と操作域を評価する。
現在の標準ビルド対象と健康データ用のMainシーンは変更していない。

## 確定したワイヤーの範囲

| 画面 | 操作できる内容 |
|---|---|
| ホーム | 冒険先、仲間、装備、運動目標、設定へ移動する |
| 冒険先 | サンプルの森・坑道を選び、実行中に保持した場所から探索する |
| 探索 | 入口を選んで戦闘へ進み、脇道で仲間・装備を獲得する。編成・装備・設定を開き、終了確認からホームへ戻る |
| 仲間・編成 | 4枠から変更する枠を選び、仲間を選択して確定する。既に編成中の仲間なら枠を交換する |
| 装備 | 対象キャラ、仮の武器、比較値を見て装備を変更する |
| 戦闘 | 味方本体またはHP欄からキャラを選び、技・敵・使用確定を操作する |
| 敗北 | 無料再戦、ルーン復活の確認、編成変更、別の道、帰還を選ぶ |
| ボス結果 | 仮の獲得内容と到達を表示し、ホームへ帰る |
| 運動目標 | 日次・週次を独立して仮設定し、条件要約、変更予約、履歴、データ未確認などの表示を確認する |
| 設定 | 仮の音量値を切り替え、運動データの連携案内を開く |

通常戦の仮勝利では探索へ戻り、簡易報酬を表示する。
初めての装備・仲間は「今すぐ装備」「編成する」で対象を選択した画面を開く。
「あとで」や戻る操作でも獲得物は仮の所持一覧に残る。
通常戦2回の後にボス表示へ進む固定の経路を使う。

編成・装備・設定は呼び出し元を保持する。
探索→編成→装備では編成、探索の順に戻り、敗北から開いた場合は敗北へ戻る。
獲得表示から直接開いた変更画面で確定すると、同じ探索場所へ戻る。
モーダル中は背面の操作を遮断し、画面の戻る操作とEscapeは最上面を閉じる。

戦闘進行中は編成・装備の画面を開かない。
スキル選択中の戻る操作は選択を取り消し、通常状態の戻るでは戦闘を抜けない。
無料再戦は敵HPが最大の表示、復活は削れた敵HPと濃淡を保った表示へ切り替える。
復活によるルーン消費は行わない。

## 配置と仮データ

2026-09-19のUI置き換え作業で、10画面の生成コードと背景・キャラ素材を追加した。
配色、素材、再生成と検証状況は[ゲームUIと生成素材](../art/game-ui.md)を参照する。

探索は森・坑道の背景に現在の4人を配置し、描かれた入口の上に行き先ボタンを重ねる。
入口を選ぶとパーティが短く移動してから戦闘・獲得へ進む。
移動中の二重操作を抑止し、戻る操作で移動を取り消す。
区間ごとに異なる部屋の配置や複数経路の地図は未実装であり、同じ場所では背景を共用する。
要求全体は[ダンジョン内の見た目による行き先選択](stage-progression.md#ダンジョン内の見た目による行き先選択)を参照する。

味方4人は左側に縦並び、敵は右側、敵予告は上部、HP兼キャラ選択とスキルは下部に置く。
短い縦画面ではHP欄を2列、十分な高さがある場合は4行にして戦場の高さを確保する。
基準解像度360×640はUIの設計座標であり、対応端末の制限やdpと同じ単位ではない。
画面全体と補助パネルはSafeAreaに追従し、高さが不足する場合はスクロールして操作へ到達できる。

スキル2枠を基本とし、確認パネルで3枠、複数予告、ボス表示へ切り替えられる。
詠唱、クールダウン、弱った濃淡、ダウン中は固定の表示状態である。
ダウンのリング・残量ゲージは置かない。
キャラ名、装備、数値、報酬、倍率、目標の実績はすべてサンプルであり、採用済みのゲームマスタではない。

編成、装備、獲得物、探索進捗、目標表示はPlayMode・アプリの実行中だけ保持する。
サーバー接続、端末の健康データ、認証、永続保存は使わない。
ダメージ計算、敵AI、自動攻撃、キャスト・クールダウン・強スローの時間制御、ダウン判定は未実装である。

## 2026-09-19のユーザー評価と残った課題

ユーザーから、ワイヤーではワクワク感と「何を楽しむゲームなのか」の両方をまだ掴めず、作っている間も体験が薄く感じるとの評価があった。
画面の印象についても確定した評価はなく、操作検証の成功をゲームの面白さの確認済みとは扱わない。

具体的な改善要求は、文字だけの行き先選択では場所が分かりにくいため、ダンジョン内の部屋・通路を見て選び、現在地も分かるようにすることである。
この要求を[探索仕様](stage-progression.md#ダンジョン内の見た目による行き先選択)へ追加した。
この評価を記録した後、背景・現在のパーティ・入口を重ねた探索UIへ置き換えた。
置き換え後の楽しさについては、まだユーザー評価を得ていない。

体験の薄さの原因すべてを探索表示に帰属させず、探索の分かりやすさと、期待・獲得・成長の楽しさをそれぞれ確かめる。
今後の評価観点と制作項目は[MVPと企画の判断基準](../game/mvp.md#ワイヤー後の体験評価)に記す。

## 実装と生成元

| 入口 | 役割 |
|---|---|
| [WireframeBootstrap](../../client/Assets/Baryonyx/App/Runtime/WireframeBootstrap.cs) | サンプルデータと画面を組み立てる |
| [WireframeSession](../../client/Assets/Baryonyx/Features/Wireframe/Runtime/WireframeSession.cs) | 画面遷移、戻り先、仮の状態を保持する |
| [WireframeView](../../client/Assets/Baryonyx/Features/Wireframe/Runtime/WireframeView.cs) | ボタン入力、文言、状態表示を結ぶ |
| [WireframeLayout](../../client/Assets/Baryonyx/Features/Wireframe/Runtime/WireframeLayout.cs) | SafeArea、幅、高さ、HP欄の配置を更新する |
| [サンプル定義](../../client/Assets/Baryonyx/Features/Wireframe/Runtime/WireframeData.cs) | キャラ、武器、場所の表示例を定義する |
| [画面の生成元](../../client/Assets/Baryonyx/Features/Wireframe/Editor/WireframeScreenAssets.cs) | uGUIのPrefabと専用フォントアトラスを作る |
| [シーンの生成元](../../client/Assets/Baryonyx/App/Editor/WireframeSceneSetup.cs) | 既存のシーンを保持して専用シーンを新規作成する |

Prefabを再生成する場合は `Baryonyx/Wireframe/Create Screen Assets` を使う。
シーンを初めて生成する場合は `Baryonyx/Wireframe/Create Scene` を使い、既存シーンは上書きしない。
Android APKはAndroidをビルド対象にして `Baryonyx/Wireframe/Build Android APK` から生成する。
画面を再生成し、Wireframeシーンだけを一時的な対象として既存の `AndroidBuild.Build` を呼び、完了後に通常のビルドシーン設定を戻す。
出力は `client/Builds/Android/baryonyx.apk` とし、成功後はルートの手順どおりGoogle Driveの所定フォルダーへコピーする。
日本語フォントの元データとライセンスは[既存のフォント配置](../../client/Assets/Baryonyx/Features/Health/UI/Fonts/README.md)を参照し、ワイヤーの動的アトラスは専用アセットへ分ける。

## 検証と未確認事項

[状態テスト](../../client/Assets/Baryonyx/Features/Wireframe/Tests/EditMode/WireframeSessionTests.cs)で、獲得・戻り先・連打・復活と再戦・目標の独立性を確認する。
[画面シナリオ](../../client/Assets/Baryonyx/Features/Wireframe/Tests/PlayMode/WireframeScenarioTests.cs)で、実Prefabへの入力から冒険・装備変更・帰還、仲間加入・敗北後の往復、モーダル、目標案内を確認する。
実施結果は[計画の検証記録](../plans/2026-09-18-game-wireframe.md)へ追記する。

押しやすさ、戦闘の窮屈さ、敵の濃淡の読み取りやすさは実物を触って評価する。
Androidの戻る、タップ領域、システムバーとの重なりは、Editorの確認とは分けて端末で確認する。
端末検証にはユーザーが手動で起動したAndroidエミュレーターを使う。
