# 遊べる試作の画面と操作

[機能索引](README.md) / [画面一覧](screens.md) / [戦闘](combat.md) / [見た目と素材](../art/game-ui.md)

## 目的と起動

全10画面とダイアログを再構成し、歩数画面を加えた11画面の試作である。
参照会話「遊べる試作へ進む」から、4人を中心にしたホーム、今日の歩数、冒険への主要操作、控えめなルーン表示、余白を取った配置を反映した。
会話のテキストは取得できたが、最新の生成画像は取得できなかったため、既存素材と新しい出発地点の生成背景で補った。

Unityで保存済みの状態から `Baryonyx/Wireframe/Open Scene` を実行し、PlayModeで起動する。
初回案内の「冒険をはじめる」からホームへ進む。
通常画面には仮の勝敗を選ぶ確認パネルを表示しない。
健康データ用のMainシーンと通常のビルドシーン設定は維持する。

## 確定したワイヤーの範囲

| 画面 | 操作と表示 |
|---|---|
| ホーム | 現在の4人、今日の歩数、ルーン、冒険への主要操作。歩数・仲間・装備・目標・設定へ進む |
| 冒険先 | 森・坑道から選択する。ホームで行き先を固定しない |
| 探索 | 背景上の入口へ4人が歩いて進み、戦闘や獲得へ遷移する。編成・装備・設定・帰還を選べる |
| 仲間・編成 | 上部に出撃中の4人、その下に選択した仲間の詳細と待機中の仲間を表示する。枠と候補を選んで確定する |
| 装備 | 対象キャラと所持武器を選び、威力・ダウン値の差を確認して変更する |
| 戦闘 | 通常攻撃が自動進行する。味方本体またはHP欄から選び、2つのスキル・標的・使用確定を操作する |
| 敗北 | 無料再戦、100ルーンでの復活、編成、別の道、帰還を選ぶ |
| ボス結果 | 獲得済みの仲間・装備とルーンを確認し、ホームへ戻る |
| 運動目標 | 日次・週次の条件を仮設定する。変更予約と目標の解除を試せる。評価・履歴の永続保存は未実装 |
| 設定 | 仮の音量値とHealth Connectの入口。試作の保存範囲を案内する |
| 歩数 | Health Connectへの接続、更新、設定への移動、直近7日間の数値・棒グラフ、日別の元JSONを表示する |

通常戦2回の後にボスへ進む固定経路である。
通常戦の勝利で120ルーン、ボスの勝利で300ルーンを加算し、最初の勝利では新しい武器を獲得する。
脇道では新しい仲間を獲得し、その後は宝箱のルーンを得る。
獲得画面で「あとで」を選んでも実行中の所持状態に残る。

編成・装備・設定は呼び出し元へ戻る。
探索→編成→装備では編成、探索の順に戻り、敗北から開いた場合は敗北へ戻る。
獲得から直接開いた編成・装備を確定すると探索へ戻る。
編成のドラッグ操作は実装していない。
参照会話のドラッグ・即時確定案は未確定であり、見た目の指示と操作の確定を分けている。

## 戦闘と再戦

戦闘の計算は画面から分離した[CombatEncounter](../../client/Assets/Baryonyx/Features/Combat/Runtime/CombatEncounter.cs)が担当する。
4人の自動攻撃、スキルの詠唱と個別クールダウン、敵の通常攻撃・大技予告、弱点、ダウン、回復・防護、勝敗を実装した。
選択中は共通の時計を0.12倍にし、攻撃・詠唱・予告・クールダウン・ダウンの時間を同じ割合で遅くする。
試作用の数値と未実装事項は[戦闘の実装との対応](combat.md#実装との対応)を参照する。

ダウンの残量数字・リング・追加バーは表示しない。
敵の濃淡、よろけ、ダウン表示と傾きで状態を表す。
命中時には数値と揺れを表示する。
味方HPは4人分を横並びにし、選択した味方の2スキルだけを下部に開く。

戦闘中は編成・装備の画面を開かない。
戻る操作はスキル選択を取り消し、通常状態では戦闘を抜けない。
背面移行中は戦闘を進めず、復帰時に背面時間分をまとめて消化しない。
無料再戦は現在の編成と装備から敵味方・クールダウンを初期化する。
ルーン復活は100ルーンを1回消費し、味方のHPと行動待ちを回復する。
敵HP・ダウン残量・ダウン中の残り時間を保持し、予告は解除する。
残高不足では確定できない。

## Health Connectと歩数

Androidでは既存のHealth Connect Providerから端末のデータを読み取る。
Googleログインは歩数取得の前提にしない。
接続、利用条件の確認、権限の拒否・取消、更新、前面復帰時の再確認は既存の[健康データ機能](health-data.md)に従う。
DB、サーバー送信、PlayerPrefsへの保存は行わない。

グラフは古い日から今日へ7本を並べ、その週の最大値を基準に高さを決める。
取得できた0歩は「0」、記録なし・未取得・権限不足・失敗はそれぞれの状態で表す。
日付列をタップすると、その日の取得元JSONを別ダイアログで開く。
読み取り状態が破棄された場合は、グラフと開いているJSONも消す。

EditorとAndroid以外では「Editor用サンプル」と明示した固定値を使う。
Android APKにはこのサンプルProviderを組み込まず、データ未取得を仮の歩数で埋めない。
ホームの今日の歩数と歩数画面は同じPresenterの結果を使う。
目標の達成履歴・運動距離の評価・日付境界での自動確定は、この試作の対象外である。

## 配置と保存範囲

生成りの背景、深緑の主要操作、控えめな金色、森とピクセル調のキャラを全画面で揃える。
設計座標は360×640とし、SafeArea、最大幅、縦スクロールを使う。
短い画面や横画面でも、スクロールで下部の操作へ到達できる。
モーダルは背面入力を遮り、「閉じる」を上部に固定する。

編成・装備・ルーン・探索進捗・目標の仮設定は、実行中だけ保持する。
キャラと装備の数値は試作値であり、完成版のマスタやバランスの確定を意味しない。
音量は表示上の設定例であり、音源の追加は今回の対象外である。

## 2026-09-19のユーザー評価と残った課題

以前のワイヤーでは、ワクワク感と楽しさの中心をまだ掴めないというユーザー評価があった。
今回の実装で探索・獲得・装備変更・実際の戦闘を続けて試せるようにした。
面白さ、技を温存する判断、ボス戦の長さ、敵の濃淡の読みやすさは、試遊で引き続き確認する。
検証観点は[MVPの体験評価](../game/mvp.md#ワイヤー後の体験評価)を参照する。

## 実装と生成元

| 場所 | 責務 |
|---|---|
| [WireframeBootstrap](../../client/Assets/Baryonyx/App/Runtime/WireframeBootstrap.cs) | 冒険画面と健康データの起動、前面・背面通知 |
| [HealthRuntime](../../client/Assets/Baryonyx/App/Runtime/HealthRuntime.cs) | MainとWireframeで共通のProvider選択、Presenter生成、破棄 |
| [WireframeSession](../../client/Assets/Baryonyx/Features/Wireframe/Runtime/Flow/WireframeSession.cs) | 画面遷移、所持状態、戦闘開始・結果の反映 |
| [Presentation](../../client/Assets/Baryonyx/Features/Wireframe/Runtime/Presentation) | 入力と描画。通常ページ、戦闘、ダイアログ、歩数、演出、配置を分離 |
| [Combat](../../client/Assets/Baryonyx/Features/Combat/Runtime) | Unityの画面に依存しない戦闘計算、状態、試作カタログ |
| [HealthWeekSummary](../../client/Assets/Baryonyx/Features/Health/Runtime/Presentation/HealthWeekSummary.cs) | 日付順、合計、最大値、欠損表示、棒の比率 |
| [画面生成](../../client/Assets/Baryonyx/Features/Wireframe/Editor/WireframeScreenAssets.cs) | 共通uGUI部品と生成の入口。ページ・戦闘・歩数の組み立ては専用ファイル |

Prefabは `Baryonyx/Wireframe/Create Screen Assets` で再生成する。
Androidをビルド対象にし、`Baryonyx/Wireframe/Build Android APK` でWireframeシーンを起動対象にしたAPKを作る。
共通の `AndroidBuild.Build` を呼び、終了後に通常のビルドシーン設定を戻す。
生成APKはルートの手順に従い、必ず指定のDriveフォルダーへコピーする。
日本語フォントは既存の[フォントとライセンス](../../client/Assets/Baryonyx/Features/Health/UI/Fonts/README.md)を使う。

## 検証と未確認事項

戦闘の時間・ダウン・回復・防護・勝敗はEditModeで検査する。
実Prefabの入力、通常戦の自動勝利と報酬、歩数・JSONの表示はPlayModeで検査する。
全画面をGameビューで撮影し、画像を開いて確認する。
実施結果は[UIの検証記録](../art/game-ui.md)へ記す。

Androidの権限ダイアログ、実際の健康記録との一致、戻る操作、タップ領域、システムバーとの重なりは端末確認が必要である。
ユーザーが手動起動したAndroidエミュレーターを使い、確認結果と必要なログの提供をユーザーへ依頼する。
Editorの成功だけで端末連携の成功とは扱わない。
