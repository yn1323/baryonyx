# 固有スキルの進化

[機能索引](README.md) / [キャラクターとパーティ編成](party.md) / [戦闘システム](combat.md) / 根拠：2026-10-18のユーザーとの相談

各キャラの[固有スキル](party.md#キャラクターの構成)は、冒険の中で別の段階のカードに変わる。
これを**進化**と呼ぶ。
進化して取得した段階はずっと残り、編成でどの段階を使うかを選べる。
冒険のたびに少しずつ固有スキルが育ち、どの枝へ育てるかをプレイヤーが選ぶ楽しさを作る。

参考にしたのは、カオスゼロナイトメアの「カードのひらめき」である（戦闘でカードを使うと確率で起き、候補から選んでカードを進化させる。[GameWith](https://gamewith.net/chaoszeronightmare/70805)、2026-10-18確認）。

## 確定している方針

### 進化の段階とツリー

固有スキルは、最初の段階から3つの枝に分かれ、それぞれの枝がもう1段進む。
最初の段階を含めて、1つの固有スキルは7つの段階を持つ。

```text
最初の段階 ─┬→ 枝1の1段目 → 枝1の2段目
            ├→ 枝2の1段目 → 枝2の2段目
            └→ 枝3の1段目 → 枝3の2段目
```

各段階の効果は、キャラの固有スキルごとに個別に作る。
どの固有スキルにも同じ型（コスト-1など）を当てはめる作り方はしない。

1回の進化で、ツリーを1段進む。
進む先は、編成でセットしている段階の次の段階である。
枝分かれでは、どの枝へ進むかをプレイヤーが選ぶ。
ランダムに決まるのは、進化が起きるかどうかだけである。

解放前の固有スキル（[レベルアップ](progression.md#レベルアップ)で解放する）は進化しない。

### 進化が起きる場面

進化は冒険の中の次の2つの場面で起き、Homeなど冒険の外では起きない。

- **戦闘**：固有スキルのカードを使ったとき、確率で進化する（[戦闘中の進化](#戦闘中の進化)）。
- **宝箱**：宝箱の中身として進化が出る。その場で、パーティの4人の固有スキル8枚から進める1枚を選び、次に進む段階を選ぶ。進められる固有スキルが1枚もないときは、宝箱から進化を出さない。

### 戦闘中の進化

進化したカードは、その戦闘の中ですぐ進化後の段階に変わる。
コストと効果も、その時点から進化後のものになる。

1回の戦闘で、1枚の固有スキルが進化するのは1段までとする。
ツリーは2段しかないため、1回の戦闘で最後の段階まで進むと、育てる手応えが薄くなるからである。

進化の確率は、敵の強さで決める。

- 部屋の種類で基本の確率を決め、魔物、強い魔物、最奥のボスの順に高くする（[部屋の種類](stage-progression.md#冒険の道の作り方)）。
- ダンジョンの推奨Lvより、その固有スキルを持つキャラのLvが高いほど、確率を下げる。

進化はずっと残るため、Lvの差による補正がないと、弱い敵の部屋を何度も通るだけでツリーを取りきれてしまう。
進化しない回数に応じて確率を上げる仕組み（天井）は、まず設けずに試し、遊んで不満が出たら足す。

### 進化の候補

進化の候補は、セットしている段階の次の段階すべてである。
最初の段階なら3つの枝の1段目、1段目ならその枝の2段目の1つが候補になる。
2段目には次の段階がないため、それ以上は進化しない。

すでに取得した段階も候補に出し、「取得済み」と書く。
取得済みの段階を選んだときも、未取得の段階を選んだときと同じく進化として扱う。
カードはその段階に変わり、1回の戦闘で1段までの上限にも数える。
そのため、次の段階がすべて取得済みでも進化は起きる。

### 取得した段階とセット

進化で取得した段階は、ずっと残る。
冒険に負けて終わっても、それまでの進化は残る（[冒険の終了と獲得物の保持](stage-progression.md#冒険の終了と獲得物の保持)）。

編成では、固有スキルごとに、取得した段階のどれか1つをセットする。
最初の段階や途中の段階もセットできる。
冒険が終わると、冒険中に進化した段階がそのままセットされた状態になる。

冒険中は、進化のほかにセットする段階を変える手段はない。
パーティの入れ替えや装備の変更は探索中にもできるが（[パーティの未決事項](party.md#未決事項)）、固有スキルの段階を手前に戻せるのはHomeの編成だけである。
別の枝へ進めたいときは、Homeの編成で手前の段階にセットし直し、次の冒険でそこから進化させる。
これを繰り返すと、7つの段階をすべて取得できる。

### 編成での見せ方

編成では、固有スキルごとのツリーを見せる。
取得した段階は名前と効果を見せ、セットする段階として選べる。
取得していない段階は、ツリーの形だけを影として見せ、名前と効果を見せない。

### 進化の保存

取得した段階とセットしている段階は、ユーザーごとにゲームサーバーのDBに保存する。

冒険中の進化は、その部屋を終えたときにサーバーへ保存する。
戦闘中にアプリが終わると、その部屋の戦闘を始めからやり直すため（[冒険の中断と再開](stage-progression.md#冒険の中断と再開)）、その戦闘の中での進化は残らない。
負けて冒険が終わるときは、その部屋での進化も保存する。

## 設計方針

進化した段階のエフェクトは、進化前より派手にし、育った手応えを見て分かるようにする（2026-10-18のユーザーの希望）。

ツリーは、2026-10-18の時点ではキャラ1人ずつ作り、手触りを確かめてから次へ進む方針だった。
2026-10-19、ユーザーの依頼で、仮データの8つの固有スキルの全段階（56段階）の効果と挿絵を、まとめて仮に作った。エフェクトはまだ段階ごとに作っていない。

枝は、同じ固有スキルを3つの違う方向へ育てる。
威力や回数を上げるだけの枝は1本までにし、残りの枝では状態・属性・対象・手札とエネルギーへの働きを変える。
2段目は1段目の方向を強め、1段目で始めた効果を大きくするか、効果を1つ足す。

### 今のツリー（仮データ）

8つの固有スキルの枝の方向は次のとおりである（2026-10-19、仮）。
各段階の効果・コスト・説明文は [UniqueSkillTrees](../../client/Assets/Baryonyx/Features/SkillEvolution/Runtime/UniqueSkillTrees.cs) を正本にする。

| 固有スキル | 使い手の職 | 1本目の枝 | 2本目の枝 | 3本目の枝 |
|---|---|---|---|---|
| マナバースト | 魔法使い | 威力を上げる（マナバースト・烈→マナバースト・極） | 魔力の弾を散らす（マナバースト・散→マナバースト・嵐） | 魔力を手元へ巡らせる（マナバースト・環→マナバースト・還流） |
| 星降り | 魔法使い | 炎の星にする（星降り・灼→星降り・焔獄） | 氷の星にする（星降り・氷晶→星降り・凍星） | 1体に集める（星降り・墜星→星降り・天墜） |
| 雷撃の矢 | 弓使い | 麻痺で縛る（雷撃の矢・痺→雷撃の矢・縛雷） | 敵から敵へ渡る（雷撃の矢・連→雷撃の矢・迅雷） | 弱点を射て次の手につなぐ（雷撃の矢・閃→雷撃の矢・閃光） |
| 矢の雨 | 弓使い | 毒を重ねる（矢の雨・毒→矢の雨・蠱毒） | 鎧を穿つ（矢の雨・穿→矢の雨・穿天） | 速く射て手を回す（矢の雨・速→矢の雨・疾風） |
| 盾の構え | 騎士 | 自分の守りを固める（盾の構え・堅→盾の構え・不動） | 攻撃をはね返す（盾の構え・返→盾の構え・鏡盾） | 仲間も守る（盾の構え・陣→盾の構え・城壁） |
| 一閃 | 騎士 | 出血を咲かせる（一閃・血華→一閃・散華） | 軽く速くする（一閃・疾→一閃・瞬） | 横に薙ぐ（一閃・薙→一閃・嵐薙） |

| 蘇生 | 癒し手 | 軽くする（蘇生・祈→蘇生・奇跡） | 守って起こす（蘇生・加護→蘇生・不死鳥） | 奮い立たせて起こす（蘇生・活力→蘇生・再起） |

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 確率の値 | 部屋の種類ごとの基本の確率と、Lvの差による下げ幅。値をサーバーの設定値にして、あとから変えられるようにする案がある |
| 推奨Lvより低いとき | 格上の相手で確率を上げるか |
| 進化できるカードの見せ方 | 戦闘で、進化が起きうるカードを光らせるなど、見て分かるようにするか |
| 候補を選ぶ画面 | 戦闘中と宝箱で候補を選ぶとき、未取得の段階の名前と効果を見せるか。編成では影で隠すため、選ぶときにだけ見せるかを決める |
| 宝箱から進化が出る確率 | 宝箱の抽選対象としての確率（[報酬・ドロップテーブル](../catalog/loot-tables/README.md)） |
| 抽選と確認をする場所 | 戦闘は端末で計算するため、確率の抽選も端末で行う形になる。サーバーは、送られた段階が「セットしている段階の次」で、固有スキルが解放済みかを確かめる案がある。端末を書き換えると進化を増やせる点は、[部屋の種類を端末から受け取ること](stage-progression.md#確認待ち)と同じ種類の問題である |
| 1段目と2段目の違い | 2段目で効果を変えるか、数値を上げるだけにするか。キャラごとに決めるか。2026-10-19の仮データでは、2段目で1段目の効果を大きくするか効果を1つ足す形にし、枝ごとに決めた |
| 段階の名前・IDの持ち方 | 各段階を[スキルの定義](../catalog/skills/README.md)に1段階ずつ置くか、[キャラの定義](../catalog/characters/README.md)にまとめるか |
| レベルアップとの関係 | 深い段階にLvの条件を付けるか。ルーンでのレベルアップで、冒険の初めから1段進化した状態にする案（カオスゼロナイトメアの潜在力に当たる）を採るか |
| 装備の「進化」との呼び分け | 装備の強化・進化・再抽選を採るかは未決である（[装備の未決事項](equipment.md#未決事項)）。装備に採るなら、固有スキルの進化と名前を分けるか |

## 実装との対応

冒険中の進化（戦闘と宝箱）、確率、サーバーへの保存は未実装である。
実装したのは、編成の[スキルの付け替え](screens.md#スキル)での、進化ツリーの表示と、取得した段階のセットである（2026-10-18）。

| 対象 | 入口 |
|---|---|
| ツリーの形（7つの段階、進化する前の段階と次の段階）と進み具合 | [UniqueSkillTree](../../client/Assets/Baryonyx/Features/SkillEvolution/Runtime/UniqueSkillTree.cs) |
| 固有スキルごとのツリーの仮データ（各段階のカード） | [UniqueSkillTrees](../../client/Assets/Baryonyx/Features/SkillEvolution/Runtime/UniqueSkillTrees.cs) |
| アプリを動かしている間の進み具合とセット | [UniqueSkillSession](../../client/Assets/Baryonyx/Features/SkillEvolution/Runtime/UniqueSkillSession.cs) |
| 付け替えの画面での表示と操作 | [プレゼンター](../../client/Assets/Baryonyx/Features/CardLoadout/Runtime/CardLoadoutPresenter.cs)・[表示](../../client/Assets/Baryonyx/Features/CardLoadout/Runtime/CardLoadoutView.cs)・[パネルの生成](../../client/Assets/Baryonyx/Features/CardLoadout/Editor/CardLoadoutAssets.cs) |

仮データと実装の差は次のとおりである。

- 8つの固有スキルとも、7つの段階すべてを仮に作った（2026-10-19）。取得していない段階は影で出す。
- 進み具合の仮データは、トーマのマナバーストだけ3つの段階を取得し、1本目の枝の1段目をセットしている。ほかは最初の段階だけである。
- 進み具合とセットはサーバーに保存せず、アプリを動かしている間だけ残す。仮データ（[TrainingMockData](../../client/Assets/Baryonyx/Features/Training/Runtime/TrainingMockData.cs)）が固有スキルのツリーのIDと、進み具合の初めの値を持つ。
- 各段階に専用の挿絵がある（`CardUnique<ツリー><段階>.aseprite`、[技・カードの定義](../catalog/skills/README.md)と同じ規格）。Codex CLIの画像生成で、ツリーごとに7枚を1枚のシートに描き、切り出して64×58・32色にした（2026-10-19）。
- [育成](screens.md#育成)の個別の画面の固有スキルも、セットしている段階のカードを出す。戦闘画面のモックは、固有スキルをまだデッキに使っていない。
- [展示室](showcase.md)では、編成の画面のPrefabの `CardLoadout` を開き、停止中の表示の切り替えの「固有スキルの進化ツリー」で、先頭の人（トーマ）の1つ目の固有スキルのツリーを確かめられる。

## 変更と判断の記録

- 2026-10-19：ユーザーの依頼「固有スキルの進化系も考えてほしい。画像はCodexも利用して」で、8つの固有スキルの残りの45段階を仮に作り、全56段階に専用の挿絵を付けた（[今のツリー](#今のツリー仮データ)）。キャラ1人ずつ作る方針は、ユーザーの依頼で今回は採らなかった。2段目を数値だけ上げるか効果を変えるかの未決は、枝ごとに決める形で仮に作った。
- 2026-10-18：ユーザーの依頼で、[スキルの付け替え](screens.md#スキル)の画面で固有スキルを押すと右に進化ツリーを出し、取得した段階を押してセットできるようにした。取得していない段階は形だけの影にした。サーバーへの保存はまだで、アプリを動かしている間だけ残す。
- 2026-10-18：ユーザーの相談を受けて、この文書を作った。ユーザーはカオスゼロナイトメアの「カードのひらめき」を参考に挙げ、カードが増える「戦闘員のひらめき」は採らなかった。
  - 進化の結果を残す範囲として、冒険の間だけ、ずっと残す、冒険の終わりに1つだけ持ち帰る、の3案を示したところ、ユーザーはずっと残す案を選んだ。
  - 進化の型をキャラ共通にする案ではなく、キャラごとに作る案を選んだ。ツリーは当初の「A→A2→A3、A→B1→B2、B1→C1」から、制作量を抑えるため、3つの枝がそれぞれもう1段進む7段階に改めた。
  - どの枝へ進むかをランダムにする案ではなく、プレイヤーが選ぶ案を選んだ。一度進むと戻れない決まりへの対応として、Homeの編成で手前の段階にセットし直す形をユーザーが示した。
  - 確率を部屋の種類とLvの差で決める案、1回の戦闘で1枚1段まで、天井なし、宝箱からその場で進める形を、ユーザーが採った。
  - 次の段階がすべて取得済みのときに進化しない案を示したところ、ユーザーは未取得のときと同じく進化する形を選んだ。
  - 名前は、「ひらめき」がロマンシング サガと重なるため改めた。芽吹き・開眼などの案は分かりにくいとされ、「進化」にした。
