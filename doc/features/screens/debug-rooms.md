# 画面一覧：デバッグルーム

## スキルのデバッグルーム

`CardSkillLab.unity` は、スキルの演出（VFX）だけを確かめるデバッグ用のシーンである。
`BattleLab.unity` では、確かめたいカードが手札に来るまでターンを進め、エネルギーをためてから使う必要があり、演出を作りながら何度も見るには手間が多すぎた。

画面には、戦闘と同じ夕暮れの高原の3Dの舞台に、味方4人と敵3体を戦闘と同じ位置で立たせる。
手札・行動順・エネルギー・HPバー・弱点・ダメージの数字は置かない。
カメラ、ポストプロセス（Bloom・レンズ・色調）、エフェクトの層の順番は戦闘画面と同じにしており、演出は戦闘中と同じ見た目で再生される。
使い手が1歩出る動き、当たった敵が白く光ってはじかれる動き、撃破で崩れて消える動き、カメラの中心のゆっくりした円運動は、戦闘画面の処理（`BattleInspectView`・`BattleStageDrift`）が出すため、このシーンには出ない。

Play Modeにすると、前回選んだスキルを再生する（初回は1枚目の斬り払い）。
選んだスキルと、当たり・ねらう敵・覚醒・くり返しの設定は、このPCの `PlayerPrefs` に残る。
演出のコードを直してPlayし直すと、同じスキルから確かめられる。

| 操作 | 動作 |
|---|---|
| 上部の表示 | 再生中のスキルの番号・名前と、使い手・コスト・種類・対象の範囲。覚醒させて再生するときは、後ろに「覚醒して使う」と書く |
| 覚醒（右上） | 入にすると、覚醒できる固有スキル（最初の段階と1段目）を、[戦闘中の覚醒](../skill-evolution.md#戦闘中の覚醒)と同じ流れで再生する。選んだ段階のカードが浮いてひびが入り、[覚醒先を選ぶ画面](../skill-evolution.md#覚醒先を選ぶ画面)で選んだ段階に割れて覚醒し、その段階の演出を再生する。選んでいる間は、上部の表示・右上・下の操作の列・「ホームへ」を隠す。その Play の間に一度覚醒した段階は、候補に「取得済み」と出す。2段目とカードスキルは、入でもそのまま再生する。初めは切 |
| スキル一覧 | 全スキルを、戦闘と同じカード（挿絵・説明文・[キラキラ](../../art/direction.md#カードのキラキラ)）で並べて開く。「カードスキル」（1〜50番、1行に8枚）と「[固有スキル](../skill-evolution.md)」（51〜134番、1行に7枚で、1行が1本の覚醒ツリー）と「[覚醒版](../skill-awakening.md)」（135〜234番、1行に8枚で、スキルごとに2つの枝が並ぶ。2026-10-24）の3つのタブに分け、上下のスワイプでスクロールする。4つめの「溜め」のタブには、スキルが最初に出す溜めを名前のボタンで1行に3つ並べる（2026-10-23、ユーザーの依頼）。押すと、トーマが溜めだけを当てる相手なしで再生し、残った光や焦げ跡が消えるまで待つ。属性のない溜めは形の違いで見比べられるよう炎の色で、属性の前触れはその属性の色で出す。並べるのは、魔法の溜め、魔法の溜め・大技、固有スキルの溜め・1段目、固有スキルの溜め・最終段、[炎の溜め](../../catalog/skills/skill-fire.md#演出の時間設計)（層に分けた魔法陣）と、2026-10-24に足した吸い込む溜め、立ち上るオーラ、刃のきらめきと踏み込み、氷・雷・土の前触れ、段階で変わる溜めの12種類である（[スキルの溜めの演出](../skill-windups.md)）。番号はスキルに続けて数え、「次へ」は最後の溜めのあと1枚目のスキルへ戻る。開くと再生中のスキルのタブとカードの位置に合わせ、そのカードの後ろに金の光を出す。押したスキルをすぐ再生し、一覧を閉じる。開いているあいだは上部の表示と下の操作の列を隠す |
| 前へ・次へ | 一覧の番号の順で、前後のスキルを再生する |
| もう一度 | 今のスキルを最初から再生する |
| 当たり | 通常・弱点・とどめを順に切り替えて再生し直す。弱点ととどめでは、ヒットストップ・揺れ・炸裂が大きくなる |
| ねらう敵 | 敵1体に使うカードの対象を、苔スライム・苔むした狼・森の守り手の順に切り替えて再生し直す |
| くり返し | 入にすると、再生が終わった0.9秒後に同じスキルを再生し続ける。切にすると1回で止まる |

どの操作でも、再生中のスキルを途中で打ち切り、次のスキルを最初から再生する。
打ち切るときは、残っている形・粒子・光、背景の暗さ、閃光、カットイン、覚醒中のカード、画面の揺れと寄せ、ヒットストップで止めた時間を元に戻す（`BattleSkillVfx.Clear`）。
味方1人に使うカードは使い手の次の味方に、全体に使うカードは全員に当たる。
やけど・毒・出血・リジェネ・爆炎の刻印・雷雲のように後から働く状態は、カードの演出に続けて、働くときの演出も再生する。
使い手と対象の決め方と再生の順序は、展示室の自動再生（`BattleSkillVfxPreview`）と同じ処理を使う。

一覧のカードはPlayの開始時にスキルの定義（`CardSkills`、固有スキルの覚醒ツリー、`CardSkillAwakenings`）から作るため、カードを足してもシーンを作り直さずに一覧へ出る。ただし挿絵はPlay中に読み込めないため、生成のときに焼き込む。新しい挿絵を足したら `Baryonyx > Combat > Create Card Skill Lab Assets` で作り直す。
停止中のシーンでは一覧の中身が空のため、並びは `CardSkillLabScreen` のInspectorの「一覧を開いた（カードスキル）」「一覧を開いた（固有スキル）」「一覧を開いた（覚醒版）」「一覧を開いた（溜め）」で確かめる（[停止中の表示の切り替え](common.md#停止中の表示の切り替え)）。
下の操作ボタンと一覧を閉じるボタンは、指で押せる高さ（設計上128）にした。
ボタンは景色の上に置く濃い板の[すりガラスのカード](guide.md#すりガラスのカード)にした。
一覧のカードは戦闘の手札のカードを0.8倍にしたもので、手札のドラッグの操作は外しており、カードの上でスワイプしても一覧がスクロールする。

シーンは `Baryonyx > App > Create Card Skill Lab Scene` で作り直す。
画面のPrefabは `Features/Combat/UI/CardSkillLabScreen.prefab` である。
[ホーム](top-home.md#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](top-home.md#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](../showcase.md)のシーン一覧から開く。
ホームから開くときは、案内人の画面と同じシャッターの演出で切り替わる。
左上の「ホームへ」を押すと、再生中のスキルを止めてホームへ戻る。連打しても1回だけ遷移する。
「ホームへ」は一覧の見出しと重なるため一覧を開いているあいだは隠し、戻り先を設定していないとき（展示室のPrefabのプレビュー）も出さない。

## 品質のデバッグルーム

`QualityLab.unity` は、[品質](../inventory.md#品質)を確かめるデバッグ用のシーンである。
スキル・固有スキル・武器・防具・アクセサリーのどれでも、倍率を動かしたときの品質の文字、[カードのキラキラ](../../art/direction.md#カードのキラキラ)、効果の数字の変わり方を、ゲームを進めずに見られる（2026-10-19、ユーザーの依頼）。

| 面 | 表示と操作 |
|---|---|
| 左上 | 「ホームへ」。[ホーム](top-home.md#ホーム画面の見た目モック)へシャッターの向こうで戻る。戻り先のないとき（展示室のPrefabなど）は隠す |
| 上 | 「スキル」「固有スキル」「武器」「防具」「アクセサリー」のタブ |
| 左 | 選んだタブの物の一覧。押した物を選び、金の帯で示す。上下のスワイプでスクロールする |
| 真ん中 | 今の倍率の見た目。スキルは戦闘と同じカード（倍率を掛けた説明文・コスト・キラキラ）、ほかは絵の板（アイコンにキラキラ、名前、★、右上に品質の文字）。下に「品質ごとの見比べ」として、C・B・A・Sそれぞれの中ほどの倍率で同じ物を小さく並べる |
| 右（上） | 名前、種類・レア度（★）・上限の倍率。大きな品質の文字（品質の色）、倍率と幅の中の位置、品質ごとの倍率の範囲 |
| 右（帯とつまみ） | 幅の帯（左端が×1.00、右端が上限。C・B・A・Sの区間を品質の色で塗り、今の位置に白い印）。倍率のつまみ（×1.00〜上限）。C・B・A・Sのボタンはその品質の中ほどへ、「−0.01」「+0.01」は1ずつ動かす |
| 右（上限） | 上限のつまみ（×1.05〜×4.00）で、種類の上限を試しに変える。変えている間は上限の後ろに「（試し）」を出す。「上限を戻す」で種類の上限に戻る |
| 右（下） | 倍率を掛けた効果、×1.00のときの効果、倍率で変わる数字の変化（スキルはコスト・威力の割合・回数・ターン・量）と、その物の光り方（「コスモ・金」など。[カードのキラキラ](../../art/direction.md#カードのキラキラ)） |

Play Modeにすると、前回選んだタブ・物・倍率から始まる（初回はスキルの1枚目を品質Sの中ほどで出す）。
選んだタブ・物・倍率は、このPCの `PlayerPrefs`（`Baryonyx.QualityLab.Tab`・`Entry`・`Multiplier`）に残る。
上限の試しの値は残さない。
倍率は百分率の整数（×0.01刻み）にそろえ、×1.00より下と上限より上には動かない。
アクセサリーはまだデータがないため、見本の3つ（見本のアクセサリー1〜3、絵はコンパスの仮）を置く。
スキルのレア度は未決のため★を出さない。

一覧の行と見た目はPlayの開始時にカードと装備の定義から作るため、スキルや装備を足してもシーンを作り直さずに出る。
ただし挿絵はPlay中に読み込めないため、生成のときに焼き込む。新しい挿絵を足したら `Baryonyx > Inventory > Create Quality Lab Assets` で作り直す。
配置は幅1700の枠に入れて中央に置き、16:9の画面にも収まるようにした。
シーンは `Baryonyx > App > Create Quality Lab Scene` で作り直す。
画面のPrefabは `Features/Inventory/UI/QualityLabScreen.prefab` である。
[ホーム](top-home.md#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](top-home.md#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](../showcase.md)のシーン一覧から開く。

## 敵の挙動デバッグルーム

`EnemyLab.unity` は、敵の挙動だけを確かめるデバッグ用のシーンである。
`BattleLab.unity` で敵を動かすには、ターン終了を押して行動順で敵の番が来るのを待つ必要がある。
凍結や出血が付いた敵の行動、撃破の動きを見るには、そのカードが手札に来るまでターンを進める手間もかかる。

画面は[戦闘画面の見た目モック](battle.md#戦闘画面の見た目モック)と同じPrefab・3Dの舞台・カメラ・ポストプロセスを使い、手札・エネルギー・山札・ターン終了だけを隠す。
行動順、HPバー、弱点のアイコン、スキル名とターンの帯、ダメージの数字は戦闘と同じく出る。
敵の動きは、戦闘画面のモックの処理（`BattleInspectView`）をそのまま呼び出して再生する。
そのため、モックの敵の行動や被弾の処理を直すと、このシーンにも同じ変更が出る。
[スキルのデバッグルーム](#スキルのデバッグルーム)は演出だけを再生し、当たった敵の反応を出さない。このシーンは、敵の側の動きと反応を確かめるためのものである。

画面の下に2段の操作盤を置き、上の段で敵を、下の段で行動を選ぶ。
選んだ敵の頭の上には、カードで対象を選ぶときと同じ▼のカーソルを出す。
行動のボタンを押すと、選んだ敵がすぐにその行動をする。
操作盤の板とボタンも[すりガラスのカード](guide.md#すりガラスのカード)にし、最後に押した行動を金の縁と光で示す。

| 操作 | 動作 |
|---|---|
| 敵の表示 | 選んでいる敵の名前、攻撃の名前と威力、HP（現在/最大）、付いている状態 |
| 前の敵・次の敵 | 選ぶ敵を、画面の左から苔スライム・苔むした狼・森の守り手の順に切り替える |
| くり返し | 入にすると、最後に押した行動を、終わるたびに0.8秒おいて再生し続ける。毎回「元に戻す」と同じ状態に戻してから再生するため、どの回も同じ状態から始まる |
| 元に戻す | 敵と味方を開始時のHPに戻し、状態とブロックを消し、弱点の開示を開始時に戻す（狼の氷と守り手の炎だけが開示済み） |
| 攻撃 | 敵のターンと同じ攻撃。1歩前に出てスキル名を出し、立っている味方1人をランダムに選んで攻撃し、戻る |
| 被弾 | 最大HPの10%のダメージを受ける。白く光り、赤くなって揺れ、数字が浮かび、HPバーが減る |
| 弱点に被弾 | 同じダメージを、まだ開示していない弱点（なければ1つ目の弱点）の属性で受ける。ダメージは弱点の倍率を掛けた値で、弱点の数字で表示する。未開示の弱点は光って開示する |
| 撃破 | 残りのHPと同じダメージを受けて崩れて消え、行動順から消える。守り手はボスとして長く重く崩れる |
| 凍結中に攻撃 | 凍結を付けてから攻撃させる。「凍結で動けない」と出て行動せず、凍結が消える |
| 麻痺中に攻撃 | 麻痺を付けてから攻撃させる。威力が25%下がる。麻痺は、元に戻すか、敵のターンを重ねて持続ターンが尽きるまで残る |
| 出血中に攻撃 | 出血を付けてから攻撃させる。行動のあとに出血のダメージを受ける |
| 反射に攻撃 | 立っている味方全員に反射を付けてから攻撃させる。攻撃は敵自身へはね返る。使われなかった反射は、攻撃のあとに外す |
| 技 | その敵の[技と行動パターン](../combat-enemy-behavior.md)で、次に使う技を1つ使う。押すたびに行動パターンが進むため、押し続けると1ターン目の技、割り込む技、激化（5ターン目から）の順に見られる。ターンの数は戦闘画面のターン（このシーンでは1のまま）で数えるため、6ターン目からの後半や激化は、敵のターンを重ねてから押すと出る |
| 大技（溜め） | その敵の溜める技を、溜め（「力を溜めている」「あと〇ターン」の2行と暖色の明滅）から当たるまで続けて使う。溜める技のない敵は、いちばん威力の大きい技を使う |
| 敵のターン | 戦闘と同じ敵のターン。「敵のターン」の帯を出し、行動順で次の味方のターンまでの敵が順に行動してから、次の味方のターンを始める |

付ける状態の持続ターンと威力は、その状態を付けるスキルの定義（`CardSkills`）から取る。
このシーンではカードの使い手が決まらないため、威力の元になるステータスが最も高い味方が付けたものとする（出血はアリアの物攻から決まる）。
倒れた敵を選んで行動させると、その敵のHPを戻してから行動させる。味方が全員倒れているときも、味方を戻してから行動させる。
行動中は操作盤のボタンを押せない。くり返しの間だけは行動のボタンを押せ、次の回から再生する行動が切り替わる。

選んだ敵・行動・くり返しの設定は、このPCの `PlayerPrefs` に残る。
敵の処理を直してPlayし直すと、同じ敵と行動から確かめられる。くり返しを入にしたまま終えると、次のPlayの開始時から再生を始める。
操作盤のボタンは、指で押せる高さ（設計上128）にした。

「攻撃」と、状態を付けてからの攻撃は、戦闘画面のモックの仮の動き（敵ごとに単体攻撃が1種類）である。
2026-10-22に、冒険の戦闘の敵が[技と行動パターン](../combat-enemy-behavior.md)で動くようにしたため、「技」と「大技（溜め）」を足した。
どちらかを押すと、その敵はそれ以後、元に戻すまで、敵のターンでも技と行動パターンで動く。
敵の行動を足したときは、このシーンの行動の種類も合わせて増やす。

シーンは `Baryonyx > App > Create Enemy Lab Scene` で作り直す。
操作盤のPrefabは `Features/Combat/UI/EnemyLabPanel.prefab` で、戦闘画面のPrefab `BattleInspectScreen` はモックと共用する。
[ホーム](top-home.md#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](top-home.md#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](../showcase.md)のシーン一覧から開く。

## 戦闘の演出デバッグルーム

`BattleMomentLab.unity` は、戦闘の節目の演出（魔物の出現、ターンの帯、勝利、ドロップ、全滅、ルーン復活）を確かめるデバッグ用のシーンである（2026-10-20、ユーザーの依頼）。
戦闘を進めて勝ったり負けたりしないと見られない演出を、ボタン1つで何度でも再生できる。
スキルの演出は[スキルのデバッグルーム](#スキルのデバッグルーム)、敵の行動と被弾は[敵の挙動デバッグルーム](#敵の挙動デバッグルーム)、カードのキラキラは[品質のデバッグルーム](#品質のデバッグルーム)で確かめる。

画面は[敵の挙動デバッグルーム](#敵の挙動デバッグルーム)と同じく、戦闘画面のモックのPrefab・3Dの舞台・カメラ・ポストプロセスを使い、手札・エネルギー・山札・ターン終了だけを隠す。
演出は戦闘画面のモックの処理（`BattleInspectView`）が再生するため、ターンの帯や撃破の崩れ方を直すと、このシーンにも同じ変更が出る。
画面の下に2段の操作盤を置き、上の段に戦闘の途中の演出、下の段に戦闘の終わりの演出を並べる。
ボタンは景色の上に置く[すりガラスのカード](guide.md#すりガラスのカード)で、最後に押した演出を金の縁と光で示す。

| 操作 | 演出 |
|---|---|
| 魔物が現れた | 敵が自分の場所の右奥から暗い影のまま1体ずつ歩み出て、光の中に入るにつれて色が戻り、着地で土煙を上げ、床を這う土ぼこりと砂利を出す（2026-10-26までは床に光の輪を出していた。着地では光の輪は生じないため外した）。そろったら赤い帯で「魔物が現れた！」、続けて「味方のターン　ターン1」を出す |
| 強敵が現れた | ほかの敵がそろったあと、景色を暗くしてからボス（森の守り手）が遅く重く歩み出る。着地で土煙を多く上げ、床に赤い光を広げ、画面を揺らす。帯は「強敵が現れた！」 |
| 味方のターン・連続ターン | 戦闘と同じターンの帯（「味方のターン　ターン1」「連続！ もう一度 味方のターン」） |
| 敵のターン | 戦闘と同じ敵のターン。帯を出し、行動順で次の味方のターンまでの敵が順に行動する |
| エネルギー不足 | スキル名の帯に、戦闘と同じ赤で「エネルギー不足」を出す |
| 勝利 | 立っている敵が0.18秒ずつずれて崩れて消え、少し間をおいて金の帯で「勝利！」を出す。帯の文字が弾んで収まり、帯の奥で光の線の花火が弾ける。味方は足元に金の光だまりを置いて照らされ、2回跳ねて喜び、細い光の線と光の粒が立ちのぼる（[勝利の演出](battle-effects.md#勝利の演出)）。冒険と街道の戦闘では、始めに手札を片付ける |

宝箱の震える間と光は、品質が高いほど長く大きくする。
宝箱は探索の宝箱と同じ絵（敵の1ドットの1.6倍で描く）で、キャラと同じ層に立てる。宝箱から漏れる光と柱は品質の色（[品質](../inventory.md#品質)の文字と同じ。Sは金、Aは紫、Bは青、Cは灰）で描く。

| 品質 | 震える間 | 開いたとき |
|---|---|---|
| C | 0.35秒 | 白い光と床の輪だけで、柱は立たない |
| B | 0.5秒。光の粒が引き寄せられる | 細い光の柱と光芒 |
| A | 0.75秒。床に魔法陣が開く | 高い柱、2重の床の輪、まわりへの光、画面の小さな揺れ |
| S | 1.1秒。引き寄せる粒も多い | 太く高い柱、多くの光の粒、柔らかな画面の閃光と揺れ |

景色は暗くしない。暗さはキャラと同じ層の宝箱も暗くするためである。

手に入れた物の札は、画面の上寄りの中央（味方の頭より上）に、宝箱が開くのと同時に0.08秒ずつずれてばねのように開く。
左にアイコン（品質S・Aは持ち物と同じキラキラを重ねる）、右に種類（今の見本は「武器　★★★★」のような装備）、名前、「持ち物に加えました」を書き、右上に品質の文字が大きく落ちてくる。
札は[探索の演出デバッグルーム](#探索の演出デバッグルーム)の宝箱と[冒険の戦闘](adventure.md#冒険の画面)のドロップと共用する部品（`Shared/UI/Reward/RewardReveal`）である。
札の縁は品質の色にする。
何も見つからなかったときは、宝箱を出さずに札だけを開いて「何も見つからなかった」と書く。
札は次の演出を始めるか、元に戻すまで残る。
ドロップの中身は、絵のある装備を武器・防具・アクセサリーから☆の多い順に2つずつ取った6つを順に3つずつ使う見本で、品質だけを操作盤で選ぶ（2026-10-24、ACTボーナスの見本から替えた）。

PlayModeにすると、前回選んだ演出を再生する（初回は「魔物が現れた」）。
選んだ演出・ドロップの品質・くり返しの設定は、このPCの `PlayerPrefs`（`Baryonyx.BattleMomentLab.Moment`・`Quality`・`Repeat`）に残る。
演出のコードを直してPlayし直すと、同じ演出から確かめられる。
演出の再生中は操作盤のボタンを押せない。くり返しの間だけは演出のボタンを押せ、次の回から再生する演出が切り替わる。
ドロップとルーン復活は、それぞれの前の状態（敵が消えた状態、味方が倒れた状態）から始める。ほかの演出は、毎回元に戻してから再生する。

出現・勝利・ドロップ・全滅・復活の演出は、[冒険の戦闘](adventure.md#冒険の画面)でも同じ処理（`BattleInspectView`）で再生する。
冒険の戦闘は、出現（最奥の間では強敵の出現）の演出のあとに手札を配り、勝利の演出、マスのドロップを1つずつ、全滅の演出のあとにダイアログを出し、ルーンで復活すると復活の演出を再生する。
このシーンで演出を直すと、冒険の戦闘にも同じ変更が出る。

シーンは `Baryonyx > App > Create Battle Moment Lab Scene` で作り直す。
操作盤とドロップの札のPrefabは `Features/Combat/UI/BattleMomentLabPanel.prefab` で、`Baryonyx > Combat > Create Battle Moment Lab Assets` で作り直す。
操作盤のPrefabを作り直したあとは、シーンも作り直す（Prefabの部品のIDが振り直され、シーンに残った古い上書きが札の配置を崩すため）。
[ホーム](top-home.md#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](top-home.md#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](../showcase.md)のシーン一覧から開く。

## 探索の演出デバッグルーム

`ExplorationMomentLab.unity` は、[探索](adventure.md#冒険の画面)の節目の演出（魔物のマスに入ったときの出現、宝箱を開ける、マスへ進む）を確かめるデバッグ用のシーンである（2026-10-20、ユーザーの依頼「Explorationの各種 魔物が現れた！みたいなやつも入ります」）。
[戦闘の演出デバッグルーム](#戦闘の演出デバッグルーム)と対になり、互いのシーンへ移るボタンを置く。

画面は探索画面のPrefabを、冒険の流れ（`ExplorationBootstrap`）を置かずに使う。
探索画面は見本の道（展示室と同じ種）を入口から描き、冒険の状態もサーバーも読まない。
地図の下側にパーティが立つため、操作盤の2段は画面の上（行き先と階の文字の下）に置く。

| 操作 | 演出 |
|---|---|
| 魔物が現れた | パーティが驚いて小さく跳ね、駒の絵の上端から30px上に太い「！」がばねのように現れて上下し（2026-10-29、駒と重ならないよう駒の絵の上端から測るようにした）、地図が少し揺れる。続けて、戦闘のターンの帯と同じ形の赤い帯で「魔物が現れた！」を出し、画面の端から横長の黒い帯が左右交互に閉じる。冒険では、閉じたところで戦闘のシーンへ移る。このシーンでは、閉じたあと帯が開いて地図へ戻る |
| 強い魔物が現れた | 「！」と帯を明るい赤にし、「！」を大きく、地図を強く揺らす。帯は「強い魔物が現れた！」 |

| 宝箱を開ける | パーティのいるマスの右手前に閉じた宝箱を置き、選んだ品質の中身で開ける（下記） |
| マスへ進む | 入口から次の階の最初のマスへ、パーティが道を歩き、着いてから新しく見えたマスの印が現れる。探索でマスを選んだときと同じ動き |
| 宝箱：S | 次の宝箱の品質を、C・B・A・S・なし（何も見つからなかった）の順に切り替える |
| くり返し・元に戻す | 戦闘の演出デバッグルームと同じ。元に戻すと、見本の道の入口に戻り、宝箱と演出の部品を消す |

宝箱は、品質が高いほど長く震えてから開く（C 0.35秒、B 0.5秒、A 0.75秒、S 1.1秒）。
震える間、宝箱の後ろに品質の色の光がふくらみ、Aからは光芒が回り始め、景色が暗くなる（Sのほうが暗い）。
開くと、白い光が弾けてから品質の色の光と光芒（Bから）が広がり、光の粒が飛び上がって落ちる。Sは宝箱から画面いっぱいに光が広がる。

PlayModeにすると、前回選んだ演出を再生する（初回は「魔物が現れた」）。
選んだ演出・宝箱の品質・くり返しの設定は、このPCの `PlayerPrefs`（`Baryonyx.ExplorationMomentLab.Moment`・`Quality`・`Repeat`）に残る。

冒険では、出現の演出で幕が閉じきったところで戦闘のシーンへ移り、宝箱は開けた中身で演出を再生する。
このシーンで演出を直すと、冒険の探索にも同じ変更が出る。
強い魔物と最奥の主の帯の文（「強い魔物が現れた！」「最奥の主が現れた！」）は、このシーンで仮に決めた。

シーンは `Baryonyx > App > Create Exploration Moment Lab Scene` で作り直す。

## TempLab

`TempLab.unity` は、ユーザーに「こういうことはできるか」と聞かれたものを仮に組み、撮影して見せるためのデバッグ用のシーンである（2026-10-25、ユーザーの依頼）。
決まった用途を持たず、試すたびに中身を入れ替える。

画面には、[スキルのデバッグルーム](#スキルのデバッグルーム)と同じ夕暮れの高原の3Dの舞台を、戦闘と同じカメラ・Bloom・レンズ・色調で置く。
キャラ・敵・操作は置かず、その上に試作のUIを置く空のCanvasを重ねる。
試作の部品は、`TempLabRoom` から舞台のカメラ・舞台・Canvasの `SafeArea` をたどる。

試作は次のように扱う。

- コードとアセットは `Features/TempLab/` に置き、シーンへの配置は `TempLabSceneSetup` に足す。シーンには手で置かない。
- 撮影した画面は `client/Assets/DevCaptures/TempLab/`（Git対象外）に置く。
- 採用が決まったものは、本来の機能の場所へ移す。試し終えたら `Features/TempLab/` から消し、シーンを作り直して舞台だけに戻す。

シーンは `Baryonyx > App > Create Temp Lab Scene` で作り直す。
[ホーム](top-home.md#ホーム画面の見た目モック)の右上の[デバッグルームの一覧](top-home.md#デバッグルームの一覧)から開くほか、シーンを単体で開くか、[展示室](../showcase.md)のシーン一覧から開く。
Homeから開いたときは、右上に共通の「ホームへ」を重ねる。

今の試作（2026-10-26、ユーザーの依頼）は、トーマがモスウルフへ放つファイア・斬撃・雷で、`TempLabEffectReel` が順に繰り返す。ユーザーから受け取ったVFXの指示書（外部の画像を使わず形・濃淡・材質を計算で作る、層を分ける、予兆・発動・余韻に分ける）に従って作った。炎と煙は3Dのノイズの密度を視線に沿って積み重ねて描き（`TempLabVolume.shader`）、光・筋・地面の跡は板の上に計算で描く（`TempLabGlow.shader`）。技ごとに点光源を持ち、舞台と2人を照らす。雷は落ちる前に舞台の主光源を落とす。2人は戦闘と同じく `Hd2dUiBillboard` で舞台に立たせる。炎と煙は深度のテクスチャで地面に隠すため、URPアセットの Depth Texture が要る（Android用の Mobile_RPAsset は切ってあり、端末では未確認）。
