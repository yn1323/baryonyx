# 画面一覧：Topとホーム

[画面一覧](../screens.md) / 根拠：[初期企画](../../game/brief.md)

## Top

起動シーンのTopは、[3Dの舞台](common.md#3dの舞台hd-2d)の星空の夜の山の門の手前に、題名と開始の案内を出す。

- 画面を覆った状態からFade演出（0.75秒）で開き、開き終わるまではタップを受け付けない。開き終わってから開始の案内を表示し、全面押下の受付を始める。
- 起動時のスプラッシュ画面や開く演出の途中で押した操作は、Homeへの遷移に使わない。
- 開始の案内は、起動処理が終わるまで「LOADING...」、終わると「TAP TO START」になる。起動処理、連携モーダル、失敗時の再試行は[起動時の連携と歩数の同期](../startup-sync.md#top画面の流れ)を正本とする。
- 全面を押すと、上下から閉じるShutter演出（閉じる・開くとも0.75秒）でHomeへ移る。シーン間の移動でこの長い演出を使うのは、TopからHomeへの移動だけとする。
- 題名と開始の案内は、Safe Areaに追従する `TopSafeArea` の中のアンカーで置く。

### 画面遷移の演出

画面遷移の演出は [SceneTransitionController](../../../client/Assets/Baryonyx/Shared/UI/SceneTransition/SceneTransitionController.cs) が受け持ち、Fade、Wipe、上下・左右のShutterから選ぶ。
共通のPrefabと、Top・Homeへの配置は `Baryonyx > App > Create Scene Transition Assets` で作り直す。ほかのシーンへの配置は、各シーンを作るメニューが行う。
Inspectorの `Exit` と `Enter` にある `SceneTransitionSettings` で、種類、色、閉じる時間、開く時間、Wipeの向き、Shutterの軸をそれぞれ選べる。
WipeとShutterはドット絵に合わせ、`Stepped Frame Rate`（初期値25）の回数だけ1秒間に位置を更新するコマ送りで動く。値を上げるほど滑らかになり、0で毎フレーム動かす。Fadeは常に滑らかに変化する。
ほかの画面へ移るときは [SceneLoader](../../../client/Assets/Baryonyx/Shared/UI/SceneTransition/SceneLoader.cs) が演出で画面を覆ってからシーンを読み込む。
遷移先には `startCovered` と `revealOnStart` を設定し、開く演出を自動で再生させる。
読み込んだ先のシーンは、遷移元が閉じたときと同じ演出で開く。遷移元の `Exit` が閉じ方と開き方を決め、遷移先の `Enter Settings` は起動直後など遷移元がないときにだけ使う。

| 遷移元 | 閉じる・開く演出 |
|---|---|
| Top | 上下のShutter（閉じる・開くとも0.75秒） |
| Top以外（Home、案内人がいる画面、探索、戦闘） | Fade（閉じる・開くとも0.15秒） |

演出は1フレームで最大1/30秒ずつ進める。シーンを読み込んだ直後の重いフレームでも短い演出が一度に終わらず、暗くなってから少しずつ明るくなる。

## ホーム画面の見た目モック

ホーム画面は、デザインモックのA2案（焚き火を囲む「野営地」）を昼の森に置いた構成である。
横長の画面の余白は、キャラクターの立ち絵ではなく背景の世界とパーティ全員で埋める。
Topの全面押下で開く。
計画と判断の経緯は[実装計画](../../plans/2026-09-24-home-camp-mock.md)に記す。

#### デバッグルームの一覧

ボタンを押すと、共通のダイアログに、[スキルのデバッグルーム](debug-rooms.md#スキルのデバッグルーム)・[品質のデバッグルーム](debug-rooms.md#品質のデバッグルーム)・[戦闘画面のモック](battle.md#戦闘の背景を選べる戦闘シーン)・[敵の挙動デバッグルーム](debug-rooms.md#敵の挙動デバッグルーム)・[戦闘の演出デバッグルーム](debug-rooms.md#戦闘の演出デバッグルーム)・[探索の演出デバッグルーム](debug-rooms.md#探索の演出デバッグルーム)・[召喚の演出デバッグルーム](debug-rooms.md#召喚の演出デバッグルーム)・[TempLab](debug-rooms.md#templab)と「閉じる」を、この順に左から右へ、2列で並べる（2026-10-21、召喚は2026-10-24、TempLabは2026-10-25に追加）。
選んだルームは、案内人の画面と同じシャッターの演出で開く。「閉じる」で一覧を閉じると、Homeのまま操作を続けられる。
スキルと品質のデバッグルームは自分の「ホームへ」を持つ。ほかの6つは持たないため、Homeから開いたときだけ、共通の「ホームへ」（`DebugRoomReturn`）を重ねる。置く角はルームごとに、ルームの操作と重ならない所を選ぶ。戦闘画面のモックと戦闘・敵の挙動のデバッグルームは、左上に行動順のアイコンがあるため右上（ルームの名前の下）、探索の演出デバッグルームは、上に場所の名前と操作盤があるため左下に置く。召喚の演出デバッグルームは、下に操作盤があるため右上（ルームの名前の下）に置く。TempLabは操作を持たないため、ほかと同じ右上に置く。戦闘と探索の演出デバッグルームは「探索の演出へ」「戦闘の演出へ」で互いに移れるため、Homeから開いたあとに移った先にも、その角に重ねる。Homeなど、この4つ以外のシーンを開くまで続ける。シーンを単体で開いたときや展示室から開いたときは重ねない。
一覧の先頭には「ルーン+10000」を置く（2026-10-24、ユーザーの指示「問答無用でルーンを10000追加するボタンがほしい」）。押すと一覧を閉じ、サーバーの所持ルーンに10,000を足して保存し、ACTパネルの所持ルーンを増える演出で更新する。サーバーのAPI（`POST /v1/debug/runes`）はローカルとDevでだけ使え、Prodでは見つからない（404）として扱う。サーバーの接続先がないときは、画面の残高に足すだけにする。足せなかったときは「ルーンを足せませんでした」と知らせる。
ダイアログの選択肢は、「ルーン+10000」と8つのルームと「閉じる」の10個を、ほかのダイアログと同じ高さ112の行に2列で並べ、5行に収める（2026-10-25、ユーザーの指示「デバッグルームが長くなってきたから2列にリストして」）。それまでは1列で、行を76まで低くしていた。
主要な操作のタップ領域は、48dpに相当する約128px（設計座標）以上を確保する。
押している間は、ボタンの明るい部分を少し暗くする（色に約0.72を掛ける）。
行き先カードは行き先の絵を暗くする。
暗い下地に置いたボタン（ACTパネル、設定、デバッグルームの一覧、左下の4つ）は、下地だけでなく上のアイコンと文字も同じ暗さにする。
位置をずらす演出は付けない。
4:3など1920より狭い画面では、中央の世界を縮めて四隅のボタンと重ねない。

### ルーン獲得の演出

ACTパネルを押してルーンを獲得すると、パネルを押した位置からルーンが四方へ一気に広がる（画面の外まで飛んでよい）。押した位置が分からないとき（ボタンを直接呼び出した場合など）は、パネルの「タップでルーン獲得」の文字から広がる。広がる距離も獲得量の桁数に応じて伸ばし、1ルーンで140px、10万ルーン以上で520px（設計座標）を上限にする。
ルーンの数は獲得量の桁数に応じて増やし（1,340で26個、36,896で34個、上限40個）、獲得量より多くはしない。
広がったルーンは間を置かずに（0.08秒）、全部まとめて加速しながら右上の所持ルーンのアイコンへ吸い込まれる。吸い込み始めは0.15秒の幅でばらけ、吸い込まれる時間は平均0.55秒で、ルーンごとに±40%（0.33〜0.77秒）の幅でばらつかせる。
ルーンが1つ着くたびに所持数を付与前の残高から増やし、アイコンを小さく跳ねさせる。
同時に、所持ルーンのアイコンから白から水色へ変わる四芒星と点のキラキラを3粒弾かせ、アイコンに重ねた加算の光を小さく明るくする。最後の1粒では16粒を大きく弾かせ、光を強くしてから広げながら0.5秒で消す。キラキラは画像を使わず計算で描き、四芒星は白い芯から四方へ細い光が伸びる20px、点は丸く光る頭に短い尾を引く粒にする（`Hd2dEmberEmitter`、マテリアル `Hd2dUiSparkle`・`Hd2dUiEmber`）。所持数の文字にかからないよう左寄りへ飛ばす。アイコンに重ねる光も、白い芯と水色のハローを計算で描く（`Hd2dUiGlowCore`）。
ルーンが弾ける瞬間にも、弾けた位置から同じ色のキラキラを24粒、四方へ散らす。広がるときも吸い込まれるときも、各ルーンは0.07秒ごとに通り道へキラキラを1粒残す。キラキラは飛ぶルーンより手前に描く。
キラキラの後ろには、ぼかした水色の光（モヤ）を漂わせる。弾けた位置には大きなモヤを6つ、通り道にはキラキラ2粒ごとに1つ、着いた位置には1粒ごとに1つ、最後の1粒で4つ出す。モヤは縁がゆらぐ柔らかい光（`Hd2dUiPuff`）で、飛ぶルーンより奥に描く。星は強めに瞬かせる。
所持数の文字は吸い込んだ量に比例して大きくし、全部が着いた時点で1.45倍・金色になる。少し止めてから元の大きさと色へ戻す。
所持ルーンのアイコンも文字と同じ倍率で大きくし、その上に1粒ごとの跳ねを重ねる。アイコンは文字の中心から同じ倍率で広げた位置へ寄せ、大きくなった文字と重ならないようにする。吸い込まれるルーン・光・キラキラは、動いたアイコンの位置へ向ける。
所持数の下には「+獲得量」を出し、所持数と一緒に少し大きくし、全部が着いてから消す。
演出は約2秒で終わり（最後の粒が着くまで最長約1.25秒）、早送り・省略の操作は設けない。
獲得量が0のときは、「獲得ルーンはありません」を[共通の通知の帯](../../rules/ui-design.md#操作を求めない通知)で約1.4秒表示する。
同期に失敗したときや未連携のときは、演出を出さずに従来のトーストで知らせる。
展示室のPrefabのプレビューでは、ACTパネルを押すたびに見本の獲得（+1,340）と「獲得ルーンはありません」を交互に表示する。
