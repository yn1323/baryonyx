# 画面一覧：共通の決まり

[画面一覧](../screens.md) / 根拠：[初期企画](../../game/brief.md)

## 確定している方針

画面は横持ちとし、1920×1080の設計座標で作る（[UI設計ルール](../../rules/ui-design.md#画面方向と拡縮)）。
2026-09-18の参照会話で採用した、探索中の仲間・装備変更、左右の戦場、上部の敵予告、下部のHP・スキルの配置は、[操作試作の記録](../../archive/game-wireframe.md)に残す。
このうち戦闘画面の配置は、2026-09-27に廃止したリアルタイム戦闘のワイヤーで採用したものである。
カードバトルの画面構成（手札、エネルギー、敵の弱点と行動の予告）、カードと標的の選び方、捨てる操作は、今の戦闘画面（`BattleInspectView`）の作りとする（[戦闘画面の見た目モック](battle.md#戦闘画面の見た目モック)。2026-11-02、ユーザーの判断で未決から確定にした）。
召喚（ガチャ）は[神殿](temple.md#神殿)、ルーンで物を買う店は[商会](shop.md#商会)の「[買う](shop.md#買う)」の画面とする（2026-11-02、同じく今の作りを確定にした）。課金で買う画面は今はない。

冒険の探索は、森を見下ろす地図で分岐ルートとマスの印を見せ、行けるマスの札を押して進む（[冒険の画面](adventure.md#冒険の画面)）。
出発前の行き先選び（旅の案内所）と、入った後の探索の操作を区別する。
探索・戦闘の具体的な表示要件と未確定事項は、下表の正本に従う。

### 持ち物のカード風の見た目

武器・防具・アクセサリー・アイテムも、スキルのようなカード風の見た目にしていく意向があった（2026-10-06、ユーザー）。
形は、今の作りを確定とする（2026-11-02、ユーザーの判断で未決から確定にした）。
一覧に並べる持ち物は、すりガラスのカードに絵・[品質](../inventory.md#品質)の文字・[レア度](../inventory.md#レア度)の☆・名前を載せた[札](../../rules/ui-design.md#装備の見せ方)で見せ、装備の付け替えの枠と一覧は[すりガラスのカード](guide.md#すりガラスのカード)の行で見せる。

## 停止中の表示の切り替え

押すと同じシーンの中で表示が切り替わる画面は、停止中のUnity Editorでも、Inspectorの「停止中の表示の切り替え」のボタンで各表示を確かめられる（規則と作り方は[停止中の表示の切り替え](../../rules/ui-design.md#停止中の表示の切り替え)）。
中身は生成時に作り込んだ仮データと、見本の値（冒険は [`AdventureDialogSamples`](../../../client/Assets/Baryonyx/Features/Adventure/Runtime/AdventureDialogSamples.cs)）で、ダイアログはPlay中と同じ組み立て（[`AdventureDialogs`](../../../client/Assets/Baryonyx/Features/Adventure/Runtime/AdventureDialogs.cs)）で出す。
「元の表示」で戻る（自動で戻る場面は[停止中の表示の切り替え](../../rules/ui-design.md#停止中の表示の切り替え)）。

## 3Dの舞台（HD-2D）

Top・Home・戦闘画面（BattleLab・Battle）は、3Dの地面と背景にドット絵のキャラを立たせ、3Dの光と影で見せる構成である。
冒険の探索（Exploration）は3Dの舞台を使わない。
キャラの位置・大きさ・動き、タップの判定、HUD・手札・HPバー・弱点などの表示と操作は変えず、UIが決めた位置の地面に3Dの板として立たせる。
カメラ・光・ポストプロセス・テクスチャ・描く順番は[3Dの舞台](../../art/hd2d-stage.md)を正本とする。
見た目は[確定している方針](../../art/hd2d-stage/stage-view.md#確定している方針)・[画面ごとの構成](../../art/hd2d-stage/stage-view.md#画面ごとの構成)（時間帯と色）・[キャラの立たせ方](../../art/hd2d-stage/stage-view.md#キャラの立たせ方)（影）・[舞台のレンズ](../../art/hd2d-stage/stage-view.md#舞台のレンズ)（ピント）・[カメラの動き](../../art/hd2d-stage/stage-view.md#カメラの動き)・[停止中の表示](../../art/hd2d-stage/stage-view.md#停止中の表示)・[Sceneタブでの表示](../../art/hd2d-stage/stage-view.md#sceneタブでの表示)を正本とする。

## 押した位置のキラキラ

画面のどこを押しても、押した位置に金の粉のキラキラを出す（2026-10-26、ユーザーの依頼）。
ホームのACTパネルや戦闘の手札も例外にしない。

- 押した瞬間に、指のまわりを細かな金の粉がゆっくり回る兆しを出す。
- 24px（設計座標）を超えて動く、0.5秒押し続ける、2本目の指が触れる、のどれかが起きたら、兆しを0.1秒かけて消す。
- 動かずに離したら、押した位置で弾ける。白い閃きのあと、22粒の粉が四方へはじけ、空気で急に遅くなって、ゆっくり落ちながら瞬いて消える。離してから消えるまで約0.7秒（長くて0.75秒）。
- 同時に弾けるのは4つまでで、超えたら古いものから消す。
- 大きさは、比べたときのブラウザの試作の0.6倍にしている（`TapSparkleLayer.Size`）。指の動きの判定（24px）には掛けない。

見た目は、TempLabで6案（金の波紋・星のきらめき・ルーンの魔法陣・金の粉・ひし形の閃き・灯火の粒）を動画で比べ、ユーザーが4番の金の粉を選び、大きく見えるため6割の大きさにするよう頼んだ。

ゲームの起動時に、すべての画面より手前（`Screen Space - Overlay`、並び順32000）に、押しても下の画面の操作を妨げない層を1つ置き、シーンを切り替えても残す（`TapSparkleLayer.Install`）。
入力は、この層がタッチ（タッチ画面がなければマウス）を直接読む。
時間は実時間で進むため、ヒットストップや一時停止の間も止まらない。
形は画像を使わず、`TapSparkle.shader` で光のにじみと点を計算して描く。
Overlayに置くためBloomは掛からず、光のにじみはシェーダーの形の中で描く。
シェーダーは名前で探すため、GraphicsSettings の Always Included Shaders に入れている（`Baryonyx > UI > Create Tap Sparkle Assets`）。
展示室では、中央を自動で押し続ける見本 `TapSparklePreview` で見る。

端末での見え方と重さ、スマホで兆しが指に隠れないかは未確認である（試作の決まりでは、兆しを指より一回り大きく出す）。
