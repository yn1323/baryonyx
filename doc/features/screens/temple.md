# 画面一覧：神殿

[画面一覧](../screens.md) / 根拠：[初期企画](../../game/brief.md)

## 神殿

神殿では、キャラ・装備・アイテムを1つにまぜた召喚を扱う（[召喚](../monetization.md#召喚)）。
メニューは「召喚」の1行で、アイコンはホームの神殿のボタンと同じ召喚の魔法陣である。
押すと、案内人を隠した全画面の召喚の画面を開く（2026-10-24、ユーザーの指示「神殿からリストを押下したらフルスクリーンにしてほしい」）。
パンくずは「神殿 › 召喚」で、「もどる」でメニューへ戻る。

| 領域 | 表示と操作 |
|---|---|
| 全面 | 聖堂のキャッチイラスト（Codex CLIの生成画像）。1回召喚の演出の始まりと同じ置き方（幅いっぱい、上端をそろえる）にし、演出へ切り替わっても絵が動かない。上の帯（もどる・パンくず・所持ルーン・×）は絵の手前に残す |
| 下の中央 | 「1回召喚」「10回召喚」の2つのボタン。どちらも下にルーンのアイコンと値段（300・3,000）を書く。「10回召喚」の上に「★3以上 1つ確定」と書く |
| 左下 | 「確率」の小さなボタン。押すと確率の窓を開く |
| 確率の窓 | 画面の中央に重ねる窓（見出し「提供割合」）。「種類ごとの確率」（キャラ・武器・防具・アクセサリー・アイテム）、「レア度ごとの確率（装備・アイテム）」（★5〜★1）、「品質ごとの確率（装備）」（S〜C）の割合の札と、「出るもの」の一覧（種類ごとに数と、名前と☆の札）を上下に流す。×・暗い幕・「もどる」・端末の戻るキーで閉じる |
| 結果の窓 | 演出のあとに重ねる窓。見出しは「1回召喚」「10回召喚」で、札を5列で2段まで並べ、1回の札は真ん中に置く。札には絵、名前、☆と分類、右上に品質の文字（装備だけ）を書く。キャラ・☆4以上・品質Sの札は金の縁と光にする。右下の「もう一度」で同じ回数を引き直す（演出も流す）。×・暗い幕・「もどる」・端末の戻るキーは、窓だけを閉じる |

ボタンを押すと、サーバーが引いてルーンを払い、出た物を持ち物に足す（[召喚の保存](../monetization.md#召喚の保存)、2026-10-24）。
応答を受けたら、案内人の画面を隠して[召喚の演出](#召喚の演出の計画)を流し、終わったら結果の窓を出す。
演出は光をBloomでにじませるため、神殿のシーンのカメラで描く（案内人の画面より奥にあるため、演出の間だけ案内人の画面を隠す）。
1回の演出では、金と虹の結果を、半分の確率で1つ下の光で灯してから上げる（昇格）。結果より上の光で灯すことはない。
演出の間は、画面を押すか「もどる」・端末の戻るキーで飛ばせる。1回は最後まで飛び、10回は1回目で札が並んだところまで飛び、2回目で終わる。押さなくても、10回は札が並んでから約1.2秒で結果の一覧へ進む（2026-10-24）。
所持ルーンが値段に足りないときは、送らずに通知の帯で「ルーンが足りません」と知らせる。
サーバーが残高の不足（`insufficient_runes`）で断ったときも同じく知らせ、それ以外の失敗（要求IDの使い回しの `request_conflict` や通信の失敗）は「召喚できませんでした」と知らせる。
キャラの札には、☆の代わりに「新しい仲間」「絆のしるし+1」「かけら+1」のように、加わったか、得た物を書く（絆のしるしは育成の画面で使って絆を深める。[キャラが被ったとき](../monetization.md#キャラが被ったとき)）。
サーバーの接続先がないとき（展示室など）は、画面に出す割合でクライアントが仮に引き、画面の残高から引くだけで、出た物は持ち物に入らない。
演出がシーンにないとき（展示室のPrefabのプレビュー）は、演出を流さずに結果の窓を出す。
引く物は、キャラと、冒険のすべての行き先の一覧にあるアイテム・装備（主の物を含む）である。

### 召喚の演出の計画

2026-10-24、ユーザーは召喚の演出を「聖堂のステンドグラス」にすると決めた。
1回は大きな薔薇窓が1枚砕け、10回は小さな丸窓が10枚並ぶ壁で1枚ずつ砕ける（10回の形はユーザーが選んだ）。
あわせて、神殿のメニューの「召喚」から全画面の召喚画面を開き、キャッチイラストと「1回召喚」「10回召喚」だけを置き、確率と出る物は左下の小さなボタンから開く窓に出すことにした。
以下は作る前の計画で、ユーザーの確認を受けて実装した（1回・10回とも、2026-10-24）。細かな値の正本はコード（`TempleSummonShow`・`TempleSummonTenShow`）である。
絵はCodex CLIで描いた（`output/temple-summon/`、Git対象外）。

**現実の現象**

- ステンドグラスは、色ガラスの小片を鉛の桟（ケイム）でつないだ板で、裏から光が当たったときだけ色が灯る（[Came](https://en.wikipedia.org/wiki/Came)）。
- 板ガラスに一点で力が加わると、その点から放射状のひびが走り、それを横切る同心円の弧のひびが入る。放射状のひびの本数は、割れに使われた力が大きいほど増える（[Horváth ほか](https://experts.mcmaster.ca/scholarly-works/162644)）。
- 割れたガラスは、ひびで分かれた多角形の破片になり、回りながら重力で落ちる。破片の面が光を返す一瞬だけ、強くきらめく。
- 窓が抜けると、裏の光が直接差し込み、空中のほこりが光の筋を見せる。

**色の段階**：結果のいちばん良い物で決める。☆3以下は白、☆4と品質Sは金、☆5とキャラは虹。白から金、金から虹への昇格は、本当にその結果のときだけ、ひびが入る直前に起こす。

**1回召喚の時間**

| 拍 | 秒 | 起きること |
|---|---|---|
| 予備動作 | 0.0〜1.2 | 聖堂が暗くなる（環境の色は残す）。窓の裏の光が、ゆっくり始まって強まる。窓から床へ光の筋が伸び、筋の中にほこりの粒が浮く。0.8秒で光が段階の色になる |
| 溜め | 1.2〜1.9 | 窓の中心から放射状のひびが走り（0.25秒）、続いて同心円の弧のひびが入る（0.2秒）。ひびから段階の色の光が漏れ、画面がわずかに揺れる |
| 発生 | 1.9〜2.2 | 窓が多角形の破片に分かれ、手前へ飛び散る。裏の光が窓の範囲から一気にあふれ、中央が明るく飛ぶ（画面全体は白くしない）。寄りを少し入れる |
| 余韻 | 2.2〜3.6 | 破片は回りながら落ち、きらめいて、縁から欠けて消える。窓から床へ光の柱が立ち、その中を札が降りて床の上で止まる（2.6〜3.4）。床に光だまり |

**10回召喚の時間**

| 拍 | 秒 | 起きること |
|---|---|---|
| 予備動作 | 0.0〜1.0 | 小さな窓が10枚並ぶ壁。暗い窓に裏から光が入り、10枚がそれぞれの段階の色で灯る |
| 発生（順に） | 1.0〜2.8 | 白の窓から、左上から順に0.18秒おきに砕け、それぞれの窓から札が落ちて下の段に並ぶ。金と虹の窓は最後まで残す |
| 溜めと発生（当たり） | 2.8〜3.8 | 残った金・虹の窓が、光をためて（0.4秒）から大きく砕ける。虹の窓は破片と光が画面いっぱいに広がる |
| 余韻 | 3.8〜4.6 | 窓から出た札は表を向いたまま窓の前に並び、段階の色で光る。最後の札が並んでから約1.2秒で、結果の一覧になる |

どちらも、画面を押すと演出を飛ばして結果を出す。

**窓が砕ける演出の層**（主役。奥から順）

| 層 | 役割と形 | 透け方 | 時間 |
|---|---|---|---|
| 裏の光 | 窓の後ろの、段階の色の丸い光。砕けると窓の範囲からあふれる | 加算。ふちはやわらかく | 予備動作で強まり、発生で最大、余韻で引く |
| ステンドグラス | 窓の絵。裏の光の強さで明るさが変わり、ひびの線（放射状と同心円の弧、太さと明るさに揺らぎ）を描く | 不透明。ひびは加算で光る | 溜めでひびが伸び、発生で破片の層に入れ替わる |
| 破片 | 窓の絵を多角形に分けた破片。1枚ずつ速さ・回り方・落ち方が違う。縁が光を返してきらめく | 不透明の絵、縁のきらめきは加算 | 発生で飛び、余韻で落ちながら縁から欠けて消える |
| 光の筋とほこり | 窓から床への光の筋と、筋の中の細かい粒。砕けたあとはガラスの細かい粉のきらめきを足す | 加算。筋は薄く、粒は小さく明るく | 予備動作から余韻まで、窓の光の強さに合わせる |

支える要素として、聖堂の暗転、床の光だまり、わずかな揺れ、寄り、札が降りる光の柱を加える。
光のにじみ（Bloom）を掛けるため、召喚画面は戦闘と同じくカメラで描くCanvasにし、ポストプロセスのBloomを使う。
窓と壁は絵（Codexの生成画像）を使い、ひび・破片・光・粒は計算で描く（[エフェクトの描き方](../../art/direction.md#エフェクトの描き方)）。
