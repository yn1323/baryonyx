# 合成と合成の記録

[機能索引](README.md) / [持ち物の分類](inventory.md) / 根拠：2026-10-05・2026-10-06のユーザーの指示

**合成**は、持ち物を材料にして、より良い持ち物を作ることである。
冒険で集めた素材や、使わなくなった装備・スキルを、強い持ち物に変える手段になる。

## 確定している方針

### 合成できる物

素材・道具・武器・防具・アクセサリー・スキルを合成できる。
合成すると、より良い素材・道具・武器・防具・アクセサリー・スキルになる（2026-10-06）。
合成は[商会](screens.md#商会)で行う（2026-10-05）。

## 設計方針

### 合成の記録

合成の結果を、あとから記録として見られるようにする（2026-10-06のユーザーの意向。作る時期は未定）。
記録の形（作った組み合わせを図鑑のように集めるか、合成した履歴を並べるか）と、見る場所は未決である。

## 仮設定

2026-10-24に、ユーザーの「合成についても考えて実装しちゃって」を受けて、次の決まりをこちらで決めた。
遊んで確かめるための仮の決まりで、ユーザーの確認はまだである。

**合成**は、同じ分類で☆が1つ低い物を3つと、ルーンを払って、見つけた物を1つ作ることである。
冒険で余った低い☆の物を、1つ上の☆の物に変える手段になる。
作る物を選んでから材料を選ぶため、出来上がる物は抽選しない。

| 項目 | 決まり |
|---|---|
| 作れる物 | [ライブラリ](library.md)で見つけた、☆2以上の武器・防具・アクセサリー・スキル・アイテム。最奥の間でだけ落ちる物（主の物）は作れない |
| 材料 | 作る物と同じ分類で、☆がちょうど1つ低い物を3つ。種類は問わず、同じ種類が混ざってもよい |
| 使えない材料 | キャラが付けている武器・防具・アクセサリー、デッキに入れているスキル。アイテムは、デッキに入れている枠の数を残す |
| 出来上がる品質 | 材料それぞれの、倍率の幅（×1.00から種類ごとの上限まで）の中の位置を平均し、出来上がる物の幅に当てはめる。百分率の整数に四捨五入する。品質の高い材料を使うほど、出来上がる品質も高い。アイテムは品質を持たない |
| 費用 | 出来上がる物の☆で、☆2 200、☆3 400、☆4 800、☆5 1,600ルーン（[商会](screens.md#商会)の買う値段の半分） |
| 材料の扱い | 材料にした物は持ち物からなくなる。アイテムは数が減り、0になった種類は消える |
| 失敗 | ない |

位置の平均を使うのは、材料と出来上がる物とで倍率の上限が違うためである。
倍率そのものを平均すると、上限の低い材料（×1.8まで）の品質Sが、上限の高い物（×3.0まで）では品質Cになってしまう。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 組み合わせ | [仮設定](#仮設定)では、同じ分類の☆が1つ低い物3つで作る物を選ぶ。種類ごとの決まった組み合わせ（レシピ）や、分類をまたぐ組み合わせ（素材と武器で武器を作るなど）を足すか |
| 結果の決まり方 | [仮設定](#仮設定)では材料の品質を引き継ぎ、失敗はない。見つけていない物を作れるようにするか |
| 費用 | [仮設定](#仮設定)の額の見直し（[ルーン経済](economy.md)） |
| 強化した物 | 磨き石で品質を上げた物を材料にしたとき、使った石やルーンを結果に反映するか（[商会の強化](enhancement.md#未決事項)） |
| 合成の記録 | 記録の形、見る画面、保存先（案はサーバー。[保存先の決め方の置き場所の一覧](../rules/data-storage.md#置き場所の一覧)） |
| 強化・進化・再抽選 | 品質強化と固有スキルの覚醒は、合成とは別に商会の「強化」として設けた（2026-10-24、[商会の強化](enhancement.md)）。装備の進化・再抽選を設けるかは未決（[育成の未決事項](progression.md#未決事項)） |

## 実装との対応

2026-10-24に、[仮設定](#仮設定)の合成を、サーバーとクライアントの商会の「合成」の画面で作った。

| 対象 | 今の実装 |
|---|---|
| API | `POST /v1/workshop/craft`（`requestId`・`category`・`id`、スキルと装備は持ち物の行のIDを3つの `materialIds`、アイテムは種類ごとの数の `items`）。作れない物は `goods_not_found`、材料が決まりに合わない・持っていない・使っている物は `invalid_materials`、見つけていない物は `not_discovered`、ルーン不足は `insufficient_runes` で拒む（[routes](../../server/src/features/workshop/routes.ts)・[値](../../server/src/features/workshop/catalog.ts)） |
| 合成の確定 | 記録（`workshop_crafts`、マイグレーション0020）・ルーンの減算・材料の削除・出来た物の追加を、残高・見つけた記録・材料の倍率と使っていないことを条件にした1回のbatchで行う。要求IDで再送を見分け、二重に使わない（[repository](../../server/src/features/workshop/repository.ts)） |
| 画面 | [商会](screens.md#商会)の「合成」。決まりは [WorkshopCraft](../../client/Assets/Baryonyx/Features/Workshop/Runtime/WorkshopCraft.cs) にサーバーと同じ計算で持ち、押す前に出来上がる品質を見せる。サーバーの答えを待ってから持ち物の表示を変える |
| サーバーがないとき | 展示室などでは、仮の持ち物（[WorkshopStock](../../client/Assets/Baryonyx/Features/Workshop/Runtime/WorkshopStock.cs) の `Mock`）と仮の残高で試せる |
| テスト | サーバーは [routes.test.ts](../../server/src/features/workshop/routes.test.ts)、クライアントは [WorkshopCraftTests（EditMode）](../../client/Assets/Baryonyx/Features/Workshop/Tests/EditMode/WorkshopCraftTests.cs) と [WorkshopCraftTests（PlayMode）](../../client/Assets/Baryonyx/App/Tests/PlayMode/WorkshopCraftTests.cs) |

合成の記録を見る画面は、まだない。

## 変更と判断の記録

- 2026-10-24：ユーザーの「合成についても考えて実装しちゃって」を受け、[仮設定](#仮設定)の決まりをこちらで決めて実装した。作る物を選んでから材料を選ぶ形は、ユーザーが「大部分はあってます」とした参考画像（作れる物の一覧と、材料の枠）に合わせた。決まったレシピを種類ごとに書く形は、アイテムが2つの行き先の分しかなく、組み合わせを用意しきれないため採らなかった。デッキの複数の枠に同じアイテムを入れられるため、アイテムは入れている枠の数を残すことにした。
- 2026-10-06：ユーザーの指示により、合成できる物を素材・道具・武器・防具・アクセサリーに広げ、合成の結果を将来は記録として見られるようにする意向を加えた。2026-10-05に決めた「素材から装備・スキルを作る」との関係を確かめたところ、ユーザーはスキルも合成できるままとした。合成の決まりを1か所にまとめるため、[装備](equipment.md)の未決事項にあった合成の記述をこの文書へ移した。
- 2026-10-05：ユーザーの指示により、合成を採用し、商会で素材から装備・スキルを作ることにした（[装備の変更記録](equipment.md#変更と判断の記録)）。
