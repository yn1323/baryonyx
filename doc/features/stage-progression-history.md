# 探索とダンジョンの進行の変更と判断の記録

[探索とダンジョンの進行](stage-progression.md)


- 2026-10-31：ユーザーが5案から選び、[段階](stage-progression.md#段階)の見せ方を札の縁と地の色から、カードの品質と同じ枠の光とキラキラ（白はC、金はA、虹はS）に変えた。
- 2026-10-31：ユーザーの「キャラごとに押して、そのキャラが強化できるものをランダムにして選ばせる」「画面を4等分して、ずっと4等分の中にキャラを置いといて、キャラごとに2個プラスのものがあるので、それから選ぶ」「横一列で」により、[戦闘後の強化](stage-progression.md#戦闘後の強化)の候補を全体で3つから仲間1人に2つずつへ変え、仲間ごとの4つの列の画面にした。2つ選ぶか1つ選ぶかは確かめたが答えがなく、強さを変えないよう1つ選ぶままにした。段階を引く回数を3回のまま残し、増えた候補を一番下の段階で埋めたのはこちらの判断で、金と虹の出やすさを候補が3つだったころとそろえるためである。
- 2026-10-27：ユーザーの「マス一つ一つに対して何かアクションが起きるように」「まだ行ったことがないマスに関しては、ルーンを消費するように」を受けて相談し、[街道](stage-progression.md#街道を開くルーンと日週月の出来事2026-10-27)を、ルーンを払ってマスを開く地図に改めると決めた。2026-10-24の「何もないマスを多く置く」と、2026-10-25の「街道では歩数を使わない」を改めた。後者はゲームのコンセプトと矛盾するというユーザーの判断による。地図を背景の2倍の拡大で広げること、1回きりの「？」、日・週・月に復活する採取地・行商人・祠も決めた。値段の式・マスの種類・出来事の案は、[計画](../plans/2026-10-27-world-map-rune-squares.md)にこちらの仮の案としてまとめた。
- 2026-10-25：ユーザーの「一番簡単なレベル10のダンジョンの強敵が硬すぎる気がする」を受け、戦闘画面のカードを自動で使わせて多数回戦わせる仕組み（[戦闘の自動対戦](../rules/client-testing.md#戦闘の自動対戦)）を作り、今の倍率で初期のパーティを測り直した（[自動対戦の仕組みでの測り直し](stage-progression.md#自動対戦の仕組みでの測り直し2026-10-25)）。同じ日に装備の効果と会心・状態異常の確率が戦闘に入ったため、初期装備あり・なしの両方を、会心・状態異常・2回発動まで種でそろえて測り直した。倍率は、目安のターン数をユーザーがまだ決めていないため変えていない。
- 2026-10-25：ユーザーの「ワールドマップで…ピンチアウト、ピンチインでズームを実装してほしい」を受け、[街道の世界地図](stage-progression.md#世界地図の形と試作2026-10-24)を2本指で拡大・縮小できるようにした。近づく上限の2倍、離す下限を地図が画面を埋めるところにしたこと、Editorのホイールでも動かせるようにしたこと、拡大率を画面を開き直したときに残さないことは、こちらで決めた。
- 2026-10-25：ユーザーの「ダンジョンとワールドマップで移動する自キャラを、ドットのキャラじゃなくてチェスのポーンみたいな感じで表現したい」を受け、影響範囲を調べて案を出した。ユーザーの「コマの数は1つ」「コーデックスで作った絵」「探索と世界地図の両方を同時に」により、Codexで6案を作って地図に重ねた見本を示し、ユーザーが木の駒（B案）を選んだ（[マス単位の探索と操作](stage-progression.md#マス単位の探索と操作)）。駒の大きさ（探索の地図で高さ132、世界地図で140。設計座標）と足元の影は、こちらで決めた。
- 2026-10-25：未着手の街道とダンジョンの項目を相談した。ユーザーの「街道の宝箱の中身はマスごとに中身決めちゃってOK」「宿とかも置く必要はないです。街に到達後、団長が解放されるぐらいでOK」（「団長」はダンジョンの聞き取り違いと解釈した）「物語のマスは今考えなくていい」により、[街道の宝箱と街](stage-progression.md#街道の宝箱と街2026-10-25)を加えた。かけらの交換所は「一旦このままでOK」とした。歩数は、ユーザーが「前回町開放してから、5000歩歩いてないと開放できないみたいにすればいいのかな」と案を出したが、本線を歩数で止めると「運動しないと遊べないゲームにはしない」と合わないことを示したところ、「歩数の積集ややこしくなってきたから、もうこの仕様なしにしちゃおう」により、2026-10-24に採った歩数の関所と道のりの表示をなくした。宝箱の中身は「一任します」を受けてこちらで仮に決め、ユーザーの「DPも含めて実装したい」（DBと解釈した）により実装した（[実装との対応](stage-progression.md#実装との対応)）。歩数の関所のマスは、どれも宝箱の手前にあったため、宝箱を並べず何もないマスにした。

- 2026-10-24：ユーザーの「ダンジョンがだんだん強くなるので、休憩に加えて各戦闘後にもボーナスとして自キャラを強化したい」「ランダムで3つぐらい提示して選ばせたい」を受け、ローグライクの報酬の選び方（Slay the Spireのカードの報酬、Hadesの恩恵、Vampire Survivorsの除外）を調べて案を出した。ユーザーの「マスごとに強くなっていくやつは冒険の間だけ有効」「誰々がアップとか、全員ちょっと低めで5%アップとか」「スキップは一旦なし」「ステータス上昇だけ。ただし雑に5%上がるだけでなくバリエーションを」「デメリットがあるけど強くなるのも少なめに」「強い敵だとより強い効果、という傾斜を」により、[戦闘後の強化](stage-progression.md#戦闘後の強化)を加え、未決事項の「冒険中のステータス〇％アップが、その冒険限定か永続か」を冒険限定に決めた。段階・系統・数値・割合（[戦闘後の強化の中身](stage-progression.md#戦闘後の強化の中身仮)）は、ユーザーの「割合とかも考えてほしい」を受けてこちらで決めた仮の値で、自動対戦での試しはしていない。まだ実装していない。
