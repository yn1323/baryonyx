# UPTボーナス

[機能索引](README.md) / [運動データとルーン換算](exercise-rewards.md) / [日付の区切り](daily-rules.md) / 根拠：[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

段階ごとの枠にプレイヤーがボーナスを入れておき、その日のUPTが段階に届くと、その枠のボーナスが翌朝4時まで効く仕組みである。
2026-09-27の企画見直しで、日次・週次の運動目標を廃止し、このUPTボーナスが目標の役割を担うことにした。
UPTからのルーン変換とは別の処理であり、ルーン変換は[運動データとルーン換算](exercise-rewards.md#uptのルーン変換)を正本とする。
確定・設計方針・仮設定・未決は[仕様の確度](README.md#仕様の確度)に従って区別する。

## 確定している方針

### 日次のUPTボーナス

段階ごとに枠を1つ設け、プレイヤーは各枠に入れるボーナスを前もって選んでおく。
その日のUPTが段階に到達すると、その段階の枠に入れたボーナスが有効になる。
有効になったボーナスは重ねて効く。

段階は上に行くほど必要なUPTが大きくなる（傾斜）。
最大の段階は1万UPT前後とする。

ボーナスは多めに用意し、どの枠にも、持っているボーナスの一覧から選んで入れられる。
枠に入れる候補をランダムに提示せず、持っているものから自由に選べるようにする。
同じボーナスを複数の枠に入れることはできない。
上の段階の枠ほど、入れたボーナスの効果が強くなる。
欲しいボーナスを強く効かせるために、より多く歩く理由ができるようにするためである。

### 枠の付け替え

枠に入れたボーナスは、いつでも付け替えられる。
ただし、冒険中は付け替えられない。
すでに有効になった枠を付け替えた場合は、付け替えた後のボーナスが効く。
枠の設定は翌日以降も残り、ふだんは同じ構成のまま使う。

付け替えは、酒場の「ボーナス」で行う。
ホームの左上のボタンを押すと、酒場のボーナス設定を直接開く。
酒場のメニューからも開ける。

### ボーナスの入手と効果量

ボーナスは、冒険でも手に入るようにする予定である。
効果量はハクスラのように、手に入れるたびに幅の中でばらつく。
同じボーナスをもう一度手に入れたときは効果量の低いほうを消し、1種類につき1つだけ持つ。

### 1日の区切りと有効期間

1日の区切りは朝4時とし、「朝4時から今までのUPT」で段階を判定する。
有効になったボーナスは、すべて翌日の切り替え時刻（朝4時）まで有効とする。
日付の区切りのほかの規則との関係は[日付の区切り](daily-rules.md)で管理する。

### UPTの反映

UPTの元は、当面は歩数だけとし、1歩＝1UPTで換算する（[運動データ](exercise-rewards.md#ゲーム共通の単位upt)）。
UPTは、ホームで歩数を同期したときに反映する（[HomeのUPTパネル](startup-sync.md#homeのuptパネル)）。
販売予定の[「5,000UPT分運動したことにする」チケット](monetization.md#5000upt分運動したことにするチケット)を使うと、ルーンは増えず、その日のUPTボーナスだけが得られる。

### ホーム画面の見た目

ホーム画面の見た目を、UPTによって変える演出はしない。

## 設計方針

- UPTボーナスは「ボーナスのみ」とし、歩かない日のペナルティにしない。
- ホームでは、セット中・有効中のボーナスの詳細を表示しない。ホームの残りの表示は「あと〇UPTで次のボーナス獲得」とし、ボーナスの名前は出さない。
- ボーナスはカテゴリ（ドロップ系・探索系・戦闘系など）で整理する。

## 候補

| 項目 | 候補 |
|---|---|
| ボーナスの中身 | ドロップ率アップ（レア度アップを含む）、探索でより詳細な情報が見える（宝箱の中身、次の部屋の敵、敵が激化するターンなど） |
| 段階のUPT | 1,000／2,000／3,000／5,000／8,000UPT |
| 枠による効果の強め方 | ボーナス自身の効果量に、枠ごとの倍率を掛ける（例：1,000UPTの枠で×1.0、8,000UPTの枠で×2.0）。情報の効果も「中身が見える確率」などの数値にして、同じ掛け方にそろえる |
| 効果量の見せ方 | 幅の中のどこに当たったかを、S〜Cのランクと幅のバーで示す |

段階のUPTの参考として、見直しの資料は「日本人の平均は約6,300歩/日、国の推奨は成人8,000歩/日」を挙げている（1歩＝1UPTで約6,300UPT・8,000UPT）。
この参考値の出典は、文書作成時に確認していない。

| 決める項目 | 状態 |
|---|---|
| ボーナスの中身 | 採用候補は[候補](#候補)のとおり。ボーナスごとの効果量の幅と、枠ごとの倍率も未決 |
| 入手 | 冒険で手に入る場所と確率、最初から持っているボーナス、入手と更新を知らせる表示 |

| 週次ボーナス | UPTを消費せず、過去1週間の実績条件で解放し、1週間有効にする方向。数個の特別なボーナスに限り、タブを分ける。条件値（候補：1週間で合計5万UPT／8,000UPT以上の日が3日）と導入時期（日次だけで遊んでから判断する案あり）は未決 |

## 実装との対応

本ページは企画上の要求・設計方針・未決事項を記す。
ボーナスの効果（冒険での入手と、効果を冒険・戦闘に効かせること）と保存は未実装である。
枠の設定は、仮データで画面だけを作った（[ボーナス設定](screens.md#ボーナス設定)）。
HomeのUPTパネルは、まだ獲得していない最初の段階までのUPTを「あと 〇 UPTで次のボーナス獲得」と表示し、ゲージの下に段階の目盛りを置く。右下のボタンで酒場のボーナス設定を直接開く（[ホーム画面](screens.md#ホーム画面の見た目モック)）。
段階は仮に上の候補値を使い、ゲージの最大は8,000UPTとする。UPTは、ルーン変換と同じ朝4時区切りの今日の歩数から換算した値である。

ボーナス設定は、[仮データ](../../client/Assets/Baryonyx/Features/StepBonus/Data/StepBonusMockData.asset)のボーナス8種・効果量・枠の設定から始まる。
仮設定は次のとおりで、確定値ではない。

| 項目 | 仮設定 |
|---|---|
| 枠の倍率 | 1,000UPTの枠から順に×1.0・×1.2・×1.4・×1.7・×2.0。効果量に掛け、確率の効果は100%で止める |
| ランク | 効果量が幅のどこに当たったか（下限0〜上限1）で、0.85以上をS、0.6以上をA、0.3以上をB、それ未満をCとする |
| 枠の設定の保存 | アプリを動かしている間だけ残す。起動し直すと仮データに戻る |
| 今日のUPT | ホームで取得した値を酒場へ渡す。取得していないときや酒場を単体で開いたときは、仮データの3,240UPTを使う |

同じボーナスを手に入れたときに効果量の高いほうを残す処理は、枠の計算（[StepBonusLoadout](../../client/Assets/Baryonyx/Features/StepBonus/Runtime/StepBonusLoadout.cs)）に入れてテストしたが、冒険からはまだ呼ばない。
現在の実装範囲は[機能索引の実装欄](README.md#現在の実装)で確認する。

## 変更と判断の記録

- 2026-10-04：ユーザーの指示により、ホームではボーナスの詳細を表示せず、ホームの左上のボタンから酒場のボーナス設定を直接開く形にした（酒場のメニューからも開ける）。あわせて、ボーナスを冒険でも手に入れられるようにする予定とし、効果量をハクスラのように入手ごとにばらつかせ、同じボーナスは効果量の低いほうを消す方針を加えた。これに伴い、枠による強め方の候補を「ボーナス自身の効果量に枠ごとの倍率を掛ける」形に改めた。

- 2026-10-04：ユーザーの指示により、段階に届くたびにボーナスを1つ選ぶ方式を、段階ごとの枠に前もってボーナスを入れておく方式へ改めた。どの枠にも同じ一覧から入れられ、上の段階の枠ほど効果が強くなる。同じボーナスを複数の枠に入れることはできない。付け替えはいつでもできるが、冒険中はできない。これに伴い、ボーナスごとに解放に必要なUPTを設定する方針を外し、未決だった「同じボーナスを重ねて選べるか」を解消した。候補の「いつものセット」は、枠の設定が翌日以降も残ることで不要になったため外した。用語集・ゲーム概要・日付の区切り・UPTボーナスの定義・保存・構成・画面の記述を合わせた。同日、ホームの残りの表示から次のボーナスの名前を外し、「あと〇UPTで次のボーナス獲得」とするようユーザーが指示した。

- 2026-09-28：ユーザーの指示により、運動量の単位の名前を「ワット」から「UPT」へ改め、ワットボーナスをUPTボーナスへ改名した（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位upt)）。段階の候補値は変えない。

- 2026-09-27：ユーザーの指示により、運動量の単位を「歩」から「ワット」へ改め、歩数ボーナスをワットボーナスへ改名した。段階の候補値は1歩＝1ワットのため同じ数値でワットへ置き換えた（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位upt)）。ファイル名と個別データのIDの接頭辞 `step-bonus-` は変えていない。

- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、日次・週次の運動目標を廃止し、この仕様を新設した。朝4時区切りの段階、段階ごとの選択、全候補からの選択、翌朝4時までの有効期間、ホームでの同期時の反映を確定事項とし、ボーナスの中身・段階の歩数・週次ボーナスは未決に分けた。運動目標の仕様（`doc/features/goals.md`）と目標の個別データの分類は削除し、旧仕様の全文はGit履歴で参照する。経済、運動データ、日付、画面、初回体験、保存、用語集、個別データの索引へ反映した。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| 「1日の目標」「1週間の目標」各1枠の任意の運動目標。歩数・距離・運動時間の基準と時間帯を選ぶ | 廃止。歩数の段階ボーナスに置き換え |
| 目標条件の難易度倍率と、直近90日／12週の達成実績による継続倍率 | 廃止 |

| 目標の変更予約、枠ごとの継続履歴、当時の条件による達成履歴のサーバー保存 | 廃止 |
| 歩数以外の目標を設定するときのワーニングと、Health Connectの設定への導線 | 廃止。対象は歩数だけ |
| 初回にデータがない場合の固定ルーン配布 | 扱いは[ルーン経済の確認待ち](economy.md#確認待ち)に記録 |
