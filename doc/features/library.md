# ライブラリ

[機能索引](README.md) / 根拠：2026-10-18のユーザーの指示 / 計画：[ライブラリの実装計画](../plans/2026-10-18-library.md)

冒険や召喚で手に入れた物、戦った敵、歩いた記録を、あとから見返せる画面を**ライブラリ**と呼ぶ。
ゲームに用意した物の定義と、プレイヤーが見つけた記録を重ねて表示し、見つけた物は中身を、まだ見つけていない物は枠と影だけを見せる。
ライブラリは見るだけの画面で、ここから装備の付け替えや売買は行わない。

## 確定している方針

### 載せる分類と、載る条件

ライブラリには次の8つの分類を載せる（2026-10-18）。
物は「今持っている物」ではなく「一度でも手に入れた物」を載せる。
商会で売ったり合成の素材に使ったりして手元からなくなっても、ライブラリからは消えない。

| 分類 | 載る条件 | 個別の画面で見せるもの | 定義の正本 |
|---|---|---|---|
| キャラクター | 仲間にした | 名前・絵・ステータス、固有スキル3つの[覚醒ツリー](skill-evolution.md) | [キャラクターとパーティ編成](party.md) |
| 武器・防具 | 一度でも手に入れた | 名前・☆・説明 | [装備](equipment.md) |
| アクセサリー | 一度でも手に入れた | 名前・☆・効果 | [アクセサリー](equipment.md#アクセサリー) |
| スキル | 一度でも手に入れた。スキルを1枚ずつ持つ仕組みができるまでは、編成で付けたことがある | カードの絵・名前・コスト・説明 | [キャラクターの構成](party.md#キャラクターの構成)・[技・カード](../catalog/skills/README.md) |
| アイテム（道具・素材） | 一度でも手に入れた | 名前・☆・効果・入手先 | [アイテム](items.md) |
| 敵 | 戦闘で遭遇した | 名前・絵、開示した弱点、倒した数 | [戦闘システム](combat.md) |
| 日々の歩数 | 歩数をサーバーに保存した日 | 日ごとの歩数とACT | [起動時の連携と歩数の同期](startup-sync.md) |

武器と防具は、一覧では別の分類として並べる。
武器・防具は1つずつの絵がまだないため、当面は武器・防具の種類のアイコンを絵として使い、1つずつの絵ができたら差し替える（2026-10-18）。

スキルを1枚ずつ持つ仕組みは未実装で、今は50枚すべてを持っている扱いである（[持ち物の実装との対応](inventory.md#実装との対応)）。
仕組みができるまでは、キャラのカスタムスキルの枠に付けたことがあるカード（初めに付いているカードを含む）を、見つけたスキルとして載せる（2026-10-18）。
仕組みができたら、手に入れた時点で載せる形に切り替える。

1つずつ違う品質と倍率（[品質](inventory.md#品質)）は、今はライブラリに出さない（2026-10-18）。☆は種類ごとに決まる（2026-10-19、[レア度](inventory.md#レア度)）。

### まだ見つけていない項目の見せ方

まだ見つけていない項目も一覧に並べ、枠と番号だけを見せる（2026-10-18）。
名前の欄は消し、絵は「？」に替えずに、形だけの影にする。
個別の画面の説明の欄にも、「まだ見つけていない」のような文は書かない。見つけていないことは、影と消えた名前でわかる（2026-10-24）。
[固有スキルの覚醒ツリー](skill-evolution.md#編成での見せ方)で、取得していない段階を形だけの影で見せるのと同じ見せ方である。
分類ごとに、見つけた数と全体の数（例：12/50）を見せる。

番号は、分類ごとに定義の並び順で1から振る（2026-10-18）。
定義の途中に項目を足すと、後ろの番号がずれる。
未リリースの間はずれてよいとし、番号を固定するかはリリースの前に決める。

### 新しく載った印

新しく載った項目には、一覧で印を付ける（2026-10-18）。
個別の画面を開くと、印は消える。
「もう見た」という記録は、消えても印がもう一度付くだけで困らないため、端末に置く（[判断の基準](../rules/data-storage.md#判断の基準)）。

### 敵の記録

敵は、戦闘で初めて遭遇した時点でライブラリに載せる（2026-10-18）。
あわせて、その種類の敵を倒した数を数え、個別の画面に出す。
倒した数は体数で数え、同じ種類の敵が3体いて全部倒したら3とする（2026-10-18）。
全滅で終わった戦闘でも、それまでに倒した敵は数える。
戦闘の途中でアプリが終わった場合は、そのマスの戦闘を始めからやり直すため（[冒険の中断と再開](stage-progression.md#冒険の中断と再開)）、その戦闘で倒した敵は数えない。
弱点は、戦闘で[開示した](combat.md#弱点の開示)ものだけを見せる。

### 固有スキルの覚醒後の段階

キャラクターの個別の画面では、固有スキルの段階のうち、そのキャラで一度でも覚醒させた段階だけを名前と効果つきで見せる（2026-10-18）。
覚醒させていない段階は、編成での見せ方と同じく形だけの影にする。
覚醒の記録は[覚醒の保存](skill-evolution.md#覚醒の保存)の記録を読む。

### 入口

ホームにライブラリのボタンを足し、そこから開く（2026-10-18）。

### 日々の歩数

日々の歩数は、日付の新しい順に、日ごとの歩数とACTを並べる（2026-10-18）。
値は1歩＝1ACTで同じだが、歩いた記録として歩数を、ゲームの単位としてACT（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）を並べて書く。

端末を複数使った日は、その日にいちばん多い端末の値を見せる（2026-10-18）。
端末ごとの値を足すと、同じ歩数を二重に数えることがあるためである。
複数の端末が記録した歩数の扱いは[運動データの未決事項](exercise-rewards.md)でも未決であり、そちらで決まったら合わせる。

### 案内人

ほかの施設と同じく、案内人がいる画面にし、新しく司書の案内人を作る（2026-10-18）。
案内人は、何百年も書庫を守ってきたエルフの司書とし、居場所は魔法の大図書館の書庫にする（2026-10-19）。
銀髪を束ね、金の片眼鏡と深緑のコートを身に着け、分厚い図鑑と羽ペンを持ち、そばに光る本が浮かぶ。
メニューの各行には、ほかの案内人の画面と同じ白一色のアイコンを置く（キャラクターは2人の仲間、装備は兜、スキルはカード、アイテムは薬瓶、敵は角のある魔物の顔、日々の歩数は足跡）。

## 設計方針

### 定義は各機能の正本から読む

名前・説明・絵・弱点の属性など、ユーザーごとに変わらない定義はライブラリへ写さず、各機能の正本から読む。
画面に出すだけの定義はクライアントに置くという[保存先の決め方](../rules/data-storage.md#判断の基準)に従い、定義をDBへは入れない。
ライブラリは分類ごとに、正本の定義を一覧の項目（ID・番号・名前・☆・絵・説明）に変える部品だけを持つ。
新しいキャラや敵を正本に足せば、ライブラリにも枠が増える。

### 見つけた記録はサーバーに置く

見つけた記録は、プレイヤーの進行の記録であり、端末で書き換えられると困るため、サーバーのDBに置く（[判断の基準](../rules/data-storage.md#判断の基準)）。
記録は持ち物の所持とは別に持つ。
所持の記録は、売ったり合成に使ったりすると消えるためである。

物の記録は、サーバーがキャラ・装備・スキル・アイテムを付与するときに、同じ書き込みの中で残す。
スキルは、1枚ずつ持つ仕組みができるまで、編成でカードを付けたときに残す。
端末から「見つけた」と知らせる操作は設けない。
敵の遭遇と撃破だけは戦闘を端末が判定するため、マスを終えた知らせに、遭遇した敵と倒した敵の種類を載せて送る。

| 記録 | 書く時点 | 状態 |
|---|---|---|
| キャラ・装備・スキル・アイテムを見つけた記録 | サーバーが付与したとき（初めのキャラ・カード・装備と、冒険のドロップ） | 未実装（保存先は決定） |
| 敵に遭遇した記録と倒した数 | マスを終えた知らせ、全滅で冒険が終わったとき | 未実装（保存先は決定） |
| 開示した敵の弱点 | 戦闘で弱点を突いたとき（[弱点の開示](combat.md#弱点の開示)の作業が所有する） | 実装中 |
| 固有スキルの取得した段階 | 冒険で覚醒したとき（[覚醒の保存](skill-evolution.md#覚醒の保存)が所有する） | 未実装 |
| 日々の歩数 | 歩数の同期のとき（既存の記録をそのまま読む） | 実装済み |
| 新しく載った項目を見た記録 | 個別の画面を開いたとき（端末に置く） | 未実装（保存先は決定） |

ライブラリが書くのは、表の上の2行と、端末に置く見た記録だけである。
弱点・覚醒・歩数は、それぞれの機能が持つ記録を読むだけにする。
テーブルとAPIの形は[ライブラリの実装計画](../plans/2026-10-18-library.md#サーバー)に記す。

### 画面の作り

[案内人がいる画面](screens.md#編成商会神殿旅の案内所の画面)と同じ作りにし、案内人の右のメニューに分類を並べる。
メニューは、キャラクター・装備・スキル・アイテム・敵・日々の歩数の6行にする。
8つの分類を1行ずつ並べると、メニューが画面の高さに収まらないためである。
装備を選ぶと武器のパネルが開き、見出しのタブで武器・防具・アクセサリーを切り替える。
定義が1つもない分類は、準備中のタブにする（2026-10-20に、アクセサリーとアイテムの定義ができた）。

分類を選ぶと、左にカードのタイル一覧（4列）、右に選んだ項目の個別の内容を並べる。
個別の内容を一覧と同じ画面の右に出すため、タイルを選んでも別の画面には移らない。
画面の枠とカードは、[枠つきの表示](screens.md#枠つきの表示)と[すりガラスのカード](screens.md#すりガラスのカード)を使う。
日々の歩数だけはタイルにせず、日付の新しい順の一覧にする。

## 実装との対応

2026-10-19に、サーバーの記録とAPI、クライアントの画面を作った（[実装計画](../plans/2026-10-18-library.md)）。

## 変更と判断の記録

- 2026-10-18：ユーザーの依頼「入手した様々な情報を確認できるライブラリシーンを作りたい。たぶんDB管理がいると思う」を受け、この文書を作った。分類は、ユーザーが挙げたキャラクター（固有スキル）・武器・防具・アクセサリー・スキル・アイテム・敵（弱点）に、続けて挙げた日々の歩数を加えた。定義はDBに入れずに各機能の正本から読み、見つけた記録だけをサーバーに置く方針と、「一度でも手に入れた物」を載せる基準を提案し、ユーザーが了承した。まだ見つけていない項目は、候補（「？」の枠で数を見せる・見つけた物だけ出す・すべて見せる）に対して、ユーザーが「枠と番号だけ表示。名前も伏せる、ただ、？ではなく、影みたいな感じにしたい」とした。敵は遭遇で載せて撃破数を数える案、入口はホームのボタン、固有スキルの進化後は進化させるまで伏せる案を、ユーザーが選んだ。開示した弱点の保存は並行する作業の担当とし、ライブラリは読むだけにすることを、その作業と取り決めた。
- 2026-10-18：続けて未決事項をユーザーと相談し、次を決めた。番号は定義の並び順、伏せた項目は名前の欄ごと消す、倒した数は体数で数え全滅した戦闘で倒した分も数える、端末を複数使った日はいちばん多い端末の値、案内人は新しい司書、武器・防具の絵は当面は種類のアイコン、1つずつ違う倍率と☆は今は出さない、新しく載った項目に印を付け見た記録は端末に置く。いずれも提案した案をユーザーが選んだ。日々の歩数は、ACTとその日に得たルーンを並べる案に対し、ユーザーは歩数とACTの両方を選んだ。スキルは、1枚ずつ持つ仕組みができるまで全部見つけた扱いにする案に対し、ユーザーは編成で付けたことがあるカードだけを載せる形を選んだ。
- 2026-10-19：ユーザーの「とりあえず実装してみて」を受けて実装した。8つの分類をメニューに1行ずつ並べると画面の高さに収まらなかったため、武器・防具・アクセサリーを「装備」の1行にまとめ、見出しのタブで切り替える形にした（ユーザーには未確認）。個別の内容は別の画面に移さず、一覧の右に並べた。
- 2026-10-19：ユーザーの「ライブラリの背景、フクロウ以外の人に切り替えて」「リストにも各々アイコンが欲しい」を受け、仮に使っていた旅の案内所のフクロウと背景を、新しい司書と大図書館の書庫に替え、メニューの6行にアイコンを付けた。司書は、三つ編みの若い女性の司書（A案）とエルフの青年の司書（B案）を生成し、ユーザーがB案を選んだ。アイコンの図案はこちらで決め、撮影した画面を見たユーザーが「このままでよい」とした。
- 2026-10-19：ユーザーの「キャラクターのカードをもう少し下に下げてほしい。×、ルーンと近すぎる」を受け、6行以上ある案内人の画面のメニュー（今はライブラリだけ）の行の間隔を20pxから12pxに詰め、メニュー全体を28px下げた。1行目のカードの上端は、×とルーンの帯の下から約40px離れる。5行以下のメニューは変えていない。
- 2026-10-25：画面を開いたときの待ち時間を減らすため、見つけた記録と日々の歩数を同時に読み、開き直したときは前に読んだ記録をすぐ出して裏で読み直すようにした（[開き直したときの表示](../rules/data-storage.md#サーバーに置くときの作り方)）。読み直せなかったときは、出している記録を残して通知の帯で知らせる。
