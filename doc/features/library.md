# ライブラリ

[機能索引](README.md) / 根拠：2026-10-18のユーザーの指示 / 計画：[ライブラリの実装計画](../plans/2026-10-18-library.md)

冒険や召喚で手に入れた物、戦った敵、歩いた記録を、あとから見返せる画面を**ライブラリ**と呼ぶ。
ゲームに用意した物の定義と、プレイヤーが見つけた記録を重ねて表示し、見つけた物は中身を、まだ見つけていない物は枠と影だけを見せる。
ライブラリは見るだけの画面で、ここから装備の付け替えや売買は行わない。

## 確定している方針

### 載せる分類と、載る条件

ライブラリには次の8つの分類を載せる（2026-10-18）。
物は「今持っている物」ではなく「一度でも手に入れた物」を載せる。
商会で売ったり合成の素材に使ったりして手元からなくなっても、ライブラリからは消えない。

| 分類 | 載る条件 | 個別の画面で見せるもの | 定義の正本 |
|---|---|---|---|
| キャラクター | 仲間にした | 名前・絵・ステータス、固有スキル3つの[覚醒ツリー](skill-evolution.md) | [キャラクターとパーティ編成](party.md) |
| 武器・防具 | 一度でも手に入れた | 名前・☆・説明、[合成のレシピ](#合成のレシピ) | [装備](equipment.md) |
| アクセサリー | 一度でも手に入れた | 名前・☆・効果、[合成のレシピ](#合成のレシピ) | [アクセサリー](equipment.md#アクセサリー) |
| スキル | 一度でも手に入れた | カードの絵・名前・コスト・説明、[合成のレシピ](#合成のレシピ) | [キャラクターの構成](party.md#キャラクターの構成)・[技・カード](../catalog/skills/README.md) |
| アイテム（道具・素材） | 一度でも手に入れた | 名前・☆・効果・入手先 | [アイテム](items.md) |
| 敵 | 戦闘で遭遇した | 名前・絵、開示した弱点、倒した数 | [戦闘システム](combat.md) |
| 日々の歩数 | 歩数をサーバーに保存した日 | 日ごとの歩数とACT | [起動時の連携と歩数の同期](startup-sync.md) |

武器と防具は、一覧では別の分類として並べる。
武器・防具は種類ごとの絵を出し、絵のない種類は武器・防具の種類のアイコンにする（[1つずつの絵](drops.md#実装との対応)）。

スキルは1枚ずつ持ち（[持っているスキル](party.md#持っているスキル)）、初めのカードと、冒険のドロップ・合成などで手に入れた時点で載る。

1つずつ違う品質と倍率（[品質](inventory.md#品質)）は、今はライブラリに出さない（2026-10-18）。☆は種類ごとに決まる（2026-10-19、[レア度](inventory.md#レア度)）。

### まだ見つけていない項目の見せ方

まだ見つけていない項目も一覧に並べ、枠と番号だけを見せる（2026-10-18）。
名前の欄は消し、絵は「？」に替えずに、形だけの影にする。
個別の画面の説明の欄にも、「まだ見つけていない」のような文は書かない。見つけていないことは、影と消えた名前でわかる（2026-10-24）。
[固有スキルの覚醒ツリー](skill-evolution/rules.md#編成での見せ方)で、取得していない段階を形だけの影で見せるのと同じ見せ方である。
分類ごとに、見つけた数と全体の数（例：12/50）を見せる。

番号は、分類ごとに定義の並び順で1から振る（2026-10-18）。
定義の途中に項目を足すと、後ろの番号がずれる。
未リリースの間はずれてよいとし、番号を固定するかはリリースの前に決める。

### 合成のレシピ

武器・防具・アクセサリー・スキルの個別の画面に、その物を[合成](synthesis.md#レシピ)で作るときの材料と数を出す（2026-10-31、ユーザーの指示「ライブラリーにもレシピを見れるように」）。
商会へ行かなくても、何を集めればよいかを確かめられるようにするためである。

| 項目 | 決まり |
|---|---|
| 出す項目 | 見つけた項目だけ。まだ見つけていない項目は影にしているため、レシピも出さない |
| 出す中身 | 説明の下に見出し「合成のレシピ」を置き、材料を1種類ずつ札にして横に並べる。札には絵と右下に要る数（「×2」）を出し、札の下に名前を書く（2026-10-31、画面の案からユーザーが選んだ。商会の合成の材料と同じ形）。特別な材料（装備・カスタムスキル）も同じ形で並べる。持っている数は出さない。ライブラリは今の持ち物ではなく、手に入れた記録を見る画面のためである |
| まだ見つけていない材料 | 商会の合成と同じく、絵を影にし、名前を「？？？」にする。要る数は出す |
| レシピのない物 | ☆1の物と主の物は、レシピの欄を出さない |

レシピの中身は、合成と同じ正本（クライアントの [WorkshopRecipes](../../client/Assets/Baryonyx/Features/Workshop/Runtime/WorkshopRecipes.cs)。[レシピ](synthesis.md#レシピ)）から読む。

### 新しく載った印

新しく載った項目には、一覧で印を付ける（2026-10-18）。
印は札の右上に金の「NEW」で出す（2026-11-01、ほかの持ち物の札と同じ位置にそろえた。[持ち物の札](../rules/ui-design.md#持ち物の札)）。
個別の画面を開くと、印は消える。
分類を開いたときに自動で選んだ項目は、押して開くまで印を残す（2026-10-26）。印に気づく前に消さないためである。
「もう見た」という記録は、消えても印がもう一度付くだけで困らないため、端末に置く（[判断の基準](../rules/data-storage.md#判断の基準)）。

### 敵の記録

敵は、戦闘で初めて遭遇した時点でライブラリに載せる（2026-10-18）。
あわせて、その種類の敵を倒した数を数え、個別の画面に出す。
倒した数は体数で数え、同じ種類の敵が3体いて全部倒したら3とする（2026-10-18）。
全滅で終わった戦闘でも、それまでに倒した敵は数える。
戦闘の途中でアプリが終わった場合は、そのマスの戦闘を始めからやり直すため（[冒険の中断と再開](stage-progression/run.md#冒険の中断と再開)）、その戦闘で倒した敵は数えない。
弱点は、戦闘で[開示した](combat/rules.md#弱点の開示)ものだけを見せる。

### 固有スキルの覚醒後の段階

キャラクターの個別の画面では、固有スキルの段階のうち、そのキャラで一度でも覚醒させた段階だけを名前と効果つきで見せる（2026-10-18）。
覚醒させていない段階は、編成での見せ方と同じく形だけの影にする。
覚醒の記録は[覚醒の保存](skill-evolution/rules.md#覚醒の保存)の記録を読む。

### 入口

ホームにライブラリのボタンを足し、そこから開く（2026-10-18）。
ボタンは、ホームの左下に並ぶボタンの4つ目（編成・商会・神殿の右）に置き、アイコンはほかのボタンと同じ白一色の開いた本の形にする（[ホーム画面](screens/top-home.md#ホーム画面の見た目モック)。2026-11-02、ユーザーの判断で、未決から今の作りを確定にした）。

### 日々の歩数

日々の歩数は、日付の新しい順に、日ごとの歩数とACTを並べる（2026-10-18）。
行は、商会のスキル覚醒と同じく画面の幅いっぱいに並べる（2026-11-01、全幅の一覧のテンプレート。[画面の型](../rules/ui-design.md#画面の型)）。
値は1歩＝1ACTで同じだが、歩いた記録として歩数を、ゲームの単位としてACT（[ゲーム共通の単位](exercise-rewards.md#ゲーム共通の単位act)）を並べて書く。

端末を複数使った日は、その日にいちばん多い端末の値を見せる（2026-10-18）。
端末ごとの値を足すと、同じ歩数を二重に数えることがあるためである。
複数の端末が記録した歩数の扱いは[運動データの未決事項](exercise-rewards.md)でも未決であり、そちらで決まったら合わせる。

### 案内人

ほかの施設と同じく、案内人がいる画面にし、新しく司書の案内人を作る（2026-10-18）。
案内人は、何百年も書庫を守ってきたエルフの司書とし、居場所は魔法の大図書館の書庫にする（2026-10-19）。
銀髪を束ね、金の片眼鏡と深緑のコートを身に着け、分厚い図鑑と羽ペンを持ち、そばに光る本が浮かぶ。
メニューの各行には、ほかの案内人の画面と同じ白一色のアイコンを置く（キャラクターは2人の仲間、装備は兜、スキルはカード、アイテムは薬瓶、敵は角のある魔物の顔、日々の歩数は足跡）。

## 設計方針

### 定義は各機能の正本から読む

名前・説明・絵・弱点の属性など、ユーザーごとに変わらない定義はライブラリへ写さず、各機能の正本から読む。
画面に出すだけの定義はクライアントに置くという[保存先の決め方](../rules/data-storage.md#判断の基準)に従い、定義をDBへは入れない。
ライブラリは分類ごとに、正本の定義を一覧の項目（ID・番号・名前・☆・絵・説明）に変える部品だけを持つ。
新しいキャラや敵を正本に足せば、ライブラリにも枠が増える。

### 見つけた記録はサーバーに置く

見つけた記録は、プレイヤーの進行の記録であり、端末で書き換えられると困るため、サーバーのDBに置く（[判断の基準](../rules/data-storage.md#判断の基準)）。
記録は持ち物の所持とは別に持つ。
所持の記録は、売ったり合成に使ったりすると消えるためである。

物の記録は、サーバーがキャラ・装備・スキル・アイテムを付与するときに、同じ書き込みの中で残す。
端末から「見つけた」と知らせる操作は設けない。
敵の遭遇と撃破だけは戦闘を端末が判定するため、マスを終えた知らせに、遭遇した敵と倒した敵の種類を載せて送る。

| 記録 | 書く時点 | 状態 |
|---|---|---|
| キャラ・装備・スキル・アイテムを見つけた記録 | サーバーが付与したとき（初めのキャラ・カード・装備と、冒険のドロップ・合成・召喚など） | 実装済み |
| 敵に遭遇した記録と倒した数 | マスを終えた知らせ、全滅で冒険が終わったとき | 実装済み |
| 開示した敵の弱点 | 戦闘で弱点を突いたとき（[弱点の開示](combat/rules.md#弱点の開示)の作業が所有する） | 実装済み |
| 固有スキルの取得した段階 | 冒険と商会で覚醒したとき（[覚醒の保存](skill-evolution/rules.md#覚醒の保存)が所有する） | 実装済み |
| 日々の歩数 | 歩数の同期のとき（既存の記録をそのまま読む） | 実装済み |
| 新しく載った項目を見た記録 | 個別の画面を開いたとき（端末に置く） | 実装済み |

ライブラリが書くのは、表の上の2行と、端末に置く見た記録だけである。
弱点・覚醒・歩数は、それぞれの機能が持つ記録を読むだけにする。
テーブルとAPIの形は[ライブラリの実装計画](../plans/2026-10-18-library.md#サーバー)に記す。

### 画面の作り

[案内人がいる画面](screens/guide.md#編成商会神殿旅の案内所の画面)と同じ作りにし、案内人の右のメニューに分類を並べる。
メニューは、キャラクター・装備・スキル・アイテム・敵・日々の歩数の6行にする。
8つの分類を1行ずつ並べると、メニューが画面の高さに収まらないためである。
装備を選ぶと武器のパネルが開き、左に縦に並べた分類（商会の左の分類と同じ形）で武器・防具・アクセサリーを切り替える。一覧は分類の右に3列で並べる（2026-11-01、横のタブをやめて縦の分類にそろえた。[共通の部品](../rules/ui-design.md#共通の部品)）。
定義が1つもない分類は、準備中のタブにする（2026-10-20に、アクセサリーとアイテムの定義ができた）。

分類を選ぶと、左にカードのタイル一覧（4列）、右に選んだ項目の個別の内容を並べる。
個別の内容を一覧と同じ画面の右に出すため、タイルを選んでも別の画面には移らない。
分類を開いたとき（装備のタブを切り替えたときも）は、右が空にならないよう、一覧の順で最初の見つけた項目を選んでおく（2026-10-26、ユーザーの指示）。
見つけた項目がない分類は、何も選ばない。
画面の枠とカードは、[枠つきの表示](screens/guide.md#枠つきの表示)と[すりガラスのカード](screens/guide.md#すりガラスのカード)を使う。
日々の歩数だけはタイルにせず、日付の新しい順の一覧にする。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 番号の固定 | 定義を足しても番号がずれないよう、リリースの前に番号を固定するか |
| 日々の歩数の範囲と集計 | 何日前まで見せるか、月ごとの区切りや合計・最高を出すか。起動時の同期は直近7日分だけを送るため、使い始めた日の7日前より古い日は記録がない |

## 実装との対応

2026-10-19に、サーバーの記録とAPI、クライアントの画面を作った（[実装計画](../plans/2026-10-18-library.md)）。

| 対象 | 実装の入口 | 仕様との差・残り |
|---|---|---|
| 見つけた記録 | [library/db-schema.ts](../../server/src/features/library/db-schema.ts) の `library_discoveries`、書く文は [discoveries.ts](../../server/src/features/library/discoveries.ts) | キャラ・カード・装備は初めに配るときに記録する。冒険のドロップ・行商人の購入・ダンジョンのクリア回数の報酬・街道の宝箱・合成・持ち物のデバッグルームは、持ち物に足す書き込みと同じbatchで記録する（[inventory/grants.ts](../../server/src/features/inventory/grants.ts) の `inventoryGrants`）。[商会](screens/shop.md#商会)の「買う」は、この記録に載っている物だけを売り、記録は書き足さない（2026-10-24）。召喚で出た物（キャラ・装備・アイテム）は、持ち物に足す書き込みと同じbatchで記録する（2026-10-24） |
| 敵の遭遇と倒した数 | `POST /v1/adventure/clear`・`/v1/adventure/end` の `enemies`、クライアントは [BattleAdventureFlow](../../client/Assets/Baryonyx/Features/Adventure/Runtime/BattleAdventureFlow.cs) | 戦闘を終えた記録を書けたときだけ足すため、送り直しても二重に数えない。接続先がないときは記録しない |
| API | `GET /v1/library`（見つけた記録）・`GET /v1/library/steps`（日々の歩数）。[routes.ts](../../server/src/features/library/routes.ts) | 編成と装備の初期データは、ログインしたときに付与する（[equipment/starter.ts](../../server/src/features/equipment/starter.ts)） |
| 画面 | `Library.unity`、[LibraryScreenAssets](../../client/Assets/Baryonyx/Features/Library/Editor/LibraryScreenAssets.cs)（`Baryonyx > Library > Create Screen Assets`）、[LibraryCatalogView](../../client/Assets/Baryonyx/Features/Library/Runtime/LibraryCatalogView.cs)・[LibraryStepsView](../../client/Assets/Baryonyx/Features/Library/Runtime/LibraryStepsView.cs) | 案内人と背景の生成指示は [ArtSource](../../client/ArtSource/UI/Library/prompts.json) に記録した。記録は開くたびに読み直し、見つけた記録と日々の歩数は同時に読む。開き直したときは、前に読んだ記録（[LibrarySession](../../client/Assets/Baryonyx/Features/Library/Runtime/LibrarySession.cs) の `Known`）をすぐ出し、変わっていたときだけ描き直す（[開き直したときの表示](../rules/data-storage.md#サーバーに置くときの作り方)） |
| 項目の定義 | 生成メニューが各機能の正本から [LibraryData.asset](../../client/Assets/Baryonyx/Features/Library/Data/LibraryData.asset) に書き出す | 定義を変えたら生成し直す。武器・防具・アクセサリー・アイテムは種類ごとの絵（[ItemArt](../../client/Assets/Baryonyx/Features/Inventory/Presentation/ItemArt.cs)）を出し、絵のない種類は武器・防具のアイコンにする。スキルの☆は[冒険のドロップ](drops.md)の一覧から入れる |
| 固有スキル | [UniqueSkillSession](../../client/Assets/Baryonyx/Features/SkillEvolution/Runtime/UniqueSkillSession.cs) の進み具合を読む | サーバーの進み具合（[覚醒の保存](skill-evolution/rules.md#覚醒の保存)）を出す。接続先がないときは仮データの進み具合を出す。取得していない段階は影の帯にした |
| 開示した弱点 | [RevealedWeaknessSession](../../client/Assets/Baryonyx/Features/Combat/Records/RevealedWeaknessSession.cs) を読む | 開示した弱点の属性のアイコンを出す |
| 新しく載った印 | [LibrarySeen](../../client/Assets/Baryonyx/Features/Library/Runtime/LibrarySeen.cs)。`PlayerPrefs` の `Library.Seen.<ユーザーID>` | 初めて開いたときは、初めに配った物にもすべて印が付く |
| 合成のレシピ | [LibraryCatalogView](../../client/Assets/Baryonyx/Features/Library/Runtime/LibraryCatalogView.cs) が、合成と同じレシピの定義（[WorkshopRecipes](../../client/Assets/Baryonyx/Features/Workshop/Runtime/WorkshopRecipes.cs)）を読み、説明の下に材料の札を出す。札は商会の合成の材料と同じ部品（生成は [LibraryScreenAssets](../../client/Assets/Baryonyx/Features/Library/Editor/LibraryScreenAssets.cs)） | なし |
| 接続先がないとき | [LibraryMemorySource](../../client/Assets/Baryonyx/Features/Library/Runtime/LibrarySource.cs) の仮の記録 | 展示室とシーンを単体で開いたときは、見つけた物と影の両方が出るよう、一部だけ見つけた仮の記録を出す |
