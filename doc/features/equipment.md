# 装備生成と厳選

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、2026-09-15のユーザー提示仕様、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)、2026-10-06のユーザーの指示

## 確定している方針

- 各キャラは武器・防具・[アクセサリー](#アクセサリー)を装備する。装備は基本的にどのキャラでも付けられる。
- 装備は固定値を持たず、「装備したキャラのステータス〇〇の〇％」で効果量が決まる（[威力の決め方](combat.md#威力の決め方)）。
- 同じ装備でも、品質・付与効果・数値幅をランダムにする。
- 装備は手に入れるたびに1つずつ倍率を持ち、同じ種類でも倍率によって効果量が違う。倍率の高さは品質（S・A・B・C）で表す（[品質](inventory.md#品質)、2026-10-06・2026-10-19）。
- レア度は☆1〜☆5で表し、装備の種類ごとに決まる。レア度は手に入りにくさだけを表し、強さは表さない（[レア度](inventory.md#レア度)、2026-10-06・2026-10-19）。
- 探索中も装備を変更でき、獲得した装備をその場で使えるようにする。
- 冒険で獲得した装備は、負けて冒険が終わっても保持する。
- 装備・パッシブスキル・スキル・パーティ構成のシナジーを作る。
- 倍率が積み重なって数字が伸びるハクスラの成長感を狙う。
- 装備の付け替えは編成の[装備](screens.md#装備)で行う（2026-10-05）。冒険者の個別の画面で武器か防具の枠を押して開く（2026-10-06）。
- 装備・スキル・素材の売り買いと合成は[商会](screens.md#商会)で行い、売買にはルーンを使う（2026-10-05）。合成できる物と決まりは[合成](synthesis.md)に従う。

### アクセサリー

**アクセサリー**は、武器・防具と同じく、キャラに付ける装備である（2026-10-06）。
1人に最大3つ付けられる。
1つ目の枠は初めから開いていて、2つ目と3つ目はレベルアップに合わせて開く（[レベルアップ](progression.md#レベルアップ)）。
パッシブスキルのように、付けたキャラのステータスを底上げしたり、ちょっとした効果を与えたりする。
効果の中身は[未決](#未決事項)である。
枠を開くレベルは、1つ目がLv 1、2つ目がLv 20、3つ目がLv 40である（2026-10-24、ユーザーの指示。[値の定義](../../client/Assets/Baryonyx/Features/Equipment/Runtime/AccessorySlots.cs)）。
画面では、開くまで「Lv 20で解放」のように出し、開いた枠には持っているアクセサリーを付けられる（2026-10-25、[装備](screens.md#装備)）。効果は、武器・防具と同じく、まだ戦闘の計算に使わない。

## 設計方針

### 戦い方を変える装備更新

装備更新を、カードの威力の伸びや戦い方の変化につなげる。
カードの説明文は威力をステータスの割合で書くため（[カードの数値の見せ方](combat.md#カードの数値の見せ方)）、付け替えによる威力の伸びの見せ方は未決とする。
育成・装備の更新によって、以前勝てなかった敵や、より深い階に挑めるようにする。
決まった役割分担を唯一の正解にせず、得意な勝ち方を変えられるようにする。

## 持っている装備と付け替えの保存

持っている装備と、キャラごとに付けている武器・防具は、ユーザーごとにサーバーのDBへ保存する。
装備は冒険で得てルーンで売り買いする持ち物になるため、消えたり書き換えられたりすると困る（[保存先の決め方](../rules/data-storage.md#判断の基準)）。

| 保存するもの | 決まり |
|---|---|
| 持っている装備 | 1つずつ別の行にし、サーバーが作ったIDで見分ける。同じ種類を2つ持てば2行になる。同じ種類でも[品質](inventory.md#品質)（倍率）や付与効果を個別に持てるようにするためである。倍率は百分率の整数（×1.37なら137）で1つずつ保存し、APIは倍率と品質（S〜C）を返す。名前・レア度・効果はクライアントの仮データが持ち、サーバーは種類のIDと、武器か防具か、種類ごとの上限の倍率を知る |
| キャラごとの武器・防具・アクセサリー | キャラごとに武器と防具の枠を1つずつ（枠の数は仮）、アクセサリーの枠を3つ持つ。アクセサリーはどのアクセサリーの枠にも付けられ、2つ目と3つ目の枠はキャラのLvが20・40になるまで付けられない（2026-10-25）。持っているキャラの枠に、持っている装備のうち枠に合う種類だけを付けられる。1つの装備は1人の1つの枠にだけ付けられる。空いた枠は行を持たない |
| 初期の装備 | 初めて読んだユーザーに、初めの4人が付けている武器・防具の8つ（どれも×1.00、品質C）を1回だけ付与する。ほかの装備とアクセサリーは、冒険のドロップで手に入れる（[冒険のドロップ](drops.md)、2026-10-20）。一度手に入れた装備は、[商会](screens.md#商会)でも×1.00（品質C）で買える（2026-10-24） |

付け替えは、端末が付けるキャラ・枠・装備のIDを送り、サーバーが整合を確かめて保存する。
ほかのキャラが付けている装備を付けると、サーバーがそのキャラから外して付け替える。
外した装備は持ち物に残る。
付け替えは装備やルーンを増減させず、同じ要求を送り直しても結果が変わらないため、要求IDは付けない。
画面では、付け替えをすぐ出してから、裏でサーバーに保存する（[楽観的更新](../rules/data-storage.md#サーバーに置くときの作り方)）。ほかのキャラから外す決まりも端末で同じように当てる。保存できなかったときは、出した付け替えを戻して通知の帯で知らせる。
APIは `GET /v1/equipment`、`PUT /v1/equipment/characters/:characterId/:slot`（`slot` は `weapon`・`armor`・`accessory1`〜`accessory3`、本文は `itemId`）、`DELETE` の同じパスで、どれも持っている装備とキャラごとの武器・防具（`weapon`・`armor`）・アクセサリー（`accessories`、3つの枠の装備のID。空きはnull）を返す。
持っていないキャラ・装備は404、枠に合わない装備と、まだ開いていない枠は409（`slot_mismatch`・`slot_locked`）で断る。

## 実装との対応

本ページは企画上の要求・未決事項を記す。
編成の[装備](screens.md#装備)で武器と防具を付け替え、サーバーに保存する（[持っている装備と付け替えの保存](#持っている装備と付け替えの保存)）。
付け替えの画面へは、冒険者の個別の画面から進む。個別の画面へは、編成のメニューの冒険者と[装備](screens.md#装備の人選び)の2つの入口がある。
装備の生成・厳選は未実装である。
売却は、[商会](screens.md#売る)の「売る」で、付けていない装備を1つずつ選んでルーンに替え、持ち物から消す（2026-10-24、[API](../../server/src/features/workshop/routes.ts)）。
購入は、[商会](screens.md#商会)の「買う」で、ライブラリに見つけた記録がある武器・防具・アクセサリーを×1.00で1つずつ持ち物に足す（2026-10-24、[API](../../server/src/features/workshop/routes.ts)）。
1つずつ持つ倍率はサーバーに保存し、編成の装備と育成の装備の欄は★に続けて品質の文字を品質の色で出し、説明の数字に倍率を掛ける（2026-10-19）。
上限の倍率は種類ごとに×1.8〜×2.6とし、サーバーの[定義](../../server/src/features/equipment/catalog.ts)とクライアントの[仮データ](../../client/Assets/Baryonyx/Features/Equipment/Runtime/EquipmentCatalog.cs)に同じ値を置く（2026-10-20、[上限の決め方](inventory.md#上限の決め方)）。
2回攻撃の炎のダガーと、木・革の素朴な装備は低め、戦鎚（×2.6）や雷鳴の槍・鎖かたびら（×2.4）のように尖った性能の装備は高めにした。
サーバーは上限から品質を決め、生成ができるまで上限を倍率の抽選には使わない。
アクセサリーは、2026-10-25から3つの枠に付けて保存できる（テーブル `equipment_character_slots` の `slot`、[0027_accessory_slots.sql](../../server/migrations/0027_accessory_slots.sql)）。

## 変更と判断の記録

- 2026-10-24：ユーザーの指示で、アクセサリーの枠を開くレベルを仮のLv 15・20・25から、Lv 1（初めから開く）・20・40に改めた。
- 2026-10-24：ユーザーの依頼「売るで実際に装備を売って、ルーン獲得できるようにして」を受け、商会で装備を売れるようにした（[売る](screens.md#売る)）。付けている装備を売れなくすることは、こちらで決めた。
- 2026-10-20：ユーザーの指示により、装備の上限の仮の×1.5（炎のダガーは×1.3）をやめ、種類ごとに×1.8〜×2.6の上限を持たせた。初期データの倍率は、品質S〜Cがそろうよう、各装備の上限の中の同じ位置へ置き直した。
- 2026-10-19：ユーザーの指示「サーバー側のDBスキーマ、コードも更新」により、持っている装備に倍率の列（`multiplier_percent`）を加え（[0012_item_quality.sql](../../server/migrations/0012_item_quality.sql)）、APIが倍率と品質を返すようにした。既にある装備は×1.00にした。
- 2026-10-19：ユーザーの指示により、レア度（☆）を装備の種類ごとに決まる手に入りにくさとし、入手ごとにランダムに決まる強さを品質（S〜C）と倍率で表すことにした（[品質](inventory.md#品質)）。「同じ装備でもレア度をランダムにする」を「品質をランダムにする」に改めた。
- 2026-10-18：ユーザーの依頼で、装備の付け替えを楽観的更新にした（[保存](#持っている装備と付け替えの保存)）。保存を待たずに画面に出し、失敗したら戻して知らせる。サーバーのAPIは変えていない。
- 2026-10-06：ユーザーの依頼で、編成の装備を、冒険者の個別の画面から開く付け替えの画面にした（[装備](screens.md#装備)）。仲間のタブをやめて◀▶で枠を選んだまま人を替え、左にステータスと準備中のアクセサリー3枠を出す。付け替えと保存の決まりは変えていない。
- 2026-10-06：ユーザーの指示により、[アクセサリー](#アクセサリー)を加えた。1人に最大3つ付けられ、初めは0枠で、レベルアップで枠が開く。装備は1つずつ倍率を持ち、レア度を☆1〜☆5で表すことにした（[持ち物の分類](inventory.md)）。合成の決まりは[合成](synthesis.md)へまとめた。
- 2026-10-05：ユーザーの依頼で、装備の付け替えを編成の「装備」へ移し、装備の画面を商会（装備・スキル・素材の売買と合成）に作り替えた（[画面一覧](screens.md#編成商会神殿旅の案内所の画面)）。編成で付け替えるのは武器と防具の両方、売買の通貨はルーン、付け替えは最初からサーバーに保存することを、ユーザーが決めた。[保存](#持っている装備と付け替えの保存)は、装備を1つずつの行にし、キャラごとに武器1つ・防具1つの枠を持つ形で作った（枠の数とほかのキャラから外す決まりは仮）。合成と売却を採用したことを未決事項に反映した。
- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、装備を基本的にどのキャラでも付けられるものとし、効果量をキャラのステータスの％で決めることにした。冒険で得た装備を負けても保持することと、付け替え時の差分表示を反映した。ダウンの廃止に伴い、戦い方の例からダウン値と追撃を外した。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| 職業ごとに武器・防具の装備適性を制限する | 基本的にどのキャラでも付けられる |
| HPダメージを伸ばす、必要なダウン値に届かせる、追撃を成立させるなど、ダウン寄り・火力寄り・追撃寄りの勝ち方を変える | カードの威力の伸びと戦い方の変化につなげる。ダウンは廃止、追撃の採否は未決 |

- 2026-09-19：参照会話と実装指示により、探索中の装備変更と獲得直後の比較・変更導線を追加した。サンプルの共通武器を完成版の職業適性や装備枠として扱わない。

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様に基づき、ダウンや連携を含む戦い方の変化を装備厳選の目的へ加えた。編成を唯一の役割分担へ固定せず、具体的な装備効果は未確定とする。パーティ・戦闘・育成・MVPへ反映する。
