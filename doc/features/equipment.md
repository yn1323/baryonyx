# 装備生成と厳選

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、2026-09-15のユーザー提示仕様、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

- 各キャラは武器・防具を装備する。装備は基本的にどのキャラでも付けられる。
- 装備は固定値を持たず、「装備したキャラのステータス〇〇の〇％」で効果量が決まる（[威力の決め方](combat.md#威力の決め方)）。
- 同じ装備でも、レア度・付与効果・数値幅をランダムにする。
- 探索中も装備を変更でき、獲得した装備をその場で使えるようにする。
- 冒険で獲得した装備は、負けて冒険が終わっても保持する。
- 装備・パッシブスキル・スキル・パーティ構成のシナジーを作る。
- 倍率が積み重なって数字が伸びるハクスラの成長感を狙う。
- 装備の付け替えは編成の[装備](screens.md#装備)で行う（2026-10-05）。
- 装備・スキル・素材の売り買いと、素材から装備・スキルを作る合成は[商会](screens.md#商会)で行い、売買にはルーンを使う（2026-10-05）。

## 設計方針

### 戦い方を変える装備更新

装備更新を、カードの威力の伸びや戦い方の変化につなげる。
付け替え時には、カードの威力・回復量の差分を実数値で見せる（[カードの数値の見せ方](combat.md#カードの数値の見せ方)）。
育成・装備の更新によって、以前勝てなかった敵や、より深い階に挑めるようにする。
決まった役割分担を唯一の正解にせず、得意な勝ち方を変えられるようにする。

## 持っている装備と付け替えの保存

持っている装備と、キャラごとに付けている武器・防具は、ユーザーごとにサーバーのDBへ保存する。
装備は冒険で得てルーンで売り買いする持ち物になるため、消えたり書き換えられたりすると困る（[保存先の決め方](../rules/data-storage.md#判断の基準)）。

| 保存するもの | 決まり |
|---|---|
| 持っている装備 | 1つずつ別の行にし、サーバーが作ったIDで見分ける。同じ種類を2つ持てば2行になる。同じ種類でもレア度や付与効果を個別に持てるようにするためである。名前・レア度・効果はクライアントの仮データが持ち、サーバーは種類のIDと、武器か防具かだけを知る |
| キャラごとの武器・防具 | キャラごとに武器と防具の枠を1つずつ持つ（枠の数は仮）。持っているキャラの枠に、持っている装備のうち枠に合う種類だけを付けられる。1つの装備は1人の1つの枠にだけ付けられる。空いた枠は行を持たない |
| 初期の装備 | 初めて読んだユーザーに、仮の武器8つ・防具6つを1つずつと、初めの4人の武器・防具を1回だけ付与する。冒険と商会で入手できるまでの仮設定である |

付け替えは、端末が付けるキャラ・枠・装備のIDを送り、サーバーが整合を確かめて保存する。
ほかのキャラが付けている装備を付けると、サーバーがそのキャラから外して付け替える。
外した装備は持ち物に残る。
付け替えは装備やルーンを増減させず、同じ要求を送り直しても結果が変わらないため、要求IDは付けない。
APIは `GET /v1/equipment`、`PUT /v1/equipment/characters/:characterId/:slot`（`slot` は `weapon` か `armor`、本文は `itemId`）、`DELETE` の同じパスで、どれも持っている装備とキャラごとの武器・防具を返す。
持っていないキャラ・装備は404、枠に合わない装備は409で断る。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| 武器・防具の種別と装備枠 | 種別は未決。装備枠は、実装ではキャラごとに武器1つ・防具1つとした（仮） |
| 「基本的に」どのキャラでも付けられるとした例外の有無 | 未決 |
| 装備が参照するステータスと割合、レア度による差 | 未決 |
| 生成時の抽選順序、Affix数・候補・重み | 未決 |
| 数値幅・分布・重複・排他・セット効果の有無 | 未決 |
| 強化・合成・進化・再抽選を採用するか | 合成は採用し、商会で素材から装備・スキルを作る（2026-10-05）。素材の種類・組み合わせ・成功の有無と、強化・進化・再抽選は未決 |
| 付け替え、比較、ロック、所持上限 | 付け替え時に差分を表示する方針は確定（差分の表示は未実装）。ほかのキャラの装備を付けるとそのキャラから外す決まりは実装での仮。ロック、所持上限は未決 |
| 売却・分解・廃棄と確認操作 | 売却は商会でルーンと引き換えに行う（2026-10-05）。値段、付けている装備を売れるか、確認操作、分解・廃棄は未決 |
| 効果計算、極端な倍率の上限・表示桁 | 未決 |
| 装備データ変更時の既存所持品への反映 | 未決 |

## 変更と判断の記録

- 2026-10-05：ユーザーの依頼で、装備の付け替えを編成の「装備」へ移し、装備の画面を商会（装備・スキル・素材の売買と合成）に作り替えた（[画面一覧](screens.md#編成商会神殿旅の案内所の画面)）。編成で付け替えるのは武器と防具の両方、売買の通貨はルーン、付け替えは最初からサーバーに保存することを、ユーザーが決めた。[保存](#持っている装備と付け替えの保存)は、装備を1つずつの行にし、キャラごとに武器1つ・防具1つの枠を持つ形で作った（枠の数とほかのキャラから外す決まりは仮）。合成と売却を採用したことを未決事項に反映した。
- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、装備を基本的にどのキャラでも付けられるものとし、効果量をキャラのステータスの％で決めることにした。冒険で得た装備を負けても保持することと、付け替え時の差分表示を反映した。ダウンの廃止に伴い、戦い方の例からダウン値と追撃を外した。

| 過去の案 | 2026-09-27時点の扱い |
|---|---|
| 職業ごとに武器・防具の装備適性を制限する | 基本的にどのキャラでも付けられる |
| HPダメージを伸ばす、必要なダウン値に届かせる、追撃を成立させるなど、ダウン寄り・火力寄り・追撃寄りの勝ち方を変える | カードの威力の伸びと戦い方の変化につなげる。ダウンは廃止、追撃の採否は未決 |

- 2026-09-19：参照会話と実装指示により、探索中の装備変更と獲得直後の比較・変更導線を追加した。サンプルの共通武器を完成版の職業適性や装備枠として扱わない。

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様に基づき、ダウンや連携を含む戦い方の変化を装備厳選の目的へ加えた。編成を唯一の役割分担へ固定せず、具体的な装備効果は未確定とする。パーティ・戦闘・育成・MVPへ反映する。
