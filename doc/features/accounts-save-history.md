# アカウントとセーブの変更と判断の記録

[アカウントとセーブ](accounts-save.md)

- 2026-11-02：ユーザーの判断で、未決だった「保存先、マスの区切り以外の保存タイミング、サーバーで確定する処理」を、今の作り（置き場所の一覧の実装済みの項目、操作のたびの保存と1本の待ち行列、結果が要る操作だけ保存を待つこと、端末の値は書いた直後にディスクへ書くこと、費用・報酬・残高はサーバーが確定すること）で[確定](accounts-save.md#確定している方針)にした（根拠：[保存先の決め方](../rules/data-storage.md#サーバーに置くときの作り方)、client/Assets/Baryonyx/Shared/Networking/SaveQueue.cs・OptimisticState.cs）。
- 2026-11-02：スキルとdocの整理で、今のコードに合わせて、装備・スキル・アイテムは冒険のドロップで入りサーバーで確定することを書き、サーバーで管理する項目の列挙を、正本の置き場所の一覧へのリンクだけにした（根拠：server/src/features/adventure/drops.ts、server/migrations/0013_drops.sql、doc/rules/data-storage.md の置き場所の一覧）。
- 2026-10-29：ユーザーの依頼で、入れ子の地図のマスに初めて入るときにルーンを払うようにし、払って開けたマスをサーバーのDBに保存するようにした（[マスを開くルーン](world-atlas/maps.md#マスを開くルーン)）。ルーンの増減を伴い、消えると払い直しになるため、[判断の基準](../rules/data-storage.md#判断の基準)からサーバーにした。
- 2026-10-24：ユーザーの依頼「世界地図の進み具合も保存できるようにして」により、街道の世界地図の今いるマスとクリアしたマスをサーバーのDBに保存するようにした（[世界地図の形と試作](stage-progression-world-map.md#世界地図の形と試作2026-10-24)）。仕様の「クリアしたマスはサーバーに置く想定」と[判断の基準](../rules/data-storage.md#判断の基準)（進行は消えたら困る）から、サーバーにした。
- 2026-10-22：仕様の決定（[進化の保存](skill-evolution/rules.md#覚醒の保存)）どおり、固有スキルの取得した段階とセットしている段階をサーバーのDBに保存するようにした。
- 2026-10-18：ユーザーの確認で、戦闘で開示した敵の弱点をサーバーのDBに保存するようにした（[弱点の開示](combat/rules.md#弱点の開示)）。
- 2026-10-05：ユーザーの指示で、持っている装備とキャラごとの武器・防具をサーバーのDBに保存するようにした（[装備の保存](equipment.md#持っている装備と付け替えの保存)）。
- 2026-10-04：ユーザーの決定と[冒険の1周](../plans/2026-10-04-adventure-loop.md)の実装で、進行中の冒険と行き先ごとの記録をサーバーで管理し、マスを選んだ時点で保存することにした。戦闘中の中断・アプリ終了からは、そのマスの戦闘を始めからやり直す。

- 2026-10-04：ユーザーの依頼で、持っているキャラ・Lv・カードスキル・編成を、ユーザーごとにサーバーのDBで管理することにした（[キャラと編成の保存](party.md#キャラと編成の保存)）。

- 2026-09-29：ユーザーの指示で、敵の弱点を突いたら開示し、以後の戦闘でも表示する仕様にした（[弱点の開示](combat/rules.md#弱点の開示)）。開示の記録を、冒険をまたいで保持する項目に加えた。保存先は他の項目と同じく未決である。

- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、運動目標の実績・履歴のサーバー保存を運動目標とともに廃止した。進捗を持ち越す旧方針に代えて、冒険のマスの区切りでの中断・再開と、冒険終了後の獲得物の保持を保存要件にした。歩数ボーナスの保存先は未決とした。

- 2026-09-24：ユーザーの指示で、ゲストで始められるようにし、Google認証を任意（引き継ぎ用）とした。端末の秘密値によるゲストAPIを実装し、ゲストとGoogleの結び付けと引き継ぎの手順は未決のまま残す。

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様を根拠に、進捗の持ち越しと成果保護を保存要件へ加えた。実現する保存先・方式と、戦闘中の保存・再開は未確定のまま残す。探索・戦闘の要求を技術上の保存設計から参照する。

- 2026-09-15：ユーザー提示の運動目標設定仕様を根拠に、目標の実績・履歴のサーバー保存を確定した。枠ごとの履歴維持と当時の条件による訂正を要件に加え、DB形式・保存期間・処理分担は未決のまま、全体構成から参照する。
