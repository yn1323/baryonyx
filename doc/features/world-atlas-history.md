# 入れ子の地図の変更と判断の記録

[入れ子の地図](world-atlas.md)

- 2026-11-04：ユーザーの依頼「街道に報酬を獲得できるエリアを設定する」を受け、世界地図の宝箱のマス3つ（ジェーロ連峰・オーロ砂漠・ボスコ大森林の手前）を、払って初めて開けたときに本当に物がもらえるマスにした（[世界地図の宝箱のマス](world-atlas/square-events.md#世界地図の宝箱のマス)）。選んだマスと中身（前の街道の宝箱から写した）は、こちらで決めた。ほかの出来事は見本のままである。
- 2026-11-03：ユーザーの依頼「小エリアのどこかに、小エリアから出てワールドマップに行くボタンを追加し、ワールドマップではその小エリアとつながっているマスに駒を置く」で、冒険の世界地図のエリアマップの家のボタンの下に、地球儀のアイコンのボタンを置いた。押すと入口に止まったときと同じく、世界地図のその地域のマスへ戻る（[地図と移動](world-atlas/maps.md)）。アイコンは家と同じ描き方（白い線の形）で、コードで描いた。
- 2026-11-03：ユーザーの依頼「小エリアにいてもダンジョンのリストを表示してほしい」で、冒険の世界地図のエリアマップにも、世界地図と同じ右下のダンジョン一覧のボタンを置いた（[地図と移動](world-atlas/maps.md)）。
- 2026-11-02：ユーザーの判断で、「賭けはサイコロと宝箱を交互に持つ」の決まりと違い、マリーナ海岸の賭け2つがどちらもサイコロである配置をそのままにし、[マスに置いた出来事](world-atlas/square-events.md#マスに置いた出来事)に今の状態を書いた。
- 2026-11-02：スキルとdocの整理で、今のコードに合わせて、駒の位置は端末に残り開き直してもそこから始まること、払って開けたマスは開き直しても何もない台のままであること、エリアマップの背景の枚数（43枚）、支払いのエラー `request_conflict`、端末で変えたマスを `place_events.py apply` で反映する道、出来事を7種類にして読むだけで終わらせない決まり（記録と計画にだけあった）を直し、入口のない `WorldMap` を「前の街道」と呼ぶようにした。「変更と判断の記録」はこのファイルへ移した（根拠：WorldAtlasNavigator.cs の `PositionKey`・`LoadPaid`、WorldMapView.cs の `Merge`・`Refresh`、Atlas/Art の JPEG、server/src/features/world-atlas/repository.ts、place_events.py の `apply`、計画の「2026-10-28：マスの出来事の種類」、SceneNames.cs の `WorldMap`）。
- 2026-11-02：ユーザーの指摘「ワールドマップ小エリアの方が絵が浮いている、飛び出しているような感じ」で、出来事の台（`WorldEvent<種類>.png` の7枚）を、ダンジョンの部屋のマスと同じく印を面に貼る形で作り直した（[マスに置いた出来事](world-atlas/square-events.md#マスに置いた出来事)）。印・縁の色・台は変えず、地図・地図エディター・展示室は同じ画像を読むため、ほかの変更はない。続く依頼で、地域・入口の台（`WorldNodeGate.png`）の旗も面に収めた（[見た目の数値](world-atlas/maps.md#見た目の数値仮)）。
- 2026-11-01：ユーザーの依頼「小エリアの左上の戻るボタンをホームボタンにし、押すとホームまで一瞬で戻る。次に冒険へ行くとき、小エリアにいれば小エリアから始めたい」で、入れ子の地図の左上のボタンを家のアイコンにし、冒険の世界地図ではエリアマップからも世界地図を経ずにHomeへ出るようにした。再開する位置は、もともと端末に残す駒の位置（`WorldAtlas.Position`）で決まるため、エリアマップから出ればそのエリアマップから始まる。試作のシーンでは、エリアマップの左上は前のとおり世界地図へ戻る。
- 2026-11-01：ユーザーの相談「APKサイズが大きくて、ビルドしてドライブに置いてインストールするのに時間がかかる」で、232MBのAPKの内訳を調べた。地図の背景がASTC 8×8で約112MBあり、最大だった。実機と同じ圧縮と倍率で、8×8・10×10・12×12・最大2048画素への縮小を並べた比較画像を見て、ユーザーが12×12を選んだ（[画像の圧縮](../rules/frontend-design.md#画像の圧縮)）。縮小は全体がぼやけ、12×12は拡大すると四角いブロックが見える。
- 2026-11-01：ユーザーの相談「サイコロのマスのギャンブルがめっちゃ面白くない」に、目で追えば当たる・選ぶのが1回だけ・外れても損がない、の3点を理由に挙げ、直し方を3案出した。ユーザーが3案すべてを選んだため、賭けをサイコロのハイ＆ローと宝箱の連続開けの2つの遊び方に作り直し、両方に1回だけの仲間の助けを付けた（[賭けの遊び方](world-atlas/square-events.md#賭けの遊び方)）。足せるマスの候補（石碑の欠片・はぐれ魔物・踏破の報酬・駅馬車）は、ユーザーが不要とした。続く依頼「ワールドマップだけでいいので、7種類のマスを入れてみて」で、世界地図に隠し宝箱とサイコロ・宝箱の賭けを1つずつ置いた。さらに「各マスにどのイベントを割り当てるかも一緒にお願い」で、世界地図の出来事をマスごとに手で決め直し、デバッグルームにマスの一覧を足した（[世界地図の出来事の割り当て](world-atlas/square-events.md#世界地図の出来事の割り当て)）。続く「Labからも手動でも調整できるといいな」で[マスの付け替え](world-atlas/square-events.md#マスの付け替え)を足し、マスの出来事を地図のPrefabへ焼き込むのをやめて配置のJSONから読むようにした。サーバーで定義するか、seedにするかの相談には、生成したファイルをデプロイする今の形を続けると答えた（[各環境への反映](world-atlas/square-events.md#各環境への反映)）。さらに「ワールドマップと諸エリアを選んで、マスの付け替えができる」「マスごとにイベントを設定できる」専用の画面の依頼で、デバッグルームを[地図エディター](screens/debug-rooms.md#地図エディター)に作り替え、[戦闘の設定](world-atlas/square-events.md#戦闘の設定)を足して、冒険の世界地図の戦闘を本物の戦闘の画面につないだ。「マップで起きることはリスト化して、確認できるように」「そのためのLabもほしい」で、[地図エディター](screens/debug-rooms.md#地図エディター)を加えた。
- 2026-11-01：ユーザーの報告「APKを入れると、ワールドマップでルーンを払えず（『ルーンを払えませんでした』）元の位置に戻る。遠くまで行けない」で、原因を調べた。端末に覚えた駒の位置（`WorldAtlas.Position`）が、サーバーで開けたマスになっていないと、隣のマスの支払いが `square_not_reachable` で断られる（ローカルのサーバーで確かめた。マスの定義はクライアントの配置と一致していた）。開けたマスを読んだあと、駒の位置と通ったマスをサーバーの開けたマスと始まりのマスに合わせ、ずれていれば地図の始まりへ戻すようにした（[マスを開くルーン](world-atlas/maps.md#マスを開くルーン)）。
- 2026-10-29：ユーザーの依頼「ワールドマップからダンジョン一覧に行って戻ると初期位置にポーンが戻ってしまう」で、駒が最後に立っていた地図とマスを端末に残し（`PlayerPrefs` の `WorldAtlas.Position`）、地図を開くとそこから始めるようにした。覚えていたマスが地図にないときは、はじめのマスから始める。
- 2026-10-29：ユーザーの依頼「ワールドマップ移動時にルーンの消費が直列になっているので、楽観的更新にしてください」で、マスの支払いをサーバーの答えを待たずに決めるようにした。前は跳ぶ直前の支払いがサーバーの答え（1往復約250ms）を待つため、複数マスを歩くとマスごとに止まっていた。編成のレベルアップと同じ作り（`OptimisticState`・`SaveQueue`）にし、受けなかった支払いは、あとから払ったマスとまとめて取り消して駒を戻す。
- 2026-10-29：ユーザーの依頼で、まだ入っていないマスに入るときにルーンを払うようにした。払うのは初めて入るときだけにし、値段は計画の値段表、払ったマスはサーバーに残す。見せ方はユーザーが5案から次のマスの値札と地図の基本の値段を選んだ（基本の値段の札は、あとでユーザーの指示で外した）。続けてユーザーの依頼で、2マス以上先へ一度に進めるようにし、合計を確かめる窓（中央、行き先の絵なし、「次回起動まで確認しない」）、左上の開発用の消費のオンオフ、左下の文字のない止めるボタン、払うたびの「-200」を加えた。途中の出来事では止まって続きを歩く形を、ユーザーが2案から選んだ。止めたときに入っていないマスを払わないよう、支払いは跳ぶ直前に1マスずつにした。
- 2026-10-29：ユーザーの指摘で、出来事のマスに止まると地図が画面の半分ほど上へ滑ってから窓が開いていたのをやめ、地図を動かさずに開くようにした。出来事の台も、平らな輪から何もないマスと同じ段のある石の台に作り直した。
- 2026-10-29：ユーザーとの相談で、出来事は一部のマスにだけ置くことにし、世界地図とマリーナ海岸に約3割ずつ試しに置いた。試作の窓は、初めて止まった何もないマスに順番に見本を出す形をやめ、置いた出来事のマスでだけ開くようにし、冒険の世界地図でも開くようにした。
- 2026-10-28：ユーザーとの相談で、マスの出来事の種類を7つ（出会い・選択・隠し宝箱・拾い物・行商人・賭け・戦闘）に絞り、試作の窓に1つずつ見本を作った。会話だけで終わる出来事は置かず、会話は仲間の加入で終え、選択には報酬を付ける。戦闘だけは画面を切り替える。種類の決め方は[計画](../plans/2026-10-27-world-map-rune-squares.md#2026-10-28マスの出来事の種類)に記した。
- 2026-10-28：7地域のエリアマップを、2倍に近づけた道なしの背景（4分の1ずつ重ねた448区画）で作り直し、世界地図も点状の描き込みを抑えた背景に替えた。JPEGの合計が約180MBになる見込みだったため、品質90・色の間引きなしから、品質85・4:2:0に変え、約88MBにした。
- 2026-10-27：世界地図の背景をミップマップ付きで取り込んだら、ASTCに圧縮されずRGBA32のまま入り、APKの中で1枚50MBになったため、ミップマップを外した。Unityの増分ビルドで、APKに前のビルドの空き（約137MB）が残り441MBになったため、Gradleが出力したAPK（`Library/Bee/Android/Prj/IL2CPP/Gradle/launcher/build/outputs/apk/debug/launcher-debug.apk`）を消してビルドし直した。
- 2026-10-27：ユーザーとの相談で、入れ子の地図の試作を作った。網の目の道、地形だけの背景、5倍の背景、エリアマップの細かい背景、マスの大きさ、切り替えの演出、デバッグルームからの入口の経緯は[計画](../plans/2026-10-27-world-map-rune-squares.md)に記した。
