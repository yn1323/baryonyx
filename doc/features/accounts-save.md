# アカウントとセーブ

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

ゲームはGoogle接続なしのゲストで始める。
Google接続は必須とせず、引き継ぎなどで使う任意の操作とする。
ゲストの識別方法は[起動時の連携と歩数の同期](startup-sync.md#アカウント)を参照する。
ゲーム進行のアカウント・保存方式は、以下で確定した要求を除き未決である。
保存する体験上の要求として、[冒険のマスの区切りでの中断・再開と、冒険が終わっても獲得した装備・スキルなどを保持すること](stage-progression/run.md#冒険の終了と獲得物の保持)を満たす。
戦闘で[開示した敵の弱点](combat/rules.md#弱点の開示)も、冒険の終了後まで保持する。開示の記録はサーバーに保存する。
戦闘中の保存・再開は、マスの区切りでの中断と分けて決める。

保存先・保存のタイミング・サーバーで確定する処理は、今の作りのとおりとする（2026-11-02、ユーザーの判断で未決から確定にした）。

- 保存先は、[保存先の決め方の置き場所の一覧](../rules/data-storage.md#置き場所の一覧)で実装済みの項目のとおりである。消えたら困る物と書き換えられたら困る物はサーバーに、端末ごとでよい物は端末に置く。
- サーバーに置く物は、マスの区切りに限らず、操作のたびに保存する。結果は保存を待たずに出し、書き込みはアプリ全体で1本の待ち行列に積んで、出した順に送る。次の操作がサーバーの結果を要るもの（冒険を始める・宝箱と戦闘の勝利・復活・冒険を終える・マスの移動・商会の強化）だけは、保存を待ってから表示を変える（[サーバーに置くときの作り方](../rules/data-storage.md#サーバーに置くときの作り方)）。
- 端末に置く物のうち消えると困る値は、書いた直後にディスクへ書く（[端末に置くときの作り方](../rules/data-storage.md#端末に置くときの作り方)）。
- 費用・報酬・残高の変化はサーバーが計算して確定する。端末は操作の内容だけを送る。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| ゲスト開始・ログイン必須範囲・アカウント作成 | ゲストで開始し、Google接続を任意とすることは確定。起動時にゲストを作成する。ログインを必須にする操作の有無は未決 |
| Google接続をゲームアカウントへ結び付けるか | 引き継ぎに使う想定。ゲストとGoogleアカウントを結び付ける方法は未決・未実装 |
| キャラ・装備・資源・進行・設定の保存項目 | サーバーと端末に置く項目と置き場所は[保存先の決め方の置き場所の一覧](../rules/data-storage.md#置き場所の一覧)を正本とし、一覧で「案」の項目と、一覧にない項目は未決 |
| 戦闘中の中断・アプリ終了からの再開 | 2026-10-04に決定。マスを選んだ時点でサーバーに保存し、戦闘の途中で中断・終了したときは、そのマスの戦闘を始めからやり直す。戦闘の状態（ターン・手札・HP）は保存しない |
| 冒険の進捗・獲得物・ルーン復活の消費を整合させる方法 | 冒険の状態・報酬・復活の消費をサーバーで確定させる（2026-10-04に実装。[実装計画](../plans/2026-10-04-adventure-loop.md)）。装備・スキル・アイテムは冒険のドロップで入り、サーバーで確定する（[冒険のドロップ](drops.md)） |
| 引き継ぎ、再インストール、複数端末、競合解決 | 未決 |
| オフラインで許可する操作と再接続時の整合 | 未決 |
| アカウント削除、退会、ゲーム・健康データの保持期間 | 未決 |
| 健康データの保存・送信範囲、同意・撤回 | 扱う運動データは歩数だけ（[運動データ](exercise-rewards.md)）。同意の具体的な方法は未決 |
| 問い合わせ、復旧に必要な識別子と操作 | 未決 |
