# アカウントとセーブ

[機能索引](README.md) / 根拠：[初期企画](../game/brief.md)、[2026-09-27の企画見直し](../game/redesign-2026-09-27.md)

## 確定している方針

ゲームはGoogle接続なしのゲストで始める。
Google接続は必須とせず、引き継ぎなどで使う任意の操作とする。
ゲストの識別方法は[起動時の連携と歩数の同期](startup-sync.md#アカウント)を参照する。
ゲーム進行のアカウント・保存方式は、以下で確定した要求を除き未決である。
保存する体験上の要求として、[冒険の部屋の区切りでの中断・再開と、冒険が終わっても獲得した装備・スキルなどを保持すること](stage-progression.md#冒険の終了と獲得物の保持)を満たす。
戦闘で[開示した敵の弱点](combat.md#弱点の開示)も、冒険の終了後まで保持する。
戦闘中の保存・再開は、部屋の区切りでの中断と分けて決める。

## 未決事項

| 決める項目 | 状態 |
|---|---|
| ゲスト開始・ログイン必須範囲・アカウント作成 | ゲストで開始し、Google接続を任意とすることは確定。起動時にゲストを作成する。ログインを必須にする操作の有無は未決 |
| Google接続をゲームアカウントへ結び付けるか | 引き継ぎに使う想定。ゲストとGoogleアカウントを結び付ける方法は未決・未実装 |
| キャラ・装備・資源・進行・設定の保存項目 | 持っているキャラ・Lv・スキル・編成は、ユーザーごとにサーバーのDBで管理する（[キャラと編成の保存](party.md#キャラと編成の保存)）。ルーンの残高もサーバーで管理する。進行中の冒険（今いる部屋・通った部屋・出来事を終えたか・復活の回数・手に入れた報酬）と、行き先ごとの記録（最深到達・踏破の回数）もサーバーで管理する（[冒険の中断と再開](stage-progression.md#冒険の中断と再開)）。ほかは未決 |
| UPTボーナスの保存 | 持っているボーナスと枠の設定は、ユーザーごとにサーバーのDBで管理する（[UPTボーナス](step-bonus.md#持ち物と枠の保存)）。有効になった枠の効果を判定する主体は未決 |
| 保存先、部屋の区切り以外の保存タイミング、サーバーで確定する処理 | 未決 |
| 戦闘中の中断・アプリ終了からの再開 | 2026-10-04に決定。部屋を選んだ時点でサーバーに保存し、戦闘の途中で中断・終了したときは、その部屋の戦闘を始めからやり直す。戦闘の状態（ターン・手札・HP）は保存しない |
| 冒険の進捗・獲得物・ルーン復活の消費を整合させる方法 | 冒険の状態・報酬・復活の消費をサーバーで確定させる（2026-10-04に実装。[実装計画](../plans/2026-10-04-adventure-loop.md)）。装備・スキルの入手は未実装 |
| 引き継ぎ、再インストール、複数端末、競合解決 | 未決 |
| オフラインで許可する操作と再接続時の整合 | 未決 |
| アカウント削除、退会、ゲーム・健康データの保持期間 | 未決 |
| 健康データの保存・送信範囲、同意・撤回 | 扱う運動データは歩数だけ（[運動データ](exercise-rewards.md)）。同意の具体的な方法は未決 |
| 問い合わせ、復旧に必要な識別子と操作 | 未決 |

## 変更と判断の記録

- 2026-10-04：ユーザーの決定と[冒険の1周](../plans/2026-10-04-adventure-loop.md)の実装で、進行中の冒険と行き先ごとの記録をサーバーで管理し、部屋を選んだ時点で保存することにした。戦闘中の中断・アプリ終了からは、その部屋の戦闘を始めからやり直す。

- 2026-10-04：ユーザーの依頼で、持っているキャラ・Lv・カードスキル・編成を、ユーザーごとにサーバーのDBで管理することにした（[キャラと編成の保存](party.md#キャラと編成の保存)）。

- 2026-09-29：ユーザーの指示で、敵の弱点を突いたら開示し、以後の戦闘でも表示する仕様にした（[弱点の開示](combat.md#弱点の開示)）。開示の記録を、冒険をまたいで保持する項目に加えた。保存先は他の項目と同じく未決である。

- 2026-09-27：ユーザーが提示した[企画見直し](../game/redesign-2026-09-27.md)により、運動目標の実績・履歴のサーバー保存を運動目標とともに廃止した。進捗を持ち越す旧方針に代えて、冒険の部屋の区切りでの中断・再開と、冒険終了後の獲得物の保持を保存要件にした。歩数ボーナスの保存先は未決とした。

- 2026-09-24：ユーザーの指示で、ゲストで始められるようにし、Google認証を任意（引き継ぎ用）とした。端末の秘密値によるゲストAPIを実装し、ゲストとGoogleの結び付けと引き継ぎの手順は未決のまま残す。

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様を根拠に、進捗の持ち越しと成果保護を保存要件へ加えた。実現する保存先・方式と、戦闘中の保存・再開は未確定のまま残す。探索・戦闘の要求を技術上の保存設計から参照する。

- 2026-09-15：ユーザー提示の運動目標設定仕様を根拠に、目標の実績・履歴のサーバー保存を確定した。枠ごとの履歴維持と当時の条件による訂正を要件に加え、DB形式・保存期間・処理分担は未決のまま、全体構成から参照する。
