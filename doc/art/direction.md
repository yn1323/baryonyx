# アート方針

[アート索引](README.md) / 根拠：[初期企画](../game/brief.md)

## 確定している方針

| 対象 | 方針 |
|---|---|
| 全体 | 2D / HD-2D寄り、王道ファンタジー |
| 戦闘のキャラ | SNES後期程度の小型ドット絵 |
| 方向性の参照 | オクトパストラベラー方向 |
| Top・Home・戦闘画面の描画方式 | 3Dの地面と背景にドット絵のキャラを立たせ、3Dの光・影・霧、舞台ごとのレンズ（被写界深度）と色調、カメラの動きで見せるHD-2Dの構成（2026-10-02）。値と配置は[3Dの舞台](hd2d-stage.md)を正本とする |
| ステータス・ガチャなどのキャラ表示 | 高品質イラストを使う方向 |

参照作品名は方向性の記録である。
本作の固有キャラ、衣装、配色、形状は各対象の文章で定義する。

## ドット絵の制作規格

2026-09-27にユーザーと決めた、ドット絵全体の規格である。
背景以外の全素材で1ドットの大きさを揃えるため、寸法は基準解像度上のドット数で表す。
ドット絵を生成・採用・取り込む作業では、[pixel-art-standards](../../.agents/skills/pixel-art-standards/SKILL.md)スキルでこの規格を指示文に入れ、出来上がりを検査する。

### 画面と寸法

| 対象 | 規格 |
|---|---|
| 基準解像度 | 480×270。4倍して1920×1080で表示する |
| 背景 | 1ドットの大きさを揃える対象から外し、キャラより細かいドットで描いてよい。寸法と表示倍率は未決（現行の[背景スキル](../../.agents/skills/pixellab-background-prompt/SKILL.md)は640×360で作り、1920×1080では3倍になる） |
| 味方キャラ | 画像は64×64。立ち姿は48×48の範囲に収め、4〜4.5頭身で描く。残りの余白は、攻撃モーションなどで48×48からはみ出す部分に使う |
| 味方キャラの配置 | 立ち姿を左右中央に置き、足元の高さを全キャラ・全フレームで揃える |
| 敵 | 攻撃モーションのない1枚絵。大128×128、中96×96、小64×64とし、画像の大きさを本体の大きさとして余白を設けない |
| アイテム | 32×32 |
| UIアイコン | 24×24 |

### 画風

| 項目 | 規格 |
|---|---|
| タッチ | スーファミ後期〜GBAのRPG |
| 色味 | 味方・敵は彩度と明るさを高めにしたGBA寄り、背景は中間色の多い落ち着いたスーファミ寄りにする |
| 描き込み | しわや細部まで多めに描く |
| 顔 | 目は点や短い線で描く |
| 色数 | 1素材あたり32色＋透明まで。パレットは素材ごとに選ぶ |
| 光源 | 左上 |
| 陰影 | 段を分けて塗り、色の境目に**ディザ**（2色を市松模様に並べ、離れて見ると中間色に見せる描き方）を使う。キャラ・背景・UIのすべてに使う |
| 輪郭 | **セルアウト**。背景と接する外周に輪郭を描き、接する部分の色に合わせて、光が当たる側は明るく、影側は暗くする。UIアイコンにも使う |
| 背景の輪郭 | 弱めにする |
| 内部線 | 腕と胴の境目などの内側の線は外周の輪郭より明るくし、その場所の色より2段暗い色で描く |
| アンチエイリアス | 描くときに中間色を手で置く。輪郭の内側にだけ置き、背景側には置かない |

### 例外

この規格は全素材の基本とし、見栄えや役割に合わせて、素材ごとに臨機応変に例外を認める。
背景をキャラより細かいドットで描いてよいとしたのも、この考え方による。
例外にするかどうかは素材ごとにユーザーと相談して決め、決めた例外は次の表に記録する。
表にない差は、例外ではなく「既存素材との差」として扱う。

| 素材 | 規格との違い | 決めた日 |
|---|---|---|
| ホームの焚き火 | 11×14を8倍で表示する。3Dの舞台では下3行の薪（11×3）だけを立て、炎は計算で描く（2026-10-04） | 2026-09-27 |
| 案内人の上半身（編成・商会・神殿・旅の案内所の画面） | 155×261〜200×257の画像を4倍で表示し、味方キャラの64×64より大きい。1ドット約2pxで描かせた高解像度の生成画像を、面積平均で縮小して32色にしたもの。格子を復元する清書では塗りのノイズが点で残ってガビガビに見え、高解像度のまま縮小表示するとドット絵らしさが薄れたため、ユーザーと調整してこの方法にした | 2026-09-28 |
| 戦闘画面のモックの弱点アイコン | UIアイコンの24×24ではなく、12×12を4倍で表示する。敵のHPバーの上に2〜3個並べるため、96pxでは大きすぎる | 2026-09-29 |
| 戦闘画面のモックの手札 | 扇状に並べるため、カード（挿絵と枠のドット絵を含む）を傾けて表示する。傾けたドットは斜めにギザギザになる。カードは70×98ドットを1ドット3pxで表示し、ほかの素材より細かいドットで描く。挿絵は64×58で、下端の16行をディザで透明にして本体へ溶かす。使い手・名前・種類の行の後ろには、Topの「LOADING...」と同じ半透明のUIの帯を重ねる。山札から配るときは、0.2倍から手札の大きさまで半端な倍率で拡大しながら飛ばし、横幅を縮めて裏から表へ返す | 2026-09-30 |
| 戦闘画面のモックの敵 | 4倍では大きすぎたため、1ドット3pxで表示する | 2026-09-29 |
| 案内人の画面（編成・商会・神殿・旅の案内所）の背景と世界地図 | Codex CLIの生成画像（1536×1024）を清書せずに使う。ドットの格子と色数の上限がない | 2026-09-27 |
| 3Dの舞台（Top・Home・戦闘画面）のテクスチャとキャラ | 3Dの面に貼るテクスチャと、3Dに立たせたキャラの板は、遠近と光で拡縮・色付けされ、1ドットを整数pxに丸めない。テクスチャはゲーム側で光と影を付けるため、強い光源の向きや投げ影を描き込まず、石の段差や葉・幹の凹凸に左上からの控えめな陰影だけを付ける（[3Dの舞台のテクスチャ](hd2d-stage.md#テクスチャ)）。3Dへの移行はユーザーの依頼によるもので、光の描き込みを控える点は実装上の判断である | 2026-10-02 |

## エフェクトの描き方

2026-10-01にユーザーと決めた、エフェクト（VFX）の描き方である。
生成画像で作った写実寄りの素材が、ドット絵のキャラや背景になじまなかったため、画像を貼る作り方をやめる。

| 項目 | 方針 |
|---|---|
| 形 | 斬撃、炎、氷、雷、輪、光の柱、ドーム、魔法陣、粒などの形を、画像を貼らずにシェーダーの計算で描く |
| ノイズ | 揺らぎや削れに使うノイズも計算で作る。端末の負荷で汎用のノイズ画像が必要になったときは、ユーザーと相談する |
| 画風 | 滑らかな光の絵とし、ドットの格子にそろえない。[ドット絵の制作規格](#ドット絵の制作規格)の対象外とする |
| 見本のテイスト | 戦闘画面のモックの衝撃波の輪（[スキルの演出と背景](../features/screens.md#スキルの演出と背景)）。先頭の線が鋭く、後半に弧へ分かれて消える |
| 例外 | 召喚獣や降ってくる武器のように、計算で描きにくい具体的な物は、素材ごとにユーザーと相談して決める |

キャラや背景に乗せる光（照り返し、光だまり）とBloomも、計算とポストプロセスで作る。
カットインに出す使い手の絵は、キャラのドット絵であり、エフェクトの素材に含めない。
Top・HomeのHD-2Dの常設演出（光芒、霧、火の粉）は、この方針を決める前に作ったため画像を使っている。
作り直すまでは現行の素材として扱う。
[3Dの舞台](hd2d-stage.md)の炎、火の粉、門の光は、この方針に従って計算で描く。

## 探索と戦闘の設計方針

2026-09-15のユーザー提示仕様で定めた、[探索背景と差分の組み合わせ](../features/stage-progression.md#アセットを増やしすぎない構成)、[戦闘UIの情報優先順位](../features/combat.md#戦闘中の情報の優先順位)、[爽快感と入力の手応え](../features/combat.md#爽快感と入力の手応え)に従う。
必要アセット数・地域数・個々の表現規格は未確定とする。

探索の絵では、今いる部屋、パーティの位置、選べる行き先を読み取れるようにする。
2026-10-04の[計画](../plans/2026-10-04-exploration-route-map.md)で、探索は森を見下ろす地図で分岐ルートを俯瞰する形に変わる。
部屋の種類のアイコンと、遠くの部屋の印や霧の向こうの最奥を行き先を選ぶ手掛かりとし、短いヒントで補う。
地図の木や草は素材画像を数種類用意し、配置・大きさ・左右の向きだけを乱数で決める。
操作と表示の要件は[ダンジョン内の見た目による行き先選択](../features/stage-progression.md#ダンジョン内の見た目による行き先選択)に従う。
この方針だけで視点・カメラ・描画方式を確定しない。

## 未決事項

| 項目 | 状態 |
|---|---|
| ドット絵のアニメーション規格（動作の種類、フレーム数、速さ） | 未決 |
| 背景・タイルの寸法と表示倍率 | 3Dの舞台のテクスチャは[3Dの舞台](hd2d-stage.md#テクスチャ)で決めた。2Dの背景は未決 |
| アイテム・UIアイコンの色味 | 未決 |
| 視点、カメラ、奥行き、ライティング、描画方式 | Top・Home・戦闘画面は[3Dの舞台](hd2d-stage.md)で決めた。探索・マップ移動と案内人の画面は未決 |
| イラストの構図・解像度・透過・差分・納品形式 | 未決 |
| 共通UI配色、フォント、演出、音・声 | 未決。ただし戦闘中の表示の優先順位は[戦闘仕様](../features/combat.md#戦闘中の情報の優先順位)に、エフェクトの描き方は[エフェクトの描き方](#エフェクトの描き方)に従う |
| ドット絵とイラストで共通に保つ識別要素 | 各対象で記入。個別内容は未決 |

既存の歩数確認画面の[UIルール](../rules/ui-design.md)は実装上の現行ルールであり、完成版RPGのアート仕様を確定する資料ではない。
[rpg-character-profile](../../.agents/skills/rpg-character-profile/SKILL.md)、[character-sprite-sheet](../../.agents/skills/character-sprite-sheet/SKILL.md)、[character-illustration](../../.agents/skills/character-illustration/SKILL.md)に記載された、ドット絵の高さ64ドット相当・4〜4.5頭身、6種類・12〜13フレーム、イラストの縦長2:3などの値は、スキルの出力上の既定値である。
このうちドット絵の寸法と頭身は、[ドット絵の制作規格](#ドット絵の制作規格)を正とする。スキルの「高さ64ドット相当」は、攻撃モーションの余白を含む64×64の画像に当たり、規格と一致する。
動作の種類・フレーム数とイラストの値は採用済みの共通アート規格ではなく、ゲーム全体の制作規格へ採用するときは、この文書の未決事項と対象ごとの定義を同時に更新する。

## 個別対象の制作と比較

1. [比較索引](visual-index.md)で輪郭・配色・モチーフ・性格が近い対象を探す。
2. 対象分類の記入項目と[画像対象テンプレート](../catalog/templates/visual-entity.md)を使って文章を書く。
3. 似ている対象のID、共通点、意図した差、同系列として揃える特徴を記録する。
4. 画像生成時は対象IDと文書の版、使った指示文、参照画像の出所、候補・採用結果を対象文書へ記録する。
5. 採用画像と文章に差があれば、文章を変更するか画像を直し、変更しない特徴を更新する。

色だけを変えた案や性格を単語一つで表す案では、重複を見分けにくい。
輪郭、服装・材質、価値観、行動の癖、得意・苦手、口調まで記録する。
生成画像に偶然現れた特徴は、採用を決めるまで公式設定にしない。

## 変更と判断の記録

- 2026-09-15：ユーザー提示の探索・進行・戦闘仕様に合わせ、背景素材の組み合わせと戦闘の視認性・演出の参照先を追加した。全体の画風や個別アセットの規格は変更せず、ダウンリングなどの決定済み表示を未決の共通規格と区別する。

- 2026-09-19：敵HPとダウンの表示の参照先を、濃淡・状態表示の方針へ揃えた。

- 2026-09-19：ワイヤー評価を受け、探索の絵が現在地と行き先を伝える要件を追加した。具体的な構図や素材規格は未確定のまま、探索仕様を正本とする。

- 2026-10-04：探索を森を見下ろす地図にする[計画](../plans/2026-10-04-exploration-route-map.md)に合わせ、探索の絵の手掛かりを地図の形へ改めた。モックの木（プログラムで円を重ねた絵）が安っぽいとのユーザーの評価を受け、木や草は素材画像を使い、配置だけを乱数で決めることにした。

- 2026-09-27：ユーザーとの相談で、ドット絵の基準解像度・寸法・色数・光源・陰影・輪郭・内部線・アンチエイリアスを決め、[ドット絵の制作規格](#ドット絵の制作規格)に追加した。味方キャラは一度48×48の画像としたが、攻撃モーションの余白を含む64×64の画像に改めた。UIアイコンの輪郭は黒に近い色からセルアウトへ変えたため、既存のアイコンは規格との差として記録した。背景は、より細かく見えてよいというユーザーの判断により、1ドットの大きさを揃える対象から外した。あわせて、素材ごとに例外を認める方針とし、ホームの焚き火（8倍表示）を例外に記録した。

- 2026-09-27：ユーザーの依頼で案内人がいる4画面を作り、案内人の上半身を細かいドットで大きく表示すること、背景と世界地図にCodex CLIの生成画像をそのまま使うことを例外に記録した。
- 2026-09-27：[企画見直し](../game/redesign-2026-09-27.md)でダウンを廃止したため、共通UIの未決事項にあった「敵HPとダウンの表示」の参照先を、戦闘中の表示の優先順位へ改めた。
- 2026-09-29：ユーザーと相談し、戦闘画面のモックの弱点アイコンを12×12・4倍で描くこと、手札のカードを扇状に傾けることを例外に記録した。同日、カードを大きくしたときに挿絵を1.5倍で表示する例外を加えたが、挿絵を等倍に戻したため取り下げた。その後、カード全体を1ドット5px、敵を1ドット3pxで表示することを例外に加えた。
- 2026-09-30：ユーザーの依頼でカードのデザインを作り直した。ドットを細かくして拡大率を下げてよいという判断により、手札のカードの例外を1ドット5pxから、70×98ドットを1ドット3pxで表示する形に改めた。挿絵を64×58にして下端をディザで溶かすこと、文字の後ろにTopと同じ半透明の帯を重ねることも、同じ例外に含めた。同日、ユーザーの依頼で山札から裏向きのカードが飛び出して表へ返る動きを加え、飛ぶ間の拡大と裏返しの横幅の変化も同じ例外に含めた。
- 2026-10-02：ユーザーの依頼で、TopとBattleInspectを屋外（星空の夜の山の門、夕暮れの高原の環状列石）に変え、Homeの昼の森と時間帯と色を分けた。空と遠景は光を当てずに描いた色で見せる（[3Dの舞台](hd2d-stage.md)）。
- 2026-10-02：ユーザーの依頼で、Homeを昼の森の野営地に変え、舞台ごとのレンズ（被写界深度）と色調、カメラの動きを描画方式に加えた。値は[3Dの舞台](hd2d-stage.md)を正本とする。
- 2026-10-02：ユーザーの依頼で、Top・Home・戦闘画面のモックを、3Dの地面と背景にドット絵を立たせるHD-2Dの構成へ移した。描画方式を確定方針に加え、3Dの舞台のテクスチャとキャラが遠近と光で拡縮・色付けされることを例外に記録した。値は[3Dの舞台](hd2d-stage.md)を正本とする。
- 2026-10-01：画像を使わずに描いた衝撃波の輪を比べたユーザーの判断で、エフェクトは画像を貼らずにシェーダーの計算で描き、滑らかな光の絵としてドット化しないことを決め、[エフェクトの描き方](#エフェクトの描き方)に記録した。
