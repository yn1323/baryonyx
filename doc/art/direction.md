# アート方針

[アート索引](README.md) / 根拠：[初期企画](../game/brief.md)

## 確定している方針

| 対象 | 方針 |
|---|---|
| 全体 | 2D / HD-2D寄り、王道ファンタジー |
| 戦闘のキャラ | SNES後期程度の小型ドット絵 |
| 方向性の参照 | オクトパストラベラー方向 |
| Top・Home・戦闘画面の描画方式 | 3Dの地面と背景にドット絵のキャラを立たせ、3Dの光・影・霧、舞台ごとのレンズ（被写界深度）と色調、カメラの動きで見せるHD-2Dの構成（2026-10-02）。値と配置は[3Dの舞台](hd2d-stage.md)を正本とする |
| ステータス・ガチャなどのキャラ表示 | 高品質イラストを使う方向 |

参照作品名は方向性の記録である。
本作の固有キャラ、衣装、配色、形状は各対象の文章で定義する。

## ドット絵の制作規格

2026-09-27にユーザーと決めた、ドット絵全体の規格である。
背景以外の全素材で1ドットの大きさを揃えるため、寸法は基準解像度上のドット数で表す。
ドット絵を生成・採用・取り込む作業では、[pixel-art-standards](../../.agents/skills/pixel-art-standards/SKILL.md)スキルでこの規格を指示文に入れ、出来上がりを検査する。

### 画面と寸法

| 対象 | 規格 |
|---|---|
| 基準解像度 | 480×270。4倍して1920×1080で表示する |
| 背景 | 1ドットの大きさを揃える対象から外し、キャラより細かいドットで描いてよい。寸法と表示倍率は未決（以前のPixelLabの背景スキルは640×360で作り、1920×1080では3倍になった。PixelLabは2026-10-24から使わない） |
| 味方キャラ | 画像は64×64。立ち姿は48×48の範囲に収め、4〜4.5頭身で描く。残りの余白は、攻撃モーションなどで48×48からはみ出す部分に使う |
| 味方キャラの配置 | 立ち姿を左右中央に置き、足元の高さを全キャラ・全フレームで揃える |
| 敵 | 攻撃モーションのない1枚絵。大128×128、中96×96、小64×64とし、画像の大きさを本体の大きさとして余白を設けない |
| アイテム | 32×32 |
| UIアイコン | 24×24 |

### 画風

| 項目 | 規格 |
|---|---|
| タッチ | スーファミ後期〜GBAのRPG |
| 色味 | 味方・敵は彩度と明るさを高めにしたGBA寄り、背景は中間色の多い落ち着いたスーファミ寄りにする |
| 描き込み | しわや細部まで多めに描く |
| 顔 | 目は点や短い線で描く |
| 色数 | 1素材あたり32色＋透明まで。パレットは素材ごとに選ぶ |
| 光源 | 左上 |
| 陰影 | 段を分けて塗り、色の境目に**ディザ**（2色を市松模様に並べ、離れて見ると中間色に見せる描き方）を使う。キャラ・背景・UIのすべてに使う |
| 輪郭 | **セルアウト**。背景と接する外周に輪郭を描き、接する部分の色に合わせて、光が当たる側は明るく、影側は暗くする。UIアイコンにも使う |
| 背景の輪郭 | 弱めにする |
| 内部線 | 腕と胴の境目などの内側の線は外周の輪郭より明るくし、その場所の色より2段暗い色で描く |
| アンチエイリアス | 描くときに中間色を手で置く。輪郭の内側にだけ置き、背景側には置かない |

### 例外

この規格は全素材の基本とし、見栄えや役割に合わせて、素材ごとに臨機応変に例外を認める。
背景をキャラより細かいドットで描いてよいとしたのも、この考え方による。
例外にするかどうかは素材ごとにユーザーと相談して決め、決めた例外は次の表に記録する。

## エフェクトの描き方

2026-10-01にユーザーと決めた、エフェクト（VFX）の描き方である。
生成画像で作った写実寄りの素材が、ドット絵のキャラや背景になじまなかったため、画像を貼る作り方をやめる。

| 項目 | 方針 |
|---|---|
| 形 | 斬撃、炎、氷、雷、輪、光の柱、ドーム、魔法陣、粒などの形を、画像を貼らずにシェーダーの計算で描く |
| ノイズ | 揺らぎや削れに使うノイズも計算で作る。端末の負荷で汎用のノイズ画像が必要になったときは、ユーザーと相談する |
| 画風 | 滑らかな光の絵とし、ドットの格子にそろえない。[ドット絵の制作規格](#ドット絵の制作規格)の対象外とする |
| 見本のテイスト | 戦闘画面のモックの衝撃波の輪（[スキルの演出と背景](../features/screens/battle-effects.md#スキルの演出と背景)）。先頭の線が鋭く、後半に弧へ分かれて消える |
| 例外 | 召喚獣や降ってくる武器のように、計算で描きにくい具体的な物は、素材ごとにユーザーと相談して決める |
| 表現の強さ | スマホ向けだからと控えめな表現にしない。霧、光のにじみ、ガスは、細かさ、明るさに合わせた色の移り変わり、縁の明るさ、暗い筋まで作り込む。計算量は重くなってよく、端末での重さは作ったあとに確かめてユーザーと相談する（2026-10-22） |
| 現実の現象から作る | その現象が現実なら何から成り、どう動き、何を残すかから、形・動き・残り方を決める。霧やガスは、現実に霧・煙・ほこりが生じる現象（沈んで床を這う冷気、湯気、煙、土ぼこり、吹雪）にだけ使い、強い風の中では居座らせずに流す。斬撃や光のように霧の出ない現象は、刃の残像と火花、塵で見える光の柱のように、現実の見え方で描く（2026-10-23） |
| 層に分ける | 主役の形を1枚の図形で済ませず、役割の違う4つ前後の層（細く明るい芯、半透明の軌跡、淡いにじみ、残像など）に分け、層ごとに透け方・太さ・明るさ・時間を変える。煙・霧・雲は単色の丸にせず、ノイズで濃淡と輪郭を崩す（2026-10-23） |
| 後から働く演出 | カードを使ったときと、状態が後から働くときで、同じ物を出し直さない。使ったときに出した物が引っ込み、働くときにまた現れる流れにしない（2026-10-23） |

キャラや背景に乗せる光（照り返し、光だまり）とBloomも、計算とポストプロセスで作る。
カットインに出す使い手の絵は、キャラのドット絵であり、エフェクトの素材に含めない。
描いた2D背景に重ねる常設演出（光芒、霧、揺らぐ光、火の粉、塵、きらめき）も、2026-10-26に画像を使わない計算の描き方へ作り直した。
霧は5段の細かさのノイズを2回ゆがめて濃淡・縁・暗い筋を持たせ、光芒は柔らかい帯の中で塵の粒を光らせ、火の粉は丸く光る頭に細い尾を引かせ、揺らぐ光は芯とハローを別の板に分ける（[展示室の仕様](../features/showcase.md#光芒の調整)）。
[3Dの舞台](hd2d-stage.md)の炎、火の粉、門の光も、この方針に従って計算で描く。

表現の強さは、2026-10-22にユーザーと決めた。
それまでの形は、スマホの負荷を気にして軽いノイズと少ない層で作っていたため、霧が綿の塊や平らな板に見え、「チープ」と言われていた。
アイスランスの冷気と光を、星雲の写真のような描き方（細かさの違う模様を重ねてゆがめ、濃さで色を変え、縁を明るくする）に作り直したところ、ユーザーから「こんな淡い霧のような表現がほしかった」「計算量は重くなってよい」と言われた。

現実の現象から作ることは、2026-10-23にユーザーと決めた。
淡い霧の描き方を、斬り払い・ブリザード・ホーリーライトにも広げたところ、「霧を使いすぎ」「斬撃で霧は出ない」「強風なら霧はその場に居座らない」と指摘された。
見た目の好みを、現象が起きる理由と切り離して当てはめていたためである。

層に分けることと、後から働く演出で出し直さないことは、2026-10-23にユーザーと決めた。
雷雲を作り直したとき、雲を1種類の塊、稲妻を1枚の形で描いていたため、雷が暗く、雲がのっぺりして見えた。
雲を暗い本体・盛り上がり・ちぎれ雲・中の稲光の光、稲妻をにじみ・残像・通り道と枝・芯の、それぞれ4層に分け、層ごとに透け方と時間を変えると、雲は空が透け、稲妻は放電の瞬間だけ白い芯が光るようになった（[雷雲の演出の時間設計](../catalog/skills/skill-thundercloud.md#演出の時間設計)）。
また、カードを使ったときにも雲を出していたため、雲が出て引っ込み、落ちるときにまた来る流れになり、ユーザーから不要と指摘された。

### カードのキラキラ

2026-10-19、ユーザーの依頼で、ソシャゲのレアカードのように、カードの挿絵の手前にキラキラを重ねることにした。
作り方の進め方は [card-foil-sparkle](../../.agents/skills/card-foil-sparkle/SKILL.md) スキルにある。
[エフェクトの描き方](#エフェクトの描き方)に従い、画像を貼らずにシェーダーの計算で描き、ドットの格子にはそろえない。

| 項目 | 規則 |
|---|---|
| 置く場所 | 挿絵の上、使い手・名前・種類の帯と説明文の下。挿絵の透明な所（下端のディザ）には出さない。品質A・Sは、カードの枠の金属の部分の色も変える（[枠の光](#枠の光)）。枠の外とカードの外は光らせない |
| 動き | 時間で動かす。手の中でカードをゆっくり傾けて戻す1つの動き（傾き）で、光の帯・粒・模様・虹をまとめて動かす。傾きは端でゆっくり、真ん中で速く、光の帯は数秒に1回、行きと帰りで向きを変えて横切る。帯が通ると、その近くの粒が箔のかけらのように光を拾って白く光り、帯が来る直前に光り始め、通った後ろで少し遅れて消える（ふだんは見えず、このときだけ光る粒もある）。小さな粒は、ほかのときも粒ごとに明るくなる・暗くなるをくり返す。模様は帯の近くほど強く出る。端末の傾きは使わない。カードごとに乱数の種を変え、並んだカードが同時に光らないようにする（2026-10-23） |
| 粒の大きさ | 挿絵のドット1つより小さくする（芯の半径が0.2〜0.5ドット）。大きな光の玉にしない（2026-10-20） |
| 暗くしたカード | エネルギーが足りずに暗くしたカードは、キラキラも同じだけ暗くする |
| 安全 | 画面全体の明滅にしない。光の帯は細く、ラメは小さくする |
| 白っぽさ | 層を加算で重ねるため、品質Sでも挿絵が白くかすまない強さに抑える。豪華さは層の種類と動きで出し、明るさを足して出さない。粒に十字の光条は付けない |

キラキラの強さは、レア度（☆）ではなく、1つずつ違う[品質](../features/inventory.md#品質)で決める（2026-10-19）。
☆は種類ごとの手に入りにくさであり、☆5でも弱い物があるためである。
品質ごとに重ねる層は次のとおりである（仮）。

| 品質 | 層 |
|---|---|
| S | 2本の光の帯、多い小さな粒、ゆっくり上へ流れる小さな粒、いつも明るめに光る粒、光り方の模様、うっすらしたホロの虹、挿絵の縁のにじみ。枠は虹 |
| A | 光の帯、小さな粒（暗いときも少し光る）、いつも明るめに光るまばらな粒、光り方の模様（Sの3分の2ほどの強さ）、Sより薄いホロの虹。光の帯が通っていない止めたコマでも、キラキラして見える（2026-10-20）。縁のにじみは出さない（2026-10-23）。枠は外側の線が金 |
| B・C | なし |

光り方（模様と色の組）は、スキル・装備の種類ごとに1つ決め、種類が違えば光り方も違う（2026-10-20）。
同じ種類なら、どの1枚も同じ光り方であり、固有スキルは覚醒しても同じ光り方を使う。
模様はレアカードのホロの種類（細かい点のスターライト、大小の丸のコスモ、割れた氷のクラックアイス、模様のない光沢のシーン）を参考にし、波紋・オーロラ・格子を加えた7種類とした。
色は9組あり、模様と合わせて63通りになる。

| 模様 | 見え方 |
|---|---|
| 星屑 | 小さな粒より細かい点が一面に散って瞬く |
| コスモ | 大小の輪と丸が浮かび、ゆっくり明滅する。色は場所と時間でずれる虹 |
| 氷の結晶 | 割れた氷のような面が1枚ずつ光を拾い、細い割れ目が瞬く |
| 光沢 | 広く柔らかな光がゆっくり往復し、細い横の筋で照りを出す |
| 波紋 | 上の縁の一点から、細い虹の輪が外へ広がり続ける |
| オーロラ | 揺れる縦の光の幕が、上ほど明るく、色を移しながら流れる |
| 格子 | 斜めの細い格子に沿って光が走り、交点がきらめく |

色の組は、金・銀・薔薇・水・翠・菫・焔・虹・薄氷と桜である。
光り方の番号は、カードスキルが一覧の順に0〜49、固有スキルと試作のカードがその後を使う（[CardSkills](../../client/Assets/Baryonyx/Features/Combat/Runtime/CardSkills.cs)・[UniqueSkillTrees](../../client/Assets/Baryonyx/Features/SkillEvolution/Runtime/UniqueSkillTrees.cs)）。
番号を7で割った余りが模様、商が色であり、隣り合うカードは模様から変わる。
装備・アクセサリーは、一覧の順から、スキルと重ならないよう歩幅をずらして選ぶ。装備は仮データの順（[EquipmentCatalog](../../client/Assets/Baryonyx/Features/Equipment/Runtime/EquipmentCatalog.cs)）から決め、見本のアクセサリーだけはデバッグルームで決める（[QualityLabEntry](../../client/Assets/Baryonyx/Features/Inventory/Presentation/QualityLabEntry.cs)）。

#### 枠の光

2026-10-20、ユーザーの判断で、品質をカードの枠の色でも見せることにした。
挿絵の上の層だけでは、挿絵自体が明るい光や炎の絵のため、品質の差が見えにくかったためである。
シャドウバースなどのカードゲームのように、レア度が上がるほど枠の格を上げる考え方を参考にした。
枠の太さと形は変えず、今の枠の画像の金属の部分（明るい2ドットの線と、説明文の上の仕切りの線）の色だけを変える（[CardFrameFoil](../../client/Assets/Baryonyx/Shared/UI/Cards/CardFrameFoil.cs)）。

| 品質 | 枠 |
|---|---|
| S | 金属の部分を4辺とも虹にし、属性の色を3割残す。虹は枠に沿ってゆっくり流れ、斜めの照りが横切る |
| A | 外側の1ドットの線を金にし、斜めの照りでゆっくり明るさを揺らす。内側の線は属性の色のまま |
| B・C | 今の枠のまま |

枠の外への光、挿絵の上の模様の追加、入手したときの演出、端末の傾きに合わせた動きは、候補を比べたうえでユーザーが不要と判断した（[比べたページ](https://claude.ai/artifact/2Pr7QU67Be9wsGXSBdYYsp)）。
枠の光は、カードの枠を描く戦闘のカード（[BattleInspectCardView](../../client/Assets/Baryonyx/Features/Combat/Presentation/BattleInspectCardView.cs)）と育成のカード（[TrainingView](../../client/Assets/Baryonyx/Features/Training/Runtime/TrainingView.cs)）に付ける。

固有スキルは品質Cで始まるため、強化して品質がAかSに上がるまでキラキラを出さない。
キラキラを付ける対象は、品質を持つスキル（カード）・装備（武器・防具・アクセサリー）である。
品質を持たない[戦闘後の強化](../features/stage-progression.md#戦闘後の強化)の札も、段階を品質に見立てて枠の光とキラキラを使う（白はC、金はA、虹はS。2026-10-31）。札の枠は札の大きさに合わせてコードで描く（[AdventureBoonPicker](../../client/Assets/Baryonyx/Features/Adventure/Runtime/AdventureBoonPicker.cs)）。
アイテムは品質を持たないため、キラキラを付けない。

シェーダーは品質に結び付ける前に作った5段階を持ち、Sは5段階目、Aは3段階目を使う（[CardFoil](../../client/Assets/Baryonyx/Shared/UI/Cards/CardFoil.cs)）。
段階と光り方の番号は、カードごとの乱数の種とともに頂点色で渡し、どのカードも1つのマテリアルを使う。
線形の色空間ではCanvasが頂点色を線形へ変えてシェーダーへ渡すため、CardFoilは値を先に逆へ変えて渡す。2026-10-23まではこれをしておらず、品質Aが1つ下の段階（光の帯だけ）で描かれ、光り方も63通りのうち1つ以外が別の光り方になっていた。
スキルを1枚ずつ持つ仕組みがまだないため、戦闘・編成・育成のカードは品質Cで、キラキラは出ない。
品質ごとの見え方は、[品質のデバッグルーム](../features/screens/debug-rooms.md#品質のデバッグルーム)と、展示室のカードのギャラリー（S・A・B・Cの順にくり返す）で確かめる。
デバッグルームでは、選んだ物の光り方の名前（「コスモ・金」など）も出す。
装備は、編成の[装備](../features/screens/loadout.md#装備)（冒険者の装備のタブ）で、アイコンにキラキラを重ねる（2026-10-20）。
カードと同じく品質S・Aの物だけが光り、デバッグルームと同じ光り方を使う。

## 探索と戦闘の設計方針

2026-09-15のユーザー提示仕様で定めた、[探索背景と差分の組み合わせ](../features/stage-progression.md#アセットを増やしすぎない構成)、[戦闘UIの情報優先順位](../features/combat.md#戦闘中の情報の優先順位)、[爽快感と入力の手応え](../features/combat.md#爽快感と入力の手応え)に従う。
必要アセット数・地域数・個々の表現規格は未確定とする。

探索の絵では、今いるマス、パーティの位置、選べる行き先を読み取れるようにする。
2026-10-04の[計画](../plans/2026-10-04-exploration-route-map.md)で、探索は森を見下ろす地図で分岐ルートを俯瞰する形に変わる。
マスの種類の色の札とアイコンと、遠くのマスの色の点や霧の向こうの最奥を行き先を選ぶ手掛かりとし、画面の端の凡例で補う。行ける道のまわりの森だけを元の色で残し、離れた森は暗く灰色に寄せて、道と札を背景から浮かせる。
地図の木や草は素材画像を数種類用意し、配置・大きさ・左右の向きだけを乱数で決める。
操作と表示の要件は[ダンジョン内の見た目による行き先選択](../features/stage-progression.md#ダンジョン内の見た目による行き先選択)に従う。
この方針だけで視点・カメラ・描画方式を確定しない。

## 個別対象の制作と比較

1. [比較索引](visual-index.md)で輪郭・配色・モチーフ・性格が近い対象を探す。
2. 対象分類の記入項目と[画像対象テンプレート](../catalog/templates/visual-entity.md)を使って文章を書く。
3. 似ている対象のID、共通点、意図した差、同系列として揃える特徴を記録する。
4. 画像生成時は対象IDと文書の版、使った指示文、参照画像の出所、候補・採用結果を対象文書へ記録する。
5. 採用画像と文章に差があれば、文章を変更するか画像を直し、変更しない特徴を更新する。

色だけを変えた案や性格を単語一つで表す案では、重複を見分けにくい。
輪郭、服装・材質、価値観、行動の癖、得意・苦手、口調まで記録する。
生成画像に偶然現れた特徴は、採用を決めるまで公式設定にしない。
