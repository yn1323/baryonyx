# VFXの作り方

このスキルは、エフェクトを「形を画面に重ねて拡大し、薄くして消す」だけで終わらせず、場面の中で光り、当たり、消えていくように作るための進め方を扱う。
一般的なゲームのエフェクトは、画像を貼った板を重ねて作ることが多い（[Realtime VFX Fundamentals](https://realtimevfx.com/t/realtime-vfx-fundamentals/1503)）。
このゲームでは、写実寄りの画像がドット絵になじまなかったため、画像を貼らずに形をシェーダーの計算で描く（[エフェクトの描き方](../../../doc/art/direction.md#エフェクトの描き方)）。
板を重ねて層を作る考え方は同じで、各層の形を画像の代わりに式で持つ。
エフェクトの出来は、形1つの質よりも、時間の組み立て、層の重ね方、周りへの光の影響に左右される。

一般的な原則と技法は `references/` に、このリポジトリの規則と数値はdocに置く。
このスキルは、作業の順序と確認の観点を持つ。

## 最初に確認すること

作り始める前に、次を実際の設定とコードで確かめる。
記憶や既存の説明文だけで判断しない。

1. **描画経路**：エフェクトを置くCanvasのRender Mode、カメラ、カメラのPost Processing、URPアセットのHDR、Volumeを確かめる。`Screen Space - Overlay` のCanvasにはカメラのポストプロセス（Bloomなど）が掛からないため、光のにじみが必要なら経路から決め直す（[明るさと光のにじみ](references/techniques.md#明るさと光のにじみ)）。
2. **既存の部品とシェーダー**：同じ画面の既存のエフェクト、共通の演出部品、形を描くシェーダー、共通の関数（ハッシュ、ノイズ、距離関数）、マテリアルを探し、使い回せるものを確かめる。同じ式を別のシェーダーへ書き写さない。
3. **描き方**：[エフェクトの描き方](../../../doc/art/direction.md#エフェクトの描き方)に従い、画像を貼らずに計算で描く。召喚獣のような計算で描きにくい物が必要になったら、例外としてユーザーに相談し、推測で画像を使わない。
4. **目的と重要度**：そのエフェクトでプレイヤーに何を感じさせ、何を読み取らせるか（だれが、だれに、どの属性で、どれだけ強く）を確かめる。
5. **画面のHD-2Dの要素**：その画面にあるポストプロセス（Bloom、色調補正、周辺減光、ティルトシフト）、霧、環境の粒、光芒、暗転の部品を確かめ、エフェクトの層がそれらの前後どこに入り、どの効果を通るかを把握する。

## 進め方

### 1. 体験と伝える情報を言葉にする

見た目から作り始めず、プレイヤーに感じてほしいことから逆算する。
「重い」「鋭い」「温かい」のような感覚の言葉を決め、形・色・タイミングへ置き換える（[置き換えの例](references/principles.md#感覚の言葉を属性へ置き換える)）。
技の重要度に合わせて、大きさ・明るさ・長さ・画面効果の格を決め、弱い技と大技が同じ派手さにならないようにする。

### 2. 時間を先に組み立てる

エフェクトを **予備動作**（溜め・予兆）、**発生**（当たる瞬間の山場）、**余韻**（消えていく残り）の3拍に分け、各拍の秒数と、その間に出す層を表にする。
最初は円や帯のような単純な式と仮の色で、タイミングだけを確かめる。
作り込んでから時間を直すより、手戻りが少ない。
遅い要素と速い要素を同じ瞬間に混ぜ、等速で始まって等速で終わる動きを避ける（[時間の組み立て](references/principles.md#時間の組み立て)）。

### 3. 層を設計する

1つの形で全部を表そうとせず、役割の違う層を重ねる。
主役の形、芯の光、衝撃（輪・光条）、粒（火花・破片）、煙や霧、地面、周りへの照り返し、画面効果のうち、どれを使うかを技の格に合わせて決める。
主役は一つに絞り、ほかの層は主役を支える側に回す。
層ごとに描く順番と、キャラより奥か手前かを決める（[層の一覧と組み立て例](references/layering-recipes.md)）。

### 4. 技法を選ぶ

層ごとに、形の式（距離関数、角度、ノイズ）、時間で形を変える方法（太さ・半径・閾値・ノイズの位置を進み具合で動かす）、合成（通常・加算・乗算済みアルファ）、明るさ（HDRとBloom）、周りへの光の影響、奥行きの出し方を選ぶ（[計算で形を描く](references/procedural-shapes.md)、[技法の一覧](references/techniques.md)）。
1つの形を拡大・回転・一様にフェードさせるだけの層は、主役に使わない。
補助の光（グロー、光だまり）に限って使う。
Unityでの実装経路（uGUI、uGUI用の粒子プラグイン、Particle System、Shader Graph、VFX Graph）は、今の画面構成とモバイル性能に合わせて選ぶ（[実装経路の比較](references/techniques.md#unityでの実装経路)）。
外部プラグインは無料の既存プラグインを基本とし、採用前に対応バージョン・保守状況・ライセンスを確かめる。

### 5. HD-2Dの画面と組み合わせる

エフェクトを画面の上に置くだけでなく、画面のHD-2Dの要素と互いに反応させる（[HD-2Dの画面とエフェクトを組み合わせる](references/hd2d-integration.md)）。

- エフェクトを光源として扱い、床・キャラ・霧を照らす。大技では使い手を足元から照らす。
- 暗転は真っ黒にせず環境の色を残し、光の届く範囲だけ明るさを戻す。
- 色と明るさは、Bloom・色調補正・周辺減光を通った最終の画面で決める。
- 主役はボケない範囲に置き、ボケの掛かり方を背景とそろえる。
- 待機中の小さな揺れ、山場の寄りや固定、ブレイクのスローモーションで緩急を付ける。
- 輪郭のはっきりした物（結晶、刃）も、滑らかな光の絵として計算で描く。ドット絵のキャラの隣で浮く場合は、縁の明るさや色を背景とキャラに合わせて調整する。

### 6. 形を式で作る

形は役割ごとに分け、層ごとに別の式（シェーダー、またはシェーダーの切り替え）にする。
芯から火花までを1つの式に詰め込むと、層ごとに時間をずらして動かせない。
式は明るさと透明度だけを決め、色は頂点色や値で後から付けると、同じ形を属性違いに使い回せる。
進み具合と乱数の種は、マテリアルではなく頂点の値で1枚ずつ渡す。
ハッシュ・ノイズ・距離関数は共通のファイルにまとめ、形のシェーダーから読み込む。
座標の作り方、基本の形、ノイズ、値の渡し方、細い線の扱い、消え方は [計算で形を描く](references/procedural-shapes.md) に従う。

### 7. コマを並べて確かめる

動いている状態で見ると勢いでごまかされるが、のっぺり感の原因は止めた1コマに現れることが多い。
発生の前後を含む連続した数コマ（予備動作の途中、発生の直前、発生、発生の直後、余韻の途中、消える直前）を撮影し、1枚に並べて見比べる。
並べた画像で、[のっぺり診断の要点](#のっぺり診断の要点)を1つずつ確かめる。
あわせて、次を確かめる。

- 明るい背景と暗い背景の両方で読めるか。エフェクトは条件の悪い背景で作り、どの背景でも成り立たせる。
- グレースケールにしても、主役と芯が読めるか。明度で読めない形は、色を変えても読みにくい。
- 標的、HPバー、弱点、予告が、エフェクトやダメージ数字で隠れていないか。
- 明滅の頻度と面積が、[安全と読みやすさ](#安全と読みやすさ)の基準を超えていないか。
- 端末で重くならないか（透明な板の重なりと面積、1ピクセルあたりのノイズの回数、粒の数）。Android端末での確認はユーザーに依頼する。

撮影画像の保存先は、[hd2d-lighting-vfxの検証の順序](../hd2d-lighting-vfx/SKILL.md#検証の順序)と同じにする。
スキルの演出は、[スキルのデバッグルーム](../../../doc/features/screens.md#スキルのデバッグルーム)で1枚ずつ選んで再生し、戦闘と同じ画面で撮る。
進み具合を指定して止めたコマを撮る方法は、[止めたコマを撮る](references/procedural-shapes.md#止めたコマを撮る)に従う。
Editorが背面にあるとフレームが進まないなど、撮影のつまずきは [HD-2D演出の実装で得た知見](../hd2d-lighting-vfx/references/implementation-notes.md#editorでの検証のつまずき) で避ける。

### 8. 展示室へ反映して報告する

追加・変更したエフェクトは、同じ変更で展示室の登録とプレビューを更新し、一覧に出ることと、プレビューで再生できることを確かめる。
確かめられなかった段階（Editorだけで確認、端末は未確認など）は、未確認として報告に残す。

## のっぺり診断の要点

完成と判断する前に、次の問いに答える。
症状ごとの原因と直し方は [のっぺり見える原因の診断](references/flatness-diagnosis.md) にある。

| 問い | 満たさないときの見え方 |
|---|---|
| エフェクトの光が、近くのキャラ・床・背景を照らしているか | 画面の上に貼ったシールに見える |
| 明るい芯の周りに光がにじんでいるか（Bloom、または描いたグロー） | 芯が平らな白い塊になる |
| 形が時間とともに変わるか（太さ・半径の変化、削れ、流れるノイズ、層の時間差） | スタンプを押して薄めただけに見える |
| 消え方が一様なフェードではなく、削れる・散る・流れるか | 全体が同時に薄くなり、安っぽい |
| キャラの奥と手前の両方に層があり、地面との接点があるか | 宙に浮いた絵に見え、標的が隠れる |
| 煙など暗い層が、光る層の奥に描かれているか | 中心が灰色に濁る |
| 大きさ・速さ・寿命の違う要素が混ざっているか | 均一なノイズに見える |
| 主役が一つで、明度の差で焦点が決まっているか | どこを見ればよいか分からない |
| 予備動作・発生・余韻に緩急があるか | 手応えがなく、ぷつりと終わる |
| 霧や環境の粒など、画面のHD-2Dの要素もエフェクトに反応しているか | エフェクトだけが別の層に見える |
| 暗転しても環境の色が残り、光の届く範囲が明るいか | 背景が黒い板になり、空気感が消える |
| ボケの掛かり方が、エフェクトと背景でそろっているか | 背景だけがぼけ、エフェクトが浮く |

## 安全と読みやすさ

- 画面全体の閃光や大きな面積の明滅は、1秒間に3回を超えないようにする（WCAG 2.3.1、Xbox Accessibility Guideline 118）。画面の約20%以上を占める明滅と、彩度の高い赤の明滅は特に避け、高コントラストの縞模様を広く出さない。
- 画面揺れ、閃光、ヒットストップは、強さを下げる・止める設定で弱められるようにする。
- 長く感じるエフェクトは長すぎる。連続して使う技ほど短くする。
- 戦闘中に隠してはいけない情報は、[戦闘中の情報の優先順位](../../../doc/features/combat.md#戦闘中の情報の優先順位)に従う。

## 完了報告

完了時は、次をまとめて報告する。

- 作った・直したエフェクトと、狙った体験（感覚の言葉）
- 3拍の時間設計と、使った層
- 形の式と使ったシェーダー、Unityでの実装経路、その理由
- 画面のHD-2Dの要素（光、暗転、ポストプロセス、ボケ、霧、カメラ）との組み合わせ方
- コマを並べた確認画像と、のっぺり診断の結果
- 展示室への登録状況
- 未確認の事項（端末での見え方と負荷、ほかの画面比率など）

Webで調べた場合は、公式資料と設計上の推論を分け、対象のUnityバージョンと参照日を添える。
