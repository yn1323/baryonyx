## 共通指示文

以下を共通指示にし、作る技のレシピを後ろへ追加する。

```text
UnityのRPG戦闘VFXを制作・改善してください。

優先順位は見た目の品質、質感、時間的なメリハリです。
今回はスマホ向けの軽量化を先回りして表現を簡略化しないでください。
ただし、計算負荷を増やすこと自体を目的にはしないでください。

最初にプロジェクトのUnityバージョン、レンダーパイプライン、
レンダラー種別、既存シェーダー、マテリアル、使用テクスチャを確認してください。
現在の環境に合う方法を選び、環境全体の変更が必要なら理由を示してください。

参考画像は形状だけでなく、以下の視覚的特徴を読み取ってください。
・鋭い主形状と柔らかい周辺光の対比
・明るい芯と淡いハローの強度差
・背景が透ける霧と、密度の高い部分の混在
・粒、筋、塊というサイズの階層
・属性ごとの材質と動きの違い
画像のゲームの内部実装を知っている前提では説明しないでください。

本体、発光コア、ハロー、霧や煙、粒子、背景歪みを、必要に応じて
独立したレイヤーに分け、各レイヤーの役割と合成方式を説明してください。
すべてをAdditiveや同じ透明度に統一しないでください。
Core/Halo等は表現名なので、存在しないAPI名を推測して使わないでください。

単調さは、粒数を増やすだけで解決しないでください。
大きな流れと小さな揺らぎ、硬い輪郭と柔らかい輪郭、
速い衝撃と遅い余韻を作り分けてください。
ランダム性は全体の方向・シルエットを壊さない範囲で使ってください。

時間構成は予兆→発動・着弾→余韻に分けてください。
発光、粒子、煙、破片の出現・ピーク・消失をずらしてください。
一様な拡大と一様なフェードだけで完了させないでください。

C#とHLSLを中心に、形・濃淡・模様・材質をコードで生成してください。
外部の画像素材、購入テクスチャ、画像生成AIの出力、写真、
外部Flipbook、既存のノイズ・法線画像を使用しないでください。
参考画像は観察用で、実行時の素材にはしないでください。
必要に応じ、Shader Graphの手続き的ノード、生成メッシュ、SDF、
fBm、Domain Warping、Curl Noise、レイマーチングを使ってください。
ノイズ関数を実装せず、存在しないnoise()等を呼ぶだけで完了させないでください。
コード生成したTexture2D/3D、RenderTexture、ComputeBuffer、
画面色・深度の取得は利用可能ですが、生成元と用途を明示してください。
外部素材なしでクリーンな状態から再生成できるようにしてください。
画像なしで難しい形は、生成メッシュや密度場で補い、表現を単色に簡略化しないでください。

強度、幅、外周減衰、ノイズのスケールと速度、Dissolve幅、
粒子の寿命とサイズ、時間カーブをInspector等から調整可能にしてください。
意味のある名前と初期値を付け、必須パラメーターを説明してください。

ゲーム内カメラで、明るい背景・暗い背景・キャラクターと重なる状況を確認してください。
同じ乱数シードで比較できるようにし、予兆・ピーク・消散の画像と
再生結果を使って改善してください。
確認した内容と未確認の内容を区別して報告してください。
```

## 追加するClaude向け指示

```text
外部のVFX画像アセットを一切使わず、コードから再生成できる構成にしてください。
画像を必要としていた役割を、以下のように置き換えてください。
形状：解析的距離関数・SDF・C#の生成メッシュ
濃淡：実装済みのPerlin/Simplex/Value/Worley系ノイズとfBm
複雑な流れ：Domain WarpingとCurl Noise、時間変化するベクトル場
凹凸：高さ関数または密度関数の勾配から求める法線
炎・煙の厚み：必要な箇所へ3D密度場とボリューム積分
亀裂・霜・泡：Voronoiセル・境界距離・形状マスクの組み合わせ

既存のデフォルト粒子テクスチャにも頼らず、基本粒形状から生成してください。
必要ならコード生成したTexture2D/3DやRenderTextureへ計算結果を保存して構いません。
これは外部画像の読み込みとは区別してください。
描画途中の画面色や深度を屈折・遮蔽へ使うことも可能です。
ただし現在のレンダラーで取得できる対象とタイミングを確認してください。

ノイズだけで全属性を色替えしないでください。
炎は密度と上昇、水は連続した面と液滴、氷は硬い面と亀裂、
斬撃は鋭い帯、回復は滑らかな上昇という材質・動きの差を維持してください。

本書の式は設計用です。noise/fbm等の仮関数名をそのまま残さず、
使う関数を実装し、データの範囲・座標系・合成方式を明示してください。
3D密度やCompute Shaderが必要な場合、対応環境とリソースの生成・破棄も実装してください。
まず一つの代表技で見た目を検証し、それから共通化してください。
```

## ユーザーが依頼するときの見本

このゲームで作り直しを頼むときの見本である（[計画を3つの表で先に見せる](lessons.md#計画を3つの表で先に見せる)）。
「豪華に」「リアルに」ではなく、層の数・透け方・秒数のように構造と数字で頼むと伝わる。

```text
〇〇（技の名前）のVFXを作り直したい。まだ実装しないで。
1. その現象が現実ならどう見えるか（何でできていて、どう動き、何が残るか）を調べて書き出して
2. 何秒から何秒に、何が、どの層で動くかの表を作って
3. 主役の形を最低4層に分けて、層ごとの役割・透け方・時間の表を作って
表を確認したら実装を頼む。実装したら0.1秒刻みのコマを撮って、表と合っているかを確かめて、今の版と同じ場面で並べて見せて。戦闘画面でもHPバーや弱点が隠れていないか撮って。
```
