# 計算で形を描く

調査日は2026-10-01。
このプロジェクトでは、エフェクトの形を画像で持たず、シェーダーの計算で描く（[エフェクトの描き方](../../../../doc/art/direction.md#エフェクトの描き方)）。
この資料は、四角い板の上で形・明るさ・透明度を式で決める一般的な技法と、試作で得た注意点をまとめる。
出典は [research-sources.md](research-sources.md#計算で描く形) にまとめる。
「推論」と書いた項目は設計上の判断であり、採用前にコマを並べて確かめる。

## 板の上の座標

エフェクトは、uGUIの四角い板（`Graphic`）を1枚置き、その中をフラグメントシェーダーで塗って描く。
形の式は、板の中の位置から求めた次の値を入力にする。

| 値 | 求め方 | 使い道 |
|---|---|---|
| 中心からの位置 `p` | UVを `uv * 2 - 1` で -1〜1 に直す | すべての形の基準 |
| 距離 `r` | `length(p)` | 円、輪、グロー、ドーム |
| 向き `dir` | `p / r` | 輪に沿った模様、継ぎ目のないノイズ |
| 角度 | `atan2(p.y, p.x)` | 光条、扇形、角度ごとに区切った粒 |
| 縦横 `p.x`・`p.y` | そのまま | 柱、帯、斬撃の幅、炎の高さ |

床に寝かせる形は、式を変えずに板の縦を縮めて表す。
形の向きの変化（回転）も、板を回して表すと、式を単純に保てる。

## 基本の形

**距離関数**は、ある点から形の縁までの距離を返す関数である。
縁で0、内側で負、外側で正になる形にしておくと、太さ・にじみ・削れを同じ値から作れる（Inigo Quilez氏の2Dの距離関数の一覧）。
距離 `d` から明るさへの直し方は、次の3つを使い分ける。

| 直し方 | 式の例 | 見え方 |
|---|---|---|
| 鋭い縁 | `1 - smoothstep(0, w, d)` | 硬い輪郭。`w` を画面の1ピクセル程度にすると、ぎざぎざにならない |
| 光のにじみ | `exp(-d * d / (w * w))` | 縁の周りに柔らかく広がる光 |
| 片側の尾 | `exp(min(d, 0) / w)` | 内側だけへ薄れる。衝撃の先頭の後ろに残る光 |

| 形 | 組み立て方 |
|---|---|
| 輪・衝撃波 | `r - 半径` を距離にして、先頭の細い線、そのにじみ、内側の尾を重ねる |
| グロー・光だまり | `r` を距離にした光のにじみ。床に置くときは板の縦を縮める |
| 光条・星 | 角度の `cos` を何乗かして細い筋にし、`r` で外へ薄める。本数は角度に掛ける数で決める |
| 弧・斬撃 | 輪の式を角度の範囲で切る。範囲の端を細く暗くし、刃の進む側を明るくする |
| 光の柱 | `p.x` の距離で太さを決め、`p.y` で上へ薄める。縦に流れるノイズを掛ける |
| ドーム・障壁 | 半円の縁を明るくし、面は薄くする。六角形の格子の距離で模様を足す |
| 魔法陣 | 同心の輪、多角形の距離、等間隔の目盛りを重ね、板ごと回す |
| 稲妻 | 折れ線の各区間への距離の最小値。折れる位置をノイズで決め、打ち直すたびに種を変える |
| 炎 | 上へ流れるノイズを、しずく形の範囲で切る。閾値で舌の形を作り、高さで白→黄→橙→赤へ色を変える |
| 煙・霧 | 細かさの違うノイズの和（fBM）を通常合成で描き、閾値を上げて削る |
| 結晶・破片 | ひし形や三角形の距離関数。割れ目はセルごとに区切った模様（ボロノイ）で作る |
| 粒・火花 | 格子や角度でセルに区切り、セルごとに乱数で位置・大きさ・寿命を決めて、点のにじみを置く |

複数の形は、距離の最小値（和集合）・最大値（共通部分）で組み合わせる。
滑らかにつなぐ最小値（smooth min）を使うと、炎の塊や煙の玉が溶け合う（Inigo Quilez氏の解説）。

## ノイズ

画像のノイズの代わりに、整数の格子点ごとに乱数（ハッシュ）を返す関数を作り、格子の間を滑らかに補間して**値ノイズ**にする。
細かさを2倍ずつ上げたノイズを、強さを半分ずつ下げて足すと**fBM**（細かい揺らぎを含むノイズ）になる（The Book of Shaders）。

- **継ぎ目を作らない**：輪に沿った模様は、角度ではなく向き `dir`（cosとsin）をノイズの2軸に使う。角度を使うと、角度が一周して戻る位置で模様が切れる。
- **時間で動かす**：ノイズの3軸目に進み具合を足すと、形を保ったまま模様が変わる。上へ流すときは縦の座標から進み具合を引く。
- **重ね方**：画像の模様を重ねるときと同じく、細かさは2倍刻みにし、流す速さの差は狭くする（[流れる模様](techniques.md#流れる模様とテクスチャの掛け合わせ)）。
- **数を絞る**：ノイズ1回で格子点8つ分のハッシュを計算する。1つの形で使う回数を決めて数え、広い面積の層ほど少なくする。

## 時間と個体差の渡し方

uGUIで1枚ずつ違う値をシェーダーへ渡すには、マテリアルではなく頂点の値を使う。
マテリアルは同じものを共有するため、マテリアルの値を書き換えると、同じマテリアルの全部の板が変わる。

| 経路 | 渡せる値 | 注意 |
|---|---|---|
| 頂点色 | 色と、アルファ1つ | アルファを「残り」（1で出たばかり、0で消えた）に使うと、色付けと時間を一度に渡せる |
| UV0 | 板の中の位置 | `RawImage.uvRect` で変わるため、形の式の入力として使うときは触らない |
| 追加のUV（UV1〜UV3） | 4成分ずつの任意の値 | Canvasの `additionalShaderChannels` で該当のチャンネルを有効にし、`Graphic` を継承したクラスの `OnPopulateMesh` で頂点に書く（Unityスクリプトリファレンス） |

- **シェーダーの時刻（`_Time`）に頼らない**：ヒットストップで戦闘を止めても、シェーダーの時刻は進む。止めたコマを撮るときも、同じ進み具合を再現できない。進み具合はC#から頂点の値で渡す。
- **個体差**：同じ技を続けて出しても形が同じにならないよう、乱数の種を追加のUVで渡す。種を渡せないときは、板を回すだけでも模様の位置が変わる。

## 細い線と明るさ

- **1ピクセルより細くしない**：形が小さいうちは、線が1ピクセルより細くなって途切れる。`fwidth(r)` で1ピクセル分の距離を求め、線の太さと縁のぼかしの最小値にする。`fwidth` を使うシェーダーは `#pragma target 3.0` にする。
- **1を超える明るさ**：頂点色は0〜1に収まるため、明るさの倍率はシェーダーの値で掛ける。芯だけを1より明るくすると、Bloomで芯だけがにじむ（[明るさと光のにじみ](techniques.md#明るさと光のにじみ)）。
- **板の端で0にする**：式の値が板の端で残ると、四角い板の縁が見える。半径とにじみの幅を、板の端より内側で0になるように決める。

## 消え方を式で作る

全体のアルファを下げるだけでは、形が変わらないまま薄くなる（[消え方](principles.md#消え方)）。
進み具合に合わせて、次の値を式の中で動かす。

- **太さと半径**：広がるほど線を細くする。
- **閾値で削る**：ノイズを閾値と比べ、閾値を上げて低い部分から消す（アルファエロージョンの考え方）。輪なら弧に分かれ、炎なら舌がちぎれ、煙なら穴があく。
- **粒を外へ流す**：粒の位置に進み具合を足して、本体から離しながら消す。

## 試作で分かった注意点

2026-10-01に衝撃波の輪を計算で描いたとき、次の失敗をコマで見つけて直した。

| 症状 | 原因 | 直し方 |
|---|---|---|
| 輪が泡やガラス玉に見える | 内側の尾が太く明るく、円の中が面で光った | 尾を細く暗くし、明るさを先頭の線とそのにじみに集める |
| パイを切ったような欠け方になる | 角度だけで決まるノイズで閾値を切り、切れ目が中心から放射状にそろった。閾値の幅も狭かった | ノイズに半径も混ぜて切れ目を斜めにし、閾値の前後の幅を広げて端を柔らかくする |
| 描いた輪郭線に見える | 先頭の線の明るさが一周同じだった | 先頭の明るさにノイズでむらを付ける |
| 粒がほとんど見えない | 粒が小さく暗く、Bloomの閾値に届かなかった | 粒を1より明るくして、Bloomでにじませる |
| 粒の端が欠ける | 粒がセルの境界をまたいだ | 粒の大きさとずれ幅を、セルの幅の4分の1程度に収める |
| 中心を横切る線が見える | 背景の石垣の縁が、加算の輪を透かして見えていた | シェーダーの問題と決める前に、背景を単色にして撮り直して切り分ける |

## 性能

- 描く負荷は、塗るピクセル数、1ピクセルの計算量、重なりの積で決まる（[性能](techniques.md#性能)）。計算で描く形は、画像を1回読むより1ピクセルの計算が重くなりやすい。
- GPUによって、計算と画像の読み込みの速さの比が違う（Armの資料）。同じシェーダーでも、端末によって重さの順位が変わる可能性がある（推論）。
- 画面の大部分を覆う層（暗転、霧、閃光）には、ノイズを使わない軽い式を使う。
- 形ごとにシェーダーを分けるか、キーワードで切り替えて、使わない形の計算を走らせない。
- 端末での重さの確認はユーザーに依頼する。Editorだけで性能を合格にしない。

## 止めたコマを撮る

計算で描く形は、進み具合を渡せば同じコマを何度でも描ける。
エフェクトの部品に、進み具合（0〜1）を指定して描くメソッドを持たせると、時間を進めずにコマを撮れる。

1. Editorのプレビュー用シーン（`EditorSceneManager.NewPreviewScene`）に、撮る対象と一時カメラを置く。
2. カメラのHDRとポストプロセスを有効にし、戦闘の画面と同じVolumeを置いて、Bloomを掛けた最終の画面で撮る。
3. 進み具合を変えながら描いて画像に保存し、コマを1枚に並べる。
4. `finally` でカメラの描画先を外し、カメラとRender Textureを破棄し、プレビュー用シーンを閉じる。カメラが残るとGameビューを塗りつぶす。

CLIからEditorを操作して撮るときに、Editorが背面にあると処理が進まず、時間切れになることがある。
撮影の前にEditorを前面に出す。
撮影のつまずきは [HD-2D演出の実装で得た知見](../../hd2d-lighting-vfx/references/implementation-notes.md#editorでの検証のつまずき) も読む。
