# のっぺり見える原因の診断

エフェクトが「のっぺり」「安っぽい」「貼り付けたよう」と言われたときに、症状から原因と直し方を引くための表である。
原因は1つとは限らず、複数が重なっていることが多い。
コマを並べた画像で、症状ごとに当てはまるかを確かめる。

## 症状と直し方

| 症状 | 主な原因 | 直し方 | 参照 |
|---|---|---|---|
| 画面の上に貼ったシールに見える | エフェクトの光が、近くのキャラ・床・背景を照らしていない | 床の光だまり、キャラへの色乗せ、背景の明暗を加える | [周りへの光の影響](techniques.md#周りへの光の影響) |
| 芯が平らなクリーム色や白の塊になる | 加算の重ねすぎで中間の明度が消えた。Bloomが掛からない経路に描いている | 芯を小さくし、明度の段階を作る。HDRとBloomの経路を通すか、グローで代える | [明度の幅を使う](principles.md#明度の幅を使う)、[明るさと光のにじみ](techniques.md#明るさと光のにじみ) |
| スタンプを押して薄めたように見える | 1つの形を拡大・回転し、全体を一様にフェードしている | 太さ・半径・閾値を進み具合で変え、削れや流れるノイズで形を変える。層ごとに時間をずらす | [消え方を式で作る](procedural-shapes.md#消え方を式で作る)、[形を動かす技法](techniques.md#形を動かす技法) |
| 中心が灰色に濁る | 暗い煙や通常合成の層が、光る層の上（手前）に描かれている | 暗い層を光る層の奥へ移す | [描く順番と前後関係](layering-recipes.md#描く順番と前後関係) |
| 宙に浮いた絵に見える | 地面との接点がなく、すべてが同じ奥行きにある | 床に寝かせた層、光だまり、焦げを置く。主形を奥と手前に分ける | [奥行きの出し方](techniques.md#奥行きの出し方) |
| 標的が見えなくなる | すべての層がキャラより手前にあり、不透明に近い | 主形を分けてキャラを挟み、当たったキャラのシルエットを残す | [描く順番と前後関係](layering-recipes.md#描く順番と前後関係) |
| 均一なノイズに見える | 粒の大きさ・速さ・寿命・色がそろっている | ばらつきを持たせ、大小と遅速を混ぜる。大きな流れは固定する | [動き](principles.md#動き) |
| 模様が滑って見える | 1つの模様（画像またはノイズ）を平行移動している | 細かさと速さの違う模様を重ねて掛け合わせる | [流れる模様](techniques.md#流れる模様とテクスチャの掛け合わせ) |
| どこを見ればよいか分からない | 主役がなく、すべての層が同じ明るさ・大きさ | 主役を1つに決め、副要素の明度と彩度を下げる | [焦点と主従](principles.md#焦点と主従) |
| 手応えがない | 等速で始まり、等速で終わる。発生の山場がない | 予備動作・発生・余韻の3拍に緩急を付け、発生に閃光とヒットストップを置く | [時間の組み立て](principles.md#時間の組み立て) |
| ぷつりと消える | 余韻の層がない | 削れ、漂う粒、残る煙で余韻を作る | [消え方](principles.md#消え方) |
| 明るい背景で見えなくなる | 加算の光だけで形を作っている | 光の奥に暗い層を敷く。乗算済みアルファで暗い部分を持たせる | [合成の選び方](techniques.md#合成の選び方) |
| 色が1色のまま薄くなるだけ | 時間による色の流れがない | 温度の流れ（白→黄→橙→赤→煙）など、時間で色を変える | [色](principles.md#色) |
| ドット絵の中で、写実寄りの絵が浮く | 生成画像などの絵柄が、ドット絵のキャラや背景と合わない | 画像を貼らずに計算で描く | [エフェクトの描き方](../../../../doc/art/direction.md#エフェクトの描き方) |
| 四角い板の縁が見える | 式の値（画像なら素材の縁）が、板の端で0になっていない | 半径とにじみの幅を、板の端より内側で0になるように決める | [形の作り方](techniques.md#形の作り方) |
| 輪や球が泡・ガラス玉に見える | 内側の尾やにじみが太く明るく、形の中が面で光る | 尾を細く暗くし、明るさを先頭の線と縁に集める | [試作で分かった注意点](procedural-shapes.md#試作で分かった注意点) |
| パイを切ったような欠け方になる | 角度だけで決まるノイズで閾値を切り、切れ目が放射状にそろう | ノイズに半径を混ぜ、閾値の前後の幅を広げる | [試作で分かった注意点](procedural-shapes.md#試作で分かった注意点) |
| 描いた輪郭線に見える | 縁や芯の明るさが一様 | 縁の明るさにノイズでむらを付ける | [試作で分かった注意点](procedural-shapes.md#試作で分かった注意点) |
| エフェクトだけが別の層に見える | 霧、埃、光芒など画面のHD-2Dの要素がエフェクトに反応しない | 発生地点の霧を明るくし、衝撃で埃を押し出す | [霧と環境の粒をエフェクトに反応させる](hd2d-integration.md#霧と環境の粒をエフェクトに反応させる) |
| 技の間、背景が黒い板に見える | 暗転を黒で一律に塗っている | 環境の色を残し、光の届く範囲だけ明るさを戻す | [暗転で背景を真っ黒にしない](hd2d-integration.md#暗転で背景を真っ黒にしない) |
| 背景はぼけているのに、エフェクトだけくっきりしている | 半透明のエフェクトに深度のボケが掛からない | 主役をボケない範囲に置く。深度のボケを使う場合は、エフェクトの奥行きに合わせたぼかしを用意する | [ボケと焦点を合わせる](hd2d-integration.md#ボケと焦点を合わせる) |
| 高解像度の「物」が、ドット絵の中で浮く | 輪郭のはっきりした物を、写実寄りに細かく描いている | 物も計算で単純な形と光にする。計算で描きにくい物は、例外としてユーザーに相談する | [ドット絵と滑らかなエフェクトを混ぜる](hd2d-integration.md#ドット絵と滑らかなエフェクトを混ぜる) |
| 単体では良いのに、画面に置くと色が変わる | Bloom・色調補正・周辺減光を通さずに色を決めた | ポストプロセスを通った最終の画面で色と明るさを決める | [画面のBloom・色調・周辺減光と合わせて調整する](hd2d-integration.md#画面のbloom色調周辺減光と合わせて調整する) |
| 大技と通常攻撃の差がない | 技の格に合わせた大きさ・長さ・画面効果の差がない | 格に合わせて層の数と画面効果を段階的に割り当てる | [重要度に合わせて格を決める](principles.md#重要度に合わせて格を決める) |

## 事例：戦闘画面の炎（2026-10-01）

戦闘画面のモックで、ユーザーから、オクトパストラベラーと比べて安っぽくのっぺりしている、画像を使っているからか、と相談を受けた。
炎の爆発を時間を追って撮影し、コマを並べて確かめたところ、次の5つの原因が重なっていた。

1. 爆発の隣の敵と床が、まったく橙に照らされていなかった。
2. 戦場を `Screen Space - Overlay` のCanvasに描いていたため、Bloomが掛からず、芯が平らな塊になっていた。
3. 芯から火花まで描き込んだ1枚の絵を拡大・回転し、全体を一様に薄くしていた。
4. すべての層がキャラより手前にあり、標的の敵が爆発に完全に隠れていた。
5. 暗い煙が爆発より後（手前）に描かれ、爆発の途中で中心が灰色に濁っていた。

どれも画像の動かし方と画面へのなじませ方の問題であり、描き方（画像か計算か）を変えても、この5点は別に確かめる必要がある。
同じ症状を見つけたら、この5点から確かめる。

## 事例：画像の衝撃波の輪と計算の輪（2026-10-01）

上の5点を直したあとも、ユーザーから、画像だと今のドット絵と背景になじまないことがある、と相談を受けた。
衝撃波の輪を画像を使わずに計算で描き、画像の輪と同じ動きで並べて、コマを撮って比べた。
画像の輪は柔らかく、細かいきらめきが多い。
計算の輪は先頭の線が鋭く、後半に弧へ分かれて消える。
ユーザーは計算の輪を選び、エフェクトを計算で描くことに決めた（[エフェクトの描き方](../../../../doc/art/direction.md#エフェクトの描き方)）。
試作の途中で出た泡・パイ・輪郭線の失敗は、[試作で分かった注意点](procedural-shapes.md#試作で分かった注意点)にまとめた。
