# HD-2Dの画面とエフェクトを組み合わせる

調査日は2026-10-01。
**HD-2D** は、ドット絵に3DCGの画面効果（動的な光と影、被写界深度、ティルトシフト、Bloom、霧、粒、カメラワーク）を重ねた表現である（スクウェア・エニックスの説明、Wikipedia）。
エフェクトをこの画面になじませるには、エフェクト単体の出来に加えて、画面効果がエフェクトをどう扱うかも合わせて考える必要がある。
この資料は、エフェクトと画面効果の組み合わせ方を扱う。
背景に常に出しておく光・霧・粒や、ポストプロセスの設計そのものは、3Dの舞台なら [hd2d-stage-set](../../hd2d-stage-set/SKILL.md)、描いた2D背景なら [hd2d-lighting-vfx](../../hd2d-lighting-vfx/SKILL.md) の担当とし、ここでは扱わない。

出典は [research-sources.md](research-sources.md#hd-2dとの組み合わせ) にまとめる。
「推論」と書いた項目は、作品の事例をuGUIの2D画面へ置き換えた設計上の案であり、採用前に撮影と端末で確かめる。

## 組み合わせのコツ

### エフェクトを光源として扱う

HD-2Dの作品は、エフェクトを「光るもの」で終わらせず、周りを照らす光源として扱っている。

- エフェクトの発生と同時に、その位置から周りを照らす。床の光だまり、近くのキャラへの色乗せ、背景の明暗の3つを基本にする（[周りへの光の影響](techniques.md#周りへの光の影響)）。
- 大技では、使い手を足元から照らす。使い手の絵の形に合わせて、下ほど明るいグラデーションを加算で重ねると、2D画面で近い印象を作れる（推論）。ふだんの光源と違う向きの光が入ることで、特別な瞬間だと伝わる。
- エフェクトの光源の反対側へ、キャラの影を短く伸ばす（推論）。疑似の投影影の採用状況は、[HD-2D技法の一覧と採用方針](../../hd2d-lighting-vfx/references/technique-catalog.md#e-キャラクターの影と陰影)で確かめる。
- 光の色は、背景の色調と温度の差を付ける。夜や洞窟の青い環境に暖色の炎や金の回復を置くと、光が際立つ。環境と同系色の光は背景に溶ける（Riotの「環境に溶け込ませない」と同じ考え方）。

### 暗転で背景を真っ黒にしない

技の間に背景を暗くする演出は、エフェクトを浮かせるのに役立つ。
ただし、黒で一律に塗ると、背景が黒い板になり、HD-2Dの空気感が消える。

- 暗転には環境の色（夜なら暗い青）を残し、形が読める明るさにとどめる。オクトパストラベラーも、環境光を足して影が真っ黒にならないようにした（講演レポート）。
- 暗くした後は、エフェクトの光が届く範囲だけ明るさを戻す（推論）。暗転の上に照り返しの光だまりを重ねるか、光の位置を中心に暗転を薄くする。全体を一律に暗くしたままでは、光が周りを照らしているように見えない。

### 画面のBloom・色調・周辺減光と合わせて調整する

ポストプロセスは、背景とエフェクトの両方に掛かる。
エフェクトだけを見て色と明るさを決めると、画面に置いたときに変わる。

- Bloomの設定は背景と共通になる。照らされた中間調までにじむ設定では、エフェクトの明るさを足すと背景のにじみも増える。エフェクトの芯を小さく保ち、足りない光はグローの描画で補う。設定値は[ポストプロセスの調整](../../../../doc/features/showcase.md#ポストプロセスの調整)を確かめる。
- 色調補正と周辺減光もエフェクトに掛かる。画面の端で出る技は周辺減光で暗くなり、彩度を上げた画面ではエフェクトの彩度も上がる。エフェクトの色と明るさは、ポストプロセスを通った最終の画面で決める。
- レンズフレアや光の筋は、大技の閃光に一瞬だけ使うと、光の強さを伝えやすい（オクトパストラベラーのレンズフレアの導入を参考にした推論）。常時出すと画面が散らかる。

### ボケと焦点を合わせる

HD-2Dでは、被写界深度で強調したい要素を際立たせ、画面をミニチュアのように見せる（トライアングルストラテジーの解説、Wikipedia）。
エフェクトの主役は、ボケない範囲に置く。

- 画面の位置でぼかす疑似ティルトシフトは、エフェクトも背景と同じようにぼかす。上下の帯に出る粒や光は柔らかくなり、奥行きの手掛かりになる。主役や読ませたい情報を帯に置くと、ぼけて読みにくくなる（[疑似ティルトシフト](../../../../doc/features/showcase.md#疑似ティルトシフト)）。
- 深度を使う本物の被写界深度では、URPの標準の処理は半透明の描画の深度を使わないため、半透明のエフェクトにはボケが掛からない（Zennの技術記事）。背景だけがぼけて、奥にあるはずのエフェクトがくっきり残ると、貼り付けたように見える。3D空間で深度のボケを使う場合は、エフェクトの奥行きに合わせたぼかしを別に用意する。このゲームの3Dの舞台は、舞台のレンズで不透明の舞台だけをぼかし、キャラ・演出・舞台のUIはぼかさない（hd2d-stage-set の[レンズと色](../../hd2d-stage-set/references/camera-light.md#レンズと色)）。奥に置く演出は、ぼけない前提で大きさと明るさを決める。
- 手前を横切る大きくぼけた粒（前景のボケ）は、ミニチュアを覗き込む感じを強める（推論）。数を絞り、主役や標的の上を長く横切らせない。

### 霧と環境の粒をエフェクトに反応させる

霧や埃が漂う画面で、エフェクトだけが光り、霧や埃が変わらないと、エフェクトが別の層に見える。

- 発生の瞬間に、発生地点の周りの霧を明るくする（推論）。霧の層の上に、エフェクトの色の光だまりを重ねる方法でもよい。
- 衝撃に合わせて、周りの埃や火の粉を外へ押し出したり揺らしたりする（推論）。
- 強い光の技では、光の筋（光芒）を一瞬だけ足すと、空間に光が満ちて見える（推論）。

### カメラで緩急を付ける

オクトパストラベラーは、待機中のゆっくりとした揺れと、山場での固定を使い分けた（講演レポート）。
オクトパストラベラーIIは、大技でカメラワークを切り替えて見せた（ファミ通のプレビュー記事）。

- 2D画面では、戦場全体を短い時間だけ少し拡大して使い手や標的に寄せる、横へ少しずらす、でカメラの寄りの代わりにする（推論）。拡大するとドット絵の1ドットの大きさがそろわなくなるため、短い時間に限り、撮影でぼけ方を確かめる。
- ブレイクや撃破の瞬間には、スローモーションで重さを出せる（講演レポート）。ヒットストップより長く遅く流す演出なので、多用すると戦闘のテンポが落ちる。山場に限って使う。
- カメラの揺れ・寄り・スローは、画面揺れと同じく、弱める設定の対象にする。

### ドット絵と滑らかなエフェクトを混ぜる

HD-2Dは、ドット絵に3DCGの画面効果を重ねる表現であり、滑らかな光がドット絵の上に乗ること自体は前提に含まれる。
一方、ドット絵では、ドットの大きさが違う絵を混ぜること（ミクセル）は、継ぎはぎに見えるとして避けられることが多い（ドット絵の用語解説）。

- 写実寄りに細かく描いた「物」（氷の結晶、岩、剣、火球の本体）は、ドット絵のキャラの隣で質感がぶつかりやすい（推論）。
- このプロジェクトでは、空気も物も計算で描き、滑らかな光の絵にする（[エフェクトの描き方](../../../../doc/art/direction.md#エフェクトの描き方)）。物は細部を描き込まず、単純な形と縁の光で見せる。
- 計算で描きにくい物をドット絵で描く例外は、素材ごとにユーザーと相談して決める。
- 例外としてドット絵で描く部品は、ドットの格子に合わせて置き、回転は90度単位に限ると、格子が崩れない（[HD-2D演出の実装で得た知見](../../hd2d-lighting-vfx/references/implementation-notes.md#部品設計の工夫)の火の粉の例）。ドット絵の規格は [pixel-art-standards](../../pixel-art-standards/SKILL.md) に従う。

### 環境の違う画面で確かめる

同じエフェクトでも、背景の明るさ、霧の濃さ、色調が違う画面では見え方が変わる。
明るい背景と暗い背景、霧の濃い背景と薄い背景で撮影して比べる。
オクトパストラベラーIIの昼夜のように環境の光が変わる場合は、その切り替え後の画面でも確かめる。

## Unityでの前提

- URPの2D Rendererは、3Dのライトと同じ描画では使えない（Unity Discussions）。Light 2Dでスプライトを照らすには、2D RendererとSprite-Litの描画が必要になる。
- 2D Rendererへの切り替えは全画面に影響するため、エフェクトの都合だけで決めない。背景の3D化は、Top・Home・戦闘画面で3Dの舞台として採用済みである（[3Dの舞台の仕様](../../../../doc/art/hd2d-stage.md)）。現在の採用状況と見送りの理由は [HD-2D技法の一覧と採用方針](../../hd2d-lighting-vfx/references/technique-catalog.md) にある。
- Unity Learnの「2D Lighting for Pixel Art」講座（Unity 6.3）は、2D Light、法線マップ、発光、影、ポストプロセスをドット絵向けに扱う。2D Rendererの採用を検討するときの入口にする。
