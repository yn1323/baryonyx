# RPGキャラ設定

人物としての魅力と、後で絵にできる具体性を備えたキャラ設定を日本語で作る。
このスキルの成果物は設定文と動作設計。画像やスプライトシートの生成は含めない。
ユーザーの最新の指定を優先し、既存キャラの変更は依頼された範囲にとどめる。

## 入力と範囲

名前、職業、種族、性別、外見、性格、既存設定など、与えられた材料から作成する。
「おまかせ」「1人作って」の場合は、足りない項目を創作して完成させる。
新規作成は指定がなければ1人。既存設定の編集では空白を勝手に改変の許可と解釈しない。
他キャラの情報が提供されている場合は、色・形・人物像の重複を避け、関係性に生かす。
他チャットを読む依頼がある場合は、利用可能なタスク閲覧ツールを使う。閲覧できない内容を読んだ扱いにしない。

「スプライト制作条件」と「戦闘スキル案」は標準出力に含めない。
解像度・頭身・画風・視点・キャンバス設定などの共通制作指示を別名で復活させない。
スキル名・効果・威力・倍率・ダウン値・クールダウンなどの性能案も追加しない。
職業や「回復役」「盾を使う」といった概念的な役割、動きに必要な装備設定は含める。
攻撃系・補助系のアニメーションは、戦闘スキルの性能を決めずに設計できる。
ユーザーがこれらの追加を明示的に求めた場合は、その範囲で応じる。

## 新規作成時の出力

完成した設定を一つの文書にまとめる。説明用の前置きや同内容のまとめを重ねない。
見出し相当の短いラベル、短い段落、比較しやすい表を使う。1人の設定は次の順序を基本とする。

| 項目 | 内容 |
|---|---|
| 二つ名・名前 | 職業の説明だけでなく、人物の印象が伝わるもの |
| キャラクターの核 | 仲間にしたくなる理由、本人が求めるもの、性格の面白い矛盾を1〜2文で |
| フレーバーテキスト | 具体的な出来事と会話で見せ、最後にオチをつける短文 |
| 基本設定・外見 | 年齢、性別、種族、職業、概念的な役割、体格、髪色・長さ・髪型、衣装、主な配色 |
| ドット絵で必ず残す特徴 | 下記の6項目を明記した表と、省略できる細部 |
| 経歴・目的・性格 | 冒険する理由、得意なこと、弱点、仲間への接し方。既知の仲間がいれば関係性も |
| 装備と持ち方 | 左右の持ち手、収納場所、動作中の扱い、見た目を固定する条件 |
| 動きの個性 | 姿勢、重心、動きの速さ・大きさ、衣装や尾などの揺れ |
| アニメーション設計 | 下記10種類のフレーム数、各コマの動き、接続・保持・発生位置 |
| 台詞 | 加入、日常、得意な行動、苦戦、勝利などから3〜5場面。性格と口調を揃える |

修正依頼ではこの全文を毎回再出力せず、依頼された部分だけを更新する。
全文の再提示を求められたときは、各部分の最新の修正を統合する。

## 必ず残す外見は6項目

「性別・髪型・髪色」を基本情報として明記し、それとは別に識別特徴を3点選ぶ。
表の項目は「性別／髪型／髪色／特徴①／特徴②／特徴③」とする。
髪型の欄には、長さ・形・分け方や結び方まで、短く具体的に書く。
髪がないキャラなどは「なし」と明記し、6項目を埋めるために髪を追加しない。

特徴3点は、輪郭、大きな衣装の色面、代表的な装備、耳や尾などから選ぶ。
髪や性別を3点の枠で重複計上しない。瞳の色や刺繍など、細部だけに識別を頼らない。
種族に不可欠な耳・尾などは優先し、本数や形を装備・外見の記述とも一致させる。
基本外見と6項目の表で、色・髪の長さ・装備を食い違わせない。

小さな人物の立ち姿が32×48に収まる用途を内部の判断基準とし、形を増やしすぎない。
このサイズを説明する制作条件の節は出力しない。別の用途が明示されればそちらを優先する。
省略できる細部は設定には残してよいが、描画必須の6項目と区別する。

## フレーバーテキストの笑い

標準は、真面目な人物紹介より一段くだけた、はっきりオチのあるコメディ。
小さな出来事、本人の妙な理屈、短い掛け合い、意外な結果で人物を見せる。
「実はお茶目」「仲間から愛されている」と説明するだけで済ませない。
しんみりした余韻や教訓で締めず、最後の一文まで笑いにつなげる。
長さはおよそ100〜200字を目安とし、オチを成立させるために調整する。

笑いの強さの参考：

> 「無茶は駄目よ」
> そう言って仲間を休ませたエルナは、崖に生えた薬草を採りに登った。
> 「落ちたらどうする！」
> 「安心して！　骨折に効くやつだから！」
> 薬草の効能は、その日のうちに確かめられた。

この人物・台詞・骨折の筋を使い回さない。几帳面さ、食い意地、見栄、勘違い、
妙なこだわりなど、そのキャラ固有の性格から笑いを作る。
全員を無能や事故を起こす人にせず、得意分野の魅力も設定全体で残す。

## 装備から動作へつなげる

左右は本人を基準に統一する。武器、盾、本などを同時に扱える持ち方を決める。
両手が塞がっているキャラが手を掲げるなら、何を収納・持ち替えするかを動作に含める。
フレーム間で装備を消したり、手を入れ替えたり、手を増やしたりしない。
設定上の小物を全部アニメーションで使う必要はない。
種族・体格・性格に合わせて動かし、全キャラに杖・詠唱・ケープを付けない。

## アニメーションの標準10種類

ユーザーから別指定がなければ、次のフレーム数を使用する。
攻撃系と補助系は、それぞれ準備4・発動と戻り8に分ける。

| 動作 | フレーム数 | 再生・接続 |
|---|---:|---|
| 待機 | 4 | ループ |
| 歩行 | 6 | ループ。方向ごとに必要 |
| 通常攻撃 | 6 | 1回再生して待機へ |
| 攻撃スキル・準備 | 4 | 最終コマを保持 |
| 攻撃スキル・発動・戻り | 8 | 攻撃準備を引き継いで待機へ |
| 補助スキル・準備 | 4 | 最終コマを保持 |
| 補助スキル・発動・戻り | 8 | 補助準備を引き継いで待機へ |
| 被弾 | 2 | 短い反応の後、元の状態へ |
| 戦闘不能 | 4 | 最終コマを保持 |
| 復帰 | 4 | 戦闘不能の最終姿勢から待機へ |

各1方向の合計は10種類・50フレーム。これは各動作のコマ枠数の合計であり、
重複姿勢を除いた固有画像数や、全方向を含む総数とは区別する。
方向数が指定されていなければ、勝手に4方向・8方向へ増やさない。

出力するアニメーション表の列は「動作／フレーム数／各コマの動き／接続・保持・発生位置」。
各行にF1からFNまで、具体的な姿勢を順番に短く書く。50コマ分を省略しない。
一つのコマに複数の連続動作を詰めず、隣接するコマで動作の段階が伝わるようにする。
動作名と枚数だけの一般表を最終成果物にしない。毎回そのキャラの装備と個性に合わせる。

準備の最終姿勢と発動の最初の姿勢を合わせ、準備4コマ全体を無条件にループしない。
保持時間は新しいコマとして数えない。呼吸する詠唱などの追加コマは標準50に勝手に加えない。
待機・歩行は最終から先頭へつなぎ、ループを閉じるためのコマを無断追加しない。
戦闘不能は倒れた姿勢で止め、最後に立たせない。復帰を別の動作として扱う。

攻撃と補助は、構え・腕の方向・力の入れ方で視覚的に区別する。
攻撃は予備動作・打撃や放出・反動・戻り、補助は構え・差し出すや掲げる動作・戻りを考える。
準備・発動の例は魔法に限定しない。盾を立てる、合図を出すなど職業に合う動作でよい。

動作の補助情報として、打撃、弾の放出、補助効果の発生に対応するコマを示す。
飛び道具の放出コマを命中コマと決めつけない。具体的なダメージ・回復量は決めない。
秒数やFPSは一律に追加しない。準備の保持時間と発動前半の再生時間は後で調整できるようにする。
通常の被弾で準備動作を中断する戦闘ルールなど、新しいシステム仕様をここで確定させない。

## 出力前の確認

外見6項目、装備の左右、各動作の手と持ち物、台詞の口調が一致しているか確認する。
フレーバーに具体的な笑いとオチがあるか、説明だけの真面目な紹介へ戻っていないか確認する。
動作は10種類、各FNまで記載し、標準合計が50であることを確認する。
ユーザーが枚数を変更した場合は新しい指定を使って合計を再計算する。
不要とされた制作条件・戦闘スキル性能・画像生成プロンプトを付け足していないか確認する。
