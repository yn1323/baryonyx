# 戦闘の不具合を画面なしで調べる

戦闘の効果の不具合は、画面なしの戦闘で再現してから直す。
画面なしの戦闘の使い分け・テストの書き方・自動対戦の `engine` は [画面なしの戦闘で確かめる](../../../doc/rules/client-testing.md#画面なしの戦闘で確かめる) を正本とし、ここには写さない。
効果の書き方と直し方の決まりは [効果の部品](../../../doc/features/combat/effects.md) と [効果の部品のAGENTS.md](../../../client/Assets/Baryonyx/Features/Combat/Runtime/Effects/AGENTS.md) に従う。

## 1. 症状を再現の条件にする

報告やユーザーの言葉から、次を1〜2文に書き出す。
足りない所はコードと定義から埋め、埋めたことを報告に書く。

- 誰が（味方の枠、敵の種類とLv）、何を（カード・技・パッシブ・装備）、どの状態で（HP・状態・ターン・エネルギー）使ったか。
- 何が起きたか、何が起きるはずだったか。数の不具合なら、期待する値まで書く。
- どこで見えたか。戦闘画面、HPバーの予測、自動対戦（`screen`・`headless`）、端末のどれか。

どこで見えたかで、疑う所が変わる。

| 見えた所 | 先に疑う所 |
|---|---|
| どこでも同じ | 効果の定義、部品、戦闘のルール（`Runtime/Effects/`・`Runtime/Battle/`） |
| 戦闘画面だけ | 画面の呼び出しの順と演出の待ち（`BattleInspectView`）、画面なしの戦闘に入れていない仕組み |
| HPバーの予測だけ | 予測の写し（`ForecastWorld`）。予測は確率の規則と会心を飛ばす |
| 自動対戦だけ | 依頼の項目、カードの選び方（`BattleAutoPolicy`・`CarefulSimPolicy`）、`screen` と `headless` の違い |

## 2. 効果の定義を読む

効果の[出どころ](../../../doc/features/combat/effects.md#効果の出どころ)の1か所を開き、きっかけ・条件・数・働き・回数・重ねを読む。
数の不具合なら、[数を変える順番](../../../doc/features/combat/effects.md#数を変える順番)のどの段でその数が変わるかを確かめ、期待する値を手で計算しておく。

## 3. 画面なしで再現する

[1手ずつ動かすテスト](../../../doc/rules/client-testing.md#1手ずつ動かすテスト)に従い、`BattleStateTests` へ再現のテストを足す。
部品だけの不具合（条件・回数・重ね）なら `BattleEffectsTests` に足す。

- 定義の誤りを疑うなら、本物の定義（`CombatPassives.Find`・`BattleFighter.OfEnemy`・カードの定義）を使う。テスト用に似せた定義では、定義の誤りが再現しない。
- 部品やルールの誤りを疑うなら、テスト用の最小の定義で書き、ほかの効果が混ざらないようにする。
- テストを実行し、報告どおりに落ちることを確かめる。通ってしまうなら、条件が足りないか、原因が画面にしかない仕組みにある。条件を足しても落ちなければ、6の画面の確かめへ進み、画面で再現してから原因を探す。

多くの戦闘のどこかで起きる不具合（ときどき止まる、ある組み合わせだけ負ける）は、先に自動対戦を `headless` で多く回して、起きる戦闘の番号と種を見つける。
見つけた戦闘を `screen` でも回し、両方で起きるかを見てから、その場面を `BattleStateTests` に写す。

## 4. 原因をたどる

落ちるテストの中で、次の順に絞る。

- `Announced` で、働いた効果と順番を見る。出るはずの名前がなければ、条件・回数の制限（`OncePerTurn` など）・きっかけが呼ばれているかを疑う。
- 数がずれるなら、効果のない同じ1手との差を取り、足す・割合・掛ける・防御・会心のどの段で差が出たかを見る。
- 2重に働いた、途中で止まったなら、働きの中で自分のきっかけをまた起こしていないか（入れ子は8段まで）を見る。
- 戦闘画面と画面なしで結果が違うなら、同じきっかけと値を、両方が同じ所で呼んでいるかを見る。

テストの場面から味方・敵・効果を1つずつ外し、まだ落ちる最小の場面まで削ると、原因の場所が残る。

## 5. 直す

[効果の部品のAGENTS.md](../../../client/Assets/Baryonyx/Features/Combat/Runtime/Effects/AGENTS.md)に従い、効果の出どころの1か所か部品で直す。
戦闘画面・予測・画面なしの戦闘の片方にだけ、1枚・1種類のための `if` を書かない。
直したら、3のテストが通ることと、同じクラスのほかのテストが通ることを確かめる。

## 6. 画面でも確かめる

画面なしの戦闘には、戦闘画面だけにある仕組みが入っていない（[予測と画面なしの戦闘](../../../doc/features/combat/effects.md#予測と画面なしの戦闘)）。
直した所が戦闘画面に関わるときは、次も行う。

- PlayModeの関連テスト（[パッシブの実装との対応](../../../doc/features/passives.md#実装との対応)の表など）を実行する。
- 表示・演出・操作が関わるなら、`BattleLab.unity` や[敵の挙動デバッグルーム](../../../doc/features/screens/debug-rooms.md#敵の挙動デバッグルーム)で動かし、撮って確かめる。
- 強さが変わる直しなら、ルートの [AGENTS.md](../../../AGENTS.md#検証と報告) に従い、[戦闘の自動対戦](../../../doc/rules/client-testing.md#戦闘の自動対戦)で測り直す。

## 7. 報告の形

1. 再現の条件と、どこで見えたか。
2. 原因の場所（ファイルと行）と、そうなった理由。
3. 直したこと。
4. 確かめたこと：足したテストと結果、実行した関連テスト、画面で見たか。
5. 未確認のこと：画面で見ていない、端末で見ていない、など。
