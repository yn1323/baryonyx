# キャラ設定からドット絵のスプライトシートを作る

キャラクター制作の2番目の工程で使う。
1番目の工程（[rpg-character-profile](../rpg-character-profile/SKILL.md)）の設定から、基本姿勢と全動作を並べたドット絵のスプライトシートを、Codex CLIの画像生成で1枚作る。
生成したシートは下書きで、コマの仕上げはユーザーが手作業で行う。
仕上げとUnityへの取り込みは、このスキルの範囲外とする。

## 呼び出し

- ユーザーがこのスキルを明示したときだけ使う。
- ドット絵やキャラクターの話題になっただけでは使わない。
- `agents/openai.yaml` の `allow_implicit_invocation: false` を保つ。

## Codexに渡すもの

| 渡すもの | 内容 |
|---|---|
| キャラ設定の全文 | rpg-character-profile の出力。修正があった場合は、最新の修正を統合した全文 |
| 依頼文 | 下の「依頼文の型」を、キャラ設定から埋めたもの |
| 画風見本 | リポジトリ直下の [witch.png](../../../witch.png)（48×48のドット絵） |

スクリプトは、小さな添付画像を最近傍法で512px以上に拡大した複製を作って渡す。
ドットの形を、Codexの画像生成に正しく伝えるためである。

## 出力先

`output/characters/<キャラID>/` に置く。
キャラIDは名前をローマ字にした小文字の英数字とハイフンにする（例：`rita-postol`）。
リポジトリの `output/` はコミットしない作業用のフォルダーとして使う。

| ファイル | 内容 |
|---|---|
| `profile.md` | キャラ設定の全文。character-illustration もこれを使う |
| `sprite-request.md` | 依頼文 |
| `sprite-sheet.png` | 生成されたスプライトシート（加工しない）。既にあれば `sprite-sheet-v2.png` のように別名にする |
| `sprite-sheet.codex-prompt.md` | Codexに実際に渡した全文 |
| `sprite-sheet.codex-reply.md` | Codexの返答（画像生成に使ったプロンプトの報告） |

## キャラ設定の探し方

次の順に探し、最初に見つかったものを使う。

1. ユーザーが指定したファイルや本文
2. 出力先の `profile.md`
3. この会話で rpg-character-profile が出した設定

どれもなければ、ユーザーに設定の全文を求める。
会話中の設定を使うときは、要約せず、最新の修正を統合した全文を `profile.md` に書き出す。
既存の `profile.md` と会話中の設定が食い違う場合は、どちらを使うかユーザーに確認する。

## 依頼文の型

下の固定文は変えずに使い、【】の中をキャラ設定から埋める。

- 必ず残す特徴は、6項目を短い日本語1行に縮める。性別、髪色と髪型（輪郭を大きく変える場合だけ短く）、特徴3点を句点と読点で区切る。
- 特徴は「深緑の丸帽子」のように色と物の名前だけにし、括弧書きの補足、向き、細部は書かない。例：`女性。オレンジのボブ。深緑の丸帽子、茶色の肩掛け鞄、短槍。`
- 各コマの動きは、アニメーション設計のF1からFNを1コマ1句に縮めて書く。
- 攻撃のコマ数は、アニメーション設計で選んだ3か4に合わせる。
- 装備の左右と持ち方は、キャラ設定の「装備と持ち方」と食い違わせない。

```
小型JRPGキャラクターのドット絵スプライトシートを1枚作ってください。

■画風
後期スーパーファミコン時代のJRPGやOctopath Travelerを思わせる、アニメ調のファンタジースプライト。
低解像度のピクセルアート。はっきりした四角いドット、大きめのピクセル単位。少ないドット数で描き、1ドットの意味を大きくする。
暗い輪郭、少ない色数、段階的な陰影。アンチエイリアスや滑らかなグラデーションは使わない。

■大きさ
各コマに人物1人を、頭から靴まで全身で描く。キャラクターの高さはおよそ64ドット相当、4〜4.5頭身、縦長のシルエット。

■キャラクター
【名前。年齢、性別、種族、職業。体格と姿勢の癖】
【衣装】
【主な配色と差し色】

■ドット絵で必ず残す特徴（最優先で描く）
【性別。髪色と髪型。特徴3点】

■基本姿勢
【基本姿勢。装備の左右と持ち方】
体はやや斜め向きで、顔はこちらに見える。全動作をこの姿から始める。

■スプライトシートの構成
1行目に基本姿勢1コマ、待機2コマ、歩行4コマ、2行目に攻撃【3か4】コマ、戦闘不能1コマ、勝利1コマを、左から順に並べる。
動作のまとまりごとに、下に「待機（2コマ）」のような動作名とコマ数のラベルを入れる。
全コマで、同じキャラ、同じ大きさ、同じ向き、同じドットの細かさにする。装備を消したり、持ち手を入れ替えたりしない。
全コマの足元の高さをそろえる。槍や剣を突き出すコマでも隣のコマと重ならないよう、コマの間を十分に空ける。
背景は単色の暗い灰色。地面、影、枠は描かない。

■各コマの動き（左から順に）
・基本姿勢（1コマ）：上記の基本姿勢
・待機（2コマ）：体は基本姿勢のまま動かさず、揺れる部分だけを変える。【F1／F2】
・歩行（4コマ）：【F1／F2／F3／F4】
・攻撃（【3か4】コマ）：【F1／…】
・戦闘不能（1コマ）：【F1】
・勝利（1コマ）：【F1】

タッチは添付の画像を参考にして
```

最後の一文は、添付する画風見本（witch.png）を指す固定文。変えずに入れる。
キャラクターの高さ（64ドット相当）は、ユーザーが最終サイズを決めたらその値に合わせる。

## 手順

1. **材料をそろえる**：キャラ設定を上の順に探し、キャラIDを決めて `profile.md` を用意する。`witch.png` がリポジトリ直下にあることを確かめる。
2. **依頼文を作る**：型を埋めて `sprite-request.md` に保存し、ユーザーに見せる。ユーザーが生成まで依頼している場合はそのまま次へ進み、依頼文の相談だけを求めている場合は送らずに止める。
3. **Codexに依頼する**：

   ```bash
   python3 .agents/skills/shared/scripts/codex_image.py \
     --out-dir output/characters/<キャラID> --name sprite-sheet \
     --request output/characters/<キャラID>/sprite-request.md \
     --profile output/characters/<キャラID>/profile.md \
     --model gpt-6-astra \
     --image witch.png --image-role "ドット絵の画風見本。タッチ（ドットの大きさ、輪郭、塗り、色数）を参考にする。人物、衣装、ポーズは写さない"
   ```

   Codexの実行には数分かかるので、Bashのタイムアウトを最大にするか、バックグラウンドで実行する。
   モデルは `--model` で必ず明示し、`~/.codex/config.toml` の設定に任せない。ユーザーが別のモデルを指定したときは、`gpt-6-astra` をその値に置き換える。
4. **見せる**：保存された `sprite-sheet.png` を、ユーザーが画像を見られる方法で表示し（Claudeのデスクトップアプリでは `SendUserFile` の `display: "render"`）、ファイルの場所と画像サイズを伝える。
5. **止める**：生成物を縮小・減色・切り抜きしない。コマの仕上げやUnityへの取り込みへ進まない。気に入らない場合は、同じ依頼文でもう一度生成するか、依頼文をどう直すかをユーザーに相談する。

## うまくいかないとき

| 症状 | 対応 |
|---|---|
| `生成画像が見つかりませんでした` | `sprite-sheet.codex-reply.md` でCodexの返答を読み、利用上限や拒否の理由をユーザーに伝える |
| 利用上限に達した | 返答にある再開時刻をユーザーに伝えて止める |
| ドットの大きさが毎回違う | Codexの画像生成は、ドット数の指定を正確には守らない。必要なら、仕上げの前にユーザーと相談して格子を整える |
