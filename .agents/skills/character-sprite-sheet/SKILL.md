# キャラ設定からドット絵のスプライトシートを作る

キャラクター制作の2番目の工程で使う。
1番目の工程（[rpg-character-profile](../rpg-character-profile/SKILL.md)）の設定から、基本姿勢と全動作を並べたドット絵のスプライトシートを、Codex CLIの画像生成で1枚作る。
結果が気に入らないとき、ユーザーが自分で再実行できるよう、Codexに送ったプロンプトと、Codexが画像生成に使った最終プロンプトもユーザーに渡す。
出力先、キャラIDとキャラ設定の探し方、Codexへの依頼の注意、結果の見せ方は、[キャラ制作の共通手順](../shared/character-pipeline.md)に従う。

## Codexに渡すもの

| 渡すもの | 内容 |
|---|---|
| キャラ設定の全文 | rpg-character-profile の出力。修正があった場合は、最新の修正を統合した全文 |
| 依頼文 | 下の「依頼文の型」を、キャラ設定から埋めたもの |
| 画風見本 | リポジトリ直下の [witch.png](../../../witch.png) |

画風見本は拡大などの加工をせず、元の画像のまま渡す。
ChatGPTのデスクトップアプリで元の画像を添付したときのほうが、イメージに近いシートができたためである。

## 出力するファイル

`output/characters/<キャラID>/` に次のファイルができる。

| ファイル | 内容 |
|---|---|
| `profile.md` | キャラ設定の全文。character-illustration もこれを使う |
| `sprite-request.md` | 依頼文 |
| `sprite-sheet.png` | 生成されたスプライトシート（加工しない） |
| `sprite-sheet.codex-prompt.md` | Codexに送ったプロンプトの全文（スクリプトの指示、依頼文、キャラ設定の全文） |
| `sprite-sheet.codex-reply.md` | Codexの返答。画像生成に使った最終プロンプトを含む |

## 依頼文の型

下の固定文は変えずに使い、【】の中を埋める。

- 「■画風」の3〜4行目は、ドット絵の規格の共通の固定文の `light` と `colors` をそのまま入れる。`python3 .agents/skills/shared/scripts/pixel_style.py ja light colors` で出力できる（[pixel-style.ja.txt](../shared/prompts/pixel-style.ja.txt)）。
- 必ず残す特徴は、[共通手順の「必ず残す特徴の1行」](../shared/character-pipeline.md#必ず残す特徴の1行)に従って1行に縮める。武器は必ず残す特徴と基本姿勢に書かず、戦闘態勢に書く。
- 各コマの動きは、アニメーション設計のF1からFNを1コマ1句に縮めて書く。
- 攻撃のコマ数は、アニメーション設計で選んだ3か4に合わせる。
- 基本姿勢の手の位置、武器の左右と構え方は、キャラ設定の「装備と持ち方」と食い違わせない。
- 「■大きさ」の値は、[ドット絵の制作規格](../../../doc/art/direction.md#画面と寸法)の味方キャラに合わせて決めたものである。規格を変えたら、同じ変更でこの値も直す。

```
小型JRPGキャラクターのドット絵スプライトシートを1枚作ってください。

■画風
後期スーパーファミコン時代のJRPGやOctopath Travelerを思わせる、アニメ調のファンタジースプライト。
低解像度のピクセルアート。はっきりした四角いドット、大きめのピクセル単位。少ないドット数で描き、1ドットの意味を大きくする。
【共通の固定文の light】
【共通の固定文の colors】

■大きさ
各コマに人物1人を、頭から靴まで全身で描く。キャラクターの高さはおよそ64ドット相当、4〜4.5頭身、縦長のシルエット。

■キャラクター
【名前。年齢、性別、種族、職業。体格と姿勢の癖】
【衣装】
【主な配色と差し色】

■ドット絵で必ず残す特徴（最優先で描く）
【性別。髪色と髪型。特徴3点】

■基本姿勢（武器なし）
【基本姿勢。両手の位置と、武器以外の装備の付け方】
武器は持たず、鞘に収めた武器や背負った武器も描かない。体はやや斜め向きで、顔はこちらに見える。攻撃以外の動作はこの姿から始める。

■戦闘態勢（武器あり）
【武器の色と形。武器の左右の持ち手と構え方。構えの姿勢】
体の向きは基本姿勢と同じ。攻撃はこの姿から始まり、この姿へ戻る。

■スプライトシートの構成
1行目に基本姿勢1コマ、待機2コマ、歩行4コマ、2行目に戦闘態勢1コマ、攻撃【3か4】コマ、戦闘不能1コマ、勝利1コマを、左から順に並べる。
動作のまとまりごとに、下に「待機（2コマ）」のような動作名とコマ数のラベルを入れる。
全コマで、同じキャラ、同じ大きさ、同じ向き、同じドットの細かさにする。
武器は戦闘態勢と攻撃のコマだけに描き、ほかのコマには描かない。武器以外の装備は消さず、武器の持ち手を入れ替えない。
全コマの足元の高さをそろえる。槍や剣を突き出すコマでも隣のコマと重ならないよう、コマの間を十分に空ける。
背景は単色の暗い灰色。地面、影、枠は描かない。

■各コマの動き（左から順に）
・基本姿勢（1コマ）：上記の基本姿勢。武器なし
・待機（2コマ）：武器なし。体は基本姿勢のまま動かさず、揺れる部分だけを変える。【F1／F2】
・歩行（4コマ）：武器なし。【F1／F2／F3／F4】
・戦闘態勢（1コマ）：上記の戦闘態勢。武器あり
・攻撃（【3か4】コマ）：武器あり。戦闘態勢から始め、最後のコマは戦闘態勢へ戻る直前の姿勢。【F1／…】
・戦闘不能（1コマ）：武器なし。【F1】
・勝利（1コマ）：武器なし。【F1】

タッチは添付の画像を参考にして
```

最後の一文は、添付する画風見本（witch.png）を指す固定文。変えずに入れる。

## 手順

1. **材料をそろえる**：[共通手順](../shared/character-pipeline.md#キャラ設定の探し方)に従ってキャラ設定を探し、キャラIDを決めて `profile.md` を用意する。`witch.png` がリポジトリ直下にあることを確かめる。
2. **依頼文を作る**：型を埋めて `sprite-request.md` に保存し、ユーザーに見せる。
3. **Codexに依頼する**：[共通手順の「Codexへの依頼」](../shared/character-pipeline.md#codexへの依頼)に従い、リポジトリ直下で次の1行を実行する。

   ```bash
   uv run --no-project python .agents/skills/shared/scripts/codex_image.py --out-dir output/characters/<キャラID> --name sprite-sheet --request output/characters/<キャラID>/sprite-request.md --profile output/characters/<キャラID>/profile.md --model gpt-6.1-sol --reasoning-effort high --image witch.png --image-role "ドット絵の画風見本。タッチ（ドットの大きさ、塗り、描き込み）を参考にする。輪郭・陰影・色数は依頼文の規則を優先する。人物、衣装、ポーズは写さない"
   ```

4. **見せる**：共通手順に従って画像を表示する。依頼文と比べて、必ず残す特徴、武器を描くコマ、コマ数、ラベル、背景の違いを報告する。
5. **プロンプトを渡す**：再実行に使えるよう、次の2つをユーザーに渡す。
   - Codexに送ったプロンプト：`<name>.codex-prompt.md` をファイルとして渡す（Claudeのデスクトップアプリでは `SendUserFile` の `display: "attach"`）。
   - Codexが画像生成に使った最終プロンプト：`<name>.codex-reply.md` から抜き出し、コピーしやすいようにコードブロックで全文を示す。ChatGPTのデスクトップアプリで新しいチャットを開き、元の大きさの `witch.png` を添付してこの文を貼れば、Codexを通さずに再実行できることを添える。
6. **止める**：共通手順に従い、生成物を加工しない。コマの仕上げやUnityへの取り込みへ進まない。

## うまくいかないとき

共通の症状（生成画像が見つからない、利用上限）は[共通手順](../shared/character-pipeline.md#うまくいかないとき)にある。

| 症状 | 対応 |
|---|---|
| 最終プロンプトが返答にない | 返答に最終プロンプトがないことを伝え、Codexに送ったプロンプトだけを渡す |
| ドットの大きさが毎回違う | 画像生成は、ドット数の指定を正確には守らない。必要なら、仕上げの前にユーザーと相談して格子を整える |
