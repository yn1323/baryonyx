# キャラ設定からドット絵のスプライトシートを作る

キャラクター制作の2番目の工程で使う。
1番目の工程（[rpg-character-profile](../rpg-character-profile/SKILL.md)）の設定から、基本姿勢と全動作を並べたドット絵のスプライトシートを、Codex CLIの画像生成で1枚作る。
結果が気に入らないとき、ユーザーが自分で再実行できるよう、Codexに送ったプロンプトと、Codexが画像生成に使った最終プロンプトもユーザーに渡す。
生成したシートは下書きで、コマの仕上げはユーザーが手作業で行う。
仕上げとUnityへの取り込みは、このスキルの範囲外とする。

## 呼び出し

- ユーザーがこのスキルを明示したときだけ使う。
- ドット絵やキャラクターの話題になっただけでは使わない。
- `agents/openai.yaml` の `allow_implicit_invocation: false` を保つ。

## Codexに渡すもの

| 渡すもの | 内容 |
|---|---|
| キャラ設定の全文 | rpg-character-profile の出力。修正があった場合は、最新の修正を統合した全文 |
| 依頼文 | 下の「依頼文の型」を、キャラ設定から埋めたもの |
| 画風見本 | リポジトリ直下の [witch.png](../../../witch.png)（48×48のドット絵） |

画風見本は拡大などの加工をせず、元の画像のまま渡す。
ChatGPTのデスクトップアプリで元の画像を添付したときのほうが、イメージに近いシートができたためである。

## 出力先

`output/characters/<キャラID>/` に置く。
キャラIDは名前をローマ字にした小文字の英数字とハイフンにする（例：`rita-postol`）。
リポジトリの `output/` はコミットしない作業用のフォルダーとして使う。

| ファイル | 内容 |
|---|---|
| `profile.md` | キャラ設定の全文。character-illustration もこれを使う |
| `sprite-request.md` | 依頼文 |
| `sprite-sheet.png` | 生成されたスプライトシート（加工しない） |
| `sprite-sheet.codex-prompt.md` | Codexに送ったプロンプトの全文（スクリプトの指示、依頼文、キャラ設定の全文） |
| `sprite-sheet.codex-reply.md` | Codexの返答。画像生成に使った最終プロンプトを含む |

2回目以降は、`--name` を `sprite-sheet-v2` のように変えて実行する。
`--name` が同じだと、画像は `sprite-sheet-v2.png` のように別名で保存されるが、プロンプトと返答のファイルは上書きされる。

## キャラ設定の探し方

次の順に探し、最初に見つかったものを使う。

1. ユーザーが指定したファイルや本文
2. 出力先の `profile.md`
3. この会話で rpg-character-profile が出した設定

どれもなければ、ユーザーに設定の全文を求める。
会話中の設定を使うときは、要約せず、最新の修正を統合した全文を `profile.md` に書き出す。
既存の `profile.md` と会話中の設定が食い違う場合は、どちらを使うかユーザーに確認する。

## 依頼文の型

下の固定文は変えずに使い、【】の中をキャラ設定から埋める。

- 必ず残す特徴は、6項目を短い日本語1行に縮める。性別、髪色と髪型（輪郭を大きく変える場合だけ短く）、特徴3点を句点と読点で区切る。
- 特徴は「深緑の丸帽子」のように色と物の名前だけにし、括弧書きの補足、向き、細部は書かない。例：`女性。オレンジのボブ。深緑の丸帽子、茶色の肩掛け鞄、黄色のマフラー。`
- 武器は必ず残す特徴と基本姿勢に書かず、戦闘態勢に書く。キャラ設定の特徴3点に武器があれば外し、2点で書く。
- 各コマの動きは、アニメーション設計のF1からFNを1コマ1句に縮めて書く。
- 攻撃のコマ数は、アニメーション設計で選んだ3か4に合わせる。
- 基本姿勢の手の位置、武器の左右と構え方は、キャラ設定の「装備と持ち方」と食い違わせない。

```
小型JRPGキャラクターのドット絵スプライトシートを1枚作ってください。

■画風
後期スーパーファミコン時代のJRPGやOctopath Travelerを思わせる、アニメ調のファンタジースプライト。
低解像度のピクセルアート。はっきりした四角いドット、大きめのピクセル単位。少ないドット数で描き、1ドットの意味を大きくする。
光源は左上。輪郭はセルアウトにする。背景と接する外周に輪郭を描き、影側は暗く、光が当たる左上側は接する部分の色に合わせて明るくする。腕と胴の境目などの内側の線は、外周より明るく、その場所の色より2段暗い色で描く。
色数は32色以内。陰影は段を分けて塗り、色の境目にディザ（2色の市松模様）を入れる。アンチエイリアスは輪郭の内側にだけ、中間色を1ドット単位で置く。背景側へのぼかしや滑らかなグラデーションは使わない。

■大きさ
各コマに人物1人を、頭から靴まで全身で描く。キャラクターの高さはおよそ64ドット相当、4〜4.5頭身、縦長のシルエット。

【名前。年齢、性別、種族、職業。体格と姿勢の癖】
【衣装】
【主な配色と差し色】

武器は持たず、鞘に収めた武器や背負った武器も描かない。体はやや斜め向きで、顔はこちらに見える。攻撃以外の動作はこの姿から始める。

■戦闘態勢（武器あり）
【武器の色と形。武器の左右の持ち手と構え方。構えの姿勢】
体の向きは基本姿勢と同じ。攻撃はこの姿から始まり、この姿へ戻る。

■スプライトシートの構成
1行目に基本姿勢1コマ、待機2コマ、歩行4コマ、2行目に戦闘態勢1コマ、攻撃【3か4】コマ、戦闘不能1コマ、勝利1コマを、左から順に並べる。
動作のまとまりごとに、下に「待機（2コマ）」のような動作名とコマ数のラベルを入れる。
全コマで、同じキャラ、同じ大きさ、同じ向き、同じドットの細かさにする。
武器は戦闘態勢と攻撃のコマだけに描き、ほかのコマには描かない。武器以外の装備は消さず、武器の持ち手を入れ替えない。
全コマの足元の高さをそろえる。槍や剣を突き出すコマでも隣のコマと重ならないよう、コマの間を十分に空ける。
背景は単色の暗い灰色。地面、影、枠は描かない。
```

## 手順

1. **材料をそろえる**：キャラ設定を上の順に探し、キャラIDを決めて `profile.md` を用意する。`witch.png` がリポジトリ直下にあることを確かめる。
2. **依頼文を作る**：型を埋めて `sprite-request.md` に保存し、ユーザーに見せる。ユーザーが生成まで依頼している場合はそのまま次へ進み、依頼文の相談だけを求めている場合は送らずに止める。
3. **Codexに依頼する**：リポジトリ直下で次の1行を実行する。WindowsのPowerShellとmacOSのターミナルのどちらでも同じコマンドで動く（行末の `\` での改行や `&&` はPowerShellで使えないため、1行のまま使う）。

   ```bash
   uv run --no-project python .agents/skills/shared/scripts/codex_image.py --out-dir output/characters/<キャラID> --name sprite-sheet --request output/characters/<キャラID>/sprite-request.md --profile output/characters/<キャラID>/profile.md --model gpt-5.6-sol --reasoning-effort high --image witch.png --image-role "ドット絵の画風見本。タッチ（ドットの大きさ、塗り、描き込み）を参考にする。輪郭・陰影・色数は依頼文の規則を優先する。人物、衣装、ポーズは写さない"
   ```

   Codexの実行には数分かかるので、Bashのタイムアウトを最大にするか、バックグラウンドで実行する。
   モデルと推論の強さは `--model` と `--reasoning-effort` で必ず明示し、`~/.codex/config.toml` の設定に任せない。ユーザーが別の値を指定したときは、`gpt-5.6-sol`・`high` をその値に置き換える。
4. **見せる**：保存された画像を、ユーザーが画像を見られる方法で表示し（Claudeのデスクトップアプリでは `SendUserFile` の `display: "render"`）、ファイルの場所と画像サイズを伝える。依頼文と比べて、必ず残す特徴、武器を描くコマ、コマ数、ラベル、背景の違いを報告する。
5. **プロンプトを渡す**：再実行に使えるよう、次の2つをユーザーに渡す。
   - Codexに送ったプロンプト：`<name>.codex-prompt.md` をファイルとして渡す（Claudeのデスクトップアプリでは `SendUserFile` の `display: "attach"`）。
   - Codexが画像生成に使った最終プロンプト：`<name>.codex-reply.md` から抜き出し、コピーしやすいようにコードブロックで全文を示す。ChatGPTのデスクトップアプリで新しいチャットを開き、元の大きさの `witch.png` を添付してこの文を貼れば、Codexを通さずに再実行できることを添える。
6. **止める**：生成物を縮小・減色・切り抜きしない。コマの仕上げやUnityへの取り込みへ進まない。気に入らない場合は、同じ依頼文でもう一度生成するか、依頼文をどう直すかをユーザーに相談する。

## うまくいかないとき

| 症状 | 対応 |
|---|---|
| `生成画像が見つかりませんでした` | `<name>.codex-reply.md` でCodexの返答を読み、利用上限や拒否の理由をユーザーに伝える |
| 利用上限に達した | 返答にある再開時刻をユーザーに伝えて止める |
| 最終プロンプトが返答にない | 返答に最終プロンプトがないことを伝え、Codexに送ったプロンプトだけを渡す |
| ドットの大きさが毎回違う | 画像生成は、ドット数の指定を正確には守らない。必要なら、仕上げの前にユーザーと相談して格子を整える |
