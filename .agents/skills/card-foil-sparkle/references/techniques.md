# キラキラの層と作り方

2026-10-19にWebで調べた、レアカードのキラキラの一般的な作り方である。
このゲームでの使い方は、正本の[カードのキラキラ](../../../../doc/art/direction.md#カードのキラキラ)に従う。

## 層の種類

レアカードの光り方は、次の層の重ね合わせで作られている。
ポケモンカードの再現（pokemon-cards-css）も、SwiftUIのShaderKitも、同じ考え方で層を分けている。

| 層 | 見え方 | 一般的な作り方 |
|---|---|---|
| 光の帯（シャイン、スイープ） | 斜めの白い帯がカードを横切る | 斜めの座標（`uv.x + uv.y * 傾き`）で帯の中心からの距離を測り、`smoothstep` で柔らかい帯にする。中心を時間で動かし、数秒に1回だけ横切らせる。加算で重ねる |
| ホロの虹色（フォイル） | 角度や時間で色がずれていく虹 | 虹のグラデーションを、`uv` と傾き（または時間）でずらした位置で引く。細かい縞やノイズで明るさを変調すると金属の箔らしくなる。覆い焼き（color-dodge）や加算で重ね、絵の明るい所ほど強く出す |
| ラメ（グリッター） | 細かい点が一瞬だけ強く光る | 画面を格子に分け、マスごとにハッシュで点の位置・大きさ・位相を決める（ボロノイの点）。時間（または傾き）で各点の明るさを `pow(max(0, sin(...)), 高い指数)` のように一瞬だけ上げる。上位のレア度で点に十字の光条を足す例もあるが、このゲームでは付けない（[カードのキラキラ](../../../../doc/art/direction.md#カードのキラキラ)） |
| 漂う光の粒（パーティクル風） | 光の粒が揺れながら流れていく | 粒子を出さずに、格子ごと座標を時間でずらして（上へ流す）、マスごとの点を小さく円を描いて揺らす。大きさと速さの違う格子を2〜3層重ねると奥行きが出る。粒ごとに明るさの山をずらし、ふわっと現れて消えるようにする |
| 光のスポット（グレア） | 指や傾きに追従するまぶしい光 | 指や傾きの位置を中心にした放射状のグラデーション。オーバーレイや加算で重ねる |
| 溝・模様（エッチング） | 箔の上の線や模様 | 模様のマスクで、虹色やラメを出す所を限る |

## 出典ごとの要点

- **pokemon-cards-css**（simeydotme、GPL-3.0）：CSSの変形・グラデーション・ブレンドモード・フィルターで、ポケモンカードの箔を再現している。ホロの層は、110度の虹の繰り返しグラデーション（大きさ400%）を指の位置でずらし、細い縞と重ねてオーバーレイで混ぜ、覆い焼きで載せる。縞の層はハードライト、指の位置のスポットは放射状グラデーションで作り、レア度（種類）ごとに層の組み合わせを変えている（[リポジトリ](https://github.com/simeydotme/pokemon-cards-css)、[regular-holo.css](https://github.com/simeydotme/pokemon-cards-css/blob/main/public/css/cards/regular-holo.css)、[デモ](https://hover-tilt.simey.me/bespoke/pokemon-cards/)）。GPLのため、コードは写さず考え方だけを参考にする。
- **2D holographic card shader**（Godot Shaders、CC0）：箔を出す所をマスクで決め、傾きから作った法線で虹のグラデーションを引く位置をずらし、ノイズを掛けて金属のきらめきにしている（`mix(元の色, 虹 * ノイズ * 2, 強さ)`）（[ページ](https://godotshaders.com/shader/2d-holographic-card-shader/)）。
- **ShaderKit**（SwiftUI・Metal）：箔 → ラメ → 光の帯の順に重ね、切り抜いた人物の後ろだけに掛けると絵がきれいに残る、と説明している（[ドキュメント](https://docsearch.algolia.com/mcp/docs/repo/jamesrochabrun/shaderkit)）。
- **WebGLのカード効果のスキル**：絵 → 枠 → 効果 → 文字の順に重ね、レア度ごとに光る層を変える。CSSの輝きとシェーダーの輝きを二重に掛けないよう注意している（[ページ](https://eliteai.tools/agent-skills/webgl-card-effects)）。
- **Glitter Shader**（Unreal Engine、Fab）：ボロノイのノイズで小さな発光の点を作る。光源によらない発光であり、計算のノイズのためモバイルに向かない、と書いている（[Fab](https://fab.com/s/767d26599d08)）。モバイルではマスの数と1ピクセルあたりの計算回数を絞る。

## Unityでの実装経路

| 経路 | 内容 | 判断 |
|---|---|---|
| UIEffect（mob-sakai、MIT、Unity 2020.3以降・Unity 6・URP対応） | uGUIにインスペクターから効果を付けるパッケージ。光の帯（Shiny）はあるが、ラメはない（[リポジトリ](https://github.com/mob-sakai/UIEffect)） | 光の帯だけなら使えるが、ラメとホロを足すには結局シェーダーを書くため、このゲームでは採らなかった（2026-10-19） |
| 自作のUI用シェーダー | `UI/Default` と同じステンシル・クリップの作りに、層の式を書く。値は頂点の色で渡す | 採用。式を1つのシェーダーにまとめ、品質で層を切り替える |

## モバイルでの注意

- キラキラはカードの数だけ重なるので、手札や一覧に並ぶ枚数×面積で負荷を見積もる。ラメのマスは近くの数マスだけを調べ、ループを短くする。
- 指の位置や端末の傾き（ジャイロ）で動かすと手触りが良いが、使わない場面でも動くよう時間で動かす形を基本にする。
- 画面全体の明滅にならないよう、光の帯は細く、ラメは小さくする（[安全と読みやすさ](../../vfx-authoring/SKILL.md#安全と読みやすさ)）。
