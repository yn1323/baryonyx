# 保存先を決めて作る

保存するデータの置き場所を決め、その置き場所の作り方で実装し、仕様へ記録するまでの進め方を扱う。
判断の基準・置き場所の一覧・作り方の正本は[保存先の決め方](../../../doc/rules/data-storage.md)であり、このスキルには写さない。

## 使う場面

- 新しい機能で、持ち物・進行・記録・設定などをアプリの再起動後も残すとき
- `PlayerPrefs`・ファイル・D1のテーブル・保存APIを追加、変更、削除するとき
- 仮データで動く画面を、サーバーへの保存つきに置き換えるとき
- 保存の処理を含む差分をレビューするとき
- 「これはどこに保存するか」と聞かれたとき

## 手順

1. **保存するデータを書き出す**：何を、どの操作のあとに、誰のもの（ユーザーごと・端末ごと）として残すかを一覧にする。ルーンや持ち物の増減が絡むかも書き添える。
2. **決まっているかを調べる**：[置き場所の一覧](../../../doc/rules/data-storage.md#置き場所の一覧)、[アカウントとセーブ](../../../doc/features/accounts-save.md)の未決事項の表、対象機能の仕様の保存の節を読む。決まっていれば、それに従う。
3. **未決なら案を作って確かめる**：[判断の基準](../../../doc/rules/data-storage.md#判断の基準)の3つの問いに当てはめて案を作り、どの問いに当てはまったかと理由を添えて、ユーザーに確かめる。一覧で「案」の項目も、仕様で決まるまでは確かめる。答えを待つ間も、決まっているデータの作業は進めてよい。
4. **作る**：サーバーなら[サーバーに置くときの作り方](../../../doc/rules/data-storage.md#サーバーに置くときの作り方)と[バックエンドの開発環境](../../../doc/rules/backend-design.md)、端末なら[端末に置くときの作り方](../../../doc/rules/data-storage.md#端末に置くときの作り方)に従う。
5. **確かめる**：下の「確かめること」のうち、変更に関係するものをテストで確かめる。
6. **記録する**：決めた置き場所を、同じ変更で次の3か所へ反映する。
   - 対象機能の仕様の保存の節と「変更と判断の記録」
   - [アカウントとセーブ](../../../doc/features/accounts-save.md)の未決事項の表
   - [置き場所の一覧](../../../doc/rules/data-storage.md#置き場所の一覧)。`PlayerPrefs` のキーを足したり消したりしたときも直す
7. **報告する**：何をどこに保存したか、ユーザーに確かめて決めたこと、確かめていないことを分けて書く。

## 判断の観点

作るときとレビューのときに、次を確かめる。各項目の根拠と詳しい作り方は、リンク先のdocにある。

- [ ] ルーン・持ち物・進行・記録を、端末だけに置いていない（[判断の基準](../../../doc/rules/data-storage.md#判断の基準)）。
- [ ] 端末からは操作の内容だけを送り、費用・報酬・残高の計算結果を送っていない（[サーバーに置くときの作り方](../../../doc/rules/data-storage.md#サーバーに置くときの作り方)）。
- [ ] ルーンや持ち物を増減するAPIは要求IDを受け取り、再送で二重に処理しない（[サーバーに置くときの作り方](../../../doc/rules/data-storage.md#サーバーに置くときの作り方)）。
- [ ] サーバーのデータを、ログイン中のユーザーごとに分けて読み書きしている（[サーバーに置くときの作り方](../../../doc/rules/data-storage.md#サーバーに置くときの作り方)）。
- [ ] 保存に失敗したとき、画面の表示を変えずに知らせている（[サーバーに置くときの作り方](../../../doc/rules/data-storage.md#サーバーに置くときの作り方)）。
- [ ] 端末に置く値は、消えたときに何が起きるかを説明できる。消えると困る値は、書いた直後に保存している（[端末に置くときの作り方](../../../doc/rules/data-storage.md#端末に置くときの作り方)）。
- [ ] 秘密値や個人情報を、ログ・文書・コミットに出していない（ルートの [AGENTS.md](../../../AGENTS.md#作業の基本)）。

## 確かめること

- **サーバー**：保存APIのテストで、初めて読んだときの値、変更が残ること、不正な入力の拒否、再送で二重にならないこと、ユーザーごとに分かれることを確かめる。複数のAPIをまたぐ流れは、[テストの配置](../../../doc/rules/backend-design.md#テストの配置)に従ってシナリオのテストに書く。
- **クライアント**：偽のサーバーを使い、読み込み・保存・保存の失敗を確かめるテストを足す。テストの選び方と実行は[Unityのテスト](../../../doc/rules/client-testing.md)に従う。
- **つないだ確認**：Editorの接続先をローカルのサーバーにし、変更してからPlayを止めて再開し、変更が残ることを確かめる。`server/` の `pnpm dev` はユーザーが起動する（ルートの [AGENTS.md](../../../AGENTS.md)）ため、起動を頼む。
- **端末の保存**：`PlayerPrefs` を書くテストは、書いたキーをテストの後に消し、ほかのテストや手元のEditorの値に影響させない。
