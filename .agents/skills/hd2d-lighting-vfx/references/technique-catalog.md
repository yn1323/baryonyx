# HD-2D技法の一覧と採用方針

調査日は2026-09-23。
HD-2Dを構成する技法を、必要な前提ごとに分けて一覧にする。
各技法の「このプロジェクトでの扱い」は、2026-09-23時点でユーザーと合意した方針であり、画面の追加や方針変更に合わせて更新する。

## 扱いの区分

| 区分 | 意味 |
|---|---|
| 採用予定 | 次の作業で実装する |
| 将来候補 | 対象画面を作るときに検討する |
| 必要時に判断 | 具体的な要件が出たときに検討する |
| 見送り | 現時点では採用しない。理由を併記する |

## A. 今の画面構造のまま重ねられる技法

`ScreenSpaceOverlay` のuGUIに透過画像や粒子を重ねる方式で、2D Rendererやポストプロセスを必要としない。
`Shared/VFX/HD2D/` の部品として汎用化しやすい。

| 技法 | 内容 | 難易度 | 汎用化 | このプロジェクトでの扱い |
|---|---|---|---|---|
| 光芒 | 画面外から斜めに差す光の筋と、床の光だまり、筋の中の埃 | 低 | 高 | 実装済み（`Hd2dLightShaft`） |
| 環境粒子 | 画面全体の埃とキラキラ | 低 | 高 | 実装済み（`Hd2dLightingVfx`） |
| 霞・霧 | 奥の空間の青い霞と、床すれすれを流れる霧。縁をぼかした矩形に継ぎ目のないノイズ画像を2枚重ね、`RawImage.uvRect` のスクロールで逆向きに流す | 低 | 高 | 実装済み（`Hd2dFog`） |
| 揺らぐ光と照り返し | 光源の加算グローを不規則に揺らし、壁と床へ弱い照り返しを置く | 低 | 高 | 実装済み（`Hd2dFlickerLight`）。背景画像に揃えた親へ置き、描かれた光源に重ねる |
| 点から出る粒子 | 指定した点・範囲から指定方向へ出る粒子。火の粉、魔法、報酬時のキラキラ | 低〜中 | 高 | 実装済み（`Hd2dEmberEmitter`）。背景より手前に出すため、Particle SystemではなくuGUIのImage方式とした。報酬などの一回だけの演出は `Burst` で出す |

## B. ポストプロセスを使う技法

背景をカメラを通すCanvas（`Screen Space - Camera`）へ分け、タイトルと操作は `ScreenSpaceOverlay` に残す構成が前提となる。
`ScreenSpaceOverlay` のUIにはカメラのポストプロセスがかからないためである。
Volume Profileは使い回せるが、画面構造の変更は全画面の方針として決める。
Topでは背景と演出を `TopBackdropCanvas`（Screen Space - Camera）、タイトルと操作を `TopCanvas`（Screen Space - Overlay）に分け、共通の `Hd2dPostProcess` Profileを全体のVolumeで適用した。

| 技法 | 内容 | 難易度 | このプロジェクトでの扱い |
|---|---|---|---|
| Bloom | 一定より明るいピクセルを抜き出してぼかし、元画像に足す。元の絵はくっきり残る | 中 | 実装済み（`Hd2dPostProcess`）。Thresholdを0.4にして、炎と加算の光に加えて照らされた中間調もにじませる（0.8程度なら炎と加算の光だけに絞れる） |
| Vignette | 画面端を暗くして中央へ視線を集める | 中 | 実装済み（`Hd2dPostProcess`） |
| Color Adjustments | 色温度、明暗、彩度を揃える | 中 | 実装済み（`Hd2dPostProcess`） |
| 疑似ティルトシフト | 奥行き情報を使わず、画面の上下を位置でぼかしてミニチュア感を出す | 中〜高 | 実装済み（`Hd2dTiltShift` のVolume ComponentとRenderer Feature）。2026-09-23にユーザーの指示で見送りから変更した。ドット絵の輪郭が濁らないよう、半径を1粒より少し大きい程度（1080px基準で8）に抑え、中央の帯は残す |

BloomとティルトシフトはA群の技法と混同しやすいため、区別を明記する。
Bloomは明るさで対象を選んで光を足す。ティルトシフトは画面上の位置で対象を選び、絵そのものをぼかす。

## C. 背景を複数レイヤーに分ける技法

背景を遠景・中景・手前の画像に分けて描くことが前提となる。

| 技法 | 内容 | このプロジェクトでの扱い |
|---|---|---|
| パララックス | 手前のレイヤーほど大きく動かす | 将来候補 |
| 手前のシルエット | 画面端に暗い柱や草を置き、覗き込んでいる感じを出す | 将来候補 |
| レイヤーごとの霞 | 遠いレイヤーほど青く薄くする（空気遠近法） | 将来候補 |
| 光芒の前後関係 | 光芒を柱の後ろへ通す | 将来候補 |

レイヤーを `SpriteRenderer` で並べる場合は、D群の2D Rendererへの切り替えと同時に判断すると、作り直しが一度で済む。

## D. 2D Rendererと法線マップを使う技法

URPの2D Rendererへの切り替えが前提となる。
現在の `Mobile_Renderer` は全シーン共通のUniversal Rendererであり、切り替えは全画面へ影響する。

| 段階 | 内容 | 難易度 | このプロジェクトでの扱い |
|---|---|---|---|
| 描画の切り替え | 2D Rendererへ変え、背景を `SpriteRenderer` へ移す | 中 | 将来候補。C群と同時に判断する |
| 2D Light（法線マップなし） | ライトの範囲内の明るさと色を変える。凹凸は光に反応しない | 低〜中 | 将来候補。切り替えを行う場合の到達点とする |
| 法線マップ | 各ピクセルの面の向きを持たせ、凹凸を光に反応させる | 高 | 2Dの背景とキャラクターは見送り。背景1枚ごと、キャラクターはアニメーションの全コマごとに必要になる。ドット絵は陰影が描き込まれているため、自動生成ツールの結果は手直しが要る。3Dの舞台のテクスチャは、2026-10-03に絵の明るさと切り抜きの縁から計算する法線マップを採用した（hd2d-stage-set の[法線マップ](../../hd2d-stage-set/references/stage-building.md#法線マップ)） |
| Shadow Caster 2D | 2D Lightが遮られた範囲を暗くする | 中 | 見送り。真上から見た平面で遮蔽を計算するため、横・正面から見る構図では影が画面の奥へ伸びて不自然になりやすい |

## E. キャラクターの影と陰影

キャラクターの影は、地面や壁に「落ちる影」と、キャラクター自身の「陰影」に分けて扱う。
いずれも法線マップや2D Rendererなしで、今のuGUIのまま作れる。

| 技法 | 内容 | 難易度 | このプロジェクトでの扱い |
|---|---|---|---|
| 丸影 | 足元に黒い楕円を置く | 低 | 必要時に判断 |
| 疑似の投影影 | キャラ画像を黒く半透明にし、足元を支点に傾けて伸ばす。光源の位置から向きと長さを計算できる。アニメーションはキャラ画像と共有するため、コマごとの追加作業はない | 低〜中 | 将来候補。キャラの影はこの方式までとする。光源に応じて影を伸ばす表現も実現できるが、松明を光源にした演出は予定しない |
| 暖色グラデーション | 光源側を暖色に、反対側を暗くするグラデーションを重ねる | 低〜中 | 見送り |
| リムライト | 光源側の輪郭だけを細く光らせる | 中 | 見送り |

## F. 3D空間にドット絵を置く技法

地形や建物を簡単な3Dで作り、キャラクターを板（ビルボード）に貼ったドット絵にする構成が前提となる。
HD-2Dの元の作品に最も近い構成である。

| 技法 | 内容 |
|---|---|
| 被写界深度・ティルトシフト | 奥行き情報を使い、距離に応じてぼかす |
| ボリュメトリックな霧・光 | 空間の中に光と霧があり、キャラクターがその中を通れる |
| 水面の反射・揺らぎ | 水面にキャラクターや光源が映る |
| カメラワーク | 回り込み、寄り、引きで箱庭を覗く感じを出す |
| SSAO | 接地面や隅を自然に暗くする |

このプロジェクトでの扱いはすべて見送りとする。
背景制作の方式そのものが変わり、現在の体制では実現できないためである。

## G. 仕組みを足して作る技法

| 技法 | 内容 | 前提 |
|---|---|---|
| 天候 | 雨、雪、舞う葉を画面ごとに切り替える | A群の粒子 |
| 時間帯 | 朝、夕、夜で色調を切り替える | B群のColor Adjustments |
| 演出用の画面遷移 | 光が強まってからフェードするなど | A群またはB群 |

このプロジェクトでの扱いは、すべて必要時に判断とする。

## D. 3Dの舞台にドット絵を立たせる技法

2026-10-02に、Top・Home・BattleInspectを3Dの舞台へ移した（[3Dの舞台の仕様](../../../../doc/art/hd2d-stage.md)）。
進め方とつまずいた点は [hd2d-3d-stage.md](hd2d-3d-stage.md) に記す。

| 技法 | 内容 | 難易度 | このプロジェクトでの扱い |
|---|---|---|---|
| 3Dの舞台 | ドット絵のテクスチャを貼った床・壁・柱・段と、遠景・書き割りの板 | 中 | 実装済み（`Hd2dStageKit`・`StageSetAssets`） |
| 望遠寄りの見下ろしカメラ | 縦30〜42度の画角で、地面とキャラを並べて見せる | 低 | 実装済み（`Hd2dStageCamera`） |
| カメラの面と平行なキャラの板 | UIの位置と大きさを写した板で、薄っぺらく見せない | 中 | 実装済み（`Hd2dUiBillboard`） |
| 影の板と接地影 | 光へ向けた垂直の板で影を落とし、足元に楕円の影を敷く | 中 | 実装済み |
| 冷色の主光源と暖色の点光源 | 月明かり・天窓の影のある光と、揺らぐ松明・焚き火の光 | 低 | 実装済み（`Hd2dLightFlicker`） |
| 昼の太陽と3色の環境光 | 暖色の太陽で影を落とし、空・木々・地面の環境光で日陰を青緑に寄せる | 低 | 実装済み（ホーム） |
| 木漏れ日 | 太陽のライトクッキーに葉の斑のマスクを敷く。キャラの板は受けない | 低 | 実装済み（`Hd2dStageKit.LeafCookie`） |
| 光の筋（ゴッドレイ） | 光の軸のまわりでカメラへ向く加算の板。両端と幅を柔らかく消し、縞で揺らす | 低 | 実装済み（`Baryonyx/HD2D/Light Beam`） |
| 漂う塵 | 光の中をゆっくり漂う丸い光の粒 | 低 | 実装済み（`Hd2dStageKit.Motes`） |
| 線形の霧 | 遠くを空気の色に寄せる | 低 | 実装済み（シーンの環境設定） |
| UIの動きに合わせたカメラの移動 | 円運動と揺れをカメラの平行移動に置き換え、視差を付ける | 中 | 実装済み（戦闘画面） |
| 計算の炎と火の粉 | 涙形とノイズの炎、丸い光の粒 | 低 | 実装済み（`Baryonyx/HD2D/Flame`・`Glow Particle`） |
| 舞台のレンズ（深度で決める被写界深度） | 半透明の列の前に、不透明の舞台だけを距離でぼかす。半分の解像度で、手前のぼけを奥へ広げて集める | 中 | 実装済み（`Hd2dStageFocus`）。URPの被写界深度は舞台のUIまでぼかすため使わない |
| 舞台ごとの色調と周辺減光 | 影を寒色・光を暖色に寄せる `Split Toning`、コントラストと彩度、強めの `Vignette` | 低 | 実装済み（`<舞台>Look`） |
| 入力待ちのカメラの揺れ | 待つ間だけカメラを小さな円で動かす | 低 | 実装済み（Top・ホーム） |
| 画面を開いたときのすべり込み | 少し離れた所からカメラを寄せ、最後をゆっくりにする | 低 | 実装済み（Top・ホーム） |
| 停止中の3D表示 | 保存しないキャラの板、保存しないCanvasGroupで消す2Dの部品、停止中も動く粒子で、停止中のGameビューもHD-2Dにする | 中 | 実装済み |
| Sceneタブの見た目合わせ | シーンを開いたらSceneタブを舞台のカメラにそろえ、手前のUIをSceneタブでだけ隠す | 低 | 実装済み（`Hd2dSceneViewSync`） |
| エフェクトと同時の点光源 | 技の演出と同時に点光源を置き、キャラの影を背景に落とす | 中 | 必要時に判断。戦闘の演出はUIで描いているため、舞台の点光源と同期する仕組みが要る |
| 画面ごとの時間帯 | 画面ごとに時間帯と色を分け、同じ構成の舞台でも見分けやすくする | 低 | 実装済み（Topは夜、ホームは昼、戦闘は夕暮れ） |
| 描いた遠景 | 空・遠い山並み・遠い荒野を、光も霧も受けずに描いた色で見せる | 低 | 実装済み（`Baryonyx/HD2D/Painted Distance`） |
| 星の瞬きと月の光 | まわりより明るいドットを星とみなして白より明るくし、ずらして瞬かせる。月も白より明るくする | 低 | 実装済み（同じシェーダー） |
| 逆光の補助光 | 逆光で黒くなる正面に、影のない弱い光を当てる | 低 | 実装済み（Top） |
| 時間帯の切り替え | 同じ画面で昼・夕・夜を移り変わらせる | 中 | 必要時に判断。今は画面ごとに時間帯を固定している |
| 3Dのカメラの回り込み | 演出でカメラを大きく回す | 高 | 見送り。キャラはカメラの面と平行な板のため、大きく回すとUIの位置と合わなくなる |
