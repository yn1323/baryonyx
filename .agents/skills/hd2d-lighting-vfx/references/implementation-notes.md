# HD-2D演出の実装で得た知見

2026-09-23に、Topへ霞と霧、揺らぐ光、火の粉、ポストプロセス、疑似ティルトシフトを実装した。
その過程でつまずいた点と、次の実装でも使える工夫を記録する。
対象はUnity `6000.6.0f1`、URP `17.6.0`、uGUI、Unity CLIで接続したEditorである。

## Editorでの検証のつまずき

**Editorが最前面にないと時間が進まない。**
CLIからPlay Modeに入っても、Editorが背面にあるとフレームが進まず、2回撮影しても粒子の位置まで同じ画像になった。
停止中の `[ExecuteAlways]` の `Update` も呼ばれず、停止中のプレビュー用の子オブジェクトが作られていないように見えた。
Play Modeでは `editor_pause` で一時停止し、`EditorApplication.Step()` で1フレームずつ進めてから撮影する。
動きの確認は、フレームを進めながらUVのずれや透明度を読み出し、値が設定どおりに変わることで確かめる。
停止中のプレビューは、Inspectorの変更時と同じ再構築メソッド（`RebuildLayers` など）を直接呼んで確かめる。

**解像度を指定した撮影では、カメラ側のCanvasの再レイアウトが1フレーム遅れる。**
`capture_game_view` に幅と高さを指定すると、`Screen Space - Camera` のCanvasだけが直前の解像度のまま描かれ、背景が拡大されて端が切れた画像になった。
同じ解像度で一度撮影し、数フレーム進めてから撮り直すと正しく写る。
実機では画面の大きさが変わらないため、この現象は撮影時だけのものである。

**CLIの操作が重なると、PlayModeテストが打ち切られる。**
テストの実行中にPlay Modeの開始・停止やシーンの切り替えが重なると、「Playmode tests were aborted because the player was stopped.」で中断し、状態は「running」のまま残った。
PlayModeテストはEditorへほかの操作をしない状態で単独で実行する。
また、Play Modeを止めた直後に `EditorSceneManager.OpenScene` を呼ぶと、Play Mode中として拒否されることがある。
`editor_status` の `playMode` が `stopped` になってから操作する。

**PlayModeテストは一時的なテスト用アセットを作る。**
実行中は `Features/*/Tests/PlayMode/Resources` がGitの未追跡ファイルとして現れ、テスト終了時に片付けられる。
コミットの対象に含めない。

## 描画のつまずき

**線形色空間では、加算の光が思ったより弱く見える。**
UIの加算シェーダーで松明の光を重ねたとき、芯の透明度0.28では撮影画像でほとんど差が見えなかった。
芯0.55、周りの光0.22まで上げて、ようやく柱の照り返しが見えるようになった。
背景に光が描き込まれている絵では、見える差が出るまで上げてから、白飛びしない位置まで戻す。

**弱いBloomでは、効いているかを判断できない。**
強さ0.8のBloomは、効いているのか見分けられなかった。
一時的に強さを4へ上げて撮影し、炎の周りがにじむことで効果の経路を確かめてから、1.6に決めた。
弱い効果を調整するときは、極端な値で経路を確かめてから下げる。

**`AddBlitPass` は `_BlitTexture_TexelSize` を設定しない。**
ティルトシフトのシェーダーが `Blit.hlsl` の `_BlitTexture_TexelSize` でサンプル位置をずらしていたが、この値は0のままで、ぼかしが掛からなかった。
Render Graphの `AddBlitPass` が設定するのは `_BlitTexture` と `_BlitScaleBias` までである。
テクセルサイズは、テクスチャの説明（`TextureDesc`）の幅と高さから求めてマテリアルへ渡す。

**ドット絵のぼかしは、1粒より大きい半径でないと見えない。**
1080px基準で半径3のティルトシフトは、撮影画像では2px程度になり、ドット絵の1粒より小さく見えなかった。
半径8で、床のタイルの縁がなめらかになる程度のぼけになった。
半径を上げすぎると輪郭が濁るため、6〜10から調整する。

**効果の範囲は、一時的に色を塗って確かめる。**
ぼかしが見えない原因が、パスが動いていないのか、効果が弱いのかを切り分けられなかった。
シェーダーの出力を一時的に「ぼかす範囲を赤で塗る」形に変えると、パスが画面に反映されていることと、帯の位置が正しいことを一度に確認できた。
計測用のコードやシェーダーの変更は、確認後に必ず元へ戻す。

**Renderer Featureの `Create` は、`Shader` を設定する前に呼ばれる。**
スクリプトで `ScriptableObject.CreateInstance` したRenderer Featureは、作成した時点で `Create` が呼ばれる。
その後で `Shader` を設定しても、マテリアルは作られないままになる。
マテリアルは `AddRenderPasses` でも、なければ作るようにする。

**`ScreenSpaceOverlay` のUIには、カメラのポストプロセスが掛からない。**
Topは背景もUIもOverlayのCanvasに置いていたため、そのままではBloomが効かない。
背景と演出を `Screen Space - Camera` のCanvasへ移し、タイトルと操作はOverlayに残した。
両方のCanvasScalerを同じ設定にすると、座標の単位がそろう。

## シーンとアセットの保存のつまずき

**画面座標で置いた光は、描かれた光源からずれる。**
背景は画面を覆うように拡大されるため、画面比率が変わると、画面上での松明の位置も変わる。
既存の光源の層（`LightLayer`）がTopで非表示にされていたのも、この位置ずれが一因と考えられる。
描かれた光源に合わせる部品は、親に背景と同じ `ResponsiveBackground`（同じ `AspectRatio`）を付け、背景画像上の正規化座標で置く。

**`ResponsiveBackground` の大きさが、Gameビューの解像度でシーンに保存される。**
この値は実行時に計算し直されるが、シーンを保存すると、そのときのGameビューの大きさ（2712×1526など）が差分に入る。
一度はこの値がコミットに入り込んだ。
スクリプトでシーンを保存する前に、`TopBackground` の `sizeDelta` を元の値（1920×1080.5741）へ戻す。

**Prefabのリストの先頭に要素を挿入すると、全要素が上書き扱いになる。**
Top専用の霞を霧の層のリストの先頭へ挿入したところ、後ろにずれたPrefab既定の床霧まで、シーン側の上書きとして記録された。
画面固有の要素はリストの末尾へ追加する。
Prefab既定の要素は上書きされないまま残り、Prefab側の変更がシーンにも反映される。

**Play Mode中に変えたアセットの値は、保存しないとDomain Reloadで戻る。**
Volume Profileの値をPlay Mode中に変えて試すと、Editorのメモリ上では変わるが、再コンパイル後には保存前の値に戻った。
決めた値は `EditorUtility.SetDirty` と `AssetDatabase.SaveAssets` で保存し、生成スクリプトの既定値もそろえる。

**Renderer Featureをスクリプトで登録するには、2つの項目を更新する。**
URPのInspectorと同じく、サブアセットとして追加したFeatureを `m_RendererFeatures` と `m_RendererFeatureMap`（ローカルのファイルID）の両方へ登録する。
登録後は、読み戻してファイルIDと対応表が一致することを確かめる。
このとき、URPが `Mobile_Renderer` と `PC_Renderer` を今の形式で書き直し、改行位置や `m_AssetVersion` などの差分が出る。

## C#とアセンブリのつまずき

**Unityオブジェクトに `??` を使うと、アナライザーのエラーになる。**
このプロジェクトでは `UNT0007`（Unityオブジェクトへのnull合体演算子）がエラー扱いで、Editorアセンブリのコンパイルが止まった。
`if (obj != null) return obj;` のように明示的に比較する。

**asmdefをJSONとして書き出し直すと、既存の整形が崩れる。**
参照の追加で `json.dumps` を使うと、1行の配列がすべて複数行に展開された。
`references` の配列だけを文字列として書き換え、差分を参照の追加だけに保つ。

## 部品設計の工夫

**同じ骨組みで部品を作る。**
霧、揺らぐ光、火の粉は、光芒（`Hd2dLightShaft`）と同じ骨組みにした。
層や光源、発生源をリストで持ち、表示用の子オブジェクトを `HideFlags.DontSave` で生成する。
`PreviewInEditor` で停止中にも表示し、Inspectorの変更時は再構築メソッドを呼ぶ。
専用InspectorはUI Toolkitで日本語のラベルを付け、`TrackSerializedObjectValue` でリストの追加・削除を含む変更を拾う。

**Prefabは汎用の既定値、画面固有の値はシーンで持つ。**
Prefabには床霧の2層や松明1つ分など、どの画面でも使える既定値だけを入れた。
Topのアーチ奥の霞や4つの松明の位置は、シーンのPrefabインスタンス側で設定する。

**式で位置を求める粒子は、停止中のプレビューが再生中と一致する。**
火の粉の位置は、生まれた点・初速・浮力・横ゆれから、経過時間の式で直接求める。
毎フレーム速度を足し込む方式と違い、任意の時刻の配置を再現できる。
乱数は固定のシードで初期化し、同じ設定なら同じ配置になる。

**火の粉は形で役割を分け、ドットの格子を崩さない。**
四角い点を大きさだけ変えて出すと、背景の1ドット（約7px）に近い大きさの点がブロックに見えた。
そこで、1〜2ドットの点を主体にし、3×3の十字と1×4の尾を引く粒を少数だけ混ぜた。
3ドット幅の頭を持つしずく形も試したが、この大きさでは「†」の形に見えたため、1ドット幅の筋にした。
形の画像はPointで読み込み、回転は90度単位に限る。

**C#とシェーダーで同じ式を持たせ、テストで確かめる。**
継ぎ目のないノイズ、炎の揺らぎ、ティルトシフトのぼかしの強さは、静的メソッドとしてC#にも実装した。
テクスチャの生成とEditModeテストが同じ式を使うため、ノイズの端が1周してつながることや、中央の帯でぼかしが0になることを数値で確かめられる。

**1枚の画像が滑って見えないようにする。**
霧は、細かさの違う2枚のノイズを逆向きに流して重ね、`RectMask2D` のsoftnessで範囲の縁をぼかした。
床の照り返しは、炎より少し遅く、控えめに揺らす。
炎の揺らぎは、ゆっくりした揺れ、速い揺れ、細かいちらつきの3つのノイズを重ねた。

**効果がない画面では処理しない。**
ティルトシフトはVolume Componentの強さが0の画面ではパスを登録せず、全画面の処理を行わない。
Rendererは全画面で共通なので、Top以外の画面の負荷を増やさない。
Bloomより前にぼかすため、ぼけた光もBloomでにじむ。

## 検証の工夫

見た目の変化が小さい効果は、画面全体の比較では判断できないことが多い。
変更前後の撮影から、同じ範囲（松明の周り、床の下端など）を切り出して並べて比べる。
Topは16:9、20:9、4:3で撮影し、背景に揃えた部品が描かれた光源に重なることを確かめた。
展示室では、プレビュー用の関数を呼んで対象のPrefabを選び、フレームを進めて撮影した。
