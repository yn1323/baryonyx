# 効果音とBGMを付ける

フリー素材から音を選び、演出に合わせて加工し、Unityで鳴らすまでの進め方を扱う。
入手先・加工の可否・置き場所・形式・取り込み設定の正本は[効果音とBGM](../../../doc/rules/sound.md)、クレジットの記録は[外部素材のクレジット](../../../doc/rules/credits.md)であり、このスキルには写さない。

## AIで音を扱うときに気をつけること

- **Claudeは音を聞けない**：使う音は、必ずユーザーが聞いてから決める（[確定している方針](../../../doc/rules/sound.md#確定している方針)）。候補選び、加工、差し替えのどれも、Claudeが聞かずに決めない。Claudeは、サイトの音の名前と分類から候補を絞り、`scripts/sfx.py inspect` で長さ・頭の無音・ピーク・ラウドネスと、波形と周波数の画像を見て、明らかに合わない候補（長すぎる、頭に無音がある、こもっている）を外すところまでを受け持つ。数値と画像からの見立ては「〜に見える」と書き、聞いた感想のように書かない。
- **音は場面の動画と一緒に見せる**：音だけを送らず、その音を鳴らす場面の動画に候補の音を重ねて送り、どの動作で鳴らすかを言葉で添える。やり方は下の「音の見せ方」に従う。
- **候補は性格の違うものを並べる**：1つの動作に3〜5個を出す。気に入らなかったときに言いやすいよう、軽い・重い、短い・余韻がある、のように性格の違う候補を混ぜる。
- **ダウンロードは依頼の範囲で**：ファイルを落とす前に、どのサイトのどの音を落とすかが依頼に含まれているかを確かめる。含まれていなければ、ファイル名・配布元・大きさを示して許可をもらう。落とした音は、ほかのファイルと混ぜずに新しいフォルダーへ置く。
- **規約は配布元ごとに違う**：表記の義務、禁止されている使い方（効果音を自由に鳴らせる画面など）は[外部素材のクレジット](../../../doc/rules/credits.md#配布元ごとに守る条件)にある。ゲームから配布元のファイルへ直接リンクして鳴らさない。
- **テストで確かめられるのは「鳴らしたか」まで**：PlayModeテストでは、決まった場面で決まった音を鳴らす処理が呼ばれたかを確かめる。聞こえ方、音量のつり合い、端末での遅れは、ユーザーが展示室やエミュレーターで聞いて確かめるまで「未確認」として報告する。

## 手順

1. **付ける音を書き出す**：何に（ボタン、技、被弾など）、どの瞬間に（押したとき、技の溜め・当たり・余韻）、どのくらいの長さで鳴らすかを一覧にする。技の音は、その技の演出の拍と長さを [vfx-authoring](../vfx-authoring/SKILL.md) の作りやコードで確かめ、拍ごとに音を分けて考える。似た用途は、技ごとに別の音を探さず、系統（斬撃・軽、斬撃・重、炎、回復など）にまとめて同じ音を使い回す。
2. **候補を探す**：[入手先](../../../doc/rules/sound.md#確定している方針)のサイトから、名前と分類で候補を探す。サイトごとの探し方は [references/sources.md](references/sources.md) にある。候補は `output/sound/<用途>/` に落とす。
3. **候補を絞る**：`python3 -I scripts/sfx.py inspect <ファイル...> --png <フォルダー>` で測り、画像を見て外すものを外す。
4. **場面の動画と一緒に見せ、選んでもらう**：下の「音の見せ方」に従って送る。ユーザーが選ぶまで次へ進まない。
5. **加工する**：選ばれた音を、演出の長さと拍に合わせて加工する。加工の選び方とコマンドは [references/editing.md](references/editing.md) にある。最後は必ず `fit` で頭の無音を切り、ピークをそろえる。加工した音も、同じく場面の動画に重ねて見せ、決めてもらう。
6. **Unityへ入れる**：[置き場所と名前](../../../doc/rules/sound.md#置き場所と名前)に従ってWAVを置き、同じフォルダーの `README.md` に配布元・元の名前・加工のコマンドを書く。新しい配布元なら[外部素材のクレジット](../../../doc/rules/credits.md)にも行を足す。取り込み設定は[Unityの取り込み設定](../../../doc/rules/sound.md#unityの取り込み設定)に従う。
7. **鳴らす処理を作る**：下の「Unityで鳴らすときの注意」に従う。仕組みの決まりが[未決事項](../../../doc/rules/sound.md#未決事項)にあるうちは、決め方の案をユーザーに確かめてから作り、決まったら doc に書き移す。
8. **確かめる**：鳴らす処理のテストを実行し、[展示室](../../../doc/features/showcase.md)に音が載って再生できることを確かめる。Unityの操作は [unity-editor-notes](../shared/unity-editor-notes.md) と [UnityのテストとCI](../../../doc/rules/client-testing.md) に従う。
9. **報告する**：入れた音、配布元、加工、確かめたことと、聞いて確かめていないこと（音量のつり合い、端末での遅れなど）を分けて報告する。

## 音の見せ方

候補を選んでもらうとき、加工した音を確かめてもらうときは、毎回この形で見せる。

1. **場面を録画する**：[unity-video-recording](../unity-video-recording/SKILL.md) で、音を鳴らす場面を録る。録画は音声なしである（[動画の録画](../../../doc/rules/client-testing.md#動画の録画)）。デバッグルームで再生できない場面や、まだ画面がない場面は、どの動画で見せるかをユーザーに聞く。
2. **鳴らす時刻を決める**：演出のコードから拍の時刻（溜め・当たりなど）を読み、`python3 -I scripts/sfx.py frames <録画.mp4> <画像.png> --start <秒> --end <秒> --step 0.1` で並べたコマを見て、動作の時刻を確かめる。コマごとの時刻は実行結果に出る。
3. **候補ごとに音を重ねる**：`python3 -I scripts/sfx.py mux <録画.mp4> <候補A.mp4> <候補Aの音>@<ミリ秒>` で、候補ごとに1本ずつ動画を作る。溜めと当たりのように複数の音を鳴らすときは、音を並べて書く（`溜め.wav@200 斬撃.wav@800:-3`）。ファイル名には候補の記号を付ける（`A-剣で斬る1.mp4`）。
4. **言葉を添えて送る**：SendUserFile で、比べやすいように候補の動画をまとめて送る。添える文は次の形にする。

```text
〈場面〉の動画です。〈動作〉（0.8秒）で鳴らす音の候補を3つ挙げます。
- A：効果音ラボ「剣で斬る1」（0.7秒）。軽く鋭く見える音
- B：魔王魂「戦闘06 深く斬る音」（0.4秒）。短く重く見える音
- C：Aを2秒に伸ばした音（extend slow）
どれを使いますか。どれも合わなければ、近い方向を教えてください。
```

使いたい音が1つに決まっているときも、「この動画の〇秒の〈動作〉で、この音を使いたい」と書き、同じ形で動画を送って確かめてもらう。
録画の秒と実際のゲームの秒は、実時間で進む演出ではずれることがある（[unity-video-recording](../unity-video-recording/SKILL.md) の「気を付けること」）。ずれが疑われるときは、そのことを添える。

## Unityで鳴らすときの注意

一般的な作法である。このプロジェクトで決めた形は[効果音とBGM](../../../doc/rules/sound.md)を優先する。

- **2Dの音として鳴らす**：画面の効果音とBGMは、`AudioSource.spatialBlend` を0にする。カメラの位置で音量が変わらないようにするためである。
- **重なる効果音は `PlayOneShot`**：`Play` は同じ `AudioSource` の前の音を止める。連打や連続攻撃で前の音を残したいときは `PlayOneShot` を使う。押すたびに `AudioSource` を作らない。
- **鳴らす瞬間を演出の拍に合わせる**：技の音は、カードを使った瞬間にまとめて鳴らさず、溜め・当たり・余韻のそれぞれの拍で鳴らす。演出の時間の進め方（`Time.timeScale` の影響を受けるか）と、音を鳴らす時刻の計り方をそろえる。
- **同じ音の連続を避ける**：同じ攻撃の音が何度も続く場面では、数種類から選ぶ、ピッチを少し揺らすなどで単調さを減らす。Unity 6 には、数種類の音から選んで鳴らす [Audio Random Container](https://docs.unity3d.com/Manual/AudioRandomContainer-UI.html) がある。
- **ボタンの音は少なく、小さく**：何百回も鳴る音ほど短く小さくし、ご褒美の音のようにまれな音だけを豪華にする。スクロールやドラッグ中には鳴らさない。
- **取り込み設定は置き場所で決まるようにする**：ファイルごとにInspectorで変えると揃わなくなる。仕組みを作るときは、置き場所から設定を決めるEditorの処理（`AssetPostprocessor.OnPreprocessAudio`）を案として出し、ユーザーに確かめる。
- **Androidの遅れ**：押してから鳴るまでの遅れは、端末と `Project Settings > Audio` の `DSP Buffer Size` で変わる。Editorでは分からないため、エミュレーターで聞いてもらう（エミュレーターの起動はユーザーが行う）。
- **容量とメモリ**：BGMや長い音を増やしたら、APKの大きさと取り込み設定を見直す。詳しい最適化はプラグインの `unity:optimize-audio` スキルが扱う。

## 担当の分け方

- 技・被弾・報酬の見た目の演出は [vfx-authoring](../vfx-authoring/SKILL.md)。音を鳴らす拍は、その演出の拍に合わせる。
- 押したときの音を付ける画面の作りやUXは [ui-advisor](../ui-advisor/SKILL.md)。
- 音量の設定を保存するときの保存先は [data-storage](../data-storage/SKILL.md)。
- AudioSourceを `AudioMixer` のグループへ振り分ける作業は、プラグインの `unity:audio-setup-mixers` スキルも使える。
