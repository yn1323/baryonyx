# 変更をコミットする

現在の変更を調べ、今回の依頼に属するものだけを論理単位でコミットする。

コミット前のテストの全件実行、失敗したときと実行できないときの扱いは、ルートの `AGENTS.md` の[commitの手順](../../../AGENTS.md#commitの手順)を正本とする。
対象の選び方・分け方・ステージの仕方・メッセージの形式・使わない操作・並行作業中の控え方は、[commitの分け方とメッセージ](../../../doc/rules/git-commit.md)を正本とする。
このスキルは、その2つに沿って進める順番と報告の形だけを持つ。

## ワークフロー

### 1. 対象範囲を確認し、検証する

- チャットの依頼と `git status` を照合し、今回の変更を特定する。
- ほかの作業が同じ作業ツリーを編集していれば、[並行作業中のcommit](../../../doc/rules/git-commit.md#並行作業中のcommit)に従って控えてから進める。
- [commitの手順](../../../AGENTS.md#commitの手順)に従ってテストを実行する。検証のために依頼外のコードを変更しない。

### 2. 変更の収集

```bash
git status          # -uallは使わない
git diff            # unstaged
git diff --cached   # staged
```

変更なしなら「コミットする変更がありません」と報告して終了。

### 3. 対象を選び、分ける

[対象の選び方](../../../doc/rules/git-commit.md#対象の選び方)で外すファイルを残し、[分け方](../../../doc/rules/git-commit.md#分け方)でまとまりに分ける。

### 4. コミット作成

各まとまりについて順番に、[ステージの仕方](../../../doc/rules/git-commit.md#ステージの仕方)でステージし、[メッセージ](../../../doc/rules/git-commit.md#メッセージ)の形で commit する。
[使わない操作](../../../doc/rules/git-commit.md#使わない操作)は使わない。

### 5. 完了報告

作成したコミット一覧と、意図的に残した変更を報告する。
